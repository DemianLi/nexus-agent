# 企業功能：自管身分、三種角色、對話隔離與可驗證的稽核

2026-10-14 的決定（類別：項目），取代 [`decisions-2026-10-14-enterprise.md`](https://github.com/DemianLi/nexus-agent/blob/archive/docs-2026-11/.docs/decisions-2026-10-14-enterprise.md)；地圖是 [#1428](https://github.com/DemianLi/nexus-agent/issues/1428)，到今天還沒動工。這一塊 dsh 沒有基準（沒有登入、角色或稽核），屬於「產品需求超出 dsh 的射程」，需求來自客戶與《資通安全責任等級分級辦法》，系統防護需求等級取中級。

決定的要點：

- **身分**：不接客戶的帳號系統，帳號、密碼雜湊（`scrypt` 加鹽）、角色與公鑰由 nexus 在 harness home 自己管。登入失敗連續 5 次鎖 15 分鐘，另有速率限制；閒置登出可設定，登入狀態最長 12 小時；重設密碼由管理員發一次性、有時效的符記；閒置帳號可停用，並提供帳號清單與最近登入時間供審核。
- **角色**：一般使用者、買方管理員、開發者管理員。買方管理員管一般使用者，開發者管理員管管理員帳號。插件、設定、重啟只有開發者管理員能動，而且只能從命令列做，網頁後台上只能看。
- **命令列**：nexus 帳號加個人金鑰（雙因素）。驗證用獨立二進位，原始碼放私有 repo、公開 repo 只放可重現建置的二進位，載入前驗簽；演算法用標準簽章演算法，安全靠私鑰保密。
- **對話**：每個人只看得到自己的對話；買方管理員唯讀、每讀一次記稽核；開發者管理員不能讀別人的對話。使用者刪除是搬到「已刪除」路徑，買方管理員仍看得到；預設保存 365 天，到期自動清除並記稽核；上線前就存在的對話歸開發者管理員。
- **稽核**：所有寫入動作、管理員讀對話、登入成功與失敗、登出都記；使用者讀自己的對話不記。稽核事件與每條 thread 的會話日誌各串雜湊鏈，後台每天顯示錨點由買方管理員保管；客戶有集中日誌主機時可選配轉送。主機要校時，時間戳記對應 UTC。
- **簽章與安裝**（第二版）：一把離線保管的發行金鑰簽插件包與驗證程式；安裝走獨立的系統帳號，`nexus` 對插件目錄只能讀。送審在系統外，系統不擋、不記紙本編號。
- **範圍**：第一版是帳號、角色、登入、對話隔離與保存、帳號管理頁、管理員讀對話記稽核、雜湊鏈與每日錨點、命令列改用帳號加金鑰、部署文件寫校時；第二版是發行金鑰與安裝流程、轉送日誌主機。

## 待查（原文第十節，仍未解）

部署主機的作業系統與 CPU 架構；客戶有沒有集中日誌主機；交付日期；附表十的數值（5 次／15 分鐘、前 3 次不重複、六個月、中級的完整性與一次性符記）要逐字核對原文，原文轉述的數值還沒核；契約有沒有原始碼交付條款；客戶主機的 sudo 由誰管。

## Consequences

- 會話日誌格式會變（每筆加雜湊、thread 加擁有者、刪除換路徑），碰到「磁碟上的日誌是真相」那條線（`harness/apps/harness/src/wire-handler.ts:705`）與 web 讀日誌的一側，兩側要一起改。
- 登入機制換掉：目前每個 serve 行程一顆啟動 token 換簽章 cookie 的做法（`harness/apps/harness/src/browser-auth.ts:12`）退場；變更紀錄的操作者今天是自報的（`docs/operations.md:271`），之後改成驗證過的身分。
