# Jev：未落地，不進產品路徑，落地要 operator 同意

2026-09-22 與 2026-09-25 的決定（類別：項目），取代 [`decisions-2026-09-22.md`](https://github.com/DemianLi/nexus-agent/blob/archive/docs-2026-11/.docs/decisions-2026-09-22.md) 與 [`decisions-2026-09-25.md`](https://github.com/DemianLi/nexus-agent/blob/archive/docs-2026-11/.docs/decisions-2026-09-25.md)。Jev 是 TypeSafe AI 的外部模型服務，只有美西端點、沒有 on-prem，而部署完全在內網、連不到外網，所以它**沒有落地、不進出貨的產品路徑**，repo 裡沒有任何對應程式。要把它落地，必須先有 operator 的同意，不能把這兩份當成已落地的決策。

當時拍板、現在仍是前提的紀律：

- 只當加速器或觀測，拔掉不會紅，不是必要相依；載體是 repo 外的 plugin（零 repo 足跡）。
- 判斷方向是純觀測：判斷只寫紀錄、不改行為；偏題的判斷放 repo 外私有目錄的側邊檔。要做補救之前，先累積到 5 個手檢確認的正例、來自至少兩顆主模型。
- 合規檢查先不做；要做就要重新回答資料外送這一題。

## 用 Jev 加速回覆：三個位置全部 no-go（2026-09-25 結案）

閘門是首個可見輸出的中位數至少省 500ms，且題組品質零退步。三個位置都沒過：

| 位置 | 結果 | 出局的理由 |
|---|---|---|
| 工具清單收窄 | 召回率 67.9%（門檻 100%） | 漏的多是 harness 自己的習慣；prefill 本來就不是瓶頸 |
| 推理強度分流 | 唯一零退步的門檻下，首可見中位反而慢 106ms | 強度要在第一次模型呼叫前決定，Jev 一定串在首可見前面 |
| 單輪內打轉提早收 | 可省的目標消失，最嚴門檻仍誤報 | 頭號長尾是已修好的 grep 工具 bug |

結論：用 Jev 買不到「變快」。使用者等的是模型推理，長尾來自工具 bug、退化輸出與供應商過載，都不需要 Jev。

## Consequences

- 重開時先看的（原文標為建議、未拍板）：新的位置不擋在首可見前面（平行跑），或省下的時間明顯大於 400ms；誤判只能換到一句提醒、不能打斷一輪。
