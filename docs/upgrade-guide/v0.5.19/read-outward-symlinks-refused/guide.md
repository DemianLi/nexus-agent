# 經往外指的符號連結讀，改成拒絕

## 變更

v0.5.19 的檔案圍堵只管變更（寫、改、刪）。讀一律放行，所以工作區裡一條指向工作區外的**目錄**連結，
`read_file`、`ls` 經它讀得到那邊的檔案。只有最後一段是檔案連結時，讀才會失敗（`ELOOP`）。

新版（#1982）讀之前先把路徑 canonicalize，落在工作區根外就拒，碼是 `FS_SANDBOX_DENIED`。
模型看到的是 `[containment] 拒絕 read "…"：經符號連結解析之後落在根之外（mode: …）`。

- **新版會拒的讀法：**
  - `read_file`、`ls`；
  - `grep`、`glob` 的起點；
  - `submit_record` 讀既有表頭；
  - 技能目錄的掃描。
- **最後一段指向根外的檔案連結：** 錯誤從 `ELOOP` 變成這一句。
- **照舊能讀的：**
  - 工作區裡互指的連結；
  - `danger-full-access` 下的讀取。
- **受影響的是：** 工作區（serve 的 `--workspace` 共用區，或 CLI 的 `--workspace`）裡，刻意放了指向工作區外的連結、
  而且要模型讀那邊內容的部署。升級後那些內容讀不到。

## 遷移

1. 找出工作區裡指向工作區外的連結。在 `--workspace` 指的目錄跑：
   `find . -type l -exec sh -c 'case "$(readlink -f "$1")" in "$(pwd -P)"/*) ;; *) echo "$1";; esac' _ {} \;`。
   沒有輸出就不受影響，後面幾步不必做。
2. 每一條連結決定怎麼處理：
   - **模型要讀那邊的內容**：把內容複製進工作區，或把連結換成實際的檔案或目錄。不要把工作區改指到更上層去包住那邊，
     那會連同不該給模型看的東西一起放進來。
   - **模型不需要讀**：不必處理；留著的話，模型讀到它會得到拒絕。
3. 確認：開一條新 thread，請模型讀其中一個留下的連結底下的檔。會話日誌（home 底下的 `sessions/`）裡那一筆 `tool/result`
   帶 `"code":"FS_SANDBOX_DENIED"`；換成工作區裡實際存在的檔，照常讀得到。
