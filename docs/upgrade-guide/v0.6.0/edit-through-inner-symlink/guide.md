# 經根內的符號連結改檔，改成落在本尊

## 變更

v0.6.0 裡，工作區有一條指向工作區內的檔案連結時：

- `read_file` 讀得到它，但接著對同一個路徑 `edit_file` 或 `write_file` 會被拒，碼是 `FS_STALE_VERSION`，模型看到的是
  「`"…"` 在你讀過之後不見了——重新讀一次，再重試。」重讀也一樣，只能改本尊的路徑；
- 沒讀過就對連結 `write_file`，會被當成新建檔而放行，直接蓋掉本尊。

新版（#2260）讀、寫前比對版本、寫入都看連結指到的那個檔：

- 讀過連結之後，`edit_file`、`write_file` 對連結的路徑會成功，改的是本尊，**連結本身留著**，不會被換成一般檔；
- 沒讀過就改，`edit_file` 與 `write_file` 都拒絕，碼是 `FS_NOT_OBSERVED`，本尊不動；要改先讀；
- 指向工作區外的連結不變，照舊拒絕。

**受影響的是：** 工作區裡放了指向工作區內檔案的連結的部署：

- 讀過再改，v0.6.0 一定失敗，新版會成功；不希望模型經由連結改到本尊的，要自己擋；
- 沒讀過就 `write_file`，v0.6.0 會蓋掉本尊，新版回 `FS_NOT_OBSERVED`，模型要先讀再寫。

## 遷移

1. 找出工作區裡指向工作區內檔案的連結。在 `--workspace` 指的目錄跑：
   `find . -type l -exec sh -c '[ -f "$1" ] && case "$(readlink -f "$1")" in "$(pwd -P)"/*) echo "$1";; esac' _ {} \;`。
   沒有輸出就不受影響，後面幾步不必做。
2. 每一條連結決定怎麼處理：
   - **本來就希望模型改得到**：不必處理，升級之後經連結改的就是本尊。
   - **不希望模型經由連結改到本尊**：在 `permissions` 對連結的路徑**和本尊的路徑**各加一條寫入的 deny 規則；只擋連結的路徑不夠，
     模型可以直接改本尊。或者把連結換成一份複本。
3. 確認：開一條新 thread，請模型先讀其中一條留下的連結，再對它做一處小修改。會話日誌（home 底下的 `sessions/`）裡那一筆
   `edit_file` 的 `tool/result` 不帶 `"code"`，本尊的內容改了，`ls -l` 看連結仍是連結；對加了 deny 的路徑，同一個請求回拒絕。
