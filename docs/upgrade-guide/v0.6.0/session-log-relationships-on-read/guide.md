# 會話日誌的事件關係在讀盤時驗

## 變更

v0.6.0 讀會話日誌（home 底下的 `sessions/`）時，只驗單筆事件的形狀與子代理目錄不重複登記，不驗輪、工具、模型呼叫、重試之間的關係。一份日誌就算出現以下情形，
照樣打得開，要到推回對話時才出錯，或者讀錯：輪沒開就收、上一輪沒收又開一輪、工具結果配不到呼叫、模型呼叫的結尾
配不到開頭、重試跳號。執行期的不變量檢查會在 `invariant-log.jsonl` 記下這些違規，但不擋讀盤。

新版（[#1597](https://github.com/DemianLi/nexus-agent/issues/1597)）讀盤時逐顆檢查這些關係，規則跟執行期的不變量檢查是同一支，
第一筆違規就把整份日誌當成壞檔拒開（請求快照與作廢那半段回覆的位置也在這一道裡驗，見
[格式 55](../session-log-format-55/guide.md)）：

- 網頁上那條對話照樣列在清單裡，點開時回 `unknown_error`，訊息是固定的「這條 thread 建不起來，原因記在 serve 的日誌。」；
- `serve` 的日誌記一行警告，開頭是 `[thread] "<對話 id>" 建不起來：會話 "<對話 id>" 的存檔壞了：第 <N> 行不合事件之間的關係（<規則>）：`；
  `session/title` 的來源不對時，這一行寫的是 `第 <N> 行的 session/title …`；
- CLI 的 `--resume` 拋同一個錯，續接失敗。

出貨過的寫入器寫得出來的形狀都照常讀得回，包括 v0.6.0 以前的版本續接過的「end-seed 落下時輪還開著、補結接在後面」那一種。正常產生的
日誌不受影響：出貨夾具 21 份，以及開發機上 482 份實跑日誌（共 927775 顆事件），都沒有任何一筆違規。會被拒的，是手改過、
拼接過，或被別的程式寫壞的日誌。離線掃描（`pnpm --filter @nexus/harness eval:sessions scan`）不跑這一道檢查，找不出這種檔。

**受影響的是：** 曾經手動編輯、合併或截斷過 `sessions/` 底下日誌的部署。

## 遷移

1. 升級前，看 home 底下的 `invariant-log.jsonl`（格式見 [`docs/operations.md`](../../../operations.md)）。`@nexus/core` 的違規紀錄記著
   會話 id，這些會話升級之後很可能打不開：
   `grep '"kind":"violation"' "$NEXUS_AGENT_HOME/invariant-log.jsonl" | grep '"package":"@nexus/core"'`。
   這份紀錄從 v0.6.0 起才有，而且只記執行期寫下的事件，手改過的日誌不在裡面。沒有這種紀錄、也沒手動改過日誌的，後面幾步不必做。
2. 備份 `sessions/` 整個目錄，做法見 [`docs/operations.md`](../../../operations.md)〈升級與回滾〉。
3. 升級之後，對話打不開時，在 `serve` 的日誌搜尋 `不合事件之間的關係`，取得對話 id、第幾行與哪一條規則。日誌門檻要在警告以下
   才看得到。
4. 每一條決定怎麼處理：
   - **不需要繼續這條對話**：留著不動。它照樣列在清單裡，只是打不開；不想看到就照平常的方式封存。
   - **需要裡面的內容**：用第 2 步的備份，在別的目錄以舊版唯讀查看，或直接讀那份 `.jsonl`（一行一顆事件）。不要手改日誌來
     繞過檢查，改出來的關係多半仍然不對。
5. 確認：重新整理網頁、點開剛才那條對話之外的任一條，照常打開；`serve` 的日誌只有第 3 步記下的那幾條對話報
   `不合事件之間的關係`。
