# 受管憑證檔拒絕顯式鍵與空鍵

## 變更

只影響掛受管檔的入口（serve、plugin 試組）。CLI、eval、spike 不讀這份檔，行為不變。

- 舊行為：`? name` 起頭的顯式鍵照一般鍵讀；沒寫鍵的 `: x`、`"": x`、`'': x` 讀成空字串的名字。頂層或外來鍵底下的，當成不認得的鍵，只警告、照常起動；`refs` 裡的因為名字不是環境變數形狀被拒，訊息是「refs 第 L 行第 C 欄的鍵不是環境變數形狀的名字」。
- 新行為：任何一層的顯式鍵、空鍵都整份拒絕。顯式鍵的訊息是 `YAML 錯誤 EXPLICIT_KEY_NOT_ALLOWED（第 L 行第 C 欄）`，空鍵的是 `YAML 錯誤 EMPTY_KEY_NOT_ALLOWED（第 L 行第 C 欄）`，都不含鍵。`refs` 裡的也換成這兩個訊息，不再是「不是環境變數形狀的名字」。用 `?` 寫的集合鍵（`? [a, b]`）從這版起回顯式鍵，不再回 `COLLECTION_KEY_NOT_ALLOWED`。
- 受影響的：受管檔的頂層或別的工具多放的鍵底下有顯式鍵或空鍵的主機，升上來之後 `serve --live` 起不來；沒帶 `--live` 的 serve 照樣起來，但引用受管檔憑證的 MCP 那幾列連線時連不上。依訊息文字判斷錯誤種類的腳本，要認得新的兩個錯誤碼。

## 遷移

1. 打開 `~/.nexus-agent/.credentials.yaml`（或你設定的 harness home 底下的那一份），找到 `?` 開頭的鍵、開頭就是冒號的行（`: x`）、`""` 或 `''` 當鍵的行，刪掉那一段；nexus 只讀 `version` 與 `refs`。
2. `refs` 裡的鍵一律寫在 `名字:` 同一行，名字是環境變數形狀，例如 `NVIDIA_API_KEY: nvapi-...`。
3. 確認改好了：重啟 `serve --live`，起得來；起不來時照訊息裡的行號回檔案裡看。
