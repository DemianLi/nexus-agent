# 受管憑證檔的訊息不印鍵名，名字重複的鍵整份拒絕

## 變更

只影響掛受管檔的入口（serve、plugin 試組）。CLI、eval、spike 不讀這份檔，行為不變。

- **拒絕訊息不再印鍵名，改寫位置。**
  - 舊行為：`refs` 底下的鍵不合格時，訊息原樣帶出鍵名，例如 `refs 的鍵 "BAD-NAME" 不是環境變數形狀的名字`、`refs.A 要是字串`、`refs.A 是空字串（…）`。
  - 新行為：三種訊息都寫鍵的行與欄，不印鍵名，例如 `refs 第 3 行第 3 欄的鍵不是環境變數形狀的名字（長 8 個字元；…）`、`refs 第 3 行第 3 欄那一把要是字串`、`refs 第 3 行第 3 欄那一把是空字串（…）`。
    YAML 錯誤原本只有錯誤碼，現在也帶上 `（第 L 行第 C 欄）`。
  - 理由：把 key 誤貼在鍵名的位置時，鍵名就是秘密，舊訊息會把它整串寫進日誌。
- **不認得的頂層鍵的警告不再印鍵名。**
  - 舊行為：`credentials: 受管憑證檔 <路徑> 有不認得的頂層鍵 "note"、"other"，已略過；…`。
  - 新行為：`credentials: 受管憑證檔 <路徑> 有 2 個不認得的頂層鍵（第 2、5 行），已略過；…`。
- **YAML 函式庫自己的警告不再印到 stderr。**
  - 舊行為：鍵是集合（例如 `? [nvapi-…]`）時，YAML 函式庫經 Node 的 `process.emitWarning` 把整個鍵印到 stderr（`Keys with collection values will be stringified …`）。
  - 新行為：這類警告關掉。檔案照舊依內容收下或拒絕。
- **換成同一個名字的兩個鍵整份拒絕。**
  - 舊行為：YAML 層不同、轉成名字之後相同的兩個鍵（`true` 與 `"true"`、`1` 與 `"1"`），後一個靜靜蓋掉前一個，檔案照收。
  - 新行為：整份拒絕，訊息是 `YAML 錯誤 DUPLICATE_KEY（第 L 行第 C 欄）`，指到後一個鍵。執行期改出這種檔，續用上一份可用的內容並警告一次，跟其他重載失敗一樣。
- **`stat` 本身失敗不再讓請求失敗。**
  - 舊行為：讀好過之後，`stat` 遇到 `ENOENT` 以外的錯誤（例如 `EACCES`）就拋，那一個請求失敗。
  - 新行為：跟讀檔失敗一樣，續用上一份可用的內容，stderr 警告一次。還沒讀成功過的，照舊拋。
- 受影響的：
  - 照舊訊息裡的鍵名找錯誤、或用 `grep` 比對那幾句訊息的人與監控；
  - 受管檔裡剛好有名字重複的兩個鍵的主機，升上來之後 `serve --live` 會起不來。

## 遷移

1. 找出名字重複的鍵：打開 `~/.nexus-agent/.credentials.yaml`（或你設定的 harness home 底下的那一份），看頂層與 `refs` 底下有沒有兩個鍵寫法不同、意思相同的，
   例如 `true:` 與 `"true":`、`1:` 與 `"1":`。留下要的那一個，刪掉另一行。別名鍵（`*名字 :`）現在整個被拒絕，見 [受管憑證檔拒絕 YAML 指令、明示 tag、錨點與別名](../credentials-file-directives-tags/guide.md)。
2. 監控或腳本比對過舊訊息的，改成比對新句子：`的鍵不是環境變數形狀的名字`、`那一把要是字串`、`那一把是空字串`、`個不認得的頂層鍵`。
   要知道是哪一個鍵，照訊息裡的行號回檔案裡看。
3. 確認改好了：重啟 `serve --live`，起得來；檔案裡有外來的頂層鍵時，stderr 那一行寫的是個數與行號，不含鍵名。
