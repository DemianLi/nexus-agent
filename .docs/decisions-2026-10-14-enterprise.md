## 一、這塊沒有 dsh 基準

dsh 沒有登入、角色或稽核（同上草稿 §3-2）。本文每一條都屬 AGENTS.md 偏離規則的第二種理由「**產品需求超出 dsh 的射程**」：需求來自客戶（國家儀器中心）與《資通安全責任等級分級辦法》，補的是 dsh 沒有的整塊。碰到 dsh 有對應物的地方（插件、會話日誌、wire）仍照 dsh。

## 二、層級

1. **系統防護需求等級：中級。** 依《資通安全責任等級分級辦法》附表十（全國法規資料庫，最新修正 115 年 1 月 7 日）。下文標「附表十」的數值是子代理從條文轉述的，**原文還沒逐字核對**，見 §十 待查。
2. **repo 維持公開。**

## 三、身分與帳號

3. **不接客戶的帳號系統。** 帳號、密碼雜湊、角色、公鑰存在 harness home，由 nexus 自己管。
4. **密碼**：`scrypt` 加鹽雜湊，不存明文、不用可逆加密；最短 12 碼；不可與前 3 次相同（附表十普級）；效期可設定，依機關規定，預設不強制更換。
5. **登入失敗**：連續 5 次鎖 15 分鐘（附表十普級），另加登入速率限制擋自動化嘗試（附表十中級）。鎖定與解鎖記稽核。
6. **會話**：閒置登出可設定，預設 30 分鐘（附表十中級，分鐘數由機關自訂）；登入狀態最長 12 小時。取代今天 30 天有效的 cookie。
7. **重設密碼**：內網沒有寄信管道，由管理員重設，發一次性、有時效的符記（附表十中級）；拿符記登入後強制改密碼。
8. **帳號管理**：閒置帳號停用，天數可設定；系統提供帳號清單與最近登入時間，供定期審核（附表十普級）。

## 四、角色

9. **三種角色**：一般使用者、買方管理員、開發者管理員。
10. **誰管帳號**：買方管理員管一般使用者的帳號（建立、停用、重設）；開發者管理員管管理員帳號，避免買方管理員自己升權。
11. **插件、設定、重啟**仍然只有開發者管理員能動（沿用 10-07）。

## 五、命令列與金鑰

12. **命令列寫入口只給 nexus 開發人員與相關團隊用。**
13. **驗證是 nexus 帳號＋個人金鑰（雙因素）。** 每人一把，私鑰只在本人手上並加密保存、不上傳遠端倉庫；資料庫只存公鑰。產生金鑰的程式另外保管，不隨產品出貨。
14. **網頁後台只用密碼。** 插拔、改設定、重啟只能從命令列做；開發者管理員在網頁上只能看。
15. **金鑰驗證程式**：
    - 用 Rust 寫成二進位，nexus 以子行程呼叫（stdin 傳挑戰、stdout 讀結果），不做 N-API。選 Rust 是為了跟日後可能的 harness Rust 重構維持最少種語言。
    - **原始碼放私有 repo**，公開 repo 只放二進位。目的是客戶要求提交原始碼時，這一塊不在公開原始碼裡。
    - 每次更新二進位的 PR 內文寫明私有 repo 的 commit SHA、建置指令、二進位的 SHA-256；建置要可重現（固定工具鏈、`--locked`、路徑重映射），審查方能自己編一次對上雜湊。
    - 二進位本身用發行金鑰簽章，nexus 載入前驗簽。
    - 演算法用標準簽章演算法（例如 Ed25519），不自己發明。安全建立在私鑰保密上，不靠驗證邏輯隱藏（repo 是公開的）。

## 六、對話

16. **每個人只看得到自己的對話。** thread 按人隔離，取代今天「拿到 cookie 就看得到 `/threads` 全部」。
17. **買方管理員能讀所有人的對話與思考過程，只讀**；每讀一次記稽核。**開發者管理員不能讀別人的對話。**
18. **刪除**：使用者刪除對話時，對話從使用者的儲存路徑搬到另一個「已刪除」路徑。對使用者來說是刪掉了，買方管理員仍看得到。搬移記稽核。
19. **保存一年**：每天自動清除到期的對話，天數可設定、預設 365；清除本身記稽核。附表十普級要求日誌至少六個月，一年在要求之上。
20. **帳號上線前就存在的對話**歸到開發者管理員帳號，當作他自己的對話；買方管理員也看不到。

## 七、稽核

21. **記哪些**：所有寫入動作（插拔、改設定、重啟、帳號與角色異動、刪除對話、清除到期資料）、管理員讀了誰的對話、登入成功、登入失敗、登出。使用者讀自己的對話不記。
22. **內容**：對話與思考過程本身就是會話日誌，屬稽核內容（第 19 條保存一年）。
23. **防竄改（附表十中級要求完整性保護）**：
    - 稽核事件串成一條雜湊鏈，每筆帶前一筆的雜湊。
    - **每條 thread 的會話日誌也各自串成一條雜湊鏈。**
    - 後台每天顯示當天的錨點：事件鏈的鏈頭，加上當天所有對話鏈的鏈頭。由買方管理員保管（抄下或截圖）。核對時從頭重算，比對錨點。
    - 客戶有集中日誌主機（syslog／SIEM）的話，稽核事件即時轉送一份過去，做成選配。
24. **時間**：主機定期與基準時間源同步，時間戳記對應 UTC（附表十各級）。寫進部署文件。

## 八、簽章與安裝

25. **一把發行金鑰**，由指定一到兩人離線保管，跟命令列登入的個人金鑰分開。公鑰編進 Rust 驗證程式。插件包與驗證程式二進位都用它簽。事先寫好撤銷與換鑰程序（外洩時靠驗證程式新版本換公鑰）。
26. **送審在系統外**，系統不擋、不記紙本編號（沿用 10-07）。
27. **安裝流程用獨立的系統帳號**：
    - `nexus` 跑 serve 與 agent，對插件目錄只能讀。
    - `nexus-installer` 擁有插件目錄。
    - 開發者管理員從命令列安裝：先過 nexus 帳號＋金鑰，再經一條只開放安裝指令的 sudo 規則切到 `nexus-installer`；安裝程式驗發行簽章、查跟 core 的版本相容性（[`decisions-2026-10-11.md`](decisions-2026-10-11.md) 第 15 條），都過才寫入，並記稽核。
    - 兩個帳號與 sudo 規則寫進部署文件；客戶主機的 sudo 由誰管待確認。

## 九、範圍

**第一版**：

1. nexus 帳號、三種角色、登入（§三全部）；thread 按人隔離、刪除搬路徑、保存一年與自動清除、上線前對話歸屬（§六）。
2. 帳號管理後台頁：買方管理員管一般使用者，開發者管理員管管理員帳號；閒置帳號停用與審核清單。
3. 買方管理員讀所有人的對話，每次讀記稽核。
4. 稽核事件與雜湊鏈（事件鏈＋每條對話鏈）、後台每日錨點。
5. 命令列改用 nexus 帳號＋個人金鑰（含 Rust 驗證二進位、私有 repo、可重現建置）。理由：變更紀錄的操作者今天是自報的 `SUDO_USER`／`LOGNAME`（`docs/operations.md` 「操作者記的是自報」那段），地圖終點要求它是驗證過的身分。
6. 部署文件寫明校時。

**第二版**：

7. 發行金鑰、插件包簽章、`nexus-installer` 帳號與 sudo 規則。今天沒有「安裝新的插件程式碼」這條路（插件隨產品出貨，寫入口只做停用、啟用、改設定，#1412），簽章跟安裝流程一起做。若客戶第一次交付就要安裝新插件，移進第一版。
8. 轉送客戶日誌主機（選配）。

## 十、待查

- 部署主機的作業系統與 CPU 架構（決定 Rust 二進位的建置目標）。
- 客戶有沒有集中日誌主機。
- 交付日期。
- 附表十原文逐字核對：本文轉述的數值（5 次／15 分鐘、前 3 次、六個月、中級的完整性與一次性符記、高級的多因子與異地備份）。
- 契約有沒有原始碼交付條款。
- 客戶主機的 sudo 由誰管。

## 十一、連帶影響

- **會話日誌格式會變**：每筆加雜湊、thread 加擁有者、刪除時換路徑。這碰到 S2「會話日誌是唯一真相」那條線，也碰到 web 讀日誌的那一側；動工時先知會 dev-ui。
- **登入機制換掉**：#424 的「一個 serve 行程一顆 token」退場。
- **執行中清單的快照**（#1406）在有管理員身分之後改走只讀路由（`docs/operations.md:572`）。
- **歸屬**：`apps/harness`、`packages/*` 歸 dev-harness；登入畫面、帳號管理、稽核與錨點頁在 `apps/web`，歸 dev-ui。
