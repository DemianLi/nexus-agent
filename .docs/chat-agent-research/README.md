# AI Agent 對話完成框架：arXiv 文獻調研

這份調研替「AI Agent Dialogue Completion Framework」的 8 個節點各寫了一章，再逐條分析節點之間的 6 條邊。本頁是入口，依序是：範圍與方法、跨節點的發現、六條邊、整個框架的未解問題，最後說明各章的標記、計數與查核工具怎麼讀。

本頁與各章維持純研究，不寫產品建議，也不寫「對 nexus 的意涵」。從八章歸納出的通用實作方案另成一份 [`blueprint.md`](blueprint.md)：它依證據分級列出每個決策，同樣不對照 nexus，也不改變各章的結論。

### 方法摘要

完整方法見 [`plan.md`](plan.md)，這裡只列骨架。

1. **發現與篩選**
   - 每個節點分三路找候選：綜述 snowball、arXiv 關鍵字、商用採納。
   - 每個 arXiv ID 都要經 [`tools/arxiv_tool.py`](tools/arxiv_tool.py) 解析並比對標題，對不上就丟。這一關由程式把守。
   - 第一輪篩選 agent 轉抄的數字不可信，所以改由 [`tools/pool.py`](tools/pool.py) 以程式建候選池、算引用數與硬旗標，agent 只判斷範圍，另設反方 agent 挑錯。
   - 之後逐節點人工複核歸屬，理由記在 [`tools/review_overlay.py`](tools/review_overlay.py)，再由 [`tools/build_shortlist.py`](tools/build_shortlist.py) 去重，產出 [`data/shortlist.json`](data/shortlist.json)。同一篇論文只會有一個主節點。
   - 影響力依據三種訊號：Semantic Scholar 引用數、發表處，以及附 URL 的商用採納證據。2025–2026 的新論文引用數還少，只能靠頂會正式論文或商用採納證據入選。
2. **精讀**
   - 一篇論文由一個 agent 讀全文（arXiv HTML 或 ar5iv），寫成結構化筆記 [`notes/<id>.json`](notes/)，並交出原文錨點。
   - 主選讀完，每個節點都已超過 20 篇，所以這一輪（W2）沒有動用候補。後來的針對性補讀（第 5 步）才讀了其中一部分。
3. **綜合與查核**
   - 每個節點先分組寫段落草稿，再組成一章。
   - 查核員先跑 [`tools/check_chapter.py`](tools/check_chapter.py)，列出找不到出處的數字，再做對抗式查核。
   - 另一個 agent 挑出能用確定性方法驗的主張，寫程式驗證，放在 [`verify/`](verify/)。
   - 修訂後再跑一次數字比對，每章另有一個 critic。
   - 六條邊各由一個 agent 分類。
4. **文字修訂（W4）**
   - 章節 critic 與全域 critic 找出的缺口裡，最多的一類是把「本調研沒讀到」寫成「領域裡沒有」。
   - 這一輪只做文字修訂、不補讀：否定句收窄到本調研讀過的論文，補上語料內的反例；critic 點名、但本調研沒讀的論文，先經 ID 閘門確認存在，再以「標題（arXiv ID，未讀）」列進各章的〈已知缺口與未讀〉，不引用它們的任何數字或結論。
   - 驗證類的缺口寫成程式，每章修訂後另做一次對抗式稽核，最後同步本頁。
5. **針對性補讀與整合（W5、W6）**
   - 選文：每一篇都對應某章一句「本調研讀過的論文裡沒有」之類的否定句，挑來檢驗那句話；不是重跑發現與篩選。
   - 精讀：20 篇各由一個 agent 讀全文，第 1 章另外補讀 1 篇，也是一個 agent；讀稿腳本都明確指定 Opus。筆記格式與錨點驗證和 W2 相同，21 篇都有筆記與快取全文，錨點全數合格、全數計入。
   - 整合：各章依新筆記改寫，腳本設定為每章一個修訂 agent、一個稽核 agent，都指定 Opus；新增的驗證程式見〈程式驗證〉。六條邊的筆記清單（`.cache/work/w3/edge-E?.md`）也依新筆記重新產生，但沒有重跑六個邊分類 agent（見〈六條邊〉）。最後同步本頁。

[`plan.md`](plan.md) 記錄了一條與名單可信度有關的事：前兩輪篩選時子代理預設跑 Haiku，它們轉抄的數字與理由裡有捏造，可能與此有關，但沒有做過對照。精讀起每個 agent 都明確指定 Opus。

## 跨節點的主要發現

以下每一條都至少橫跨兩個主節點，括號裡是出處論文所屬的節點。這些是本調研讀過的論文裡看到的形狀，不是對整個領域的判斷：句子裡的「只有」「沒有」「很少」，範圍都是本調研讀過的論文，包括針對性補讀的 21 篇；沒讀的部分見各章的〈已知缺口與未讀〉。補讀的論文多半在第一次出現時標明「補讀的」。論文自己的結論不另加標記；精讀 agent 的分析標「精讀時發現」「精讀時指出」這類字樣；章節撰寫者的歸納標「依 Tn 章的歸納」，換算則寫出算式；程式重算過的標「程式驗證」。

1. **不需要模型的平凡解，在多個節點追平或勝過被報告的方法，而原論文多半不報這個基準**（T1、T3、T4、T7、T8）
   - IN3 的模糊判斷準確率 85.19%，低於一律判模糊的 95/108 = 87.96%（精讀時發現，程式驗證證實）[arXiv:2402.09205]。
   - 補讀的 ID-OOS 那篇補報了拒識的 precision。5-shot BANKING77-OOS 的 ID-OOS 情境下，precision 是 39.8–46.3；隨機拒識的 precision 就是測試集的 OOS 比例 1,080/(2,000＋1,080)≈35.1%，只高出 39.8 − 35.1 = 4.7 到 46.3 − 35.1 = 11.2 點（精讀時指出，程式驗證證實）[arXiv:2106.04564]。
   - 補讀的 AgentMonitor 的測試集約 30% 是插入的正例。精讀時推算，全配置的誤報率約 9.2%，陽性比例若只有 1%，Precision 只剩約 10%（程式驗證證實）[arXiv:2311.10538]。
   - R-Judge 以 unsafe 為正類，全部判 unsafe 的全集 F1 就有 69.04；11 個模型中只有 GPT-4o 的 74.45 高於它（精讀時發現，程式驗證證實）[arXiv:2401.10019]。
   - AgentRewardBench 的副作用金標只有 72/1106 ≈ 6.51%，GPT-4o mini (A) 的 precision 7.2 幾乎等於基率（精讀時發現，程式驗證證實）[arXiv:2504.08942]。
   - OSWorld 一律回 FAIL 可拿 30/369 = 8.13%；Table 5 的 26 組模型×設定只有 5 組高過這個地板（精讀時發現，程式驗證證實）[arXiv:2404.07972]。
   - τ-bench airline 上，ABC 的 do-nothing agent 拿到 38% [arXiv:2507.02825]；τ-bench 原排行榜在 airline 最高的是 gpt-4o 的 35.2 [arXiv:2406.12045]。這兩個數字不能直接並排讀成「什麼都不做贏過最強模型」，T8 章列了三條但書，與這組對照直接相關的是下面兩條；第三條是 retail 的分母不明：3.6% 對不上 115 題的任何整數題數（4 / 115 = 3.48%、5 / 115 = 4.35%），ABC 也沒交代 retail 用的是哪一組題目 [arXiv:2507.02825][arXiv:2406.12045]。一是版本不同：ABC 的 38% 出自它撰寫當下的 τ-bench 版本，τ-bench 事後修過資料集，所以這是拿不同版本的數字相比 [arXiv:2507.02825][arXiv:2406.12045]。二是口徑不同：精讀時指出，38% 是 trivial agent 的得分，不是真實 agent 分數的偏差量，一個真的查了規則並拒絕的 agent，在那些不可能題上拿分是應得的 [arXiv:2507.02825]。
   - 觸發修正的評估器也可能有同樣的形狀。2404.06474 的評估器與 WebArena oracle 的一致率是 74.4–82.1% [arXiv:2404.06474]。精讀時指出，若這批軌跡的成功率確實落在 agent 原報與重現的 14.4%–15.6% 之間，一律判失敗就有約 84–86% 的準確率（100% − 15.6% = 84.4%，100% − 14.4% = 85.6%）；論文只報 accuracy，混淆矩陣只畫在 Figure 4，所以這是條件式的推算 [arXiv:2404.06474]。
   - 不是每個平凡基準都站得住：Who&When 的「一律猜第 1 步」能不能勝過所有方法，程式驗證的結論是無法判定 [arXiv:2505.00212]。

2. **決定「要不要介入」的閘門，訊號普遍偏弱；閘門的準確度也不足以預測接上之後的淨效益**（T1、T3、T4、T5、T6）
   - 何時問：Clarify When Necessary 裡，六個組合各自最佳方法的 AUROC 只有 0.531–0.628，四種方法全部算進來還有 5 格低於隨機的 0.5（程式驗證）[arXiv:2311.09469]。精讀時依 Future Turns 的表格相減，在相同直接回答比例下，提問決策的 F1 只比隨機高一點，Llama2、Llama3、Gemma 依序是 24.3 − 23.4 = 0.9、25.1 − 24.5 = 0.6、24.6 − 23.6 = 1.0 [arXiv:2410.13788]。
   - 何時拒識：補讀的 ID-OOS 那篇的門檻，取在開發集上 in-scope 準確率加 OOS recall 最大的地方。精讀時回推，5-shot BANKING77-OOS 的 ID-OOS 情境有約 52% 到 73% 的合法語句被判成範圍外，論文自己沒有點出（程式驗證證實）[arXiv:2106.04564]。
   - 何時修正：SCORE 固定 refiner、只換驗證器，self-verifier 的增益只有 −0.3 到 +0.4 [arXiv:2404.17140]。補讀的 Stechly et al. 讓 GPT-4 驗證自己的答案，偽陰性率在圖著色是 95.8%、在 Mystery Blocksworld 是 97.09%，整條迴圈低於單次作答；換成程式驗證器才穩定提升 [arXiv:2402.08115]。
   - 何時要回饋：Self-feeding 的滿意度分類器 F1 是 0.84，不確定度基線是 0.56。但分類器看了使用者的下一句話，基線是 bot 開口前的預測，兩者可用的資訊不同（程式驗證以原文證實）[arXiv:1901.05415]。
   - 何時告警：CoT 監控器對只看行動的監控器，合併召回率是 95% 對 60% [arXiv:2503.11926]；SHADE-Arena 的 monitor 最佳 AUC 0.87 [arXiv:2506.15740]。直接對 CoT 監控器施加 RL 壓力後，召回率掉到接近 0 [arXiv:2503.11926]。不施壓也不保證看得見：補讀的 Chen et al. 在 6 個注入 reward hack 的合成 RL 環境裡，有 5 個環境的 CoT 說出 hack 的比例不到 2% [arXiv:2505.05410]。T3 章指出，這和 Baker 等人的 95% 不是受控對照，模型、任務、觀測範圍與判定方式全都不同 [arXiv:2505.05410][arXiv:2503.11926]。
   - 閘門準確度與下游淨效益對不上的例子有三個，分屬三個節點，方向也不一樣：
     - SCORE（T5）：gpt-3.5-turbo 驗證器的 F1 是 59.7，接上之後修正後的準確率卻 −11.2 [arXiv:2404.17140]。
     - Clarify When Necessary（T1）：MT GPT-3 上 Self-Ask 的 AUROC 0.371 是全表最低，b=20% 與 30% 的增益占比 25%、37% 卻是四個方法中最高 [arXiv:2311.09469]。精讀時推論，AUROC 的正類是二元的「會不會變好」，預算指標算的是淨增益，兩者量的不是同一件事 [arXiv:2311.09469]。
     - 2404.06474（T4）：評估器一致率只有 74.4–82.1%，依第 1 條的條件式推算可能還不及一律判失敗；接上 Reflexion 之後，仍帶來 16% 與 29% 的相對提升 [arXiv:2404.06474]。
     - 三個例子各只有一篇、都沒有檢定。本頁只拿它們說明「閘門準確度這一個數字，不足以判斷接上之後的淨效益」，不當成規律。
   - 與門檻無關的量法很少見：依 T1 章的歸納，在 T1 讀過的論文裡，量「不作為」決策時用上與門檻無關量法的只有兩處，都是 AUROC [arXiv:2101.03778][arXiv:2311.09469]。補讀的 ID-OOS 那篇專門檢討拒識的評估，報的三個指標也都依門檻而定 [arXiv:2106.04564]。別節點另有兩處：CRITIC 當幻覺偵測器的 AUROC 是 0.81–0.83，但只有降毒任務拿偵測結果當閘門 [arXiv:2305.11738]；SHADE-Arena 的監控器也以 AUC 計（見上一項）[arXiv:2506.15740]。

3. **知道答案的一方常被放進迴圈裡，量到的增益有一部分只是上限**（T1、T3、T4、T5、T6、T7）
   - Huang et al. 在同一個 GPT-3.5、CommonSenseQA 上，用標籤決定何時停止得 89.7，拿掉標籤只剩 41.8 [arXiv:2310.01798]。RCI 附錄自己的無標籤版本，CommonSenseQA 也從 64.56 掉到 46.06 [arXiv:2303.17491]。
   - 補讀的 Stechly et al. 裡，帶來穩定提升的是 sound 驗證器，而它同時也是最終判對錯的那一方；依 T5 章的歸納，它給的位元等於 oracle [arXiv:2402.08115]。
   - 精讀時發現，Future Turns 的評估模擬器拿得到答案 [arXiv:2410.13788]。Clarify When Necessary 裡被選中發問的輸入，拿到的是 oracle 問答而不是模型自己的問題，所以表中增益是上限（精讀時發現）[arXiv:2311.09469]。
   - iEvaLM 的模擬器會說出目標標題。排除這類洩漏造成的成功後，UniCRS 在 ReDial 的 Recall@1 從 0.219 掉到 0.029 [arXiv:2403.16416]。
   - MINT 的環境在模型提出解答時以 ground truth 判對錯並回報，預設的 GPT-4 回饋者則看不到 ground truth [arXiv:2309.10691]；精讀時指出，這讓 MINT 的「使用者」實際上握有神諭式的對錯訊號 [arXiv:2309.10691]。
   - 失敗定位後注入診斷重跑的閉環，都在整條任務被判定失敗之後才啟動（AgentDebug、AgenTracer）[arXiv:2509.25370][arXiv:2509.03312]。AgenTracer 的設計本身就以 oracle 失敗訊號為前提 [arXiv:2509.03312]；精讀時指出，AgentDebug 接近帶 oracle 的 pass@k [arXiv:2509.25370]。
   - 監控這一側也有同樣的形狀。補讀的 Ctrl-Z 量到的安全性，精讀時指出是在攻擊目標已知、監控器提示詞照著攻擊特徵寫、載荷一經稽核就很明顯的條件下量的；換成未知威脅時能補多少，論文沒有量 [arXiv:2504.10374]。

4. **產生行為或訓練訊號的一方，常常也是判分的一方**（T1、T4、T5、T6、T7、T8）
   - 精讀時依 repo 發現，Proactive Agent 用同一個 RM 篩訓練資料又當評審 [arXiv:2410.12361]；精讀時指出，STaR-GATE 的 gold 與評審都是 GPT-4 [arXiv:2403.19154]；精讀時發現，CollabLLM 的訓練與評估用同一個模擬器、同一份提示詞 [arXiv:2502.00640]。
   - 精讀時發現，Alexa 的標籤、上傳前過濾與 A/B 缺陷率，都出自同一個 friction 模型 [arXiv:1911.02557]；精讀時發現，JOUST 的 RL-Joint 是對著一起被最佳化的模擬器量成功率 [arXiv:2107.11904]；CIPHER 的模擬使用者與偏好推論都是 GPT-4 [arXiv:2404.15269]。
   - 補讀的幾篇也是。1909.01388 的 Auto Success 在用來訓練該系統的同一個模擬器上量，精讀時依 Table 2 自算它與真人 Solved Ratio 的 Spearman 只有 0.14 [arXiv:1909.01388]。Chai 以延續標籤訓練的獎勵模型 MCL 最高、D30 留存卻最低，而延續標籤與 MCL 量的是同一件事，也就是一則回覆之後使用者有沒有再送訊息 [arXiv:2303.06135]。
   - T8 補讀的兩篇對話獎勵論文：精讀時指出，GDPL 的 agenda 與 VHUS 兩組結果都在同一個模擬器上訓練和評估；依 T8 章的歸納，同一個模擬器出題、扮演使用者、判成敗，也是訓練環境 [arXiv:1908.10719]。Fantastic Rewards 的逐輪獎勵以 Combined Score 的排序監督，精讀時指出監督目標就是測試指標 [arXiv:2302.10342]。
   - T4 補讀的 IPR：精讀時指出，它用來量「每步 reward 有沒有提升」的，正是建構訓練訊號的同一個 scorer，是循環量測 [arXiv:2406.11176]。
   - 精讀時發現，Self-Refine 對話任務的評審與回饋共用同一套面向 [arXiv:2303.17651]。
   - 依 T7 章的歸納，T7 讀過的八篇評審研究裡，自我偏好都只有觀察式比較，沒有一篇固定回答品質做受控實驗 [arXiv:2306.05685][arXiv:2305.17926][arXiv:2404.04475]。MT-Bench 說明了原因：沒辦法在不改變品質的前提下把一個回答改寫成另一個模型的風格，但這是 2023 年的說法 [arXiv:2306.05685]。以自我偏好為題的後續研究本調研沒讀，例如 LLM Evaluators Recognize and Favor Their Own Generations（arXiv 2404.13076，未讀）；依標題，它研究 LLM 評估者認不認得、偏不偏好自己的生成，能檢驗「沒有受控實驗」這一句是否只是選文造成的。
   - 精讀時發現，HAL 用來回收自我修正片段的 judge 本身也是受測模型 [arXiv:2510.11977]。
   - 在本調研讀過的論文裡反例很少：2410.13788 讓訓練與評估用不同的模擬器 [arXiv:2410.13788]；GenTUS、NUS 與補讀的 1909.01388 用交叉模型評估，每個策略除了自己的訓練模擬器，也拿別的模擬器測 [arXiv:2208.10817][arXiv:1805.06966][arXiv:1909.01388]。

5. **偵測做得細的地方沒有接上修正，接上修正的地方偵測很粗**（T3、T4、T5、T8）
   - Who&When 的 step-level 最佳只有 14.2% [arXiv:2505.00212]；TRAIL 的聯合準確率在 GAIA 是 0.183、在 SWE 是 0.050 [arXiv:2505.08638]。E3 的邊分類把兩篇都歸為只做偵測、沒有接到修正迴路 [arXiv:2505.00212][arXiv:2505.08638]。
   - Tyen et al. 的 LLM 找錯最佳只有 52.87，低於它用模擬分類器估出的約 60–70% 門檻 [arXiv:2311.08516]；精讀時發現，論文微調出的偵測器從沒接回修正迴圈跑端到端 [arXiv:2311.08516]。
   - 依 T3 章的歸納，R-Judge、SHADE-Arena、Llama Guard 只做偵測 [arXiv:2401.10019][arXiv:2506.15740][arXiv:2312.06674]。補讀的 AgentMonitor 設計上低於門檻就中止測試、把紀錄交給人審查，不觸發修正；精讀時指出，它的數字全來自錄好紀錄的離線重播，攔截沒有實際發生 [arXiv:2311.10538]。
   - 在 T3 計入的監控論文裡，接上處置的有三篇：AI Control、補讀的 Ctrl-Z 與 Baker 等人。處置都由 agent 以外的一方執行：可信模型接手、在同一個模型的幾個樣本之間重抽挑選，或測試期 rejection sampling [arXiv:2312.06942][arXiv:2504.10374][arXiv:2503.11926]。依 T3 章的歸納，其中只有 Ctrl-Z 在多步 agent 的每一步執行前處置，但「部署」是模擬出來的 [arXiv:2504.10374]。
   - T3 章也說明，它的監控一塊實際涵蓋的是「監控器看什麼、怎麼被評估」，以安全為主。範圍裡的追蹤與日誌、白箱監控，在 T3 計入的論文裡仍是零篇；非安全類的異常偵測只有補讀的 AgentMonitor 碰到一角，它的陽性類含離題輸出，但逐步判斷、和不安全合併計分 [arXiv:2311.10538]。追蹤與日誌、非安全類的異常偵測兩塊，別的節點有論文。這是名單的覆蓋，不是文獻現況。
   - 補讀的兩篇各缺一塊。T5 的 Stechly et al. 把觸發器的偽陽性率與偽陰性率分開報，也量了觸發後整條迴圈的準確率，但判定對象是整份最終答案，不是軌跡 [arXiv:2402.08115]。T4 的 IPR 在軌跡上用多次 rollout 估出的步驟分數定位錯誤步，被修正的卻是模型權重，發生在訓練期 [arXiv:2406.11176]。
   - 在本調研讀過的論文裡，真正由軌跡內容觸發修正的，觸發器多半是手調規則或精確比對。例如 Reflexion 在 ALFWorld 以「同一動作同一回應連續出現」或「動作數超限」判失敗 [arXiv:2303.11366]；AgentQuest 以字串比對擋下重複的猜測 [arXiv:2404.06411]。T3 章指出，這類重複動作觸發規則都沒有評估自己的誤報與漏報 [arXiv:2303.11366][arXiv:2404.06411][arXiv:2406.12373]。
   - 依 T4 章的歸納，失敗歸因的評估集（Who&When、AgenTracer、AgentDebug）只收失敗軌跡，這三篇的偵測器從沒在成功軌跡上量過誤報率 [arXiv:2505.00212][arXiv:2509.03312][arXiv:2509.25370]。本調研讀過的論文裡最接近的是 2404.06474：它的評估器兩類軌跡都判，但文字只報 accuracy，混淆矩陣只畫在圖裡（精讀時指出）[arXiv:2404.06474]。

6. **模擬使用者是好幾個節點共用的量具，偏差沒有固定方向，效度證據也不穩**（T1、T2、T6、T7、T8）
   - 只換使用者 LLM、agent 固定為 GPT-4o，τ-Bench retail 的成功率就在 67.0% 到 75.9% 之間變動 [arXiv:2601.17087]。真人對話的失敗有 62.2% 歸因於使用者，模擬對話只有 40.0% [arXiv:2601.17087]。
   - 有的偏差讓任務變簡單：排除目標洩漏後，ChatGPT 在 ReDial 的 R@10 從 0.539 掉到 0.271 [arXiv:2403.16416]。有的讓任務變難：τ²-bench 模擬器的 critical error 在 airline 達 13% [arXiv:2506.07982]；iEvaLM 自己的對照裡，模擬端的 R@10 全面低於人扮使用者 [arXiv:2305.13112]。規則式模擬器偏易還是偏難也依實作而定：T6 章原本依 NUS 與 GenTUS 的模擬端資料，把 agenda 模擬器讀成「太好對付」；補讀 1909.01388 後改成「依實作而定」，NUS 與 GenTUS 用的 ABUS 偏容易，MetaSim 重做的 Agenda 與 1909.01388 自建的 agenda 偏難 [arXiv:1805.06966][arXiv:2208.10817][arXiv:2204.00763][arXiv:1909.01388]。
   - 換一個模擬器，分數可以整個移位。T8 補讀的 GDPL 在 agenda 模擬器上的 Success 是 86.5%，換成 VHUS 神經模擬器只剩 19.7%，19.7 ÷ 86.5 ≈ 0.23 [arXiv:1908.10719]。精讀時指出，兩組都在同一個模擬器上訓練和評估，所以這不是跨模擬器泛化的測試，而是兩個環境各自的難度 [arXiv:1908.10719]。
   - 模擬器的取樣會混進量到的變異。Lost in Conversation 的使用者模擬器以 T=1.0 取樣，精讀時發現量到的 unreliability 混進了模擬器端的變異 [arXiv:2505.06120]。精讀時也發現，τ-bench 重跑的變異主要來自溫度 1.0 的使用者模擬器 [arXiv:2406.12045]。
   - 排名效度的證據互相打架。GenTUS 的真人 success 是 GenTUS 0.86、ABUS-S 0.79、ABUS-T 0.75；以 ABUS-T 或 ABUS-S 測試時，模擬端的順序完全相反（程式驗證證實）。但作者自己說兩個 ABUS 的真人差距不顯著 [arXiv:2208.10817]。NUS 的真人端照表面值六對都不顯著（程式驗證）[arXiv:1805.06966]。T6 章計入的比較裡，做過「多個系統、模擬與真人各排一次」的有六篇：NUS、1909.01388、2006.08732、GenTUS、MetaSim、iEvaLM [arXiv:1805.06966][arXiv:1909.01388][arXiv:2006.08732][arXiv:2208.10817][arXiv:2204.00763][arXiv:2305.13112]。
   - 系統數最多的是 MetaSim Table 5：同一個基礎系統造出的 7 個受控降級變體，模擬與真人兩端都有 Success，放在一起時名次幾乎無關，事後拿掉兩個矛盾格才大致一致（程式驗證）；而且這 7 個不是彼此獨立的系統 [arXiv:2204.00763]。
   - 彼此獨立的系統最多的是補讀的 1909.01388：6 個模擬器各訓出一個 RL 系統 [arXiv:1909.01388]。程式驗證以 Kendall τ 重算，6 個模擬器的交叉平均對真人 Solved Ratio 只有 2 對逆序，τ = (15 − 2 × 2) ÷ 15 ≈ 0.733；在各自訓練模擬器上量的 Auto Success 有 7 對逆序，τ = (15 − 2 × 7) ÷ 15 ≈ 0.067 [arXiv:1909.01388]。單用一個模擬器時，一致程度依用的是哪一個而定，有的與交叉平均相當，有的幾乎無關（程式驗證）[arXiv:1909.01388]。
   - 補讀的 2006.08732 只有 3 個系統，C 在所有名次都墊底，有資訊的只有 A、B 的先後；群眾最常誤認為真人的 CIR6-PKG，是三個模擬器裡唯一把 Success Rate 名次排錯的（程式驗證證實）[arXiv:2006.08732]。1909.01388 也是同一個方向：人讀模擬對話打的 Overall 分數與用該模擬器訓出的系統的真人 Solved Ratio，精讀時算出 Spearman 約 −0.09，程式驗證重現了這個係數 [arXiv:1909.01388]。兩篇論文本身都沒有把逼真度與下游名次放在一起分析。
   - 放寬到其他節點，T7 的 AlpacaFarm 報模擬與真人的方法排名 Spearman 0.98，拿掉 4 個未訓練系統後是 0.94 [arXiv:2305.14387]。但它模擬的是單輪的偏好標註者，不是多輪互動中的使用者；精讀時指出，真正是「模擬回饋訓練對上真人回饋重訓」的只有 4 個方法 [arXiv:2305.14387]。
   - 所以 T6 章的判斷改成條件式的：就本調研讀過的論文而言，多輪互動的模擬使用者排出的對話系統名次能不能保住真人名次，系統數最多、彼此獨立的正面證據來自 1909.01388 的 6 個系統，一致程度取決於測試池的組成；它的模擬器是經典的 agenda 與監督式模擬器，不是 LLM，真人也拿著與模擬器同分佈的既定目標 [arXiv:1909.01388]。T6 章認為真正沒解的，是在夠多、彼此獨立的系統上同時跑模擬使用者與真人，並交代測試池怎麼挑。
   - 其他節點也在用這把量具：依 T1 章的歸納，在 T1 把「問、答、再推斷」閉起來的論文裡，量化對照過真人的只有 GATE [arXiv:2310.11589]；T7 的 MT-Bench-101 用金上下文重播，它自己的對照顯示這會讓後續輪次的分數虛高 [arXiv:2402.14762]。

7. **同名指標不是同一把尺：實作、版本、施測協定或刻度一換，數字就跟著換**（T2、T7、T8）
   - 同一個 MDBT，MultiWOZ 論文報的 JGA 是 80.9，TRADE 重跑只有 17.98 [arXiv:1810.00278][arXiv:1905.08743]。FnCTOD 的逐領域平均比多領域 Overall 高 62.59 − 38.71 = 23.88 [arXiv:2402.10466]。
   - 被別篇引用時數字也會變。補讀的 SOM-DST 在 MultiWOZ 2.1 自報 53.01，TripPy 的表把它列成 52.57，D3ST 的主表列成 51.2 [arXiv:1911.03906][arXiv:2005.02877][arXiv:2201.08904]。T2 章指出，快取裡只有 SOM-DST 一個版本的全文，分不出另兩個數字是來自早期版本還是抄錯。
   - 同一篇、同一個模型換 MultiWOZ 版本也會變：D3ST Base 在 2.1／2.2／2.3／2.4 的 JGA 是 54.2／56.1／59.1／72.1；但它只對 2.1 套用 TRADE 的前處理腳本，所以 2.1 與後三版之間的差距混著版本與前處理兩個因素 [arXiv:2201.08904]。
   - MultiWOZ 統一重算後，UniConv 的 Inform／Success 從 84.7／76.3 掉到 66.7／58.7，而語料本身只有 93.7／90.9 [arXiv:2106.05555]。
   - WebArena 自報的人類成功率是 78.24% [arXiv:2307.13854]；OSWorld 用自己的協定重測 WebArena 題目，得到 88% [arXiv:2404.07972]。GAIA 的人類分數只在有效題上計算，而論文對有效題有兩種定義 [arXiv:2311.12983]。
   - 2602.16666 轉述 Cuadron et al.，τ-bench airline 原本 50 題中有 24 題有錯 [arXiv:2602.16666]；HAL 承認新版 τ²-bench 修掉了任務規格與評估指標上的已知問題，仍使用原版 TAU-bench [arXiv:2510.11977]。
   - 把逐題成敗聚合成一個分數時，刻度也會換。T8 補讀的 METR 以人類完成時間為刻度：同一個 Claude 3 Opus，用本文題組算出 6.42 分鐘，用 SWE-bench Verified 標註的時間算出 0.83 分鐘，Table 9 列的比值是 7.8 倍 [arXiv:2503.14499]。依 T8 章比對 Table 9，兩把尺的比值從 0.8 倍到 7.8 倍不等，換尺不是乘上一個常數；GPT-4o 與 Claude 3.5 Sonnet (Old) 的先後也會對調，雖然在 SWE-bench Verified 上兩者幾乎打平 [arXiv:2503.14499]。在同一個內部 repo 的真實 issue 上，外部約聘基線者比 repo 維護者慢 5–18 倍 [arXiv:2503.14499]。

8. **只讀終態或最終答案的判準，看不到過程錯誤，也擋不住不作為**（T4、T5、T7、T8）

### E1 External Input（T6 → T1）：使用者（模擬器）的輸入進入目標對齊

**判定：有被處理，而且有多篇直接把輸入當自變數操縱。** full 的 19 篇全部計入；partial 裡有一篇 📖（2309.13233），related 裡也有一篇 📖（2407.20859）。

**full 由哪些論文撐。** 在標了這條邊的論文裡，這條流多半長成這樣：握有隱藏目標的模擬器逐輪釋出需求，agent 以澄清提問或偏好推斷吸收，再用下游成敗計分 [arXiv:2403.19154][arXiv:2410.13788][arXiv:2502.00640]。把 T6 那一側的輸入當自變數的研究量到：

- 排除模擬器洩漏的目標標題後，UniCRS 在 ReDial 的 Recall@1 從 0.219 掉到 0.029 [arXiv:2403.16416]。精讀時發現，排除規則沒有定義，有些格子排除後 recall 反而上升 [arXiv:2403.16416]。
- 意圖分片逐輪揭露時，15 個模型平均比單輪給齊掉 39%；一次給齊的 Concat 平均保留 Full 的 95.1% [arXiv:2505.06120]。精讀時發現，使用者模擬器同樣以 T=1.0 取樣，量到的 unreliability 混進了模擬器端的變異 [arXiv:2505.06120]。
- 從 No-User 改成 Default，pass^1 在 gpt-4.1 下滑 18%、在 o4-mini 下滑 25% [arXiv:2506.07982]。精讀時發現，No-User 的 agent 另外拿到了成功條件與改寫過的政策，所以這段落差混了資訊取得難度與溝通成本 [arXiv:2506.07982]。
- 以 UserLM-8b 取代提示型模擬器，GPT-4o 的 Assistant Score 從 74.6 降到 57.4 [arXiv:2510.06552]。精讀時發現，數學題上 UserLM-8b 的覆蓋率只有 76.5，落差裡混了必要條件沒講出來的效果 [arXiv:2510.06552]。但 T6 章的程式驗證指出，這一格所在的列與 Table 3 的總體值對不上，唯一能算回總體值的讀法是數學列 GPT-4o 與 UserLM-8b 兩格互換，所以 76.5 本身存疑 [arXiv:2510.06552]。
- 固定 GPT-4o agent、只換輸入來源時，真人對話的失敗有 62.2% 歸因於使用者端，模擬對話只有 40.0% [arXiv:2601.17087]。精讀時發現，失敗歸因由作者自行標註，沒有報告標註一致性 [arXiv:2601.17087]。

- 1909.01388 把這條輸入流的性質當成自變數：6 個模擬器的對話管理與 NLG 各不相同，各訓一個 RL 系統，再交給真人互動 [arXiv:1909.01388]。它量的是下游的 Solved Ratio，沒有單獨量系統對使用者意圖的解讀 [arXiv:1909.01388]。
- 2006.08732 的模擬器以偏好模型建構目標，逐輪把使用者動作送進黑盒的推薦系統；系統回應不適當時，推入同一目標的替代動作重試 [arXiv:2006.08732]。
- Instruction (In)Stability 讓帶著自己 system prompt 的模擬使用者與 agent 自聊，量到 agent 對自己 system prompt 的遵循在 8 個 round 內明顯下降 [arXiv:2402.10962]。作者的附帶實驗還看到 agent 逐漸採用模擬使用者那一方的指令；作者把它當成安全疑慮，不是漂移的成因 [arXiv:2402.10962]。
- GDPL 的模擬器在每段對話開頭取樣目標，並以一定機率加上一個之後會被放棄的「失敗目標」，用來模擬目標改變 [arXiv:1908.10719]。論文說獎勵估計器能從對話中推斷使用者目標；依筆記，它沒有單獨量目標推斷的準確度 [arXiv:1908.10719]。
- PlatoLM 的 Socratic 模擬器產生的提問，就是送進助理的外部輸入；它比較這份輸入像不像真人，對助理學到的多輪能力有什麼影響 [arXiv:2308.11534]。依筆記，論文沒有意圖偵測或目標對齊的建模 [arXiv:2308.11534]。

這 5 篇沒有一篇把「agent 推斷出的目標」當成獨立的量測對象，所以下面〈缺什麼〉第一條在補讀之後仍成立。

**缺什麼。** 以下各條的範圍都是本調研讀過的論文，前三條只看標了這條邊的筆記。

- 「agent 推斷出的目標」沒有被當成獨立的量測對象。多數研究只量端到端成功：精讀時發現 τ-bench 的結果導向獎勵分不出是 agent 錯還是模擬器錯 [arXiv:2406.12045]，one-shot success 也同時混了推斷與推薦 [arXiv:2311.05584]。
- 模擬器與受測者之間的資訊不對稱常被破壞：精讀時發現，模擬器拿得到目標 item 或答案 [arXiv:2305.13112][arXiv:2410.13788]；已有論文量到洩漏會灌高評估結果 [arXiv:2403.16416]。
- 真人對照很少。最完整的是跨方言、年齡、國家的那一篇，但它只固定一個 agent [arXiv:2601.17087]；GATE 附錄有比，但只有圖、沒有相關係數 [arXiv:2310.11589]；iEvaLM 有比，但精讀時發現扮使用者的真人也拿到同一份含目標的指令 [arXiv:2305.13112]。
- T1 章另外指出：其他節點量到的模擬器偏差，還沒被拿回來重估 T1 的「何時問」與「目標推斷」結果 [arXiv:2310.11589][arXiv:2502.00640]。T1 章也說，在 T1 讀過的論文裡，沒有一篇把使用者中途改變目標放進評估；卡在沒有固定目標就不知道怎麼算「對齊成功」[arXiv:2310.11589][arXiv:2311.05584][arXiv:2402.09205]。但別的節點已經有會製造目標變更的一端：
  - T6 的 NUS 在系統回報查無結果時會改變目標，並在下一句說出新目標；它訓出的策略也拿去做了交叉模型與真人評估；但這些評估比的是兩種模擬器訓出的策略，沒有把目標變更當成自變數（本頁讀法）[arXiv:1805.06966]。
  - T2 的 MultiWOZ 在蒐集設計裡明文有一種目標變更，就是讓初始約束查無資料、使用者改用替代值；實際資料裡這類變更占多少輪次，本調研讀過的論文都沒有統計 [arXiv:1810.00278]。
  - CollabLLM 的真人研究也觀察到使用者會中途改變方向，但只是定性描述 [arXiv:2502.00640]。
  - T8 補讀的 GDPL 讓模擬器以一定機率加入之後會被放棄的失敗目標；依筆記，論文沒有單獨量測意圖或目標偵測的準確度 [arXiv:1908.10719]。

### E2 State Adjustments（T5 → T2）：反思修正的結果回寫對話狀態

**判定：量過寫回效果的，寫回對象都不是對話狀態；真的改寫了對話歷史或工作脈絡的幾篇，又沒有量這一步的效果。** 在標了這條邊的 11 篇裡，E2 實際的樣子是把口語反思、自評或批評附加進 agent 下一步會讀的脈絡或記憶，沒有一篇改寫 DST 式的槽位狀態 [arXiv:2310.04406][arXiv:2310.08560][arXiv:2304.03442][arXiv:2402.08115]。補讀的 Stechly et al. 落在判定的前半：它量了寫回的效果，但寫回的是同一題、最多 15 輪迴圈內的提示詞歷史，T2 章與 T5 章都判定這不是對話狀態 [arXiv:2402.08115]。

**full 由哪些論文撐。** 三篇都有閉環寫回與消融，但寫回對象都不是同一段對話的狀態：

- **Reflexion**：把反思附加到跨嘗試的長期記憶，寫回發生在環境重置之後的下一次嘗試。HotpotQA 的 EPM 消融裡，反思比只放上一條軌跡多出 8%，在 100 題上是 8%×100 = 8 題；觸發訊號是與標準答案做 EM 比對 [arXiv:2303.11366]。
- **LATS**：把反思寫回搜尋樹與 agent 提示。拿掉反思後 HotPotQA EM 從 0.63 降到 0.58，差 0.63 − 0.58 = 0.05 [arXiv:2310.04406]。
- **WebCanvas**：把自評 reward 寫進步驟 memory，GPT-4 的 Task SR 反而從 16.9 降到 13.8。同一個模組也負責判定何時完成，所以寫回本身的效果分不出來 [arXiv:2406.12373]。

**partial。**

- RCI 的計劃只在回合開始時修正一次 [arXiv:2303.17491]。
- Generative Agents 的反思是綜合而不是修正；消融只限制回答時可讀的記憶型別，TrueSkill μ 是 29.89 對 26.88 [arXiv:2304.03442]。
- MemGPT 會用函式呼叫改寫 working context；精讀時發現，狀態更新的正確性完全沒被量化 [arXiv:2310.08560]。
- SWE-agent 把格式錯誤的輪次從歷史中刪掉，效果沒有量化 [arXiv:2405.15793]。
- RMM 改的是讀取策略，不是狀態內容；LongMemEval 準確率從 58.8 到 60.2 [arXiv:2503.08026]。

related 的兩篇：一篇綜述沒有自己的系統或實驗 [arXiv:2308.03188]；Hindsight 的意見寫回只停在設計層 [arXiv:2512.12818]。

**補讀新增的 1 篇（沒有經過分類 agent）。** T5 補讀的 Stechly et al. 每輪把猜測與驗證器的批評連同全部歷史附回提示詞，最多 15 輪；它的 Sampling 對照把歷史與批評一起拿掉，每輪用原題重問，由 sound 驗證器判停 [arXiv:2402.08115]。精讀者指出，拿掉這份歷史後 Game of 24、圖著色、Mystery 仍拿到相當的增益，只有 Blocksworld 帶第一個錯誤的歷史明顯較好（87% 對 68–72%）[arXiv:2402.08115]。T5 章指出，Sampling 同時拿掉了批評與歷史，分不開兩者各自的貢獻；寫回的也是同一題的重試歷史，不是多輪對話裡之後會換題的狀態 [arXiv:2402.08115]。

**與章節的讀法對照。** 三處對「E2 量過幾筆寫回效果」的數法不同，差在判準，不是事實：

- **邊分類**：full 三筆，Reflexion、LATS、WebCanvas。補讀的 Stechly et al. 沒有經過分類。
- **T2 章**：用兩個判準逐篇重判，(a) 寫回的是不是由偵測到錯誤觸發的修正，(b) 寫回對象是不是同一段互動內的狀態。只數 (a)(b) 都不是「否」、又報了寫回後下游數字的論文，得到三筆：WebCanvas、LATS 與補讀的 Stechly et al. [arXiv:2406.12373][arXiv:2310.04406][arXiv:2402.08115]。Reflexion 有數字，但寫回發生在環境重置之後，(b) 判「否」，所以不計 [arXiv:2303.11366]。LATS 的 (b) 判「部分」：寫回的是 agent 的工作狀態與搜尋樹，不是對話狀態的槽位 [arXiv:2310.04406]。Stechly et al. 的 (b) 也判「部分」：寫回的是同一題、最多 15 輪迴圈內的提示詞歷史 [arXiv:2402.08115]。
- **T5 章**：量過寫回效果的有六筆，只計其中四筆：Reflexion 是跨嘗試的記憶，LATS 是搜尋樹，WebCanvas 是同一個 episode 的 memory，Stechly et al. 是同一題的重試歷史，寫回對象都不是對話狀態 [arXiv:2303.11366][arXiv:2310.04406][arXiv:2406.12373][arXiv:2402.08115]。排除的兩筆是 Generative Agents 與 RMM：前者寫回的是綜合出的洞見，不是修正；後者改的是讀取策略，不是記憶內容 [arXiv:2304.03442][arXiv:2503.08026]。
- **MemGPT 與 SWE-agent**：T2 章把兩篇的 (a)(b) 都判「是」。MemGPT 以函式呼叫改寫 working context，SWE-agent 在 agent 改出合法回覆後把先前格式錯誤那幾輪從訊息歷史中刪掉，改的都是互動內的狀態；但兩篇都沒有報這一步的數字 [arXiv:2310.08560][arXiv:2405.15793]。邊分類因此把兩篇歸 partial。T2 章認為資料流最接近完整的是 MemGPT。

三種讀法說的是同一件事：改寫對話狀態的資料流有了，量測沒有；量過效果的，寫回的都不是對話狀態。

**缺什麼。**

- 在標了這條邊的論文裡，沒有一篇在同一段多輪對話內，把偵測到的錯誤修正寫回對話狀態（槽位、使用者事實、任務進度），再量寫回前後的狀態正確率 [arXiv:2303.11366][arXiv:2310.04406][arXiv:2406.12373]。
- 非 oracle 觸發的正面證據也缺。兩篇正面結果的消融都在 HotpotQA 上，以標準答案判定對錯來觸發 [arXiv:2303.11366][arXiv:2310.04406]；在這三筆裡，唯一不看參考答案的自評寫回反而拉低了 Task SR，而且精讀時指出那只是 130 題、單次執行、沒有誤差棒 [arXiv:2406.12373]。補讀的 Stechly et al. 是同一個方向：由 GPT-4 自己判錯、把批評寫回歷史時，4 個領域有 3 個低於單次作答；換成 sound 驗證器判定，結果才穩定提升 [arXiv:2402.08115]。
- 在標了這條邊的論文裡，錯誤反思怎麼失效與回收沒有人處理：精讀時發現 Generative Agents 的反思未經驗證就寫回，還能引用舊反思 [arXiv:2304.03442]；RMM 的記憶更新只有 Add／Merge，沒有 Delete [arXiv:2503.08026]。
- T2 章從另一端補了一句：在本調研讀過的論文裡，記憶系統的更新這一步本身沒被單獨量過，量的一直是下游問答 [arXiv:2504.19413][arXiv:2512.12818]。DST 那一側，補讀的 SOM-DST 報了每一種狀態操作的 F1，delete 只有 2.86；但 T2 章指出，這個 F1 量的是能不能偵測金標裡的撤銷，量不到外部送進來的修正寫進狀態之後的效果 [arXiv:1911.03906]。精讀 LoCoMo 時還發現，它沒有事實被更新或推翻的題目，所以 Mem0 的主基準即使要量 UPDATE／DELETE 做得對不對也量不到 [arXiv:2402.17753]。

### E3 Anomalies Detected（T4 → T5）：軌跡中偵測到異常時觸發自我修正

**判定：有閉環，但觸發多半靠 oracle 成敗訊號或手調規則。** 在標了這條邊的論文裡，偵測對象是異常、修正由偵測器自己的判定觸發，而且兩半都量了的，只有 2404.06474：偵測那一半量了評估器與 WebArena oracle 的一致率，修正那一半量了接上 Reflexion 後的相對提升，但兩者分屬兩個實驗 [arXiv:2404.06474]。它的偵測那一半只報 accuracy，誤報與漏報沒有分開報；精讀時指出，若這批軌跡的成功率落在 14.4%–15.6%，這個 accuracy 可能還不及一律判失敗的基準（見跨節點發現第 1 條）[arXiv:2404.06474]。補讀的兩篇各差一個條件，所以這個判定在補讀之後不變：Stechly et al. 把觸發器的偽陽性率與偽陰性率分開報，也量了整條迴圈，但判定對象是整份最終答案，不是軌跡 [arXiv:2402.08115]；Ctrl-Z 在軌跡上逐步偵測、觸發重抽，但偵測的是紅隊攻擊，量的是安全性，不是修正後的正確率 [arXiv:2504.10374]。

**full 由哪些論文撐。** 10 篇分成三種形狀。

- **執行中由軌跡內容觸發**
  - Reflexion 在 ALFWorld 以重複動作或動作數超限判失敗，12 次嘗試內解出 130／134 題 [arXiv:2303.11366]。精讀時發現，門檻是為該環境手調的 [arXiv:2303.11366]。
  - LATS 由 LLM 逐節點評分驅動回溯；拿掉 LM 評分，EM 由 0.63 掉到 0.37 [arXiv:2310.04406]。精讀時發現，價值解析器會把推理中的年份或價格讀成高分，所以這組消融量到的是含雜訊的解析器加上 oracle 終局 reward [arXiv:2310.04406]。
  - ToolLLM 的 DFSDT 讓模型自判走不下去就回溯，pass rate 是 63.8，成本對齊的 ReACT@N 是 44.5 [arXiv:2307.16789]。精讀時發現，ReACT@N 怎麼對齊成本沒有寫，評審 ChatGPT 同時也是 teacher [arXiv:2307.16789]。
  - AgentQuest 偵測到重複猜測就重新提示，15 個實例的 SR 從 0.47 升到 0.60 [arXiv:2404.06411]。精讀時發現，RR 歸零是機制強制出來的，而且只有單一模型、每題看來只跑一次、沒有誤差棒 [arXiv:2404.06411]。執行期的偵測器是精確字串比對，這條規則是開發者離線讀曲線、診斷出重複動作之後才加上的 [arXiv:2404.06411]。
  - WebCanvas 的 reward 模組會判 loop，但自評 reward 反而拉低了表現 [arXiv:2406.12373]。
- **失敗後以二元判定觸發重試，不定位**
  - 2404.06474 的評估器讀完一次執行，判定失敗就觸發 Reflexion 式的反思、最多 3 輪，在 WebArena 上帶來 16% 與 29% 的相對提升，基線重現值是 15.6% [arXiv:2404.06474]。它只給二元判定，沒有指出哪一步出錯 [arXiv:2404.06474]。精讀時發現，評估器實際多半只看最後一張截圖，而且 accuracy 可能低於一律判失敗（條件式推算，見跨節點發現第 1 條）[arXiv:2404.06474]。
- **失敗後定位再修正**
  - AgentDebug 從最早的關鍵錯誤重跑，ALFWorld 上 GPT-4o-mini 從 21 升到 55 [arXiv:2509.25370]。精讀時發現，修正指令由較強的 GPT-4.1 產生，缺少「通用回饋同樣從中途重跑」的對照，下游數字也沒標單位與評估集大小 [arXiv:2509.25370]。
  - AgenTracer 把歸因推理當回饋：OWL Workforce 在 GAIA 上 +4.8%，MaAS 在 MATH-500 上 +14.21% [arXiv:2509.03312]。精讀時發現，缺少換另一個模型做同樣歸因的對照，分不出增益來自精準歸因還是任何外部診斷，多數數字也只在圖中 [arXiv:2509.03312]。
  - Tyen et al. 依錯誤步的位置回滾重抽 [arXiv:2311.08516]。
- **監控觸發重抽**：Baker 等人在測試期以 rejection sampling 丟棄被標記的樣本 [arXiv:2503.11926]。精讀時發現，這一節的關鍵結果只有曲線圖，沒有數值、誤差區間或重跑次數 [arXiv:2503.11926]。

**與章節的讀法對照。** 邊分類比兩章寬，兩章在 AgentQuest 上的歸類也相反。

- T5 章照字面收緊判準，要求偵測對象是多步軌跡、偵測結果真的觸發修正。它的「完整的資料流」一類，除了 Reflexion 與 LATS，還收了 2404.06474、AgentQuest、AgentDebug、AgenTracer、ToolLLM 的 DFSDT 與 WebCanvas，各附保留；但它的判斷是，T5 自己的論文裡真正從多步軌跡偵測異常、再觸發修正的只有 Reflexion 與 LATS [arXiv:2303.11366][arXiv:2310.04406]。
- T4 章把 2404.06474 列為兩半都做到的一篇，也是 T4 論文裡唯一由偵測器自己的判定觸發修正、不靠 oracle 的例子 [arXiv:2404.06474]。
- AgentQuest：T4 章把它放在「偵測只在離線或訓練期成立」，理由是偵測那一半是開發者離線讀軌跡曲線得出的，執行期只加了一條手寫的精確字串比對，觸發條件不是讀軌跡的偵測器 [arXiv:2404.06411]。T5 章把它放在「完整的資料流」，並附上同樣的保留 [arXiv:2404.06411]。兩章對事實的描述一致，差在「規則式的執行期檢查算不算偵測器」；邊分類採 full。
- 兩半都量了的論文，T5 章算三篇，都附保留：2404.06474；WebCanvas，它的 HAS 量的是完成判斷與人類標註的一致度，不是異常偵測的準確率，加上自評模組後的結果也是負的 [arXiv:2406.12373]；補讀的 Stechly et al.，它的偽陽性率與偽陰性率是在作者配好的候選集上另外量的，判定對象是最終答案 [arXiv:2402.08115]。本頁的判準要求偵測對象是軌跡上的異常，所以後兩篇都不算；Tyen et al. 的修正由模擬分類器觸發，兩邊都不算 [arXiv:2311.08516]。
- 補讀的兩篇在 T4 章的位置：Ctrl-Z 列為其他節點在執行期觸發的例子，IPR 列在「偵測只在離線或訓練期成立」[arXiv:2504.10374][arXiv:2406.11176]。
- 邊分類另外收的幾篇各有保留：Tyen et al. 的軌跡是一句一步的 CoT 推理，「修正」是不帶回饋文字的重抽 [arXiv:2311.08516]；Baker 等人的修正是重抽與 reward 懲罰，不是 agent 自己反思 [arXiv:2503.11926]。
- SWE-agent 的 lint：T3 章寫的是「在 T3 計入的論文裡」，執行期由外部偵測觸發、再由 agent 自己修正的只有 SWE-agent 的單步 lint；一次失敗後，最終成功的機率從 90.5% 降到 57.2% [arXiv:2405.15793]。T3 章也列了別節點的反例，觸發形狀各不相同：Reflexion（T5）是跨嘗試的重複門檻加步數上限，AgentQuest（T8）是同一回合內的精確比對，WebCanvas（T8）是 agent 自己的 reward 模組依提示詞判 loop；三者的重複動作觸發規則都沒有評估自己的誤報與漏報 [arXiv:2303.11366][arXiv:2404.06411][arXiv:2406.12373]。邊分類則因為 SWE-agent 只在單步層級偵測而歸 partial [arXiv:2405.15793]。

**補讀新增的 6 篇（沒有經過分類 agent，以下是本頁依筆記與各章的讀法）。**

- **Ctrl-Z**：監控器帶著整段指令歷史替目前行動評分，超過門檻就丟掉這個行動、向同一個模型重抽，全部可疑才改用可信模型的行動；三振規則與回頭補抽則把軌跡中過去步驟的分數納入 [arXiv:2504.10374]。只用可信監控、同為 95% usefulness 時，風險從 defer to trusted 的 100 − 72.7 = 27.3% 降到 time travel 的 100 − 87.1 = 12.9%（程式驗證證實）[arXiv:2504.10374]。修正手段是重抽或換成可信模型的行動，不是 agent 自我反思；精讀時發現監控器看到的歷史只有指令、沒有輸出 [arXiv:2504.10374]。
- **Stechly et al.**：操弄的就是「誰判定答案有錯、觸發下一輪」，GPT-4 自己判，或程式驗證器判 [arXiv:2402.08115]。GPT-4 當觸發器時，圖著色的偽陰性率是 95.8%，整條迴圈低於單次作答；換成程式驗證器就穩定提升 [arXiv:2402.08115]。
- **Olausson et al.**：單元測試失敗就是觸發修復的訊號，只有初始程式全部沒過測試才進入回饋與修復 [arXiv:2306.09896]。觸發器是 oracle 等級的測試，偵測對象是單一程式。
- **IPR**：以多次 rollout 估出的步驟分數在軌跡上定位錯誤步，再把該步之後的後綴交給步驟層級 DPO；資料流是真的，但發生在訓練期，被修正的是模型權重 [arXiv:2406.11176]。
- **AgentMonitor**：逐步替每個網路或檔案系統動作打分，低於門檻就中止測試、交給人審查，不觸發修正 [arXiv:2311.10538]。精讀時指出，數字全來自已錄好的 CI 紀錄的離線重播 [arXiv:2311.10538]。
- **Chen et al.**：量的是只讀 CoT 的偵測器能抓到多少 reward hack，6 個環境中有 5 個說出比例不到 2%；論文沒有修正步驟 [arXiv:2505.05410]。

依這 6 篇的筆記，Ctrl-Z 是唯一在執行期由讀軌跡的偵測器觸發處置、又量了處置效果的；但它的效果量是安全性，而且是在攻擊目標已知、監控器提示詞照著攻擊特徵寫的條件下量到的（精讀時指出）[arXiv:2504.10374]。

**缺什麼。**

在標了這條邊的論文裡，沒有一篇在同一個迴圈裡同時做到下列三件事，而且是在不能重置重來的多輪情境下：

1. 用非 oracle 的軌跡異常偵測器觸發修正，而不是成敗標籤或手調門檻。
2. 單獨量這個偵測器在成功與失敗軌跡上的誤報與漏報。
3. 量它對下游修正的淨效果。

目前的缺口分散在各處：

- 最接近的是 2404.06474。它的觸發器不是 oracle，也量了修正的效果；但偵測那一半只報 accuracy、混淆矩陣只在圖裡，觸發只有二元判定、不定位，修正方式是判定失敗後整條任務重試，不是在不能重來的多輪情境下 [arXiv:2404.06474]。
- 定位型的閉環全靠 oracle 失敗訊號，或 oracle／模擬的錯誤位置啟動 [arXiv:2509.25370][arXiv:2509.03312][arXiv:2311.08516]。
- 只做偵測的軌跡研究都沒有接到修正 [arXiv:2505.08638][arXiv:2505.00212][arXiv:2412.06559][arXiv:2504.08942][arXiv:2506.15740][arXiv:2401.10019]。
- 作者自述偽陰性會逼 agent 重做已經成功的任務，傷害比偽陽性大，但沒有給數字 [arXiv:2404.06474]。補讀的 Stechly et al. 裡，偽陰性率高的圖著色與 Mystery 整條迴圈都低於單次作答，與這個說法相容；但該文沒有直接比較兩種錯的傷害，這一步是 T5 章的推論 [arXiv:2402.08115]。
- 補讀的 6 篇裡，在執行期讀軌跡觸發處置的只有 Ctrl-Z，但處置不是自我修正，量的也不是修正後的正確率 [arXiv:2504.10374]。T5 章引它的摘要，最佳協定的代價是誠實 agent 的表現降 5% [arXiv:2504.10374]。
- 若偵測只讀 CoT，觸發訊號可能大量漏失：Chen et al. 的 6 個環境中有 5 個，模型在 CoT 裡說出 reward hack 的比例不到 2% [arXiv:2505.05410]。
- 偵測器成為最佳化目標後會失效，這一點也只在單一 coding 情境、以曲線呈現 [arXiv:2503.11926]。

### E4 Nominal Path（T4 → T6）：正常路徑繼續與使用者互動

**判定：照這條邊自己的定義（由 T4 的軌跡分析判定正常，再繼續與使用者互動），標了這條邊的 3 篇裡沒有實例。** 這 3 篇的主節點是 T6 與 T7，沒有一篇是 T4；這個判定只說明這 3 篇，不說明文獻，而 3 篇這個規模本身就是抽樣方式的結果（見〈這份調研自己的限制〉）。

**唯一的 full 其實是 T6 的閘門。** 1901.05415 每輪由滿意度分類器讀使用者對上一句的反應，判定滿意就續談，並把回覆收成訓練例。這條分支的產物有量過：hits@1/20 從 20k HH 單獨的 30.3，升到加 60k HB 的 35.4 [arXiv:1901.05415]。把被判為不滿的回覆也併進去，hits@1/20 在 20k／131k HH 下分別掉 1.2／0.6 點 [arXiv:1901.05415]。但判定者讀的是使用者反應，屬 T6 的滿意度估計，不是 T4 的軌跡分析；量到的是離線重訓的價值，不是「繼續對話」對使用者的效果 [arXiv:1901.05415]。T4 章與 T6 章也都寫，這 3 篇沒有一篇由 T4 的軌跡分析決定要不要繼續互動 [arXiv:1901.05415][arXiv:2309.10691][arXiv:2506.07982]。T4 章另外說明，「T4 這一側沒有論文實作這個分支」有一部分是收錄範圍造成的：T4 計入的八篇合成論文，軌跡都從一次給定的指令開始，中途沒有使用者回合 [arXiv:2310.12823][arXiv:2403.12881]。T4 補讀的 IPR 與 GiGPO 也沒有使用者回合，而且方法都要求環境能重放或複製：IPR 要能重放到專家軌跡的任意前綴，GiGPO 要能開出初始狀態完全相同的多個副本 [arXiv:2406.11176][arXiv:2505.10978]。精讀時指出，換成真實使用者或隨機的使用者模擬器時這個前提不成立 [arXiv:2406.11176][arXiv:2505.10978]。含使用者回合的多輪軌跡合成本調研沒讀，例如 APIGen-MT: Agentic Pipeline for Multi-Turn Data Generation via Simulated Agent-Human Interplay（arXiv 2504.03601，未讀）；依標題，它研究以模擬的 agent 與人互動生成多輪資料，能檢驗這一句是否只是選文造成的。

**partial 與 related。**

**缺什麼。**

- 在本次語料標了這條邊的論文裡，沒有一篇讓軌跡層級的「正常」判定去決定是否繼續與使用者（模擬器）互動 [arXiv:1901.05415][arXiv:2309.10691][arXiv:2506.07982]。

  - ProcessBench 平衡了全對與有錯的樣本，在步驟層級量「全對時答 -1」，但只有數學題 [arXiv:2412.06559]。

  - T5 補讀的 Stechly et al. 直接量了觸發器在對的答案上的誤判：GPT-4 當自己的驗證器時，圖著色 118 個正確答案中有 113 個被判錯，偽陰性率 95.8% [arXiv:2402.08115]。T4 章指出，那是整份答案的判定，不是軌跡上的逐步偵測 [arXiv:2402.08115]。
  - 2404.06474 的評估器成功與失敗的執行都判，但文字只報 accuracy，混淆矩陣只在 Figure 4（精讀時指出）[arXiv:2404.06474]。

### E5 Correction Logs（T5 → T7）：修正紀錄回流評估

**判定：在標了這條邊的論文裡，只有離線、一次性的處理。** 27 篇中有 23 篇是 T5 自己的論文，T7 的 26 篇一篇都沒有標這條邊。補讀新增的 4 篇也只做離線分析，判定不變。

**full 由哪些論文撐。** 兩篇都是訓練過的 critic 把 critique 交給人類評審，再比較有無輔助時的評估結果。

- 模型 critique 讓標註者整體多找約 50% 的 critique；模型答案被找到 critique 的比例從 54% 升到 78% [arXiv:2206.05802]。精讀時發現，「有效且新穎」的 critique 只從 0.18±0.05 增到 0.24±0.06，差距落在誤差內 [arXiv:2206.05802]。

**partial 的四種形狀。** 共 19 篇。

- 把逐輪紀錄拆成對→錯、錯→對的轉移，或算逐輪準確率，評的是修正方法自己 [arXiv:2310.01798][arXiv:2311.08516][arXiv:2404.17140][arXiv:2405.14092][arXiv:2407.18219][arXiv:2409.12917][arXiv:2305.14325]。

**補讀新增的 4 篇（沒有經過分類 agent，以下是本頁依筆記與 T5 章的讀法）。**

- Stechly et al. 逐輪記下候選答案、驗證判斷與批評內容，各自對照 sound 驗證器的真值：逐輪正確題數、驗證判斷的偽陽性率與偽陰性率、批評的幻覺類型與逐層正確率 [arXiv:2402.08115]。

- 在本次語料標了這條邊的論文裡，沒有一篇讓修正模組在執行期輸出持久的修正紀錄，由 agent 層級的評估系統自動讀取，再以「有無這份紀錄」的對照量出評估結論的差異；最接近的兩篇 full 由人類評審讀 critique，HAL 則由 judge 事後從軌跡重建修正事件 [arXiv:2206.05802][arXiv:2407.00215][arXiv:2510.11977]。
- 紀錄欄位各記各的：有的記轉移類別與呼叫次數 [arXiv:2310.01798]，有的記觸發頻率與貢獻 [arXiv:2404.17140]，有的記證據報告 [arXiv:2210.08726]。
- 精讀時發現，閘門的逐步判定沒有保留，所以閘門的準確度無從量起 [arXiv:2210.08726]。反例是補讀的 Stechly et al.：每一次驗證判斷都對照真值記下，偽陽性率與偽陰性率才算得出來 [arXiv:2402.08115]。但它的修正迴圈是同一題的離線實驗，紀錄也沒有交給 agent 層級的評估系統持續消費。
- critique 本身缺可靠的評審：Alpaca 的 critique 平均分，GPT-4 給 4.69、人工給 2.91 [arXiv:2308.04592]。

### E6 Interaction Logs（T6 → T7）：互動紀錄回流評估

**判定：處理得最多，但檢驗這條流本身的研究，多半得到警訊。** full 27 篇中 2309.13233 是 📖，所以計入的是 27 − 1 = 26 篇；partial 27 篇中 2510.07777 是 📖。另有補讀新增、未經分類的 9 篇，見本節「補讀新增」一段；它們沒有改變這個判定。

**判準是兩道門。**

1. 紀錄要由模擬器、群眾或真實使用者與受測系統即時互動產生，也就是使用者輪會隨系統回覆改變，而且評估端實際消費了這份紀錄、產出報告裡的分數。

**full 由哪些論文撐。**

- **同一批任務或系統同時交給模擬與真人（或人扮使用者）評** [arXiv:1805.06966][arXiv:2208.10817][arXiv:2305.13112][arXiv:2204.00763][arXiv:2601.17087][arXiv:2310.11589]，另有 📖 的 [arXiv:2309.13233]。
  - ABUS 訓出的策略換到 NUS 上，平均成功率只剩 45.5% [arXiv:1805.06966]。精讀時發現，這個落差分不開逼真度與解析器雜訊 [arXiv:1805.06966]。
  - 精讀時發現，GenTUS 訓出的系統在模擬交叉評估裡平均最低，在真人試驗裡卻是最高的 0.86 [arXiv:2208.10817]。
  - iEvaLM 在 100 筆樣本上排出的四個系統名次與人扮使用者一致 [arXiv:2305.13112]，但後續稽核指出它的模擬器會洩漏目標 [arXiv:2403.16416]。
  - 這一組裡真正拿多個對話系統比模擬與真人名次的，有 NUS、GenTUS、MetaSim、iEvaLM 四篇 [arXiv:1805.06966][arXiv:2208.10817][arXiv:2204.00763][arXiv:2305.13112]。T6 章與 T7 章再加上補讀的 1909.01388 與 2006.08732，算成六篇 [arXiv:1909.01388][arXiv:2006.08732]。2601.17087 只固定 GPT-4o 一個 agent，談不上名次 [arXiv:2601.17087]；GATE 附錄比的是偏好引出方法，不是對話系統 [arXiv:2310.11589]。
- **模擬器閉環，以紀錄或終態計分並稽核** [arXiv:2406.12045][arXiv:2408.04682][arXiv:2506.07982][arXiv:2507.02825][arXiv:2505.06120][arXiv:2510.06552][arXiv:2309.10691][arXiv:2502.00640][arXiv:2403.19154][arXiv:2404.15269][arXiv:2107.11904][arXiv:1804.06512][arXiv:2310.11667][arXiv:2306.00774]。
  - 什麼都不做的 agent 在 τ-bench airline 拿到 38% [arXiv:2507.02825]。精讀時指出，38% 是 trivial agent 能拿的分數，不是真實 agent 的偏差量 [arXiv:2507.02825]。
  - τ²-bench 逐回合稽核模擬器，total 錯誤率在 telecom 是 16%、retail 40%、airline 47% [arXiv:2506.07982]。
  - 精讀時發現，這項稽核量的是模擬器有沒有照指令走，不是逼真度 [arXiv:2506.07982]。
- **稽核紀錄中的洩漏**：排除兩種洩漏後，Recall@50 最多降 39.1% [arXiv:2403.16416]。精讀時發現，部分排除條件下 recall 反而上升，排除規則的分母也沒有交代 [arXiv:2403.16416]。
- **真人部署或群眾紀錄直接變成指標或排名** [arXiv:1605.07669][arXiv:1911.02557][arXiv:2208.03188][arXiv:2403.04132][arXiv:2306.05685]。
  - Arena 平均每筆紀錄只有 1.3 輪 [arXiv:2403.04132]。精讀時依勝率粗估機會同意率後，群眾對專家的 κ 只有約 −0.07 到 0.42 [arXiv:2403.04132]。T7 章的程式驗證只部分證實：方向成立，但 Table 3 的同意率有一半寫不成「整數 ÷ 160」，與勝率很可能不是同一個分母，所以個別 κ 值只是粗估 [arXiv:2403.04132]。
  - BB3-175B 部署中，只有 4.0% 的 bot 訊息被按讚 [arXiv:2208.03188]。

**partial 卡在哪一道門。**

- 靜態或事先生成的紀錄，使用者輪不隨系統改變 [arXiv:1805.04655][arXiv:1810.00278][arXiv:2105.03748][arXiv:2303.16634][arXiv:2305.10250][arXiv:2305.14387][arXiv:2402.14762][arXiv:2402.17753][arXiv:2410.10813][arXiv:2410.12361]。

- 沒有受測系統、只評模擬器本身，或對話雙方都是受測架構 [arXiv:2208.10264][arXiv:2304.03442]，另有 📖 的 [arXiv:2510.07777]。
- 只用到紀錄的單一欄位（token 數）[arXiv:2504.13359]。
- 過了第一道門，但沒有檢驗這條流：沒有人評對照、judge 未經人工驗證，或模擬分數與人評只是並列 [arXiv:1612.05688][arXiv:2208.03270][arXiv:2212.08073][arXiv:2305.13626][arXiv:2306.02552][arXiv:2308.03688][arXiv:2311.05584][arXiv:2402.09205][arXiv:2410.13788][arXiv:2412.14161][arXiv:2510.11977][arXiv:2602.16666]。

related 有兩篇 [arXiv:2009.11352][arXiv:2411.16594]。

**補讀新增的 9 篇（沒有經過分類 agent，以下是本頁依筆記與各章的讀法）。**

- **模擬與真人的紀錄放在一起比。** 1909.01388 以 6×6 的交叉矩陣讓每個系統對每個模擬器各跑一批互動，再請 AMT 工作者與每個系統互動評分，拿兩種紀錄導出的名次互相對照；結果見跨節點發現第 6 條 [arXiv:1909.01388]。2006.08732 把模擬對話與真人對話都記下來，比較兩者的對話特徵與系統名次，並請群眾評審並排判斷哪段是真人 [arXiv:2006.08732]。
- **真實使用者的紀錄直接變成評估與獎勵。** Chai 把「回覆之後使用者又送了幾則訊息」「有沒有按重新生成」「星等」彙總成線上 A/B 的指標，同一批紀錄也被轉成獎勵模型的偽標籤 [arXiv:2303.06135]。T6 章指出，延續標籤與 MCL 量的是同一件事；以延續標籤訓練的獎勵模型 MCL 最高、D30 留存卻最低 [arXiv:2303.06135]。
- **群眾工作者的互動紀錄。** 2201.04723 讓群眾工作者親自和模型聊 6 輪，逐輪或在結尾記下選擇、勾選與 Likert，比較這些紀錄要怎麼收、怎麼聚合，才能用最少工時分出兩個模型 [arXiv:2201.04723]。
- **模擬器閉環的紀錄回流成評估。** GDPL 的模擬對話同時是獎勵估計器的負樣本、全部自動指標的計算來源，以及 Turker 人評閱讀的素材 [arXiv:1908.10719]。Instruction (In)Stability 的自聊紀錄以確定性函式逐輪打分，變成指令穩定度曲線 [arXiv:2402.10962]。PlatoLM 拿互動紀錄量多樣性與 human-like ratio，再與回應模型的分數做相關；精讀時指出，下游分數來自 GPT-4 評審，不是真人 [arXiv:2308.11534]。
- **靜態語料或假設資料。** Fantastic Rewards 用 MultiWOZ 的人對人對話與自動指標的排序學出評分器，沒有使用者模擬器，也不構成閉環；學到的評分器拿去訓練策略 [arXiv:2302.10342]。PARADISE 把對話紀錄與滿意度問卷一起送進迴歸，但全文只用假設資料示範 [arXiv:cmp-lg/9704004]。

**缺什麼。** 以下各條的範圍都是標了這條邊的筆記。

- 在標了這條邊的論文裡，把同一組系統同時交給模擬與真人評、比較系統排名的研究很少，規模也小 [arXiv:2305.13112][arXiv:1805.06966][arXiv:2208.10817]。系統數最多的是 MetaSim Table 5 的 7 個受控降級變體，名次幾乎無關，而且 7 個不是彼此獨立的系統（程式驗證）[arXiv:2204.00763]。補讀的 1909.01388 有 6 個彼此獨立的系統，交叉平均的名次大致跟得上真人，但一致程度取決於測試池的組成，系統在自家模擬器上的分數則與真人名次幾乎無關（程式驗證）[arXiv:1909.01388]。其餘比較只有 2 到 4 個系統，補讀的 2006.08732 是 3 個 [arXiv:2006.08732]。AlpacaFarm 模擬的是單輪偏好標註者，不是多輪互動中的使用者（見跨節點發現第 6 條）[arXiv:2305.14387]。
- 模擬器看起來多像真人，和它訓出或評出的系統在真人面前怎麼樣，論文本身都沒有放在一起分析。補讀的兩篇各有一組資料可以並讀：1909.01388 的人評 Overall 分數與真人 Solved Ratio，精讀時算出 Spearman 約 −0.09；2006.08732 群眾最常誤認為真人的那個模擬器，是唯一把 Success Rate 名次排錯的 [arXiv:1909.01388][arXiv:2006.08732]。兩篇各只有 6 個與 3 個點，沒有檢定（精讀時指出）[arXiv:1909.01388][arXiv:2006.08732]。
- 模擬器稽核只量指令遵循與幻覺 [arXiv:2408.04682][arXiv:2506.07982]；精讀時指出，τ²-bench 的稽核不量逼真度，也只用一種模擬器模型 [arXiv:2506.07982]。
- 終態與子字串判準讀不到過程，可以被 do-nothing agent 鑽漏洞 [arXiv:2507.02825]；讀整段軌跡的 LLM judge 又常沒有經過人工驗證 [arXiv:2602.16666]。
- 真人紀錄的多輪性與訊號密度都薄 [arXiv:2403.04132][arXiv:2208.03188]。
- 部署紀錄回流後很少重新上線、再量使用者端的效果；精讀時發現，Self-feeding 的迴路就沒有閉合 [arXiv:1901.05415]。補讀的 Chai 在一輪之內做到了：以不由訓練訊號直接定義的 D30 留存當結果量測；但只完成一輪，聊天模型本身沒有更新，目標是閒聊的投入度而不是任務完成 [arXiv:2303.06135]。
- 評估與訓練共用同一個模擬器或判斷來源，精讀時在三篇論文都看到 [arXiv:2502.00640][arXiv:2410.12361][arXiv:1911.02557]。補讀的兩篇也是：精讀時指出，GDPL 的 agenda 與 VHUS 兩組結果都在同一個模擬器上訓練和評估 [arXiv:1908.10719]；T6 章指出，Chai 的延續標籤與主指標 MCL 同源，§5 還讓 MCL 當留存實驗的閘門 [arXiv:2303.06135]。

## 整個框架的未解問題

以下八題都是就本調研讀過的論文而言還沒解的問題。每題的「沒有」「缺」，有一部分可能只是本調研沒讀到，各章的〈已知缺口與未讀〉列出了能檢驗它們的未讀論文。

1. **「不作為」這一類決策要怎麼雙向計分。** 拒識、不問、不修正、判正常後繼續、放棄任務，這類決策在 T1、T4、T5、T7、T8 都出現；在本調研讀過的論文裡，也都缺同時計入誤拒與誤收、並對照平凡基準的量法。
   - 在 T1 讀過的論文裡，沒有一篇提出能把真拒答、解析失敗、拒答偏移分開計分的評估協定，也沒有把誤拒與誤收一起算進任務完成率的端到端指標 [arXiv:1909.02027][arXiv:2101.03778][arXiv:2106.04564][arXiv:2305.07157][arXiv:2310.10176]。補讀的 ID-OOS 那篇是 T1 唯一在單一操作點同時報拒識 recall 與 precision 的，但已知意圖被誤拒的比例併進了 in-scope 準確率，論文自己沒有點出 [arXiv:2106.04564]。
   - T4 的失敗歸因評估集只收失敗軌跡 [arXiv:2505.00212][arXiv:2509.03312]。
   - 在 T5 讀過的論文裡（含補讀的三篇），沒有一篇同時報觸發率、對改錯率、錯改對率與成本 [arXiv:2311.08516][arXiv:2404.17140][arXiv:2402.08115]。
   - T7 與 T8 則有「正確放棄」墊出來的分數地板 [arXiv:2404.07972][arXiv:2507.02825]。

2. **非 oracle 的軌跡異常偵測器接上修正之後，淨效益是正還是負。** 前提是在不能重置重來的多輪情境下。這一題同時卡在 T4 的偵測準確度、T5 的觸發門檻，以及 E3 缺的同一迴圈量測 [arXiv:2505.08638][arXiv:2311.08516][arXiv:2404.06474][arXiv:2509.25370]。本調研讀過的論文裡最接近的是 2404.06474：觸發器不是 oracle，接上之後淨效益為正；但修正方式是整條任務重試，偵測那一半也只報 accuracy [arXiv:2404.06474]。
   - 補讀的 Stechly et al. 給了反方向的點：GPT-4 自己當觸發器時，4 個領域有 3 個整條迴圈低於單次作答 [arXiv:2402.08115]。但判定對象是整份最終答案，任務也可以重來 [arXiv:2402.08115]。
   - T3 補讀的 Ctrl-Z 在執行期由讀軌跡的監控器觸發重抽，量的是安全性，不是修正後的正確率 [arXiv:2504.10374]。T5 章引它的摘要，最佳協定的代價是誠實 agent 的表現降 5% [arXiv:2504.10374]。

3. **修正怎麼寫回對話狀態，寫回之後狀態有沒有變對。**
   - 在本調研讀過的論文裡，記憶系統的更新這一步沒有操作層級的 ground truth，也就是該抽哪些事實、該 UPDATE 還是 DELETE [arXiv:2504.19413][arXiv:2512.12818]。現有考場也不合用：精讀 LoCoMo 時發現它沒有事實被更新的題目 [arXiv:2402.17753]。
   - DST 那一側，補讀的 SOM-DST 由相鄰兩回合的金標狀態導出操作標籤，報了每種操作的 F1，delete 只有 2.86 [arXiv:1911.03906]。但 MultiWOZ 2.1 測試集含 delete 的回合最多只占 30 × 109 ÷ (212,297 + 8,399 + 235 + 109) ≈ 1.48%（程式驗證），精讀時也懷疑這些標籤多半是標註前後不一致 [arXiv:1911.03906]。T2 章指出，這個 F1 量的是能不能偵測金標裡的撤銷，量不到外部修正寫進狀態之後的效果。
   - 錯誤的反思寫回後怎麼失效 [arXiv:2304.03442][arXiv:2406.12373][arXiv:2503.08026]。
   - 修正怎麼傳到依賴它的下游步驟 [arXiv:2210.08726][arXiv:2303.11366]。
   - 這一題橫跨 T2、T5 與 E2。

4. **模擬使用者能不能代表真人。**
   - 模擬器排出的系統名次，對真人名次有多少預測效度 [arXiv:2305.13112][arXiv:2601.17087]。補讀的 1909.01388 是系統數最多、彼此獨立的正面證據，但一致程度取決於測試池的組成；精讀時指出，論文沒交代怎麼挑測試池 [arXiv:1909.01388]。
   - 模擬器看起來多像真人，和它訓出或評出的系統在真人面前怎麼樣，是什麼關係。精讀時從補讀的兩篇資料看到兩者不同向，但各只有 6 個與 3 個點、沒有檢定，論文本身也沒有放在一起分析 [arXiv:1909.01388][arXiv:2006.08732]。
   - 怎麼給模擬器目標又不洩漏 [arXiv:2403.16416][arXiv:2510.06552]。
   - 誰有權結束一集 [arXiv:2506.07982]。補讀的 PlatoLM 讓模擬器從不自己結束，歷史超過 2048 token 就截斷；精讀時指出，代價是模擬使用者永遠不會主動結束或放棄 [arXiv:2308.11534]。
   - 使用者中途改變目標時，怎麼評估「對齊成功」[arXiv:2310.11589][arXiv:2502.00640]。T8 補讀的 GDPL 模擬器會加入之後被放棄的失敗目標，但依筆記，論文沒有單獨量測意圖或目標偵測的準確度 [arXiv:1908.10719]。
   - 這一題同時決定 T1、T6、T7、T8 的分數，也就是 E1 與 E6 兩條邊的效度。

5. **評估器自己的雙向誤差，怎麼傳進任務層級的誤差棒。** 判定器、LLM judge、監控器、模擬器都是量具，在本調研讀過的論文裡多半只被往一個方向稽核過。反例有兩篇：AgentRewardBench 以專家標註為準，量了軌跡判定兩個方向的錯；ABC 同時量到高估與低估，例如 WebArena 的判定造成高估、OSWorld 的 UI-TARS 被低估 28% [arXiv:2504.08942][arXiv:2507.02825]。但兩篇都沒有把這些誤差傳進任務層級的誤差棒。補讀的 Stechly et al. 也把 GPT-4 驗證者的偽陽性率與偽陰性率分開報，圖著色的偽陰性率是 95.8%，同樣沒有傳進誤差棒 [arXiv:2402.08115]。
   - 判定器 [arXiv:2207.01206][arXiv:2404.07972][arXiv:2601.11868]。
   - 精讀時發現，ABC 附錄 F 的誤差傳遞式方向有誤 [arXiv:2507.02825]；Mind2Web 2 只量到葉節點 [arXiv:2506.21506]。
   - 監控門檻依賴一份「確定誠實」的參考分布 [arXiv:2312.06942]。

6. **多次試驗的變異從哪裡來。** agent 取樣、使用者模擬器取樣、API 非確定性與環境漂移，還沒被分開量 [arXiv:2406.12045][arXiv:2411.00640][arXiv:2602.16666]。T2 的多輪退化研究量到的 unreliability 也混了模擬器端的變異（精讀時發現）[arXiv:2505.06120]。在本調研讀過的論文裡，pass^k 在「任務 × 每任務 k 次」兩層結構下的估計量與信賴區間還沒有定論 [arXiv:2406.12045][arXiv:2602.16666]。pass^k 提出後，接手實測的例子是 T6 的 τ²-bench：主指標沿用 pass^k，每題在 temperature 0 下跑 4 次 [arXiv:2506.07982]。T8 補讀的 METR 每個 agent 與任務的組合約跑 8 次，誤差棒把 run 併進 task family、任務、run 三層 bootstrap，沒有拆開 [arXiv:2503.14499]。精讀時指出，這些重跑足以算出逐題的 pass^k，全文卻沒有報 [arXiv:2503.14499]。

7. **成本要用什麼共同單位記帳。** 各節點的單位各自為政：
   - T1：多問一輪值多少任務成功 [arXiv:2410.13788][arXiv:2310.11589][arXiv:2502.00640]。
   - T3：觀測壓縮的 token、延遲與任務損失 [arXiv:2405.15793][arXiv:2501.12326]。
   - T5：修正對重抽的呼叫數與 token [arXiv:2310.01798][arXiv:2407.18219]。補讀的 Olausson et al. 以樣本數與 token 數兩種單位都對齊過，但 token 只計輸出 [arXiv:2306.09896]。
   - T8：沒有可執行驗證器時的成本怎麼算 [arXiv:2504.13359]。補讀的 METR 以人類完成時間當刻度，而在同一個內部 repo 上，外部約聘者比 repo 維護者慢 5–18 倍 [arXiv:2503.14499]。

   成本口徑一換，frontier 就跟著換 [arXiv:2510.11977][arXiv:2407.01502][arXiv:2504.13359]。

8. **軌跡、修正紀錄與互動紀錄沒有共同格式，評估端無法持續消費。**
   - 軌跡格式與失敗分類法無法互相對照。T4 章收了五套失敗分類（含 T3 的 SWE-agent），依這五份筆記，沒有一批軌跡被兩套以上的分類法標過 [arXiv:2505.08638][arXiv:2503.13657][arXiv:2509.25370][arXiv:2506.18824][arXiv:2405.15793]。
   - 修正紀錄的欄位各記各的，閘門判定也沒有保留 [arXiv:2310.01798][arXiv:2210.08726]。補讀的 Stechly et al. 是反例：逐輪記下候選答案、驗證判斷與批評內容，各自對照真值 [arXiv:2402.08115]。
   - Terminal-Bench 的失敗分類每個模式都附判定流程，可以當軌跡 rubric，但只拿來做離線統計 [arXiv:2601.11868]。
   - E5 目前只有離線、一次性的處理 [arXiv:2310.01798][arXiv:2404.17140]，E6 的消費端也常只讀終態 [arXiv:2406.12045][arXiv:2507.02825]；本頁推論，兩者都缺一份評估端能持續讀取的紀錄格式。

## 怎麼讀這份調研

### 每一章的結構

八章都有相同的十一個段落：這一章回答什麼、問題的演進、方法比較、評估方式與關鍵數字、程式驗證、爭議矛盾與反證、商用採納現況、與其他節點的關係、未解問題、已知缺口與未讀、文獻表。章末的文獻表由程式依 [`data/reading-status.json`](data/reading-status.json) 與精讀筆記產生，「一句話」取自筆記的 `one_liner`，不是人手寫的。

### 標記

- **✅**：讀完全文、錨點驗證合格，計入本節點。
- **📖**：讀完全文但不計入，原因寫在文獻表裡。這次的 7 篇都是精讀後判為低價值。📖 論文只能當脈絡或反例，任何主張都不能只靠它們撐。
- **❌**：只拿得到摘要。這次沒有任何一篇是 ❌。沒有讀的候補不列在章末文獻表，名單在 [`data/shortlist.json`](data/shortlist.json)。

### 計數規則

一篇論文要計入某節點，下面四條都要成立：

1. 主節點是這個節點。
2. 讀到全文（`read_level=full`，來源是 arXiv HTML 或 ar5iv）。
3. 精讀後沒有被判成低價值。
4. 錨點驗證合格。

計數由 [`tools/check_notes.py`](tools/check_notes.py) 重跑錨點比對後算出，不採用閱讀 agent 自己回報的數字，結果寫在 [`data/reading-status.json`](data/reading-status.json)。同一篇論文只有一個主節點；別的章可以引用它，但不重複計入。

### 錨點驗證

筆記裡每個關鍵數字與主張都附一小段原文錨點，由 `tools/arxiv_tool.py anchors` 對快取全文做字串比對。至少要 3 段完全相符，而且其中至少 2 段落在全文 20% 之後。第二個條件是為了驗到方法與實驗的主張，不讓錨點全取自摘要與引言。錨點原文與全文快取只存在 `.cache/`，不進版控。

### 數字比對工具

[`tools/check_chapter.py`](tools/check_chapter.py) 對一份 Markdown 逐句檢查：句子裡的每個數字，都要能在該句引用論文的筆記或快取全文裡找到；沒附出處的句子沿用同一行的出處。寫出來的四則算式（例如 a − b = c）會直接驗算，算對了，結果就不必在筆記裡。0–10 的整數、年份、章節號與表號不比對。

它只抓「根本找不到這個數字」的句子，不判斷數字用得對不對，後者是查核員的事。本頁也用它檢查過；它對本頁仍會列出的，只有流程數字，沒有一個出自論文：

- 節點篇數表、合計、子領域配額與計入數：出處是 [`data/reading-status.json`](data/reading-status.json) 與 [`data/topics.json`](data/topics.json)。
- 「至少 20 篇」、T3 的 12／8 切法、錨點規則裡的 20%、2025–2026 的新論文規則：計劃參數，出處是 [`plan.md`](plan.md)。
- 針對性補讀的 21 篇、其中 7 篇與 14 篇的來源，以及上一版（W4）的計入、已精讀與候補未讀篇數：出處是 [`data/reading-status.json`](data/reading-status.json) 與 [`data/shortlist.json`](data/shortlist.json) 的 from 欄。
- 六條邊的篇數：「標了這條邊的筆記」由程式從 [`notes/`](notes/) 的 `edges` 欄數出，full／partial／related 是各邊分類 agent 的輸出，「本輪新增」是兩者之差；T3 與 T8 標了幾次邊、補讀論文標了幾次邊，也是從 `edges` 欄數的。
- [`verify/`](verify/) 的程式支數：直接數目錄裡的 `.py` 檔。
- 〈這份調研自己的限制〉裡一篇未讀論文標題中的資料集版本號：標題照 ID 閘門清單逐字抄錄，不是數字主張。

### 程式驗證

[`verify/`](verify/) 有 86 支程式，八章依序是 9、8、11、10、10、15、13、10 支，結論與方法寫在各章的 `verify/NN-results.md`（例如 [`verify/01-results.md`](verify/01-results.md)）。W3 時八章各挑四條能用確定性方法驗的主張；W4 修訂時，稽核指出數字比對工具驗不到的主張，例如全表計數、多格重算、跨表比對，也改寫成程式。W6 整合針對性補讀時新增 14 支，多半驗補讀論文的表格與精讀筆記自己的推算，另改寫 2 支既有程式（`05-scope-counts.py` 與 `06-sim-human-rank-tau.py`）以納入新筆記。

- 程式只用 Python 標準函式庫，輸入數字直接從快取全文或筆記的原文解析，不手抄；錨點與快取的處理細節各章略有不同，見各自的 results 檔。
- 結論分成證實、有條件或部分證實、無法判定、不成立或推翻幾種；一條主張的幾個子主張判讀不同時，會分開下結論。
- W3 的挑選對象多半是精讀筆記 `limitations_observed` 裡的主張；W4 另外納入章節撰寫者自己的換算與計數。

這些驗證推翻過精讀筆記，也推翻過章節自己的句子。例如筆記說 MetaSim 全文沒做顯著性檢定，程式驗證找到好幾張表有顯著性標記 [arXiv:2204.00763]；筆記說 Self-feeding 的「不滿意」約佔 38%–39%，程式驗證指出那只是上限 [arXiv:1901.05415]。T6 章原本說模擬與真人的名次對照「規模最大的也只有 4 個系統」，程式驗證找到 MetaSim Table 5 的 7 個變體 [arXiv:2204.00763]；T5 章原本說 RISE 的宣稱「重算後縮水」，程式驗證只能判定為無法定位 [arXiv:2407.18219]。補讀之後的驗證也一樣：1909.01388 說交叉矩陣的對角線通常最高，程式驗證推翻了這一句 [arXiv:1909.01388]；精讀時判斷它的交叉平均靠的是測試池裡難的 agenda 模擬器，程式驗證把這個判斷收窄成「含 agenda 模擬器不是充分條件」[arXiv:1909.01388]；PARADISE 筆記的缺點清單只列了改用母體標準差算出的那組原始滿意度係數，程式驗證指出與論文一致的是另一組 [arXiv:cmp-lg/9704004]。

### 出處標籤：誰說的

各章與本頁的出處一律寫成 [arXiv:ID]，同一個 ID 下的內容分幾種來源，讀的時候要分開：

- **沒有額外標籤**：論文自己的主張、表格數字，或筆記的 `limitations_stated`（論文自述的限制）。
- **「精讀時發現」「精讀時指出」「精讀時依公開資料重算」**：出自筆記的 `limitations_observed`。這是精讀 agent 自己的分析，有些是它依論文表格或公開 repo 重算的結果；它不是論文的結論，也沒有經過同儕審查。上一節的例子說明它可能錯。
- **「撰寫時推算」「組章時重算」「本章推論」「本章歸納」「本章比對」「修訂時查全文」，以及本頁的「依 Tn 章的歸納」「本頁推論」「本頁讀法」**：章節撰寫者或本頁自己的換算、歸納或對快取全文的核對。換算會把算式與原始數字寫在句子裡。
- **「程式驗證證實」「有條件證實」「部分證實」「無法判定」**：[`verify/`](verify/) 的結論。
- **「標題（arXiv ID，未讀）」**：本調研沒讀的論文，只經 ID 閘門確認存在。各章與本頁只寫「依標題，它研究什麼」與它能檢驗哪一句，不引用它的任何數字或結論，也不寫成 [arXiv:ID]。
- **本頁「六條邊」的 full／partial／related，以及各邊小節裡對論文的描述性判斷**（例如「反思是綜合而不是修正」「兩篇都是單輪輸入」）：分類 agent 或本頁的讀法，不是論文的主張。

### 商用採納

各章「商用採納現況」一節只收附 URL 的證據，例如模型卡、產品文件、廠商官方部落格。被論文引用、學術引用數、作者單位都不算採納；沒有證據就寫「未見證據」。本頁不另作採納判斷，要看採納請到各章該節。

### 這份調研自己的限制

- **名單階段**：前兩輪篩選在 Haiku 預設下跑，轉抄有捏造（見 [`plan.md`](plan.md)）。後段改由程式算數字、人工逐節點複核來補救，但名單漏收了什麼，無法完全排除。
- **落選理由多半是制式句**：[`plan.md`](plan.md) 承諾落選附理由，但 [`data/candidates/`](data/candidates/) 的落選紀錄裡，有 1,151 筆是 rejected，其中 735 筆的理由都是同一句「未入選（篩選者依範圍與影響力判斷）」，其餘 416 筆是程式硬規則 RECENT-INELIGIBLE；同一篇論文可能在兩個節點的檔案裡各有一筆。被制式句處理的包括 Tree of Thoughts: Deliberate Problem Solving with Large Language Models（arXiv 2305.10601，未讀）與 MultiWOZ 2.1: A Consolidated Multi-Domain Dialogue Dataset with State Corrections and State Tracking Baselines（arXiv 1907.01669，未讀），兩篇各在兩個節點落選；依標題，後者是修正了狀態標註的 MultiWOZ 整合版資料集。這些論文為什麼沒入選，無法從紀錄稽核。
- **子領域覆蓋**：W4 版有七個子領域低於配額；針對性補讀之後剩兩個，T1 的 LLM 時代意圖差兩篇、T4 的失敗歸因差一篇（見「範圍」）。W4 版這一條點名的兩篇 T3 監控論文，有一篇已經補讀：Reasoning Models Don't Always Say What They Think 量到只讀 CoT 的偵測器會大量漏失 reward hack [arXiv:2505.05410]。另一篇 Measuring Faithfulness in Chain-of-Thought Reasoning（arXiv 2307.13702，未讀）仍列在 T3 章的〈已知缺口與未讀〉；依標題，它研究 CoT 忠實度怎麼量。
- **邊的證據怎麼抽樣**：每條邊的論文，只來自依節點選進來、再由精讀者自己在筆記 `edges` 欄標了那條邊的那一批，是兩層篩選後的樣本；本調研沒有針對任何一條邊做過檢索。所以六條邊的「缺什麼」只描述這批筆記，不是全文獻的缺口。這個抽樣方式的後果看得到：E4 只剩 3 篇，而且沒有一篇的主節點是它的起點 T4；E5 的 27 篇沒有一篇的主節點是它的終點 T7。針對性補讀也沒有改變這一點：補讀是為了檢驗章節的否定句挑的，不是為了邊，E4 一篇都沒有增加。
- **邊的分類**：由 agent 判斷，各邊的判準寬嚴不一。本頁寫出了已知與章節讀法不同的地方：E2 的三種計數、E3 的 AgentQuest 與 2404.06474、SWE-agent 的 lint；其他邊沒有逐篇對照過章節。針對性補讀的論文在筆記裡新標的邊，沒有重跑分類 agent；本頁在各邊的「補讀新增」一段寫的是自己依筆記與各章的讀法，總表的「判定」一欄仍是分類 agent 依原有筆記下的。
- **地圖本身可能漏了邊**：六條邊與八個節點是框架事先給定的，本調研沒有檢討地圖本身。依章節內容，下面幾處值得問，但都只是疑問，本調研沒有檢驗：
  - T3 章判斷，E3 的異常訊號實際多半由 T3 的監控器讀 T4 的軌跡產生，T3 的筆記也標了 11 次 E3，其中 3 次來自補讀的 AgentMonitor、Ctrl-Z 與 Chen et al.。那麼「監控訊號觸發修正」是否該是一條從 T3 出發的邊，而不是掛在 T4 → T5 名下？
  - T7 章首寫明，分數怎麼定義與聚合歸 T8、軌跡的步驟級評分歸 T4，遇到時只點出交界；T8 章說 τ-bench、ToolSandbox、TheAgentCompany 這幾篇同時提出了環境與分數。T8 在地圖上沒有任何邊，筆記卻標了 22 次邊。T7 與 T8 之間、T4 與 T7 之間，是否各少了一條邊？
  - T6 章把 JOUST 列為「模擬器的話語是系統唯一的外部輸入」的例子，系統從模擬使用者的話語抽出 slot-value 限制；T2 的 Lost in Conversation 也由模擬器逐輪揭露意圖。使用者輸入直接進入狀態追蹤，只靠 E1（T6 → T1）表達是否足夠？
  - E4 與 E5 的端點節點自己沒有論文標它們。這兩條邊的方向或端點是否畫對了？
- **針對性補讀讀了 21 篇，其餘仍未讀**：W4 只做文字修訂，把否定句收窄到本調研讀過的論文。之後的針對性補讀（W5、W6）讀了 21 篇，筆記、錨點與快取全文都齊，內容已整合進各章，本頁也依整合後的各章同步。各章〈已知缺口與未讀〉裡仍列著的論文，都還沒讀；它們只經 ID 閘門確認存在，各章與本頁沒有引用它們的任何數字或結論。所以各章寫「本調研讀過的論文裡沒有」的地方，有一部分可能只是還沒讀到。
- **補讀的選文不是隨機樣本**：21 篇都是為了檢驗某章某一句否定句挑的，沒有重跑發現與篩選，挑的人也知道要檢驗的是哪一句。它們全數計入，讓計入篇數從 185 篇增為 206 篇、讓十二個子領域超過配額；這些增加集中在被檢驗的那幾句附近，不能讀成那幾個子領域被更完整地抽樣，也不能拿補讀前後的篇數或比例去推論文獻的分佈。補讀推翻、收窄或證實了哪些句子，寫在各章，例如 T6 對模擬器名次效度的判斷改成條件式的（見跨節點發現第 6 條）。
- **程式驗證的範圍**：只挑能用確定性方法驗的主張，不是全面稽核。
- **快取**：`.cache/` 不進版控。沒有快取時，數字比對工具只能對筆記比；[`tools/check_notes.py`](tools/check_notes.py) 找不到錨點原文與全文，每篇的相符錨點都算成 0，重算出來的計入篇數會是零，這時請以版控裡的 [`data/reading-status.json`](data/reading-status.json) 為準。驗證程式在一份不含 `.cache/` 的副本上重新實測（W6 之後）：86 支中只有 13 支跑得起來，也就是第 1 章的 9 支與第 2 章的 4 支，它們印出的結論與有快取時相同，其中第 1 章的 9 支是略過錨點檢查照樣算；其餘 73 支直接開啟 `.cache/` 讀輸入，沒有本機快取就跑不起來。W4 版能跑的 `05-scope-counts.py` 改寫後要讀 `.cache/work/w3/` 的邊彙整檔，現在也跑不起來。

### 重現

在 repo 根目錄執行。第一行與第三行都需要本機的 `.cache/`：沒有快取時，第一行的計入篇數會是零，第三行的 86 支程式只有 13 支跑得起來（見上一節）：

```bash
python3 .docs/chat-agent-research/tools/check_notes.py                  # 重算每個節點的計數
python3 .docs/chat-agent-research/tools/check_chapter.py \
  .docs/chat-agent-research/chapters/01-goal-intent.md                   # 章節數字比對
for f in .docs/chat-agent-research/verify/*.py; do python3 "$f"; done   # 全部程式驗證
```
