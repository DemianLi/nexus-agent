# AI Agent 對話完成框架：arXiv 文獻調研

這份調研替「AI Agent Dialogue Completion Framework」的 8 個節點各寫了一章，再逐條分析節點之間的 6 條邊。本頁是入口，依序是：範圍與方法、跨節點的發現、六條邊、整個框架的未解問題，最後說明各章的標記、計數與查核工具怎麼讀。

本頁與各章都是純研究，不寫產品建議，也不寫「對 nexus 的意涵」。

### 方法摘要

完整方法見 [`plan.md`](plan.md)，這裡只列骨架。

1. **發現與篩選**
   - 每個節點分三路找候選：綜述 snowball、arXiv 關鍵字、商用採納。
   - 每個 arXiv ID 都要經 [`tools/arxiv_tool.py`](tools/arxiv_tool.py) 解析並比對標題，對不上就丟。這一關由程式把守。
   - 第一輪篩選 agent 轉抄的數字不可信，所以改由 [`tools/pool.py`](tools/pool.py) 以程式建候選池、算引用數與硬旗標，agent 只判斷範圍，另設反方 agent 挑錯。
   - 之後逐節點人工複核歸屬，理由記在 [`tools/review_overlay.py`](tools/review_overlay.py)，再由 [`tools/build_shortlist.py`](tools/build_shortlist.py) 去重，產出 [`data/shortlist.json`](data/shortlist.json)。同一篇論文只會有一個主節點。
   - 影響力依據三種訊號：Semantic Scholar 引用數、發表處，以及附 URL 的商用採納證據。2025–2026 的新論文引用數還少，只能靠頂會正式論文或商用採納證據入選。
2. **精讀**
   - 一篇論文由一個 agent 讀全文（arXiv HTML 或 ar5iv），寫成結構化筆記 [`notes/<id>.json`](notes/)，並交出原文錨點。
   - 主選讀完，每個節點都已超過 20 篇，所以候補沒有動用。
3. **綜合與查核**
   - 每個節點先分組寫段落草稿，再組成一章。
   - 查核員先跑 [`tools/check_chapter.py`](tools/check_chapter.py)，列出找不到出處的數字，再做對抗式查核。
   - 另一個 agent 挑出能用確定性方法驗的主張，寫程式驗證，放在 [`verify/`](verify/)。
   - 修訂後再跑一次數字比對，每章另有一個 critic。
   - 六條邊各由一個 agent 分類。

[`plan.md`](plan.md) 記錄了一條與名單可信度有關的事：前兩輪篩選時子代理預設跑 Haiku，它們轉抄的數字與理由裡有捏造，可能與此有關，但沒有做過對照。精讀起每個 agent 都明確指定 Opus。

## 跨節點的主要發現

以下每一條都至少橫跨兩個主節點，括號裡是出處論文所屬的節點。論文自己的結論不另加標記；精讀 agent 的分析標「精讀時發現」「精讀時指出」這類字樣；章節撰寫者的歸納標「依 Tn 章的歸納」，換算則寫出算式；程式重算過的標「程式驗證」。

1. **不需要模型的平凡解，在多個節點追平或勝過被報告的方法，而原論文多半不報這個基準**（T1、T3、T4、T7、T8）
   - IN3 的模糊判斷準確率 85.19%，低於一律判模糊的 95/108 = 87.96%（精讀時發現，程式驗證證實）[arXiv:2402.09205]。
   - R-Judge 以 unsafe 為正類，全部判 unsafe 的全集 F1 就有 69.04；11 個模型中只有 GPT-4o 的 74.45 高於它（精讀時發現，程式驗證證實）[arXiv:2401.10019]。
   - AgentRewardBench 的副作用金標只有 72/1106 ≈ 6.51%，GPT-4o mini (A) 的 precision 7.2 幾乎等於基率（精讀時發現，程式驗證證實）[arXiv:2504.08942]。
   - OSWorld 一律回 FAIL 可拿 30/369 = 8.13%；Table 5 的 26 組模型×設定只有 5 組高過這個地板（精讀時發現，程式驗證證實）[arXiv:2404.07972]。
   - τ-bench airline 上，ABC 的 do-nothing agent 拿到 38% [arXiv:2507.02825]；τ-bench 原排行榜在 airline 最高的是 gpt-4o 的 35.2 [arXiv:2406.12045]。
   - 觸發修正的評估器也有同樣的形狀。2404.06474 的評估器準確率是 74.4–82.1%。精讀時依 agent 成功率約 14.4%–15.6% 推算，一律判失敗就有約 84–86% 的準確率（100% − 15.6% = 84.4%，100% − 14.4% = 85.6%）[arXiv:2404.06474]。
   - 不是每個平凡基準都站得住：Who&When 的「一律猜第 1 步」能不能勝過所有方法，程式驗證的結論是無法判定 [arXiv:2505.00212]。

2. **決定「要不要介入」的閘門，訊號普遍偏弱，而且閘門的準確度換算不成下游的淨效益**（T1、T3、T5、T6）
   - 何時問：Clarify When Necessary 的 AUROC 只有 0.371–0.628 [arXiv:2311.09469]；精讀時發現，Future Turns 在相同直接回答比例下，F1 只比隨機高 0.6–1.0 [arXiv:2410.13788]。
   - 何時修正：SCORE 固定 refiner、只換驗證器，self-verifier 的增益只有 −0.3 到 +0.4 [arXiv:2404.17140]。gpt-3.5-turbo 驗證器的 F1 是 59.7，修正後的準確率卻 −11.2，驗證器的 F1 預測不了淨增益 [arXiv:2404.17140]。
   - 何時要回饋：Self-feeding 的滿意度分類器 F1 是 0.84，不確定度基線是 0.56。但分類器看了使用者的下一句話，基線是 bot 開口前的預測，兩者可用的資訊不同（程式驗證以原文證實）[arXiv:1901.05415]。
   - 何時告警：CoT 監控器對只看行動的監控器，合併召回率是 95% 對 60% [arXiv:2503.11926]；SHADE-Arena 的 monitor 最佳 AUC 0.87 [arXiv:2506.15740]。直接對 CoT 監控器施加 RL 壓力後，召回率掉到接近 0 [arXiv:2503.11926]。
   - 與門檻無關的量法很少見：依 T1 章的歸納，全章只有兩處報 AUROC [arXiv:2101.03778][arXiv:2311.09469]。

3. **知道答案的一方常被放進迴圈裡，量到的增益有一部分只是上限**（T1、T4、T5、T6、T7）
   - Huang et al. 在同一個 GPT-3.5、CommonSenseQA 上，用標籤決定何時停止得 89.7，拿掉標籤只剩 41.8 [arXiv:2310.01798]。RCI 附錄自己的無標籤版本，CommonSenseQA 也從 64.56 掉到 46.06 [arXiv:2303.17491]。
   - 精讀時發現，Future Turns 的評估模擬器拿得到答案 [arXiv:2410.13788]。Clarify When Necessary 裡被選中發問的輸入，拿到的是 oracle 問答而不是模型自己的問題，所以表中增益是上限（精讀時發現）[arXiv:2311.09469]。
   - iEvaLM 的模擬器會說出目標標題。排除這類洩漏造成的成功後，UniCRS 在 ReDial 的 Recall@1 從 0.219 掉到 0.029 [arXiv:2403.16416]。
   - MINT 的環境在模型提出解答時以 ground truth 判對錯並回報，預設的 GPT-4 回饋者則看不到 ground truth [arXiv:2309.10691]；精讀時指出，這讓 MINT 的「使用者」實際上握有神諭式的對錯訊號 [arXiv:2309.10691]。
   - 失敗定位後注入診斷重跑的閉環，都在整條任務被判定失敗之後才啟動（AgentDebug、AgenTracer）[arXiv:2509.25370][arXiv:2509.03312]。AgenTracer 的設計本身就以 oracle 失敗訊號為前提 [arXiv:2509.03312]；精讀時指出，AgentDebug 接近帶 oracle 的 pass@k [arXiv:2509.25370]。

4. **產生行為或訓練訊號的一方，常常也是判分的一方**（T1、T5、T6、T7、T8）
   - 精讀時依 repo 發現，Proactive Agent 用同一個 RM 篩訓練資料又當評審 [arXiv:2410.12361]；精讀時指出，STaR-GATE 的 gold 與評審都是 GPT-4 [arXiv:2403.19154]；精讀時發現，CollabLLM 的訓練與評估用同一個模擬器、同一份提示詞 [arXiv:2502.00640]。
   - 精讀時發現，Alexa 的標籤、上傳前過濾與 A/B 缺陷率，都出自同一個 friction 模型 [arXiv:1911.02557]；精讀時發現，JOUST 的 RL-Joint 是對著一起被最佳化的模擬器量成功率 [arXiv:2107.11904]；CIPHER 的模擬使用者與偏好推論都是 GPT-4 [arXiv:2404.15269]。
   - 精讀時發現，Self-Refine 對話任務的評審與回饋共用同一套面向 [arXiv:2303.17651]。
   - 依 T7 章的歸納，評審研究裡的自我偏好都只有觀察式比較，沒有一篇固定回答品質做受控實驗 [arXiv:2306.05685][arXiv:2305.17926][arXiv:2404.04475]。
   - 精讀時發現，HAL 用來回收自我修正片段的 judge 本身也是受測模型 [arXiv:2510.11977]。
   - 反例很少：2410.13788 讓訓練與評估用不同的模擬器 [arXiv:2410.13788]，GenTUS 用交叉模型評估估計泛化 [arXiv:2208.10817]。

5. **偵測做得細的地方沒有接上修正，接上修正的地方偵測很粗**（T3、T4、T5、T8）
   - Who&When 的 step-level 最佳只有 14.2% [arXiv:2505.00212]；TRAIL 的聯合準確率在 GAIA 是 0.183、在 SWE 是 0.050 [arXiv:2505.08638]。E3 的邊分類把兩篇都歸為只做偵測、沒有接到修正迴路 [arXiv:2505.00212][arXiv:2505.08638]。
   - Tyen et al. 的 LLM 找錯最佳只有 52.87，低於它用模擬分類器估出的約 60–70% 門檻 [arXiv:2311.08516]；精讀時發現，論文微調出的偵測器從沒接回修正迴圈跑端到端 [arXiv:2311.08516]。
   - 依 T3 章的歸納，R-Judge、SHADE-Arena、Llama Guard 只做偵測 [arXiv:2401.10019][arXiv:2506.15740][arXiv:2312.06674]。監控論文裡接上處置的只有 AI Control 與 Baker 等人，處置也都由 agent 以外的一方執行，也就是可信模型接手或測試期 rejection sampling [arXiv:2312.06942][arXiv:2503.11926]。
   - 真正由軌跡內容觸發修正的，觸發器多半是手調規則或精確比對。例如 Reflexion 在 ALFWorld 以「同一動作同一回應連續出現」或「動作數超限」判失敗 [arXiv:2303.11366]；AgentQuest 以字串比對擋下重複的猜測 [arXiv:2404.06411]。
   - 依 T4 章的歸納，失敗歸因的評估集（Who&When、AgenTracer、AgentDebug）只收失敗軌跡，偵測器的誤報率從沒量過 [arXiv:2505.00212][arXiv:2509.03312][arXiv:2509.25370]。

6. **模擬使用者是好幾個節點共用的量具，偏差沒有固定方向，效度證據也不穩**（T1、T2、T6、T7、T8）
   - 只換使用者 LLM、agent 固定為 GPT-4o，τ-Bench retail 的成功率就在 67.0% 到 75.9% 之間變動 [arXiv:2601.17087]。真人對話的失敗有 62.2% 歸因於使用者，模擬對話只有 40.0% [arXiv:2601.17087]。
   - 有的偏差讓任務變簡單：排除目標洩漏後，ChatGPT 在 ReDial 的 R@10 從 0.539 掉到 0.271 [arXiv:2403.16416]。有的讓任務變難：τ²-bench 模擬器的 critical error 在 airline 達 13% [arXiv:2506.07982]；iEvaLM 自己的對照裡，模擬端的 R@10 全面低於人扮使用者 [arXiv:2305.13112]。
   - 模擬器的取樣會混進量到的變異。Lost in Conversation 的使用者模擬器以 T=1.0 取樣，精讀時發現量到的 unreliability 混進了模擬器端的變異 [arXiv:2505.06120]。精讀時也發現，τ-bench 重跑的變異主要來自溫度 1.0 的使用者模擬器 [arXiv:2406.12045]。
   - 排名效度的證據互相打架。GenTUS 的真人 success 是 GenTUS 0.86、ABUS-S 0.79、ABUS-T 0.75；以 ABUS-T 或 ABUS-S 測試時，模擬端的順序完全相反（程式驗證證實）。但作者自己說兩個 ABUS 的真人差距不顯著 [arXiv:2208.10817]。NUS 的真人端照表面值六對都不顯著（程式驗證）[arXiv:1805.06966]。
   - 其他節點也在用這把量具：依 T1 章的歸納，把「問、答、再推斷」閉起來的論文裡，量化對照過真人的只有 GATE [arXiv:2310.11589]；T7 的 MT-Bench-101 用金上下文重播，它自己的對照顯示這會讓後續輪次的分數虛高 [arXiv:2402.14762]。

7. **同名指標不是同一把尺：實作、版本或施測協定一換，數字就跟著換**（T2、T7、T8）
   - 同一個 MDBT，MultiWOZ 論文報的 JGA 是 80.9，TRADE 重跑只有 17.98 [arXiv:1810.00278][arXiv:1905.08743]。FnCTOD 的逐領域平均比多領域 Overall 高 62.59 − 38.71 = 23.88 [arXiv:2402.10466]。
   - MultiWOZ 統一重算後，UniConv 的 Inform／Success 從 84.7／76.3 掉到 66.7／58.7，而語料本身只有 93.7／90.9 [arXiv:2106.05555]。
   - WebArena 自報的人類成功率是 78.24% [arXiv:2307.13854]；OSWorld 用自己的協定重測 WebArena 題目，得到 88% [arXiv:2404.07972]。GAIA 的人類分數只在有效題上計算，而論文對有效題有兩種定義 [arXiv:2311.12983]。
   - 2602.16666 轉述 Cuadron et al.，τ-bench airline 原本 50 題中有 24 題有錯 [arXiv:2602.16666]；HAL 承認新版 τ²-bench 修掉了任務規格與評估指標上的已知問題，仍使用原版 TAU-bench [arXiv:2510.11977]。

8. **只讀終態或最終答案的判準，看不到過程錯誤，也擋不住不作為**（T4、T5、T7、T8）
   - ProcessBench 的 Omni-MATH 上，答案對而過程錯的比例是 51.8% [arXiv:2412.06559]；MAST 的失敗模式在成功的 run 裡照樣常見 [arXiv:2503.13657]。
   - 訓練自我修正的獎勵也只看最終答案（SCoRe、RISE）[arXiv:2409.12917][arXiv:2407.18219]。精讀時發現，SCoRe 附錄標為修正成功的例子裡有錯誤推理 [arXiv:2409.12917]。
   - getter＋evaluator、單元測試與 r_prog 都只描述「最後要成立什麼」，只看終態的判分會被 do-nothing agent 鑽過去 [arXiv:2306.06070][arXiv:2404.07972][arXiv:2307.13854][arXiv:2507.02825]。
   - 部分分數也沒有補上這個洞。依 T8 章的歸納，子目標、里程碑、checkpoint 這些錨點都要人從參考解法寫出來，效度驗證幾乎沒有 [arXiv:2408.04682][arXiv:2401.13178][arXiv:2412.14161]。ScienceWorld 4-2 上，隨機代理的 0.63 高於所有訓練代理 [arXiv:2203.07540]。

9. **成本一對齊，結論常常改變，而記帳單位各節點不同**（T1、T5、T8）
   - 回應數相同時，多代理辯論輸給 self-consistency，9 個回應時是 83.0 對 88.2 [arXiv:2310.01798]。RISE 的 m1@t5 對 m5@t1，T5 章依 Table 1 重算 Llama2 Iter1，只多 50.7 − 49.7 = 1.0 點 [arXiv:2407.18219]。
   - HumanEval 上，不帶反思的 Warming（GPT-4）是 93.2%、成本 $2.45；LATS（GPT-4）是 88.0%、$134.50 [arXiv:2407.01502]。T8 章指出，AATM／HAL 的凸包 frontier，與 Cost-of-Pass 逐題取 min 的 frontier 互不相容 [arXiv:2510.11977][arXiv:2407.01502][arXiv:2504.13359]。
   - 發問的成本沒有共同單位：GATE 量主觀心力負擔，CollabLLM 量使用者時間（比 Base 少 10.4%）；T1 章指出，兩者都沒換算成共同指標 [arXiv:2310.11589][arXiv:2502.00640]。

10. **單次執行、小分母與論文內部不自洽，在各節點都查得到**（T1–T8）
    - SWE-agent 的消融每格只跑一次，無示範那一格的 1.7 點不到 2 個標準差（程式驗證證實）[arXiv:2405.15793]。
    - Reflexion 的 EPM 消融多出 8%，在 100 題上只是 8%×100 = 8 題 [arXiv:2303.11366]。
    - 精讀時依表格算出，Proactive Agent 的 Qwen2-7B 只以 1.87 點勝 GPT-4o，差距落在雜訊內 [arXiv:2410.12361]。
    - 精讀時發現，Self-feeding 在 131k 筆資料時，單加 HB 的三組與基線 44.7 只差約一個標準差 [arXiv:1901.05415]。
    - 1709.06560 的 KS p 值來自舊版 scipy 的漸近公式。改用精確檢定後，p=0.036 的那 14 格（實為 7 組不重複的比較）在 0.05 水準下都不顯著（程式驗證證實）[arXiv:1709.06560]。
    - 精讀時發現，τ-bench Table 2、ToolSandbox、TheAgentCompany 都沒有誤差棒 [arXiv:2406.12045][arXiv:2408.04682][arXiv:2412.14161]。
    - 程式驗證證實不自洽的表格與正文：
      - Shepherd Table 5 的平均欄高低顛倒 [arXiv:2308.04592]
      - OmniParser 的 Mind2Web 表有四列把 Cross-Domain 抄進 Cross-Task [arXiv:2408.00203]
      - TRADE Table 2 五領域那一格的 slot accuracy 違反 JGA 下界 [arXiv:1905.08743]
      - Chatbot Arena Table 5 把精確率當成真陽性率 [arXiv:2403.04132]
      - Agent-FLAN Table 3 有一列 H_Score 與子指標對不上 [arXiv:2403.12881]
      - 2310.10176 Table 5 的 ChatGPT GID 欄其實是 3:1 的數字 [arXiv:2310.10176]
      - 2602.16666 的 C_out 有 (2·acc−1)² 的下限，與它引言說的「與原始準確率無關」相左 [arXiv:2602.16666]

### E1 External Input（T6 → T1）：使用者（模擬器）的輸入進入目標對齊

**判定：有被處理，而且有多篇直接把輸入當自變數操縱。** full 的 19 篇全部計入；partial 裡有一篇 📖（2309.13233），related 裡也有一篇 📖（2407.20859）。

**full 由哪些論文撐。** 文獻裡這條流多半長成這樣：握有隱藏目標的模擬器逐輪釋出需求，agent 以澄清提問或偏好推斷吸收，再用下游成敗計分 [arXiv:2403.19154][arXiv:2410.13788][arXiv:2502.00640]。把 T6 那一側的輸入當自變數的研究量到：

- 排除模擬器洩漏的目標標題後，UniCRS 在 ReDial 的 Recall@1 從 0.219 掉到 0.029 [arXiv:2403.16416]。精讀時發現，排除規則沒有定義，有些格子排除後 recall 反而上升 [arXiv:2403.16416]。
- 意圖分片逐輪揭露時，15 個模型平均比單輪給齊掉 39%；一次給齊的 Concat 平均保留 Full 的 95.1% [arXiv:2505.06120]。精讀時發現，使用者模擬器同樣以 T=1.0 取樣，量到的 unreliability 混進了模擬器端的變異 [arXiv:2505.06120]。
- 從 No-User 改成 Default，pass^1 在 gpt-4.1 下滑 18%、在 o4-mini 下滑 25% [arXiv:2506.07982]。精讀時發現，No-User 的 agent 另外拿到了成功條件與改寫過的政策，所以這段落差混了資訊取得難度與溝通成本 [arXiv:2506.07982]。
- 以 UserLM-8b 取代提示型模擬器，GPT-4o 的 Assistant Score 從 74.6 降到 57.4 [arXiv:2510.06552]。精讀時發現，數學題上 UserLM-8b 的覆蓋率只有 76.5，落差裡混了必要條件沒講出來的效果 [arXiv:2510.06552]。
- 固定 GPT-4o agent、只換輸入來源時，真人對話的失敗有 62.2% 歸因於使用者端，模擬對話只有 40.0% [arXiv:2601.17087]。精讀時發現，失敗歸因由作者自行標註，沒有報告標註一致性 [arXiv:2601.17087]。

其餘 full 論文把模擬或真人的輸入接進澄清、偏好引出與意圖改寫的訓練或評估：[arXiv:1804.06512][arXiv:1907.06554][arXiv:1911.02557][arXiv:2305.13112][arXiv:2310.11589][arXiv:2311.05584][arXiv:2311.09469][arXiv:2402.09205][arXiv:2404.15269][arXiv:2410.12361][arXiv:2602.16666]。

**partial 的四種形狀。**

- 模擬器是固定的評估管線，實驗只換 agent，沒有操縱輸入 [arXiv:2406.12045][arXiv:2408.04682]。
- 換模擬器是為了比較訓出的策略或評估模擬器本身，沒有分析輸入怎麼被系統吸收 [arXiv:1805.06966][arXiv:2208.10817][arXiv:2306.00774][arXiv:2107.11904][arXiv:2204.00763][arXiv:1612.05688][arXiv:2208.10264]。另有 📖 的 [arXiv:2309.13233]，它對兩個系統的排名與人類相反，只能當反例。
- 靜態、單輪、離線的輸入，沒有模擬器也沒有互動迴圈 [arXiv:1909.02027][arXiv:2101.03778][arXiv:2310.10176][arXiv:1805.04655][arXiv:2305.07157][arXiv:1909.05855][arXiv:2207.01206]。
- 只有示範或計劃，沒有評估 [arXiv:2304.03442][arXiv:2009.11352]。

related 的三篇只在輸入端做安全分類或注入攻擊，沒有進入目標對齊的資料流 [arXiv:2208.03188][arXiv:2312.06674][arXiv:2407.20859]。

**缺什麼。**

- 「agent 推斷出的目標」沒有被當成獨立的量測對象。多數研究只量端到端成功：精讀時發現 τ-bench 的結果導向獎勵分不出是 agent 錯還是模擬器錯 [arXiv:2406.12045]，one-shot success 也同時混了推斷與推薦 [arXiv:2311.05584]。
- 模擬器與受測者之間的資訊不對稱常被破壞：精讀時發現，模擬器拿得到目標 item 或答案 [arXiv:2305.13112][arXiv:2410.13788]；已有論文量到洩漏會灌高評估結果 [arXiv:2403.16416]。
- 真人對照很少。最完整的是跨方言、年齡、國家的那一篇 [arXiv:2601.17087]；GATE 附錄有比，但只有圖、沒有相關係數 [arXiv:2310.11589]；iEvaLM 有比，但精讀時發現扮使用者的真人也拿到同一份含目標的指令 [arXiv:2305.13112]。
- T1 章另外指出：其他節點量到的模擬器偏差，還沒被拿回來重估 T1 的「何時問」與「目標推斷」結果；使用者中途改變目標也沒有進入任何評估 [arXiv:2310.11589][arXiv:2502.00640]。

### E2 State Adjustments（T5 → T2）：反思修正的結果回寫對話狀態

**判定：只在對話狀態之外處理過。** 在標了這條邊的 10 篇裡，E2 實際的樣子是把口語反思或自評附加進 agent 下一步會讀的脈絡或記憶，沒有一篇改寫 DST 式的槽位狀態 [arXiv:2310.04406][arXiv:2310.08560][arXiv:2304.03442]。

**full 由哪些論文撐。** 三篇都有閉環寫回與消融，但寫回對象都不是同一段對話的狀態：

- **Reflexion**：把反思附加到跨嘗試的長期記憶。HotpotQA 的 EPM 消融裡，反思比只放上一條軌跡多出 8%，在 100 題上是 8%×100 = 8 題；觸發訊號是與標準答案做 EM 比對 [arXiv:2303.11366]。
- **LATS**：把反思寫回搜尋樹與 agent 提示。拿掉反思後 HotPotQA EM 從 0.63 降到 0.58，差 0.63 − 0.58 = 0.05 [arXiv:2310.04406]。
- **WebCanvas**：把自評 reward 寫進步驟 memory，GPT-4 的 Task SR 反而從 16.9 降到 13.8。同一個模組也負責判定何時完成，所以寫回本身的效果分不出來 [arXiv:2406.12373]。

**partial。**

- RCI 的計劃只在回合開始時修正一次 [arXiv:2303.17491]。
- Generative Agents 的反思是綜合而不是修正；消融只限制回答時可讀的記憶型別，TrueSkill μ 是 29.89 對 26.88 [arXiv:2304.03442]。
- MemGPT 會用函式呼叫改寫 working context；精讀時發現，狀態更新的正確性完全沒被量化 [arXiv:2310.08560]。
- SWE-agent 把格式錯誤的輪次從歷史中刪掉，效果沒有量化 [arXiv:2405.15793]。
- RMM 改的是讀取策略，不是狀態內容；LongMemEval 準確率從 58.8 到 60.2 [arXiv:2503.08026]。

related 的兩篇：一篇綜述沒有自己的系統或實驗 [arXiv:2308.03188]；Hindsight 的意見寫回只停在設計層 [arXiv:2512.12818]。

**與章節的讀法對照。** T2 章認為資料流最接近完整的是 MemGPT，但沒有任何實驗量它的正確率 [arXiv:2310.08560]，邊分類因此把它歸 partial。兩種讀法說的是同一件事：資料流有了，量測沒有。

**缺什麼。**

- 在標了這條邊的論文裡，沒有一篇在同一段多輪對話內，把偵測到的錯誤修正寫回對話狀態（槽位、使用者事實、任務進度），再量寫回前後的狀態正確率 [arXiv:2303.11366][arXiv:2310.04406][arXiv:2406.12373]。
- 非 oracle 觸發的正面證據也缺。兩篇正面結果的消融都在 HotpotQA 上，以標準答案判定對錯來觸發 [arXiv:2303.11366][arXiv:2310.04406]；唯一不看參考答案的自評寫回反而拉低了 Task SR [arXiv:2406.12373]。
- 錯誤反思怎麼失效與回收，沒有人處理：精讀時發現 Generative Agents 的反思未經驗證就寫回，還能引用舊反思 [arXiv:2304.03442]；RMM 的記憶更新只有 Add／Merge，沒有 Delete [arXiv:2503.08026]。
- T2 章從另一端補了一句：更新這一步本身從來沒被單獨量過，量的一直是 JGA 或下游問答 [arXiv:2504.19413][arXiv:2512.12818]。

### E3 Anomalies Detected（T4 → T5）：軌跡中偵測到異常時觸發自我修正

**判定：有閉環，但觸發多半靠 oracle 成敗訊號或手調規則。** 偵測器的誤報與它對修正的淨效果，沒有在同一個迴圈裡一起量過。

**full 由哪些論文撐。** 10 篇分成三種形狀。

- **執行中由軌跡內容觸發**
  - Reflexion 在 ALFWorld 以重複動作或動作數超限判失敗，12 次嘗試內解出 130／134 題 [arXiv:2303.11366]。精讀時發現，門檻是為該環境手調的 [arXiv:2303.11366]。
  - LATS 由 LLM 逐節點評分驅動回溯；拿掉 LM 評分，EM 由 0.63 掉到 0.37 [arXiv:2310.04406]。精讀時發現，價值解析器會把推理中的年份或價格讀成高分，所以這組消融量到的是含雜訊的解析器加上 oracle 終局 reward [arXiv:2310.04406]。
  - ToolLLM 的 DFSDT 讓模型自判走不下去就回溯，pass rate 是 63.8，成本對齊的 ReACT@N 是 44.5 [arXiv:2307.16789]。精讀時發現，ReACT@N 怎麼對齊成本沒有寫，評審 ChatGPT 同時也是 teacher [arXiv:2307.16789]。
  - AgentQuest 偵測到重複猜測就重新提示，15 個實例的 SR 從 0.47 升到 0.60 [arXiv:2404.06411]。精讀時發現，RR 歸零是機制強制出來的，而且只有單一模型、每題看來只跑一次、沒有誤差棒 [arXiv:2404.06411]。
  - WebCanvas 的 reward 模組會判 loop，但自評 reward 反而拉低了表現 [arXiv:2406.12373]。
- **失敗後定位再修正**
  - 2404.06474 的評估器判定失敗後才觸發反思，在 WebArena 上帶來 16% 與 29% 的相對提升 [arXiv:2404.06474]。精讀時發現，評估器實際多半只看最後一張截圖，而且準確率低於一律判失敗（見跨節點發現第 1 條）[arXiv:2404.06474]。
  - AgentDebug 從最早的關鍵錯誤重跑，ALFWorld 上 GPT-4o-mini 從 21 升到 55 [arXiv:2509.25370]。精讀時發現，修正指令由較強的 GPT-4.1 產生，缺少「通用回饋同樣從中途重跑」的對照，下游數字也沒標單位與評估集大小 [arXiv:2509.25370]。
  - AgenTracer 把歸因推理當回饋：OWL Workforce 在 GAIA 上 +4.8%，MaAS 在 MATH-500 上 +14.21% [arXiv:2509.03312]。精讀時發現，缺少換另一個模型做同樣歸因的對照，分不出增益來自精準歸因還是任何外部診斷，多數數字也只在圖中 [arXiv:2509.03312]。
  - Tyen et al. 依錯誤步的位置回滾重抽 [arXiv:2311.08516]。
- **監控觸發重抽**：Baker 等人在測試期以 rejection sampling 丟棄被標記的樣本 [arXiv:2503.11926]。精讀時發現，這一節的關鍵結果只有曲線圖，沒有數值、誤差區間或重跑次數 [arXiv:2503.11926]。

**與章節的讀法對照。** 邊分類比兩章寬。

- T5 章照字面收緊判準，要求偵測對象是多步軌跡、偵測結果真的觸發修正；T5 自己的論文只剩 Reflexion 與 LATS [arXiv:2303.11366][arXiv:2310.04406]。
- 邊分類另外收的幾篇各有保留：Tyen et al. 的軌跡是一句一步的 CoT 推理，「修正」是不帶回饋文字的重抽 [arXiv:2311.08516]；Baker 等人的修正是重抽與 reward 懲罰，不是 agent 自己反思 [arXiv:2503.11926]。
- T3 章把 SWE-agent 的單步 lint 視為唯一「執行期由外部偵測觸發、再由 agent 自己修正」的例子：一次失敗後，最終成功的機率從 90.5% 降到 57.2%。邊分類則因為它只在單步層級偵測而歸 partial [arXiv:2405.15793]。

**partial 的四種形狀。** 共 29 篇。

- 觸發或偵測不是讀軌跡的異常閘門，而是單一輸出、單步、答案層級、步數預算、固定輪數或逐輪回饋 [arXiv:2210.08726][arXiv:2211.00053][arXiv:2303.17491][arXiv:2303.17651][arXiv:2304.05128][arXiv:2305.11738][arXiv:2308.13724][arXiv:2310.01798][arXiv:2404.17140][arXiv:2405.14092][arXiv:2405.15793][arXiv:2407.01502][arXiv:2407.18219][arXiv:2408.04682][arXiv:2309.10691][arXiv:2210.03629][arXiv:2310.05915]。
- 只有偵測，沒有接到修正 [arXiv:2312.06674][arXiv:2401.10019][arXiv:2412.06559][arXiv:2504.08942][arXiv:2505.00212][arXiv:2505.08638][arXiv:2506.15740]。
- 修正發生在執行期之外：離線訓練、人工重新設計，或等使用者提供修正後離線重訓 [arXiv:2403.02502][arXiv:2501.12326][arXiv:2503.13657][arXiv:1901.05415]。
- 偵測對象是單次產出，由另一個模型接手重寫 [arXiv:2312.06942]。

related 有三篇 [arXiv:2308.03188][arXiv:2406.01297][arXiv:2507.11473]。

**缺什麼。**

在標了這條邊的論文裡，沒有一篇在同一個迴圈裡同時做到下列三件事，而且是在不能重置重來的多輪情境下：

1. 用非 oracle 的軌跡異常偵測器觸發修正，而不是成敗標籤或手調門檻。
2. 單獨量這個偵測器在成功與失敗軌跡上的誤報與漏報。
3. 量它對下游修正的淨效果。

目前的缺口分散在各處：

- 定位型的閉環全靠 oracle 失敗訊號，或 oracle／模擬的錯誤位置啟動 [arXiv:2509.25370][arXiv:2509.03312][arXiv:2311.08516]。
- 只做偵測的軌跡研究都沒有接到修正 [arXiv:2505.08638][arXiv:2505.00212][arXiv:2412.06559][arXiv:2504.08942][arXiv:2506.15740][arXiv:2401.10019]。
- 作者自述偽陰性會逼 agent 重做已經成功的任務，傷害比偽陽性大，但沒有給數字 [arXiv:2404.06474]。
- 偵測器成為最佳化目標後會失效，這一點也只在單一 coding 情境、以曲線呈現 [arXiv:2503.11926]。

### E6 Interaction Logs（T6 → T7）：互動紀錄回流評估

**判定：處理得最多，但檢驗這條流本身的研究，多半得到警訊。** full 27 篇中 2309.13233 是 📖，所以計入的是 27 − 1 = 26 篇；partial 27 篇中 2510.07777 是 📖。

## 整個框架的未解問題

1. **「不作為」這一類決策要怎麼雙向計分。** 拒識、不問、不修正、判正常後繼續、放棄任務，這類決策在 T1、T4、T5、T7、T8 都出現，也都缺同時計入誤拒與誤收、並對照平凡基準的量法。
   - T1 沒有評估協定能把真拒答、解析失敗、拒答偏移分開計分 [arXiv:2305.07157][arXiv:2310.10176]。
   - T4 的失敗歸因評估集只收失敗軌跡 [arXiv:2505.00212][arXiv:2509.03312]。
   - T5 沒有一篇同時報觸發率、對改錯率、錯改對率與成本 [arXiv:2311.08516][arXiv:2404.17140]。
   - T7 與 T8 則有「正確放棄」墊出來的分數地板 [arXiv:2404.07972][arXiv:2507.02825]。

2. **非 oracle 的軌跡異常偵測器接上修正之後，淨效益是正還是負。** 前提是在不能重置重來的多輪情境下。這一題同時卡在 T4 的偵測準確度、T5 的觸發門檻，以及 E3 缺的同一迴圈量測 [arXiv:2505.08638][arXiv:2311.08516][arXiv:2404.06474][arXiv:2509.25370]。

3. **修正怎麼寫回對話狀態，寫回之後狀態有沒有變對。**
   - 更新這一步沒有操作層級的 ground truth，也就是該抽哪些事實、該 UPDATE 還是 DELETE [arXiv:2504.19413][arXiv:2512.12818]。
   - 錯誤的反思寫回後怎麼失效 [arXiv:2304.03442][arXiv:2406.12373][arXiv:2503.08026]。
   - 修正怎麼傳到依賴它的下游步驟 [arXiv:2210.08726][arXiv:2303.11366]。
   - 這一題橫跨 T2、T5 與 E2。

4. **模擬使用者能不能代表真人。**
   - 模擬器排出的系統名次，對真人名次有多少預測效度 [arXiv:2305.13112][arXiv:2601.17087]。
   - 怎麼給模擬器目標又不洩漏 [arXiv:2403.16416][arXiv:2510.06552]。
   - 誰有權結束一集 [arXiv:2506.07982]。
   - 使用者中途改變目標時，怎麼評估「對齊成功」[arXiv:2310.11589][arXiv:2502.00640]。
   - 這一題同時決定 T1、T6、T7、T8 的分數，也就是 E1 與 E6 兩條邊的效度。

5. **評估器自己的雙向誤差，怎麼傳進任務層級的誤差棒。** 判定器、LLM judge、監控器、模擬器都是量具，但多半只被往一個方向稽核過。
   - 判定器 [arXiv:2207.01206][arXiv:2404.07972][arXiv:2601.11868]。
   - 精讀時發現，ABC 附錄 F 的誤差傳遞式方向有誤 [arXiv:2507.02825]；Mind2Web 2 只量到葉節點 [arXiv:2506.21506]。
   - 監控門檻依賴一份「確定誠實」的參考分布 [arXiv:2312.06942]。

6. **多次試驗的變異從哪裡來。** agent 取樣、使用者模擬器取樣、API 非確定性與環境漂移，還沒被分開量 [arXiv:2406.12045][arXiv:2411.00640][arXiv:2602.16666]。T2 的多輪退化研究量到的 unreliability 也混了模擬器端的變異（精讀時發現）[arXiv:2505.06120]。pass^k 在「任務 × 每任務 k 次」兩層結構下的估計量與信賴區間還沒有定論 [arXiv:2406.12045][arXiv:2602.16666]。

7. **成本要用什麼共同單位記帳。** 各節點的單位各自為政：
   - T1：多問一輪值多少任務成功 [arXiv:2410.13788][arXiv:2310.11589][arXiv:2502.00640]。
   - T3：觀測壓縮的 token、延遲與任務損失 [arXiv:2405.15793][arXiv:2501.12326]。
   - T5：修正對重抽的呼叫數與 token [arXiv:2310.01798][arXiv:2407.18219]。
   - T8：沒有可執行驗證器時的成本怎麼算 [arXiv:2504.13359]。

   成本口徑一換，frontier 就跟著換 [arXiv:2510.11977][arXiv:2407.01502][arXiv:2504.13359]。

8. **軌跡、修正紀錄與互動紀錄沒有共同格式，評估端無法持續消費。**
   - 軌跡格式與失敗分類法無法互相對照，沒有任何一批軌跡被兩套以上的分類法標過 [arXiv:2505.08638][arXiv:2503.13657]。
   - 修正紀錄的欄位各記各的，閘門判定也沒有保留 [arXiv:2310.01798][arXiv:2210.08726]。
   - Terminal-Bench 的失敗分類每個模式都附判定流程，可以當軌跡 rubric，但只拿來做離線統計 [arXiv:2601.11868]。
   - E5 目前只有離線、一次性的處理 [arXiv:2310.01798][arXiv:2404.17140]，E6 的消費端也常只讀終態 [arXiv:2406.12045][arXiv:2507.02825]；本頁推論，兩者都缺一份評估端能持續讀取的紀錄格式。

## 怎麼讀這份調研

### 每一章的結構

八章都有相同的十個段落：這一章回答什麼、問題的演進、方法比較、評估方式與關鍵數字、程式驗證、爭議矛盾與反證、商用採納現況、與其他節點的關係、未解問題、文獻表。章末的文獻表由程式依 [`data/reading-status.json`](data/reading-status.json) 與精讀筆記產生，「一句話」取自筆記的 `one_liner`，不是人手寫的。

### 標記

- **✅**：讀完全文、錨點驗證合格，計入本節點。
- **📖**：讀完全文但不計入，原因寫在文獻表裡。這次的 7 篇都是精讀後判為低價值。📖 論文只能當脈絡或反例，任何主張都不能只靠它們撐。
- **❌**：只拿得到摘要。這次沒有任何一篇是 ❌。沒有讀的候補不列在章末文獻表，名單在 [`data/shortlist.json`](data/shortlist.json)。

### 計數規則

一篇論文要計入某節點，下面四條都要成立：

1. 主節點是這個節點。
2. 讀到全文（`read_level=full`，來源是 arXiv HTML 或 ar5iv）。
3. 精讀後沒有被判成低價值。
4. 錨點驗證合格。

計數由 [`tools/check_notes.py`](tools/check_notes.py) 重跑錨點比對後算出，不採用閱讀 agent 自己回報的數字，結果寫在 [`data/reading-status.json`](data/reading-status.json)。同一篇論文只有一個主節點；別的章可以引用它，但不重複計入。

### 錨點驗證

筆記裡每個關鍵數字與主張都附一小段原文錨點，由 `tools/arxiv_tool.py anchors` 對快取全文做字串比對。至少要 3 段完全相符，而且其中至少 2 段落在全文 20% 之後。第二個條件是為了驗到方法與實驗的主張，不讓錨點全取自摘要與引言。錨點原文與全文快取只存在 `.cache/`，不進版控。

### 數字比對工具

[`tools/check_chapter.py`](tools/check_chapter.py) 對一份 Markdown 逐句檢查：句子裡的每個數字，都要能在該句引用論文的筆記或快取全文裡找到；沒附出處的句子沿用同一行的出處。寫出來的四則算式（例如 a − b = c）會直接驗算，算對了，結果就不必在筆記裡。0–10 的整數、年份、章節號與表號不比對。

它只抓「根本找不到這個數字」的句子，不判斷數字用得對不對，後者是查核員的事。本頁也用它檢查過；它對本頁仍會列出的，只有篇數表、配額與計劃參數這類流程數字，它們的出處是 [`data/reading-status.json`](data/reading-status.json)、[`data/topics.json`](data/topics.json) 與 [`plan.md`](plan.md)，不是論文。

### 程式驗證

[`verify/`](verify/) 有 32 支程式，八章各挑四條能用確定性方法驗的主張，結論與方法寫在各章的 `verify/NN-results.md`（例如 [`verify/01-results.md`](verify/01-results.md)）。

- 程式只用 Python 標準函式庫，輸入數字直接從快取全文或筆記的原文解析，不手抄；錨點與快取的處理細節各章略有不同，見各自的 results 檔。
- 結論分成證實、有條件證實、無法判定、推翻幾種；一條主張的幾個子主張判讀不同時，會分開下結論。
- 挑選對象多半是精讀筆記 `limitations_observed` 裡的主張。

這些驗證也推翻過精讀筆記。例如筆記說 MetaSim 全文沒做顯著性檢定，程式驗證找到好幾張表有顯著性標記 [arXiv:2204.00763]；筆記說 Self-feeding 的「不滿意」約佔 38%–39%，程式驗證指出那只是上限 [arXiv:1901.05415]。

### 出處標籤：誰說的

各章與本頁的出處一律寫成 [arXiv:ID]，同一個 ID 下的內容分幾種來源，讀的時候要分開：

- **沒有額外標籤**：論文自己的主張、表格數字，或筆記的 `limitations_stated`（論文自述的限制）。
- **「精讀時發現」「精讀時指出」「精讀時依公開資料重算」**：出自筆記的 `limitations_observed`。這是精讀 agent 自己的分析，有些是它依論文表格或公開 repo 重算的結果；它不是論文的結論，也沒有經過同儕審查。上一節的例子說明它可能錯。
- **「撰寫時推算」「組章時重算」「本章推論」「本章歸納」，以及本頁的「依 Tn 章的歸納」「本頁推論」**：章節撰寫者或本頁自己的換算或歸納。換算會把算式與原始數字寫在句子裡。
- **「程式驗證證實」「有條件證實」「無法判定」**：[`verify/`](verify/) 的結論。
- **本頁「六條邊」的 full／partial／related，以及各邊小節裡對論文的描述性判斷**（例如「反思是綜合而不是修正」「兩篇都是單輪輸入」）：分類 agent 或本頁的讀法，不是論文的主張。

### 商用採納

各章「商用採納現況」一節只收附 URL 的證據，例如模型卡、產品文件、廠商官方部落格。被論文引用、學術引用數、作者單位都不算採納；沒有證據就寫「未見證據」。本頁不另作採納判斷，要看採納請到各章該節。

### 這份調研自己的限制

- **名單階段**：前兩輪篩選在 Haiku 預設下跑，轉抄有捏造（見 [`plan.md`](plan.md)）。後段改由程式算數字、人工逐節點複核來補救，但名單漏收了什麼，無法完全排除。
- **子領域覆蓋**：七個子領域低於配額（見「範圍」），T1 的 LLM 時代意圖與 T3 的監控各差兩篇。
- **邊的分類**：由 agent 判斷，各邊的判準寬嚴不一，本頁已逐條寫明與章節讀法的差異。
- **程式驗證的範圍**：只挑能用確定性方法驗的主張，每章四條，不是全面稽核。
- **快取**：`.cache/` 不進版控。沒有快取時，數字比對工具只能對筆記比；驗證程式裡只有第 1 章的四支會略過錨點檢查照樣算，其餘各章的程式直接開啟 `.cache/text/` 讀輸入，沒有本機快取就跑不起來；[`tools/check_notes.py`](tools/check_notes.py) 則找不到錨點原文與全文，每篇的相符錨點都算成 0，重算出來的計入篇數會是零，這時請以版控裡的 [`data/reading-status.json`](data/reading-status.json) 為準。

### 重現

在 repo 根目錄執行。第一行與第三行都需要本機的 `.cache/`：沒有快取時，第一行的計入篇數會是零，第三行除了第 1 章的四支都跑不起來（見上一節）：

```bash
python3 .docs/chat-agent-research/tools/check_notes.py                  # 重算每個節點的計數
python3 .docs/chat-agent-research/tools/check_chapter.py \
  .docs/chat-agent-research/chapters/01-goal-intent.md                   # 章節數字比對
for f in .docs/chat-agent-research/verify/*.py; do python3 "$f"; done   # 全部程式驗證
```
