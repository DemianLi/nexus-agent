## 主張 1：ToolSandbox 的 II 類別讓 do-nothing agent 白拿分

**主張**：28 個 Insufficient Information（II）基底情境中，有 26 個沒有 milestone。評分程式在 milestone 為空時把 milestone 分數預設為 1，所以只要沒踩到 minefield 就是滿分。組章時據此推論，一個什麼都不做的 agent 光靠 II 就能拿到總分 26×8/1032 ≈ 20.2 分。

**出處**：[arXiv:2408.04682]，`notes/2408.04682.json` 的 `limitations_observed[0]`（28、26 與「預設為 1」）與 `limitations_observed[4]`（129 × 8＝1032）。章節位置：「問題的演進」的 ToolSandbox 段、陷阱三、爭議第四條。20.2 分是組章時延伸的推論。

**方法**（[`08-toolsandbox-ii-weight.py`](08-toolsandbox-ii-weight.py)）：

- 從 `.cache/text/2408.04682.txt` 解析兩張表：
  - Table 6：第 1392–1415 行，各類別的情境數。
  - Table 5：第 399–658 行，13 個模型各 16 欄。
- 檢查 Table 6 各類別數能不能被 8 整除，以及 STC＋MTC＋II 是否剛好等於 1032。
- 逐模型用兩種方式重算 Avg，都要落在四捨五入誤差（約 0.10）以內：
  - (a) (152·STC＋656·MTC＋224·II) / 1032
  - (b) 8 個工具擴增欄的簡單平均
- 確認筆記裡寫著 28、26、「預設為 1」。這三個是精讀 agent 讀 repo 得來的，本程式無法重數。
- 算 26×8/1032，以及 do-nothing agent 在 II 類的分數下限 26/28，並拿後者對照 Table 5 的 II 欄。
- 讀論文對 II minefield 的描述（第 285、386 行）。

**實際輸出（摘要）**：

- **Table 6**：全部 7 類都能被 8 整除。STC＋MTC＋II = 152＋656＋224 = **1032**，也就是這三類把全部情境切成互斥的三塊，基底數 19＋82＋28 = 129。II 的基底數是 224 ÷ 8 = **28**，與筆記一致。
- **Avg 的加權方式**：13 列全部重算得出。式 (a) 的最大誤差是 0.040，式 (b) 是 0.063，都在 0.10 以內。所以 Avg 是 1032 個情境的等權平均，II 佔 224/1032 = 21.7% 的權重。
- **算術**：26×8/1032 = **20.155**，四捨五入是 20.2，與章節一致。
- **do-nothing 在 II 類的下限是 26/28 = 92.86**，比 13 個受測模型的 II 分數都高。II 最高的是 Mistral-7B 的 76.8，GPT-4o 是 42.0。
- 20.2 是 Table 5 總分最低的 C4AI-Command R+（24.7）的 82%。
- **minefield**：論文第 386 行說 II 的 minefield 是用來抓「會暗示幻覺的工具有沒有被呼叫」，Figure 3 的例子也是工具呼叫。照這個描述，一個不呼叫工具的 agent 不會觸發 minefield。但這是描述，不是逐一清點。

**結論：無法判定（核心）；算術與加權前提證實。**

- 以下三件事都要 apple/ToolSandbox 的 repo，依規則不下載，所以無法判定：
  - 26 個情境沒有 milestone
  - 空 milestone 預設為 1
  - 實跑 do-nothing agent 的分數
- 能由論文推出的部分都成立：
  - II 有 28 個基底，每個情境佔總分 1/1032，26×8/1032 ≈ 20.2 的算術正確。
  - 「光靠 II 的貢獻 = 情境數 × 分數 / 1032」這個加權前提，由 Table 5 的 13 列重算證實。
- 章節寫「就能在總分拿到 ≈20.2 分」，精確說是**下限**。另外 2 個有 milestone 的 II 基底情境，以及 STC／MTC 情境裡可能的部分分數，都沒有算進去。
- 這個主張帶出一個可檢驗的推論：前提若成立，do-nothing 在 II 類至少拿 92.9，**13 個受測模型的 II 分數全部比它低**。日後有 repo 時，實跑 `UnhelpfulAgent` 就能一次驗掉整條主張。

  - L.2 AlfWorld 第 2741 行：「the set of N subgoals」

## 主張 3：C_out 有由準確率決定的下限

**主張**：2602.16666 的 outcome consistency 滿足 C_out ≥ (2·acc−1)²，準確率 0.9 或 0.1 時下限都是 0.64，與論文引言「這些指標與原始準確率無關」的宣稱相左。

**出處**：[arXiv:2602.16666]，`notes/2602.16666.json` 的 `limitations_observed[1]`（Jensen 推導）與 `limitations_observed[2]`（K=5 只有三個值、τ-bench 26 題×5 次）。章節位置：「問題的演進」的 2602.16666 段、陷阱八、爭議第二條。

**方法**（[`08-cout-accuracy-bound.py`](08-cout-accuracy-bound.py)）：

- 從 `.cache/text/2602.16666.txt` 取出以下原文並印出：
  - C_out 定義：第 220 行，C_out = (1/T) Σ_t (2p̂_t − 1)²
  - p̂_t 與 0.25 正規化：第 224–225 行
  - K=5：第 489 行
  - 引言原句：第 84 行
  - §2 原句：第 197 行
  - 附錄 C.1.1：第 1493 行
- **推導**：g(p) = (2p−1)² 的二階導數是 8，是凸函數。由 Jensen 不等式得 mean g(p̂_t) ≥ g(mean p̂_t) = (2·acc−1)²。
- **精確恆等式**：C_out = (2·acc−1)² + 4·Var_t(p̂_t)。所以等號成立的充要條件是所有題目的 p̂_t 相同。
- **模擬**：
  - K=5，T ∈ {26, 100}，q ∈ {0.1, 0.3, 0.5, 0.7, 0.9}
  - 四種逐題成功率分佈：同質、Beta 分散、兩極 0/1、兩點混合
  - 每組 2000 次，共 80000 次
  - 檢查下限與恆等式
- **可達性**：K=5 時 p̂ 只能取 0.2 的倍數。對 T=26，把總成功次數 S 分到各題，求 C_out 的最小值與最大值。
- **極限**：同質 p=0.9 時，用二項分佈算 E[C_out] 對 K 的精確值。

**實際輸出（摘要）**：

- **原文**：第 84 行確實寫「we propose twelve concrete metrics that are independent of raw accuracy」，第 197 行寫「all four dimensions are independent of raw capability」。
- **單題取值**：K=5 時單題 (2p̂−1)² 只有 {0.04, 0.36, 1.0} 三個值。p̂=0（每次都失敗）與 p̂=1 都得 1.0。
- **模擬**：80000 次中，C_out − (2·acc−1)² 的最小值是 0（沒有負值），恆等式的最大誤差是 3.4e-15。兩極 0/1 分佈不論準確率多少，C_out 都是 1。
- **可達性**（T=26、K=5）：

  | acc | 下限 (2acc−1)² | 可達最小 C_out | 下限可達 |
  | --- | --- | --- | --- |
  | 0.1 | 0.64 | 0.68 | 否 |
  | 0.2 | 0.36 | 0.36 | 是 |
  | 0.5 | 0.00 | 0.04 | 否 |
  | 0.8 | 0.36 | 0.36 | 是 |
  | 0.9 | 0.64 | 0.68 | 否 |

  acc=0.9 最緊的情形，是一半題目 p̂=0.8、一半 p̂=1.0。
- **極限**：同質 p=0.9 時，E[C_out] = 0.64 + 0.36/K，K=5 是 0.712，K=1000 是 0.6404。0.64 是 K→∞ 的極限。
- **可行範圍隨準確率改變**：acc=0.5 的 C_out 最低可到 0.04，acc=0.9 不可能低於 0.68。

**結論：證實。**

- 下限 C_out ≥ (2·acc−1)² 成立：由凸性與 Jensen 推得，並由精確恆等式與 80000 次模擬確認。
- 引言第 84 行「independent of raw accuracy」的措辭確實存在，這個下限與它相左。
- **補充一**：0.64 的算術正確，但在論文實際用的 K=5 下達不到，acc=0.9 或 0.1 時最緊只到 0.68。下限只在 acc 落在 1/K 的格點時才可達。所以章節寫「下限都是 0.64」沒有錯，但若寫成「可以達到」就不對。
- **補充二**：附錄 C.1.1 第 1493 行說 C_out「normalized by the maximum possible variance at a given accuracy level」，但 Table 2 的式子是除以常數 0.25（第 225 行），兩處描述不一致。這個下限針對的是 Table 2 實際用的式子。

## 主張 4：1709.06560 的 KS p 值是舊版 scipy 的漸近近似

**主張**：1709.06560 在 n=5 對 n=5 時報的 KS p 值只有四種：0.004、0.036、0.209、0.697。這四個值是舊版 scipy ks_2samp 的漸近近似。改用精確檢定時，D=0.8 的雙尾 p 是 20/252 ≈ 0.079，所以 Table 9–12 中 14 格報 KS=0.80、p=0.036 的比較，在 0.05 水準下都不顯著。

**出處**：[arXiv:1709.06560]，`notes/1709.06560.json` 的 `limitations_observed[0]`（只有四種 p 值）。「漸近近似」「20/252」「14 格不顯著」是組章時的重算。章節位置：陷阱九、爭議第一條、爭議第九條的表格。

**方法**（[`08-ks-small-sample-pvalue.py`](08-ks-small-sample-pvalue.py)）：

- 從 `.cache/text/1709.06560.txt` 解析 Table 9–12 的每一格，得到 (表, 列, 欄, D, p)，並用 KS(i,j) = KS(j,i) 做解析自檢。
- 附錄第 2030 行寫明 n=5（「from the 5 trials」），並附上 scipy-0.14.0 的 ks_2samp 文件網址。
- **精確分佈**：把 10 個相異值分給兩組各 5 個，列舉 C(10,5) = 252 種等機率排列，得到 P(D ≥ d)。
- **舊版 scipy（0.14）公式**，以純 Python 重寫：
  - en = √(n·m/(n+m))
  - p = Q_KS((en + 0.12 + 0.11/en)·D)
  - Q_KS(x) = 2 Σ (−1)^{k−1} e^{−2k²x²}
- **對照**：另算不加修正項的純漸近 Q_KS(en·D)。
- 數 KS=0.80、p=0.036 的格數與不重複配對數，並確認 t 檢定的 p 值裡沒有 0.036。
- 掃全文有沒有宣告顯著水準，並用 /95%/ 當正向對照。

**實際輸出（摘要）**：

- **解析**：共 47 格。Table 11 的 TRPO 列 PPO 欄在快取全文中是空的，它的鏡像格 PPO 對 TRPO 是 KS=0.40，不影響計數。對稱自檢 0 對不一致，24 組配對齊全。D 與 p 一對一對應，只有 0.004、0.036、0.209、0.697 四種。
- **p 值對照**：

  | D | 論文 | 舊 scipy 漸近 | 純漸近 | 精確 |
  | --- | --- | --- | --- | --- |
  | 0.4 | 0.697 | 0.6974 | 0.8186 | 220/252 = 0.8730 |
  | 0.6 | 0.209 | 0.2090 | 0.3291 | 90/252 = 0.3571 |
  | 0.8 | 0.036 | 0.0361 | 0.0815 | **20/252 = 0.0794** |
  | 1.0 | 0.004 | 0.0038 | 0.0135 | 2/252 = 0.0079 |

  四個值全由舊 scipy 公式重現。純漸近一個都對不上，所以這個吻合不是巧合。
- **KS=0.80、p=0.036**：共 **14 格**，t 檢定的 p 值裡沒有 0.036。每對演算法在矩陣裡正反各出現一次，所以是 **7 組不重複的比較**：
  - Table 9：ACKTR–TRPO、DDPG–PPO、PPO–TRPO

## 主張 5：pass@k 與 pass^k 是同一個無偏估計式的兩面，Eq. 8 的 0/1 形式有負偏誤
