# 06｜User Simulator & User Feedback Loop（使用者模擬器與回饋迴路）

## 這一章回答什麼

本章處理對話 agent「使用者那一端」的兩件事：一是用模擬使用者當強化學習的訓練對手或評估者，從經典的 agenda 規則、神經模擬器到 LLM 扮演的使用者，也包括它們像不像真人、會帶來什麼偏差；二是從部署中的顯式與隱式回饋學習，並估計使用者當下滿不滿意。節點的收錄規則有兩條排除：以 benchmark 為主、使用者模擬只是其中一環的論文，除非對模擬器本身有獨立貢獻，否則歸 T7；一般的 RLHF 偏好資料收集不收。τ²-bench 依「獨立貢獻」這個例外留在本章：它讓使用者擁有工具、以環境狀態約束模擬器，並逐回合稽核模擬器本身的錯誤；精讀時也判斷它的四項貢獻中只有這一項直接屬於本節點，其餘屬評估與任務完成分數 [arXiv:2506.07982]。τ-bench 在選題時是以「用資料庫終態判定成功並提出 pass^k」選進任務完成分數那個節點，本章只在與其他節點的關係一節引用它 [arXiv:2406.12045]。本節點精讀二十四篇、計入二十三篇；計入的論文分屬經典與神經使用者模擬器 5 篇（名單配額 6）、LLM 使用者模擬器 10 篇（配額 10）、使用者回饋迴路與滿意度估計 8 篇（配額 8）。LLM 那一格在名單上的全名是「評估／訓練用，含逼真度研究」，但計入的 10 篇全是評估系統、重現人類研究或量模擬器逼真度的論文，「訓練用」那一半只出現在其他節點的論文裡，演進一節另有交代；回饋那一格計入的 8 篇裡，以滿意度估計為主題的只有 USS 一篇 [arXiv:2105.03748]。讀了但不計入的 [arXiv:2309.13233] 精讀後判為低價值，本章只拿它當準則的出處與反例。撰寫時把三條線並讀，歸納出兩個反覆出現的弱點：產生使用者行為或訓練訊號的一方，常常就是判定成敗的一方 [arXiv:1612.05688][arXiv:2107.11904][arXiv:2204.00763][arXiv:1911.02557][arXiv:2208.03270][arXiv:2404.15269]；在本章計入的論文裡，模擬器給出的系統名次很少有人拿真人在同一批系統上對照過，對照過的規模小，結果又不一致 [arXiv:1805.06966][arXiv:2208.10817][arXiv:2204.00763][arXiv:2305.13112]。

**時間窗與未讀。** 本章文獻表裡的論文，arXiv 年月最早是 2016-05 [arXiv:1605.07669]，最晚是 2026-01 [arXiv:2601.17087]；「與其他節點的關係」一節另外引用其他節點讀過的論文，其中有一篇是 2026-02，只拿來說明節點之間的接點 [arXiv:2602.16666]。選題時另有七篇候補沒有讀，依標題，各自對應的區塊是：模糊問題的選擇性澄清，CLAM: Selective Clarification for Ambiguous Questions with Generative Language Models（arXiv 2212.07769，未讀）；滿意度估計，User Satisfaction Estimation with Sequential Dialogue Act Modeling in Goal-oriented Conversational Systems（arXiv 2202.02912，未讀）與 Interpretable User Satisfaction Estimation for Conversational Systems with Large Language Models（arXiv 2403.12388，未讀）；把對壞回應的負面回饋轉成訓練標籤，When Life Gives You Lemons, Make Cherryade: Converting Feedback from Bad Responses into Good Labels（arXiv 2210.15893，未讀）；以隱式使用者回饋改進大規模對話系統的 NLU，A scalable framework for learning from implicit user feedback to improve natural language understanding in large-scale conversational AI systems（arXiv 2010.12251，未讀）；早期的 seq2seq 使用者模擬器，A Sequence-to-Sequence Model for User Simulation in Spoken Dialogue Systems（arXiv 1607.00070，未讀）；以受訪者自述為依據模擬個人，LLM Agents Grounded in Self-Reports Enable General-Purpose Simulation of Individuals（arXiv 2411.10109，未讀）。後兩篇在選題時就確認沒有 HTML 全文。篩選理由裡關於產品採納與生產系統驗證的說法都沒有核實，本章不採用。本章的結論只涵蓋這個時間窗內讀過的論文，不涵蓋 2026-01 之後的工作，也不涵蓋上述未讀的區塊；審稿另外點出的漏收，以及因此要收窄的句子，見「已知缺口與未讀」一節。

## 問題的演進

三條線的時間大致重疊，年月取自 arXiv 編號的前四碼。經典與神經模擬器從 2016-12 到 2022-08 [arXiv:1612.05688][arXiv:2208.10817]。LLM 扮演使用者從 2022-08 到 2026-01 [arXiv:2208.10264][arXiv:2601.17087]。回饋迴路從 2016-05 到 2024-04 [arXiv:1605.07669][arXiv:2404.15269]。三條線在幾個地方接上，這些接點放在本節最後一小節。

### 經典與神經使用者模擬器：從訓練對手到評估者

這五篇要解的是同一件事。任務型對話的策略若用強化學習訓練，需要大量互動，找真人太貴，所以要一個模擬使用者當訓練對手；後來這個對手也被拿來當評估者 [arXiv:1612.05688][arXiv:1805.06966][arXiv:2107.11904][arXiv:2204.00763][arXiv:2208.10817]。整條線沿三條軸推進：

- **使用者的行為從哪裡來。** 起點是手寫的 agenda 規則，接著換成從語料學出的 seq2seq（本章讀過的論文裡是 NUS，它自述受 El Asri 等人 2016 年的 seq2seq 模擬器啟發，那篇沒有讀），再來是與對話系統對稱的端到端 LSTM、五個 T5 模組加檢索，最後是單一個 BART 以 JSON 字串同時輸出動作與句子 [arXiv:1612.05688][arXiv:1805.06966][arXiv:2107.11904][arXiv:2204.00763][arXiv:2208.10817]。
- **模擬器輸出到哪一層。** 從 dialog act 加模板句，到輸出自然語言、訓練時卻又被解析回語意，到雙方都以自然語言收發，再到 semantic action 與自然語言雙輸出 [arXiv:1612.05688][arXiv:1805.06966][arXiv:2107.11904][arXiv:2208.10817]。
- **怎麼證明模擬器夠好。** 從完全不評，到交叉模型評估加真人試驗、self-play 加人工兩兩比較，到用受控降級的系統變體檢驗鑑別力，再回到直接指標、交叉模型與真人試驗並用 [arXiv:1612.05688][arXiv:1805.06966][arXiv:2107.11904][arXiv:2204.00763][arXiv:2208.10817]。這條軸到最後都沒有共識。

**2016-12，TC-Bot：把 agenda 模擬器工程化並公開。** 作者指出當時沒有標準的模擬器建法，也沒有公認的評估指標，演算法之間難以比較，所以提供一個公開、可插拔的框架 [arXiv:1612.05688]。每場對話從目標庫抽一個目標，目標由限制條件（inform_slots）與想問的 slot（request_slots）組成；目標庫取自 280 段 MTurk 電影購票對話，含 11 個 intent、29 個 slot [arXiv:1612.05688]。之後依 agent 上一個動作的 intent 分派回應規則；不接 NLU 時，用 error model 在 intent 層與 slot 層加噪；語言層是模板加 seq2seq 的混合 NLG [arXiv:1612.05688]。成敗由模擬器自己判：要在輪數上限內答完所有 requestable slot、訂對票才算成功 [arXiv:1612.05688]。它在 §5 留下一個警告：模型式模擬器有不確定性，RL agent 可能學會利用它的錯誤，把失敗的對話做成「成功」 [arXiv:1612.05688]。它留下的缺口有三：

- **沒有評估模擬器本身。** 全文唯一的實驗結果是兩張學習曲線，也沒有真人測試；精讀時發現，§5 說已證明規則式模擬可以安全地訓練 RL，這個結論沒有實驗撐著 [arXiv:1612.05688]。
- **裁判和對手是同一套規則。** 精讀時依公開程式碼發現，判定成敗的邏輯與產生使用者行為的規則同在一個模擬器裡，而且預設用同一個模擬器、同一份目標庫訓練、選模和報成功率 [arXiv:1612.05688]。
- **沒有目標改變。** 作者自己把它列為改進方向 [arXiv:1612.05688]。

**2018-05，NUS：從語料學出使用者，並在實驗中看到策略鑽模擬器漏洞。** NUS 每一輪把系統輸出壓成與值無關的四段二元特徵，累積成歷史交給 LSTM encoder，decoder 生成去詞彙化的使用者語句 [arXiv:1805.06966]。系統說 canthelp 時它會改變目標；一般的 beam search 是確定性的，所以改成每個 beam 抽樣 n 個詞（n = 2）[arXiv:1805.06966]。評估改走間接路線：比較 NUS 與 ABUS 各自訓出的 GP-SARSA 策略，放到另一個模擬器上、放到真人面前各表現如何；作者的理由是直接的統計相似度指標會偏袒以同類指標訓練的模型 [arXiv:1805.06966]。這裡的 ABUS 是 Schatzmann 等人在 2007 年提出的 agenda-based 使用者模擬器，NUS、GenTUS 與 ICL 模擬器那篇都拿它當對照；它不在 arXiv 上，所以本章沒有收 [arXiv:1805.06966][arXiv:2208.10817][arXiv:2306.00774]。NUS 訓出的策略在 NUS 與 ABUS 上的平均成功率是 96.6% 與 94.0%，ABUS 訓出的是 45.5% 與 99.5% [arXiv:1805.06966]。本文最重要的實證是過擬合：NUS 訓出的策略在 ABUS 上的成功率，訓 1000 場是 97.3%、訓 4000 場降到 94.0%，5 個 seed 都一樣 [arXiv:1805.06966]。這替 TC-Bot 對模型式模擬器的警告提供了實驗佐證 [arXiv:1612.05688][arXiv:1805.06966]。它留下的缺口：真人端每個策略只有 250 場、沒有檢定；精讀時發現，NUS 的文字在訓練策略時又被 PyDial 的 regex 解析器解回語意，自然語言這個賣點並沒有進到實驗裡 [arXiv:1805.06966]。

**2021-07，JOUST：模擬器以自然語言收發，並與對話系統一起學。** JOUST 把使用者模擬器做成與對話系統對稱的端到端 LSTM，以二元 goal state 追蹤哪些目標還沒講或還沒問 [arXiv:2107.11904]。兩者先在 MultiWOZ 上監督式預訓練，再以自然語言 self-play，用 policy gradient 同時更新；獎勵除了對話層的成敗，還有按角色區分的逐輪規則獎勵 [arXiv:2107.11904]。換領域時，每個目標領域只用 300 則對話微調，再做 self-play RL [arXiv:2107.11904]。self-play 下，監督式版本的 Succ 是 58.02，四個 RL 變體介於 70.34 到 73.04 [arXiv:2107.11904]。它把模擬器從固定的環境變成可以一起改進的對手，也因此留下新問題：同時更新使用者端（RL-Joint）的成功率高於只更新系統端（RL-DS），但這是對著一起被最佳化的模擬器量出來的，精讀時發現無法區分是系統變好了，還是模擬器變得好對付 [arXiv:2107.11904]。

**2022-04，MetaSim：專為評估而設計，並提出「怎麼評估模擬器」。** 前三篇的模擬器主要是訓練對手，MetaSim 則以評估對話系統為目的 [arXiv:2204.00763]。它由五個 T5 模組組成：Metaphor 以目前對話狀態做 TF-IDF 檢索，再用 monoT5 重排訓練語料中真人說過的話；Policy 把使用者滿意度當成動作裡的一個特殊 slot 一起預測，這個做法沿用 USS；MetaSim 只以一般引用提到 USS，兩篇的第一作者相同，撰寫時依作者重疊把 USS 視為前作 [arXiv:2204.00763][arXiv:2105.03748]。它另外提出 tester：從同一個基礎系統 SOLOIST 以單一控制變因造出能力遞減的變體，讓模擬器與三個變體分別對話、打分、排序，順序與預期完全一致記 1，對 1K 組偏好取平均得到 ExactDistinct（ED）[arXiv:2204.00763]。它回應的是前幾篇的共同缺口：「用它訓出的策略好不好」無法直接回答「這個模擬器分不分得出系統好壞」[arXiv:2204.00763]。在 MultiWOZ 上，MetaSim 三個 tester 的 ED 是 33.23、40.11、35.21，高於 Seq2seq 與 Agenda，但低於 40 位標註者親自與變體對話得到的 43.63、40.54、42.54 [arXiv:2204.00763]。它留下的缺口：tester 的標準答案由設計者規定，精讀時發現自家 Table 5 有兩格與「變體單調變弱」相反；打分用的逐輪滿意度由模擬器自己預測，訓練標籤大多是後驗網路補的偽標籤 [arXiv:2204.00763]。

**2022-08，GenTUS：把動作與語言放進同一次解碼。** GenTUS 用 BART 把輸入（系統 act、前 3 輪使用者 act、goal、輪次）與輸出（使用者 act 加句子）全部序列化成 JSON 字串，一次解出 act 再生句子 [arXiv:2208.10817]。它的直接前作是 TUS；GenTUS 在相關研究中說，TUS 用與領域無關的特徵表示，可以 zero-shot 換到沒見過的領域，但不模擬使用者的語言 [arXiv:2208.10817]。TUS 本身本章沒有讀，見「已知缺口與未讀」第 1 條。解 act 時沿一張由 ontology 與 goal 導出的圖走，擋掉非法動作；ontology 只當輸入，所以可以 zero-shot 換 ontology；再以不同的 turn-level reward 做 PPO，塑形出話少或話多的使用者 [arXiv:2208.10817]。它的真人試驗是這一組唯一報告顯著差異的：以 GenTUS 訓出的系統 success 0.86，ABUS-T 與 ABUS-S 訓出的是 0.75 與 0.79，p<0.05 [arXiv:2208.10817]。它留下的缺口：同一篇的交叉模型評估裡，GenTUS 訓出的系統平均最差（程式驗證證實；不含對角線時只比 ABUS-T 低 (0.63 + 0.50) ÷ 2 − (0.68 + 0.43) ÷ 2 = 0.01），精讀時發現論文沒有討論這個矛盾；zero-shot 只單向成立，SGD 訓練、MultiWOZ 測試的 F1 是 0.49，反向只有 0.27；self-BLEU 0.95 是全表最差 [arXiv:2208.10817]。

### LLM 使用者模擬器（評估與逼真度）：從「扮一群人」到「拿真人校準」

2022 年起，扮演使用者的換成 LLM。這個子領域有兩個源頭：社會科學想用 LLM 重現人類實驗與問卷，任務型對話與推薦系統想用 LLM 使用者做互動評估；到 2025 年以後，重心移到 agent benchmark 的使用者端，以及拿真人校準模擬器 [arXiv:2208.10264][arXiv:2209.06899][arXiv:2305.13112][arXiv:2306.00774][arXiv:2506.07982][arXiv:2601.17087]。撰寫時查到的明確承接至少有這幾條：2403.16416 沿用 iEvaLM 的設定去稽核它，參考文獻也列了 RecAgent；TE 的修訂版把 OOOM 列為同期工作；RecAgent 的參考文獻列了 TE；Lost in Simulation 在 §1 引用了 τ²-bench [arXiv:2403.16416][arXiv:2305.13112][arXiv:2306.02552][arXiv:2208.10264][arXiv:2209.06899][arXiv:2601.17087][arXiv:2506.07982]。本節其餘的承接是撰寫時依主題歸納的，不代表後作在回應前作。

撰寫時歸納出三條軸：

- **模擬器拿到什麼條件。** 從稱謂加姓氏、真實受訪者的背景，到資料集標註的目標 item、few-shot 目標、人設與私有目標，再到「只給屬性、不給答案」、讓使用者擁有工具，最後是從真實對話摘要出的高階意圖 [arXiv:2208.10264][arXiv:2209.06899][arXiv:2305.13112][arXiv:2306.00774][arXiv:2310.11667][arXiv:2403.16416][arXiv:2506.07982][arXiv:2510.06552]。
- **怎麼判斷模擬器好不好。** 從與人類研究的分佈比對、人工判斷像不像人、詞彙多樣性、LLM 評審與人類評分的相關，到從互動紀錄反查洩漏、逐回合標註模擬器違反指令的錯誤、真實使用者語句的 perplexity，最後是讓真人做同一批任務來校準 [arXiv:2208.10264][arXiv:2209.06899][arXiv:2306.00774][arXiv:2310.11667][arXiv:2403.16416][arXiv:2506.07982][arXiv:2510.06552][arXiv:2601.17087]。
- **誰決定對話結束。** 從 NLU 加規則判定，到模擬器自己輸出結束 token、細分成三種結束 token，再到把「離開」當成訓練目標；提早結束一路都是主要的失敗模式之一 [arXiv:2306.00774][arXiv:2506.07982][arXiv:2510.06552]。

本節標題寫「評估與逼真度」，因為計入的 10 篇都用來評估系統、重現人類研究，或量模擬器本身像不像人；名單上這一格原本也涵蓋「訓練用」，但本節沒有一篇拿 LLM 模擬使用者訓練對話 agent。本節裡接進訓練迴圈的只有 RecAgent，它讓推薦器用 agent 的互動增量重訓，但被訓練的是 MF 推薦器，不是對話 agent [arXiv:2306.02552]。

「訓練用」的那一半，撰寫時在其他節點讀過的論文裡找到幾篇，多半是為了教模型主動澄清或引出偏好。STaR-GATE 讓 Mistral-7B 與握有隱藏 persona 的 LLM 模擬使用者對話，以 GPT-4 寫的個人化回應被引出的程度當提問獎勵，反覆 SFT [arXiv:2403.19154]。2311.05584 讓 GPT-3.5 依 persona 想像出大量對話，再用離線 RL 訓練對話 agent [arXiv:2311.05584]。2402.09205 用兩個 GPT-4 分別扮演使用者與助理，合成澄清對話來微調模型 [arXiv:2402.09205]。2410.13788 讓多位持有不同標準答案的模擬使用者回答同一個澄清問題，據以產生 DPO 的偏好 [arXiv:2410.13788]。CollabLLM 用 GPT-4o-mini 模擬使用者往後模擬數輪，以整段對話的結果當每一輪的獎勵 [arXiv:2502.00640]。Proactive Agent 不屬於澄清或偏好引出：它讓 agent 看著使用者的電腦活動，決定要不要主動提議一個任務，並以人工的接受／拒絕標註訓練獎勵模型，當作使用者判斷的替身；它模擬的是使用者對提議接受與否的判斷，不是在多輪對話裡扮演使用者 [arXiv:2410.12361]。精讀時指出，CollabLLM 的訓練與評估用的是同一個模擬器與同一份提示詞，模型學到的可能是那個模擬器的習性 [arXiv:2502.00640]；2410.13788 則刻意讓訓練與評估的模擬器不同 [arXiv:2410.13788]。UserLM 的相關研究一節也說，既有的微調式使用者模型主要用來產生 assistant 的合成訓練資料 [arXiv:2510.06552]。依標題以使用者模擬器改進對話模型的論文，本章沒有讀，見「已知缺口與未讀」第 3 條。

**2022-08，TE（Turing Experiment）：把「模擬一個人」改成「模擬一群人」。** TE 認為 Turing 的模仿遊戲只問 AI 能不能裝成某一個人，對「能忠實模擬哪些人、在哪裡系統性走樣」沒有診斷力 [arXiv:2208.10264]。它只用稱謂加姓氏區分受試者，用 k-choice 提示把各選項的序列機率正規化，直接當成群體中選該選項的比例，零樣本重跑最後通牒賽局、花園路徑句、Milgram 電擊、群眾智慧四個實驗 [arXiv:2208.10264]。人與模型共有的偏差叫 bias，模型與人系統性不同的地方叫 distortion [arXiv:2208.10264]。以 text-davinci-002 模擬的 100 人中，75 人服從到 450V，人類是 26/40 [arXiv:2208.10264]。群眾智慧的結果出自修訂版：text-davinci-003 在全部 10 題都有過半受試者給出完全正確的答案、每題 IQR 為 0；ChatGPT 與 GPT-4 每題的中位數也是真值或近似真值、IQR 為 0，作者稱之為 hyper-accuracy distortion，並推測來自對齊 [arXiv:2208.10264]。這三個模型都在初版之後才推出，這是撰寫時依公開發布時間判斷的；快取的全文是 2023-07 的 v5 [arXiv:2208.10264]。精讀時指出，個體差異只來自名字，模擬群體的異質性上限取決於模型對姓氏與稱謂有多敏感，與真實人群在年齡、教育、文化上的異質性無關 [arXiv:2208.10264]。

**2022-09，OOOM（Out of One, Many）：改用真實受訪者的背景當條件。** OOOM 把模型的偏差重新理解成許多對應不同人口群體的條件分佈，稱為 algorithmic fidelity，並提出四條準則 [arXiv:2209.06899]。做法是 silicon sampling：把每位真實受訪者在 ANES 等調查中的人口與態度變數寫成第一人稱背景故事，交給 base 的 GPT-3 davinci [arXiv:2209.06899]。評估者把人類清單與 GPT-3 清單判為人寫的比例是 61.7% 對 61.2%（p = 0.44）；個人層級的投票與 ANES 自報的 tetrachoric 在 2012、2016、2020 年分別是 0.90、0.92、0.94；11 個題目兩兩之間的 Cramer's V，GPT-3 與人類的差值平均 −0.026 [arXiv:2209.06899]。精讀時依 Table 16 指出，在同樣 1,782 筆完整個案上，GPT-3 生成的 White 比例是 0.974（ANES 0.803）、Graduate Degree 0.002（ANES 0.196）、年齡平均 35.5（ANES 50.1），條件分佈本身就偏了，而關聯指標把這件事蓋住 [arXiv:2209.06899]。TE 的修訂版認為問卷模擬可能比行為實驗容易，因為政治問卷與人口屬性的相關在網路語料裡很常見 [arXiv:2208.10264]。

**2023-05，iEvaLM：把帶目標的 LLM 使用者放進對話推薦的互動評估。** 前兩篇只評模擬器本身，沒有被測的系統 [arXiv:2208.10264][arXiv:2209.06899]。iEvaLM 的出發點是對話式推薦（CRS）的靜態評估：在 Table 2 的靜態評估中，zero-shot 的 ChatGPT 在 ReDial 的 R@10 只有 0.172，落後 MESE 的 0.256 [arXiv:2305.13112]。以模擬使用者評 CRS 並不是從 iEvaLM 開始：它在引言把 Zhang 與 Balog 在 2020 年的工作，歸為受限於預先定義對話流程或樣板語句的既有模擬方法 [arXiv:2305.13112]；那篇本章沒有讀，見「已知缺口與未讀」。作者抽查失敗案例，發現少於三輪的失敗中 51% 偏好本來就模糊，ChatGPT 的失敗回覆中 36% 其實是在主動釐清需求，而寫死的對話無法回應反問 [arXiv:2305.13112]。它把資料集標註的 ground-truth item 寫進 text-davinci-003 的角色指令，讓模擬器扮演「心裡有目標、但不說出片名」的使用者，與受測系統互動最多 5 輪；解釋的說服力交給另一個 LLM 評分器打分 [arXiv:2305.13112]。互動評估的 Table 5 以 ChatGPT 加 text-embedding-ada-002 為基線，論文說明選它是因為它在傳統評估中表現較好；它在 Table 2 的靜態 R@10 是 0.174，與上面 zero-shot ChatGPT 的 0.172 是同一張表的兩列 [arXiv:2305.13112]。改成互動評估後，這個基線在 ReDial 的 R@10 從 0.174 升到 0.536（attr）與 0.440（free）；精讀時指出，attr 設定的使用者回應全由規則樣板產生，沒有用到 LLM 模擬器，只有 free 設定用了 text-davinci-003 模擬器 [arXiv:2305.13112]。它也拿 100 筆 ReDial 樣本比較模擬器與人扮使用者給 4 個系統的排名，兩邊一致 [arXiv:2305.13112]。精讀時指出，模擬器指令裡直接寫著目標 item，這是結構性的洩漏；模擬器又用 temperature 0，每個角色只有一種行為 [arXiv:2305.13112]。

**2023-06，ICL 使用者模擬器：用 few-shot 提示取代規則與訓練資料。** agenda 模擬器換領域就得重寫規則，神經模擬器要大量標註；這篇改問不微調、只靠提示詞，能不能得到可用的任務型對話使用者 [arXiv:2306.00774]。提示詞依序放任務描述、K 段「目標加對話」範例、目標對話的目標與歷史，結尾停在 CUSTOMER:；評估另掛兩顆 BERT NLU 追蹤目標 [arXiv:2306.00774]。在 MultiWOZ 2.1 上對 ConvLab-2 的 pipeline 系統，Succ Rate 是 ABUS-T 0.83、ABUS-D 0.60，GPT-3.5 只有 0.29（依 Jaccard 挑範例）與 0.30（隨機挑）[arXiv:2306.00774]。詞彙多樣性反過來：GPT-3.5 的 unique unigram 是 876／871，ABUS-T 是 527，訓練集人類語句是 919 [arXiv:2306.00774]。使用者端的失敗有放棄、漏提要求、重複同一句、反過來扮演 ASSISTANT、與目標衝突的幻覺；系統說 bye 時，LLM 模擬器也常跟著提早收掉對話 [arXiv:2306.00774]。精讀時依公開程式碼發現，對話何時結束由 NLU 與幾條規則決定，LLM 模擬器還要多經一顆 NLU 解析自己說的話，所以量到的是整組 harness，不只是模擬器 [arXiv:2306.00774]。

**2023-06，RecAgent：把模擬使用者做成有記憶、會互相影響的 agent 群體。** RecAgent 針對 RecSim 這類傳統推薦模擬器的三個問題：決策過度簡化、要先用真實資料訓練、只能處理單一環境 [arXiv:2306.02552]。每位使用者是一個 LLM agent，由 profile、仿認知科學的感官／短期／長期三層記憶與受限格式的動作模組組成，放進回合制沙盒裡搜尋、瀏覽、點擊、私聊與廣播 [arXiv:2306.02552]。在 MovieLens-1M 抽 20 位使用者的辨別任務中，它比最佳基準高約 68%、比 Real Human 低約 8%；50 個 agent 跑 50 回合時，推薦類別熵的最終值比峰值低約 8.5% [arXiv:2306.02552]。它留下的問題：聊天與廣播的可信度到第 15 回合時 4 題全部低於 4 分，長程模擬會漂移；精讀時指出，可信度證據多半是自我一致性評分，樣本只有 20 位使用者、3 位標註者，沒有檢定 [arXiv:2306.02552]。

**2023-09（📖，只當脈絡）：提出「GSR 應貼近真人」的準則。** 這篇用 GPT-NeoX-20B 加兩篇範例扮演使用者，收集 1165 篇真人與 PPTOD／Soloist 的對話當基準，主張模擬器的目標達成率（GSR）應貼近真人，而不是越高越好 [arXiv:2309.13233]。它自己的模擬器沒有達到這個準則：Table 3 中真人在 PPTOD／Soloist 的 GSR 是 56.9／71.9，本法只有 25.0／23.4，對照的 TUS 是 63.7／60.4 [arXiv:2309.13233]。

**2023-10，SOTOPIA：對手換成帶人設與私有目標的角色，評分也交給 LLM。** SOTOPIA 把社交情境寫成帶向量獎勵的 Dec-POMDP，由 GPT-4 生成、人工校正 40 個角色與 90 個情境，組出 450 個任務，雙方可以是 LLM 或人類 [arXiv:2310.11667]。GPT-4 評審依七個維度打分：人類標註者之間的 Randolph κ 是 0.503，由模型扮演角色時 GPT-4 與人類平均分在 Goal 上的相關是 0.71 [arXiv:2310.11667]。換成人類扮演時，Goal 反而升到 0.78，Fin、Bel、Kno 從 0.62、0.45、0.33 明顯降到 0.34、0.27、0.19，Rel 從 0.56 小降到 0.49，Soc 從 0.33 升到 0.42，Sec 沒有資料 [arXiv:2310.11667]。論文正文說除 Goal 外都明顯下降，撰寫時核對全文，這句與它自己的 Table 1 不符 [arXiv:2310.11667]。在 SOTOPIA-hard 的 20 題上，人類的目標達成度顯著高於 GPT-4；GPT-4 每回合 45.5 字、人類 16.8 字，GPT-4 還傾向先覆述對方、較早妥協 [arXiv:2310.11667]。精讀時判斷它是本節點的邊界案例：對手是與 agent 對等、各有目標的角色，不是向助理求助的使用者 [arXiv:2310.11667]。

**2024-03，2403.16416：稽核模擬器有沒有把任務變簡單。** 這篇沿用 iEvaLM 的設定，把「推薦成功」拆成三個來源：對話歷史本來就含目標標題、模擬器在互動中說出標題、CRS 真的從偏好表達中學到東西 [arXiv:2403.16416][arXiv:2305.13112]。排除受兩種洩漏影響的成功對話（-both）後，ReDial 的 Recall@50 下降 KBRD −21.6%、BARCOR −13.8%、UniCRS −13.5%、ChatGPT −21.4%；ReDial 原始 Recall@10 是 KBRD 0.229 勝 BARCOR 0.190，-both 後變成 0.143 對 0.187，名次翻了 [arXiv:2403.16416]。成功推薦也高度集中在第 1 輪，CRS 還沒用到模擬器的回覆就已命中 [arXiv:2403.16416]。它提出的 SimpleUserSim 在成功前只讓模擬器知道目標的屬性，並依 CRS 當輪意圖切換提示詞；ReDial Recall@50 在 -response 下的跌幅，從 iEvaLM 的 12.0%、6.8%、10.3%、17.9% 降到 0%、0%、0.3%、0.1% [arXiv:2403.16416]。但模擬器仍會用自己的世界知識補充偏好，例如列舉導演代表作，無意間說出標題 [arXiv:2403.16416]。它沒有任何真人對照；精讀時發現，換成 SimpleUserSim 後多數 CRS 的 recall 反而下降 [arXiv:2403.16416]。

**2025-06，τ²-bench：讓使用者擁有工具，用環境狀態約束模擬器。** τ²-bench 指出 τ-bench 這類基準是「單控制」，只有 agent 能改動世界；它把客服寫成雙控制 Dec-POMDP，使用者也有工具，可以操作自己的模擬手機 [arXiv:2506.07982]。使用者是 gpt-4.1 實作的 function-calling agent：只在 agent 要求時呼叫工具、一次只做一個動作、等 agent 問了才揭露資訊，並以 ###STOP###、###TRANSFER###、###OUT-OF-SCOPE### 三種 token 結束 [arXiv:2506.07982]。telecom 由 15 個原子子任務組出 2285 題，再抽 114 題 [arXiv:2506.07982]。主指標沿用 τ-bench 的 pass^k：每題在 temperature 0 下跑 4 次，報 k = 1 到 4；各 k 的數值只畫在 Figure 3，正文給的是 pass^1 [arXiv:2506.07982]。精讀時指出，temperature 0 下各次之間的差異主要來自 API 的非決定性與模擬器，k 也只到 4，pass^k 量到的「一致性」意義因此變弱 [arXiv:2506.07982]。gpt-4.1 的 pass^1 是 retail 74%、airline 56%、telecom 34%；從 agent 自己操作所有工具的 No-User 改成要指導使用者動手的 Default，論文寫 gpt-4.1 下滑 18%、o4-mini 下滑 25%，撰寫時核對全文，論文沒說明這是百分點還是相對比例 [arXiv:2506.07982]。它也稽核模擬器本身：兩位標註者逐一檢查每個使用者回合，total／critical 錯誤率是 airline 47%／13%、retail 40%／12%、telecom 16%／6%，telecom 的 8 個錯誤全是 agent 還沒轉接、使用者就先輸出 ###TRANSFER### [arXiv:2506.07982]。撰寫時核對全文，四項標註準則中有三項檢查模擬器有沒有照 guideline、使用者指令與工具說明走，只有一項看對話延續是否自然、一致 [arXiv:2506.07982]。精讀時指出，這些準則都沒有真人對照，量得出「聽話」，量不出「像人」的程度；論文也沒有拿掉使用者工具的消融 [arXiv:2506.07982]。

**2025-10，UserLM：直接從真實對話訓練使用者模型。** UserLM 針對當時的主流做法，也就是提示 assistant 去扮演使用者 [arXiv:2510.06552]。它認為 assistant 經過後訓練，扮演使用者時太合作、太完整、很少主動結束，所以模擬環境裡的 assistant 分數會被高估 [arXiv:2510.06552]。它把 WildChat 的對話翻轉，以 GPT-4o 摘要出的一句高階意圖加上對話歷史為條件，預測下一個使用者回合或代表離開的結束 token，對 Llama3 base 全參數微調出 UserLM-1b 與 UserLM-8b [arXiv:2510.06552]。帶意圖條件的 UserLM-8b 在人類使用者語句上的 PPL，WildChat 為 4.33、PRISM 為 7.42；對話結束 F1 為 63.54，GPT-4o 只有 1.38；AI 偵測器 Pangram 判為人寫的機率是 80.21，提示型模型只有 0.04–3.31 [arXiv:2510.06552]。在 Lost in Conversation 的 65 個數學與程式任務上，把使用者換成 UserLM-8b 後，GPT-4o assistant 的 Assistant Score 從 74.6 降到 57.4 [arXiv:2510.06552]。撰寫時歸納：在本章收的論文裡，它是第一篇以真實使用者語句的似然直接量模擬器的 [arXiv:2510.06552]。精讀時指出，74.6 到 57.4 的落差混進了資訊沒給夠的效果，四道生成護欄只套在 UserLM-8b，也沒有真人對照組 [arXiv:2510.06552]。

**2026-01，Lost in Simulation：拿真人來校準。** 這篇讓美國（SAE／AAVE、三個年齡層）、印度、肯亞、奈及利亞的受試者在 τ-Bench retail 上與固定的 GPT-4o agent 對話，再與 LLM 模擬使用者的結果比較 [arXiv:2601.17087]。agent 固定、只換使用者 LLM，115 題 3 次平均的成功率就從 Sonnet 3.7 的 67.0% 到 Sonnet 4.5 的 75.9%，差 75.9 − 67.0 = 8.9 個百分點 [arXiv:2601.17087]。它先用 GPT-4o 自我對弈 5 次把任務分成六個難度箱，再定義 ECE_Human-LLM，也就是各箱真人與模擬成功率差距的加權和 [arXiv:2601.17087]。美國整體真人成功率 45.2%、ECE 15.1；SAE 成功率 50.6%、ECE 11.7，AAVE 是 39.4%、ECE 20.3，控制年齡、教育、AI 經驗與難度後方言差距仍顯著（GEE β=0.61，p<0.001）[arXiv:2601.17087]。模擬使用者在 18.8% 的回合發問、39.2% 的回合用禮貌詞，真人是 9.8% 與 19.9%；真人對話的失敗有 62.2% 歸因於使用者，模擬對話只有 40.0% [arXiv:2601.17087]。精讀時發現，難度分箱與模擬端成功率用的是同一組 5 次量測，ECE 也沒有信賴區間，效度只驗了 GPT-4o 一種模擬器 [arXiv:2601.17087]。

### 使用者回饋迴路與滿意度估計：訊號的形狀越來越自然，真實使用者卻停在 BB3，迴路很少閉合

這八篇回答同一組問題：部署中的使用者能給出什麼訊號、什麼時候向使用者要、要來的訊號怎麼變成獎勵或訓練資料，以及怎麼估計使用者此刻滿不滿意 [arXiv:1605.07669][arXiv:1804.06512][arXiv:1901.05415][arXiv:1911.02557][arXiv:2105.03748][arXiv:2208.03270][arXiv:2208.03188][arXiv:2404.15269]。沿時間讀下來有三條軸在移動：

- **訊號的形狀。** 從對話結束時的二元任務成功，到逐輪更正追蹤到的使用者目標，到使用者下一句話的語氣，到跨使用者的改述、打斷與放棄，到逐輪讚／倒讚加上「錯在哪個模組」，再到使用者直接改 agent 的輸出 [arXiv:1605.07669][arXiv:1804.06512][arXiv:1901.05415][arXiv:1911.02557][arXiv:2208.03270][arXiv:2208.03188][arXiv:2404.15269]。
- **什麼時候要。** 依獎勵模型的不確定度決定要不要問，依滿意度分類器判定上一句出錯才問，每一輪都強制收，由使用者自己決定按不按，或完全不問、只讀行為 [arXiv:1605.07669][arXiv:1901.05415][arXiv:2208.03270][arXiv:2208.03188][arXiv:1911.02557][arXiv:2404.15269]。
- **誰扮演使用者。** 付費受試者、agenda 模擬器、群眾外包工作者、第三方標註者、GPT-4 模擬使用者都有；在本章計入的八篇裡，真實、無償的使用者只出現在 Alexa 與 BB3 兩篇 [arXiv:1605.07669][arXiv:1804.06512][arXiv:1901.05415][arXiv:2105.03748][arXiv:2404.15269][arXiv:1911.02557][arXiv:2208.03188]。其中只有 Alexa 那篇把學到的東西接回上線系統並做了 A/B 測試 [arXiv:1911.02557]；精讀時指出，BB3 的部署回饋在論文裡只用於評估，沒有回到訓練 [arXiv:2208.03188]。

訊號的形狀越來越接近使用者自然會做的事，但真實使用者這一端在本章停在 2022 年的 BB3：之後的 CIPHER 用的是 GPT-4 模擬的修改，本章沒有任何一篇用真實 LLM 聊天產品裡的重新生成、讚／倒讚或自然語言抱怨來學習 [arXiv:2404.15269][arXiv:2208.03188]。其他節點讀過的論文裡，真實使用者的訊號出現在評估與模擬器訓練，而不在學習迴圈：Chatbot Arena 把真實使用者的投票做成排行榜 [arXiv:2403.04132]，UserLM 拿 WildChat 的真實對話訓練使用者模型 [arXiv:2510.06552]。以真實部署資料重訓，或以大量真實使用者的互動訊號當獎勵的工作，本章沒有讀，見「已知缺口與未讀」。

學習發生的位置也在變：早期更新小型對話模型或獎勵模型的權重，Alexa 那篇不動模型、改在 NLU 之前查表替換使用者輸入，FITS 與 BB3 回到分批重新微調，CIPHER 則把 LLM 凍結，學到的東西只以自然語言偏好的形式進入提示詞 [arXiv:1605.07669][arXiv:1804.06512][arXiv:1901.05415][arXiv:1911.02557][arXiv:2208.03270][arXiv:2208.03188][arXiv:2404.15269]。

**2016-05，On-line active reward learning：只在獎勵模型沒把握時才問使用者。** 用 RL 最佳化任務型對話策略時，每通對話都要知道任務成功了沒；真實使用者沒有預先指定的目標，每通都問又打擾又不準，先用模擬器資料訓練成功估計器又受限於模擬器只是粗略近似 [arXiv:1605.07669]。它把每通對話經 BLSTM 編碼器壓成 64 維向量，交給帶白雜訊 kernel 的 GP 分類器估計成功機率；機率落在 0.15 與 0.85 之間才問使用者，其他時候直接用預測當獎勵 [arXiv:1605.07669]。三個獎勵模型共 2550 通，只問了 454 通，454 ÷ 2550 ≈ 17.8% [arXiv:1605.07669]。500–850 通時 on-line GP 的主觀成功率 90.9±0.9% 顯著優於直接問使用者（Subj）的 87.1±1.0% [arXiv:1605.07669]。精讀時發現，這個顯著差異主要來自 Subj 從 400–500 通的 90.7% 退化，而且論文一面說使用者評分不可靠、一面拿同一個 Subj 當評估的金標準 [arXiv:1605.07669]。

**2018-04，人類教學與回饋：先用昂貴的逐輪更正補分佈落差，再用便宜的二元回饋做 RL。** 監督預訓練的 agent 上線後，自己的回應會把對話帶進語料少見的狀態，錯誤逐輪累積 [arXiv:1804.06512]。它先請使用者逐輪更正 agent 追蹤到的使用者目標，把這些對話併回語料重訓（DAgger 式），再只在對話結束時給二元獎勵做 REINFORCE [arXiv:1804.06512]。監督模型的 joint DST 從固定語料的 84.57% 掉到互動評估的 50.51%，500 段模仿學習對話後升到 67.47% [arXiv:1804.06512]。精讀時發現，兩個階段的互動對象都是 agenda 使用者模擬器，逐輪更正與成功訊號都由持有真實目標的模擬器給出，這是真實使用者給不出的訊號 [arXiv:1804.06512]。

**2019-01，Self-feeding chatbot：從使用者下一句話判斷滿意度，再決定模仿使用者或開口要回饋。** 它的前提是事後判斷比事前預測容易：另外訓練一個滿意度分類器，讀使用者最新一句話估計 ŝ [arXiv:1901.05415]。ŝ 高於門檻時，把人類的回覆（不是 bot 的話）收成 Human-Bot（HB）對話範例；ŝ 低於門檻時，bot 問剛才應該說什麼，使用者的回答成為輔助任務 Feedback 的目標，兩者與原本的人對人（HH）資料一起多任務重訓 [arXiv:1901.05415]。hits@1/20 在 20k HH 下從 30.3 升到 39.7；滿意度分類器只用 1k 筆就有 F1 0.84，不確定度基線只有 0.56 與 0.55 [arXiv:1901.05415]。把 bot 自己的回應當訓練目標會降分，即使只留 ŝ 高的也一樣 [arXiv:1901.05415]。精讀時指出，這裡的「部署」在群眾外包平台上進行，工作者有報酬；重訓後的模型再上線時使用者有沒有更滿意，全文沒有量 [arXiv:1901.05415]。

**2019-11，Alexa 的 feedback-based self-learning：把跨使用者的改述聚成改寫表直接上線。** 語音助理的 ASR、NLU 與實體解析錯誤，傳統上靠人工轉寫與標註修正，網域一擴張就撐不住；使用者遇到錯誤時常會自己改述 [arXiv:1911.02557]。它把相鄰間隔不超過 45 秒的 utterance 串成 session，投影到 NLU 解讀，session 結尾依打斷或放棄注入失敗、其他情況一律注入成功，形成吸收馬可夫鏈；對每個來源解讀找出比原句更可能成功的目標解讀 [arXiv:1911.02557]。上傳前以 Z-test（p=0.01）剔除比不改寫差的改寫，每天重跑離線挖掘，線上在 ASR 之後、NLU 之前查表替換 [arXiv:1911.02557]。5,679 對人工標註的改寫 accuracy 93.4%，同一批改用 pointer-generator seq2seq 是 55.2%；生產環境 A/B 測試兩週以上，被改寫的 utterance 缺陷率降低 30% 以上（p<0.001）[arXiv:1911.02557]。精讀時指出，吸收狀態的標籤、上傳前的過濾、A/B 的缺陷率全來自同一個未公開的 friction 模型，30% 只能讀成「friction 模型判定的缺陷」降低 [arXiv:1911.02557]。

**2021-05，USS：把滿意度當成使用者模擬器的內部狀態。** 使用者模擬器能大規模自動評估，卻只會機械地給 slot；滿意度建模能反映對話品質，卻要人標 [arXiv:2105.03748]。它讓標註者只看目前為止的前文，推定使用者開口前的滿意度（1–5），任務是同時預測下一輪滿意度與下一個使用者動作；資料集有 6,800 場對話、99,569 則發言，來自五個語料，每筆至少 3 人標註 [arXiv:2105.03748]。Fleiss Kappa 0.574；滿意度預測的最佳 UAR 在 JDDC 是 0.339，英文四個語料是 0.237 到 0.293 [arXiv:2105.03748]。精讀時指出，標題承諾的模擬器沒有建出來，全文只在既有語料上做離線逐輪分類；五類的隨機 UAR 約 0.2，英文四個語料的最佳結果只比隨機高 0.237 − 0.2 = 0.037 到 0.293 − 0.2 = 0.093，JDDC 的 0.339 高出較多 [arXiv:2105.03748]。

**2022-08，FITS：在同一份資料上比較回饋類型與學習演算法。** 人機對話不對稱，沒有人會示範答案該長怎樣，模仿人類發言的做法用不上；部署時可以要哪幾種回饋、各配什麼演算法，此前沒有系統性比較 [arXiv:2208.03270]。152 位 MTurk 標註者寫出 1108 個任務類型，再與 BB1、BB2、SeeKeR 對話，每一輪收二元滿意度、不滿意時的自由文字、錯在查詢／結果使用／回應的歸因，以及對應模組的 gold 修正；模型出錯時，下一輪直接改用人給的 gold [arXiv:2208.03270]。SeeKeR 基線的 Good response% 是 49.3%，Director 加模組與二元回饋是 59.1% [arXiv:2208.03270]。精讀時指出，二元回饋類方法學的標籤就是 Good% 的標籤，比較獨立的 Rating 在 BB2 上三個二元方法的 2.83、3.00、3.07 全都低於基線 3.09 [arXiv:2208.03270]。

**2022-08，BlenderBot 3：公開部署並收真實使用者的逐則回饋。** 付費群眾工作者規模上不去，分佈也由研究者的指示決定；公開部署能解決這兩件事，但會碰上使用者不願給回饋、惡意 troll，以及不能直接模仿人類那一側的問題 [arXiv:2208.03188]。BB3 公開部署在 blenderbot.ai，每則 bot 訊息可按讚或倒讚，倒讚時選五類原因之一，bot 以樣板道歉並追問 [arXiv:2208.03188]。BB3-175B 的 9,197 則 bot 訊息中 Liked 只有 4.0%；在 BB3-3B 的部署資料上，使用者的讚與 crowdworker 一致 70%，倒讚一致 79%；SafetyMix 的 50% troll 設定下，錯誤率從不過濾的 31% 降到結合使用者與例子層過濾的 12% [arXiv:2208.03188]。精讀時依 Table 7 換算，倒讚五類合計 1.15% + 1.10% + 0.16% + 0.12% + 0.46% = 2.99%，超過九成的回合沒有任何訊號 [arXiv:2208.03188]。精讀時也指出，標題寫 continually learns，本文卻沒有任何以真實部署回饋重訓後的快照 [arXiv:2208.03188]。

**2024-04，PRELUDE／CIPHER：把使用者的修改當隱式回饋，學成提示詞裡的自然語言偏好。** 寫作助理的使用者最自然的回饋是直接改 agent 的輸出；偏好是潛在、依脈絡而異的，替每位使用者微調 LLM 成本高，還可能破壞上線前做過的安全評估 [arXiv:2404.15269]。每一輪的成本是 agent 回應與使用者修改版之間的 token 級 Levenshtein 距離，目標是最小化整段互動的累積成本 [arXiv:2404.15269]。CIPHER 在修改量超過門檻時叫 LLM 推論「使用者為何這樣改」並存成偏好，遇到新脈絡時依嵌入相似度取回 k 筆、彙整成一句插進提示詞，LLM 全程凍結 [arXiv:2404.15269]。使用者由兩階段 GPT-4 模擬：先判斷回應是否符合偏好，不符合才改寫 [arXiv:2404.15269]。累積編輯成本在摘要上從 No Learning 的 48,269 降到 32,974，在 email 上從 31,103 降到 8,391；Oracle 是 6,573 與 1,851 [arXiv:2404.15269]。精讀時指出，模擬使用者與偏好推論都是 GPT-4，偏好推論解讀的其實是 GPT-4 自己的改寫風格 [arXiv:2404.15269]。

### 三條線的交會

以下接點由撰寫時並讀各篇整理而得。

- **滿意度從離線標籤變成模擬器的內部狀態。** USS 的標題承諾了模擬器卻沒有建出來 [arXiv:2105.03748]。MetaSim 沿用 USS（兩篇第一作者相同，撰寫時依作者重疊判斷為前作，MetaSim 本身只以一般引用提到它），把 5 級滿意度改成 3 級，讓 Policy 模組與使用者動作一起預測，再與 Success 平均成系統分數，才把「會表達滿意度的模擬使用者」做成可以跑的東西 [arXiv:2204.00763][arXiv:2105.03748]。代價是 USS 的標籤本來就是第三方讀前文推定的滿意度，MetaSim 又拿後驗網路補偽標籤；撰寫時並讀兩份筆記的判斷是，模擬器「感受到的滿意」因此離對話當事人又遠了一層 [arXiv:2204.00763][arXiv:2105.03748]。
- **回饋迴路的「使用者」常常就是第一條線的模擬器。** 人類教學那篇的逐輪更正與成功訊號，實際上來自 agenda 模擬器 [arXiv:1804.06512]。CIPHER 的修改來自 GPT-4 模擬使用者 [arXiv:2404.15269]。在本章計入的論文裡，LLM 模擬使用者被放進對話 agent 學習迴圈的只有 CIPHER，而它學的是提示詞，不是權重；RecAgent 的迴圈訓練的是推薦器 [arXiv:2404.15269][arXiv:2306.02552]。放寬到其他節點讀過的論文，STaR-GATE、CollabLLM、2410.13788 等以 LLM 模擬使用者產生訓練資料或獎勵，更新的是對話模型的權重，見 LLM 使用者模擬器一節 [arXiv:2403.19154][arXiv:2502.00640][arXiv:2410.13788]。
- **LLM 模擬器一開始就拿經典模擬器當對照，而且在任務成功率上輸了。** ICL 模擬器在同一套 ConvLab-2 harness 裡以 ABUS 為對照，成功率遠低於 ABUS [arXiv:2306.00774]。📖 那篇以 TUS 為對照，GSR 也比 TUS 離真人更遠 [arXiv:2309.13233]。兩篇都讀出「LLM 模擬器較多樣」[arXiv:2306.00774][arXiv:2309.13233]。ICL 模擬器那篇沒有真人基準 [arXiv:2306.00774]。📖 那篇有自收的 Human2Bot 真人基準，照表面值它的 LLM 模擬器離真人更遠：PPTOD 上 GSR 與真人差 56.9 − 25.0 = 31.9，TUS 只差 63.7 − 56.9 = 6.8 [arXiv:2309.13233]。但精讀時指出，那批真人對話只來自 8 位贊助方的資料收集人員，他們被要求刻意加入同一 slot 給兩個值、中途改值這類複雜化行為，與模擬器用的一般測試目標不是同條件 [arXiv:2309.13233]。所以「低成功率是缺點還是更貼近真人」在這兩篇裡仍無法判定；兩篇證據中有一篇是 📖，只能當脈絡。
- **「過度配合」的觀察從社交模擬一路延伸到 agent 評估。** SOTOPIA 看到 GPT-4 較早妥協 [arXiv:2310.11667]；UserLM 主張提示型 assistant 扮使用者時太合作 [arXiv:2510.06552]；Lost in Simulation 量到模擬使用者用禮貌詞的回合比例是真人的 39.2 ÷ 19.9 ≈ 1.97 倍，失敗也較少算在使用者頭上 [arXiv:2601.17087]；TE 則在對齊過的模型上看到超準確 [arXiv:2208.10264]。這幾篇量的都是模擬使用者或角色太配合；依標題研究語言模型諂媚的論文，本章沒有讀，見「已知缺口與未讀」第 8 條。所以這一條只是本章語料內的歸納，也無法判斷模擬使用者的過度配合與助理端的諂媚是否出自同一個原因。

UserLM 沒有真人對照組；它與真人資料的比對，是人類語句上的 PPL，以及 AI 偵測器 Pangram 判為人寫的機率，真人語句（PRISM）是 90.15，提示型 assistant 扮演的使用者只有 0.04–3.31 [arXiv:2510.06552]。

撰寫時從這張表讀出三件事。第一，在本章計入的論文裡，做過「多個系統、模擬與真人各排一次」的是 NUS、GenTUS、MetaSim、iEvaLM 四篇 [arXiv:1805.06966][arXiv:2208.10817][arXiv:2204.00763][arXiv:2305.13112]；不計入的 📖 那篇也做過，只當反例 [arXiv:2309.13233]。修訂前本章寫「規模最大的也只有 4 個系統」，程式驗證推翻了這一句：MetaSim 的 Table 5 有 7 個變體，模擬端與真人端都有 Success [arXiv:2204.00763]。但這 7 個是設計者從同一個基礎系統造出的降級變體，不是彼此獨立的系統；7 個放在一起時，21 對之中順序相反的有 11 對、一致的有 10 對，名次幾乎無關，只有事後拿掉 β=0.1 與 γ=0.01 兩格，剩下 5 個變體的順序才大致一致 [arXiv:2204.00763]。第二，其餘比較只有 2 到 4 個系統；n 個系統完全排對的機率是 1 ÷ n!，所以 2、3、4 個系統即使完全一致，偶然發生的機率也分別有二分之一、六分之一與 1 ÷ (4 × 3 × 2 × 1) ≈ 4.2%，只有 iEvaLM 的 4 個系統碰得到 5% 以下 [arXiv:2305.13112]。第三，唯一在同一批任務上用多個真人族群校準 LLM 模擬器的 Lost in Simulation，只固定一個 agent，談不上名次 [arXiv:2601.17087]。

其他節點讀過的論文裡還有四組相關證據，撰寫時納入判斷但不放進上表，因為比的不是「多輪互動的模擬使用者評同一批對話系統」。AlpacaFarm 以模擬的成對偏好標註者訓練並評估從回饋學習的方法，論文報模擬與真人的方法排名 Spearman 0.98，拿掉兩邊只差在評估者的 4 個未訓練系統後是 0.94；程式驗證以 Table 2 兩欄都有值的 10 個系統重算，只有 2 對順序相反，與作者自己點名的兩處名次對調一致 [arXiv:2305.14387]。但它模擬的是單輪指令的標註者，不是互動中的使用者 [arXiv:2305.14387]。依 Table 2 的說明，自己訓練的方法左欄在模擬中訓練與評估、右欄用真人回饋訓練與評估；精讀時指出，0.94 所依據的 6 個自訓方法裡，SFT 10k 與 SFT 52k 沒有用任何回饋，兩欄其實只差在評估者，真正是「模擬回饋訓練對上真人回饋重訓」的只有 PPO、best-of-n、expert iteration、Binary FeedME 這 4 個 [arXiv:2305.14387]。程式驗證另以這 4 個方法重算，模擬與真人的名次完全一致，但 4 個系統完全排對的機率本來就有 1 ÷ (4 × 3 × 2 × 1) ≈ 4.2%；作者點名的兩處對調，一處在 SFT 10k 與 SFT 52k 之間，另一處牽涉未訓練的 ChatGPT [arXiv:2305.14387]。精讀時也指出 0.98 主要由能力跨度極大的未訓練系統撐起 [arXiv:2305.14387]。GATE 在附錄 D 以 GPT-4 扮演 persona 的模擬使用者重跑各種偏好引出方法，把模擬與真人的互動紀錄改算成同一套輪數制指標；作者說兩者在內容推薦與 email 領域大致相關，在道德推理領域不相關 [arXiv:2310.11589]。精讀時指出，相關只畫在 Figure 12，正文沒有係數，也沒交代 persona 數量，比的對象是引出方法而不是對話系統 [arXiv:2310.11589]。CollabLLM 用 GPT-4o-mini 模擬使用者訓練，再請 201 位 MTurk 使用者在寫作任務上比較原始模型、提示詞版與 CollabLLM；真人端量的是文件品質評分與花費時間，模擬端量的是 BLEU、token 數與互動性，兩端指標不同，論文沒有算名次相關 [arXiv:2502.00640]。2402.09205 用 GPT-4 扮演的使用者合成訓練對話，評估時換成 8 位真人，但沒有在同一批模型上同時跑模擬使用者 [arXiv:2402.09205]。

### 成功率與分數：同一個名字，各自的定義

跨篇比較任何「成功率」之前，要先看是誰、用什麼標準判的：

- **TC-Bot 的成功率混進了知識庫覆蓋率。** 限制在資料庫中無法滿足時，即使 agent 正確告知無票也算失敗，README 給的上限是 0.9765 [arXiv:1612.05688]。
- **NUS 的模擬成功率與真人 reward 不能比。** 模擬端以目標改變後的最終目標判定，真人試驗的目標全部可達成，論文自己註明兩邊不能直接比 [arXiv:1805.06966]。
- **JOUST 的 Comb 把比例和 BLEU 加在一起。** Comb = 0.5 ×（Info + Succ）+ BLEU，self-play 沒有參考句、算不出 BLEU，所以 self-play 表只報 Info／Succ [arXiv:2107.11904]。撰寫時用 Table 2 驗算公式：0.5 × (83.2 + 73.5) + 17.6 = 95.95，與表中的 96.0 相符 [arXiv:2107.11904]。
- **MetaSim 的系統分數是兩種尺度的平均。** calibrated satisfaction 是 0／1 的 Success 與逐輪滿意度的平均，論文沒說明怎麼正規化；同分時再以輪數少者為佳 [arXiv:2204.00763]。
- **LLM 模擬器的成功率包含整組 harness。** ICL 模擬器的 Succ 同時受 LLM、兩顆 BERT NLU、系統端 NLU 與終止規則影響；同一個 agenda policy 只把表層 NLG 換成 SC-LSTM，Succ 就從 0.83 掉到 0.60 [arXiv:2306.00774]。
- **τ 系列的判分只看終態或子字串。** τ-Bench 的成功要同時滿足資料庫終態正確，以及 agent 回覆以子字串比對含有應提供的資訊；模擬對話的 output error 是 31.4%，真人是 12.2–23.6%，精讀時推測可能與模擬器提早結束有關，論文沒有檢查 [arXiv:2601.17087]。τ²-bench 的 telecom 只用終態 assertion 判成敗，精讀時發現沒確認價格就加購之類的政策違規，只要終態正確就算成功 [arXiv:2506.07982]。
- **互動 Recall 與靜態 Recall 不能直接比。** iEvaLM 在最多 5 輪中每次推薦一張 10 項清單，推中即止；精讀時指出，拿它的 R@10 比既有 CRS 的 R@50，等於拿最多 5 × 10 = 50 個推薦位置加上 oracle 提示去比單次的 50 項清單 [arXiv:2305.13112]。
- **FITS 的完成率含人工代打。** 模型出錯時下一輪改用人給的 gold，精讀時指出 90.4% 的任務完成率衡量的是人機協作，弱模型被修得越多，墊得越高 [arXiv:2208.03270]。

### 怎麼評模擬器本身：五種量法，各有漏洞

**詞彙多樣性不是逼真度。** GenTUS 的摘要說它增加了語言變化，但 self-BLEU 0.95 是全表最差，真人 0.77（精讀時發現摘要與表格衝突）[arXiv:2208.10817]。MetaSim 在 MultiWOZ 的 Distinct 是 17.29，輸給檢索式基準的 20.20 [arXiv:2204.00763]。ICL 模擬器那篇的 FLAN-T5 在 temperature 0.9 時 unique unigram 994、高於訓練集的 919，Succ 卻只有 0.13；精讀時也發現角色錯置、幻覺這類離題文字一樣會把分數推高 [arXiv:2306.00774]。

**「人分不出來」是很弱的證據。** OOOM 的評估者判人類與 GPT-3 四詞清單為人寫的比例是 61.7% 對 61.2%；精讀時指出它沒有正對照，而且 GPT-3 清單平均 7.78 個詞、人類 4.54 個，長度差這麼多仍被判為一樣像人，比較可能反映判斷任務的資訊量太低 [arXiv:2209.06899]。iEvaLM 的自然度成對比較中，模擬器對資料集原始人類發話是 39% 對 10%；撰寫時看到兩種全文無法分辨的解釋：判準可能獎勵流暢，或兩者的上下文本來就不同 [arXiv:2305.13112]。UserLM 改用 AI 偵測器，結果剛好相反，提示型 assistant 扮的使用者幾乎全被認出來 [arXiv:2510.06552]。RecAgent 的生成實驗 win rate 45.0% 對 33.3%，正文稱顯著；撰寫時推算，若每組是 20 位使用者各由 3 位標註者判斷，27 ÷ (20 × 3) = 45.0%、20 ÷ (20 × 3) ≈ 33.3% 正好對得上；雙比例 z 檢定的合併比例是 (27 + 20) ÷ (2 × 20 × 3) ≈ 0.392，差值的變異數是 0.392 × (1 − 0.392) × 2 ÷ (20 × 3) ≈ 0.00794，開根號後當分母，z = (45.0% − 33.3%) ÷ 0.0891 ≈ 1.31、p 約 0.19，並不顯著，而且同一位使用者的 3 次判斷並不獨立 [arXiv:2306.02552]。程式驗證掃描所有能同時四捨五入成 45.0% 與 33.3% 的每組判斷數：最小的相容值就是 20 × 3 = 60；若同一位使用者的 3 次判斷完全相關，差距更不顯著；要低於 0.05，每組需要的獨立判斷數是這個設計能給的兩倍以上 [arXiv:2306.02552]。全文沒寫生成實驗每組有幾個判斷、用了什麼檢定，所以論文「顯著」的說法無法由全文重現 [arXiv:2306.02552]。

**關聯指標蓋得住邊際失真，限縮輸出會美化逼真度。** OOOM Study 3 的 Cramer's V 差值平均只有 −0.026，但同一批資料上 GPT-3 的 Male 是 0.759 對 ANES 0.481、Hispanic 0.001 對 0.089（精讀時依 Table 16 指出，撰寫時核對過全文）[arXiv:2209.06899]。精讀時指出，Cramer's V 經過邊際校正，對這種邊際偏移較不敏感 [arXiv:2209.06899]。程式驗證以 Table 16 的 White 與 Trump 邊際構造 2×2 表，確認 ANES 與 GPT-3 兩組邊際可以給出幾乎相同的 V；但同一個例子也顯示，GPT-3 那種極端的邊際會把 V 可達的上限壓得很低，V 並不是不受邊際影響 [arXiv:2209.06899]。所以較精確的說法是「V 的差值接近零，不代表邊際分佈一致」[arXiv:2209.06899]。OOOM Study 2 只在兩黨候選人之間正規化，2016 年投共和黨的機率 0.432 對 ANES 0.477；精讀時對照 Study 3 的自由取樣，GPT-3 有 0.523 選第三人（ANES 0.078）[arXiv:2209.06899]。二元一致率在基準率一面倒時也是假高：精讀時指出 2012 年黑人子群 κ 0.31、proportion agreement 0.97，撰寫時用 κ 的定義反推機會一致率為 (0.97 − 0.31) ÷ (1 − 0.31) ≈ 0.9565，表示這個子群的高一致率幾乎不帶鑑別資訊 [arXiv:2209.06899]。

**LLM 評審會壓縮差距。** 精讀時算出，SOTOPIA 的 Goal 維度上 GPT-4 對 GPT-3.5 的差距，GPT-4 評審下是 7.62 − 6.45 = 1.17，人類評審下是 7.30 − 5.19 = 2.11 [arXiv:2310.11667]。精讀時也註明，兩組數字的夥伴池不同（Table 2 含 MPT，Table G.3 不含），差距只能粗略比較 [arXiv:2310.11667]。Sec 維度四個模型的平均都擠在 -0.07 到 -0.14 之間（範圍 -10 到 0），在評審提示詞加上細粒度 rubric 反而讓 Soc 相關從 0.33 變成 -0.59 [arXiv:2310.11667]。

**標準答案本身就可疑。** MetaSim 的 ED 以設計者規定的變體順序為準，三個變體完全排對的隨機機率是 1/6 ≈ 16.7%，論文沒有報這個基準，人類也只有四成 [arXiv:2204.00763]。精讀時判斷，τ²-bench 的模擬器錯誤率主要量遵守指令（四項準則中有三項屬於這一類）；精讀時也依 Wilson 95% 區間重算，telecom 3/50 的 critical error 約 2–16%、retail 6/50 約 6–24%，兩者重疊 [arXiv:2506.07982]。Lost in Simulation 的 ECE 有三個結構性陷阱，都是精讀時發現的：分箱與模擬端共用同一組量測而會回歸均值；模擬端的平均 (0 + 20 + 40 + 60 + 80 + 100) ÷ 6 = 50 是設計值；ECE 沒有信賴區間 [arXiv:2601.17087]。撰寫時依 ECE 定義補一條三角不等式：若各箱權重相等，ECE 至少是真人成功率與 50 的差，AAVE 為 50 − 39.4 = 10.6 [arXiv:2601.17087]。修訂前本章據此寫「真人成功率越低，ECE 越會被機械地推高」，程式驗證把這個說法收窄：機制是偏離 50 的距離，不是成功率高低 [arXiv:2601.17087]。一是這條下界對 50 對稱，成功率高於 50 的族群下界同樣會升，正確的說法是「成功率偏離 50 越遠，下界越高」；程式從 Table 2 與 Table 3 解析出的族群成功率介於 33.4 到 52.2，高於 50 的只有 SAE 的三列，而且都只略高，所以在論文觀察到的範圍內，原句的方向大致仍然成立 [arXiv:2601.17087]。二是 ECE 的水準遠高於下界：各群 ECE 比下界高出的量，從 AAVE 55 歲以上的 20.5 − (50 − 33.4) = 3.9 到印度 18–34 歲的 18.9 − (50 − 46.2) = 15.1，機械下界撐不起 ECE 的全部水準 [arXiv:2601.17087]。但方言之間的差距是另一回事：AAVE 與 SAE 的 ECE 差 20.3 − 11.7 = 8.6，比兩者下界的差 (50 − 39.4) − (50.6 − 50) = 10.0 還小，所以在權重相等的前提下，這段差距整段都落在機械下界可能造成的範圍內；程式驗證也在 9 個不重疊的子群上兩兩比對，下界與 ECE 的大小順序多數一致（Kendall τ 與各類對數見驗證檔），支持確實有機械成分 [arXiv:2601.17087]。三是權重相等這個前提只核對得到兩箱：論文給的 0% 與 60% 兩箱 ECE 正好是 (30.8 − 0 + 60 − 39.0) ÷ 2 = 25.9，其餘四箱的權重全文沒有數字，上面兩點都以這個前提為條件 [arXiv:2601.17087]。方言之間的 ECE 差距實際有多少是這種機械效果，沒有逐箱資料無法判定 [arXiv:2601.17087]。UserLM 的意圖分解只獎勵「和意圖重疊少」，精讀時指出完全離題的模擬器也會拿高分；意圖又是 GPT-4o 看過整段對話才摘要出來的，拿它當條件評 PPL 時，後續回合的資訊會洩漏給所有模型 [arXiv:2510.06552]。

### 統計：樣本小、沒有檢定，撰寫時重算的幾處

本節點多數論文沒有做顯著性檢定。以下是精讀或撰寫時重算的結果，其中幾處修正了精讀筆記原本的說法。

- **NUS 的真人差距。** 精讀時估算各組的 z 約 0.7 到 1.4 [arXiv:1805.06966]。撰寫時用兩比例 z 檢定重算 A1 對 A2：差值的變異數是 0.900 × (1 − 0.900) / 250 + 0.885 × (1 − 0.885) / 250 ≈ 0.000767，開根號後當分母，z = 1.5 / 2.77 ≈ 0.54，比筆記的「約 0.7」更低 [arXiv:1805.06966]。即使取最有利的一對 N2 對 A2，差值的變異數是 0.934 × (1 − 0.934) / 250 + 0.885 × (1 − 0.885) / 250 ≈ 0.000654，開根號後當分母，z = (93.4 − 88.5) / 2.56 ≈ 1.91，照表面值仍未達雙尾 0.05 的門檻，但已落在邊界 [arXiv:1805.06966]。程式驗證另外發現，93.4% × 250 = 233.5、91.8% × 250 = 229.5、88.5% × 250 = 221.25 都不是整數，表列成功率不可能由剛好 250 場得到，每個策略實際跑了幾場論文沒交代 [arXiv:1805.06966]。改用與表列百分比相容的其他場數或取整時，N2 對 A2 有些組合的 p 會落到 0.05 以下，其他五對則在所有組合下都不顯著；所以較精確的說法是「五對不顯著，N2 對 A2 在邊界、結論取決於實際場數」[arXiv:1805.06966]。
- **MetaSim 在 ReDial 與 JDDC 的 ED。** 精讀時說只比隨機高 1 到 4 個百分點，鑑別力「幾乎不存在」[arXiv:2204.00763]。撰寫時假設 1K 組偏好彼此獨立、沒有平手，隨機排序下 ED 的變異數是 1/6 × 5/6 / 1000 ≈ 0.000139，標準誤約 1.18 個百分點 [arXiv:2204.00763]。照這個假設，ReDial 的 Recommender 與 Domain tester 高出 20.61 − 16.7 = 3.91 與 20.43 − 16.7 = 3.73 個百分點，都超過 3 個標準誤；JDDC Context tester 高出 19.17 − 16.7 = 2.47，約 2.1 個標準誤；另兩格只高出 17.48 − 16.7 = 0.78 與 17.47 − 16.7 = 0.77 [arXiv:2204.00763]。所以較精確的說法是：五格中三格統計上高於隨機（未做多重比較校正），但幅度都在 4 個百分點以內，仍撐不起引言「跨領域泛化良好」的說法 [arXiv:2204.00763]。程式驗證證實這組算式，並補上兩點：以 Holm 或 Bonferroni 校正五格的多重比較後，只剩 ReDial 的 Recommender 與 Domain 兩格顯著；三個模擬器在表上的數值乘以 10 都不是整數，例如 17.48 × 10 = 174.8，不可能是單一次 1000 組 0／1 的平均，所以 n = 1000 這個前提本身無法確認，上面的檢定都只是條件式的 [arXiv:2204.00763]。
- **iEvaLM 的排名一致。** 精讀時說 4 個系統排名一致「偶然發生的機率並不低」[arXiv:2305.13112]。撰寫時修正：4 個系統共有 4 × 3 × 2 × 1 = 24 種排法，完全隨機時排成同一順序的機率是 1 ÷ (4 × 3 × 2 × 1) ≈ 4.2% [arXiv:2305.13112]。真正的弱點在於只有 KBRD 與 BARCOR 這一對的順序帶資訊，差距在模擬側是 0.21 − 0.18 = 0.03、人扮側是 0.25 − 0.21 = 0.04，而 n = 100 時 Recall 0.18 附近的標準誤是 0.18 × (1 − 0.18) ÷ 100 開根號，約 0.038，差距不到一個標準誤 [arXiv:2305.13112]。
- **TE 的 Milgram。** 75/100 對 26/40 沒有檢定，精讀時以雙比例 z 檢定粗算 z≈1.19、p≈0.23，撰寫時重算得到相同結果，程式驗證另以 Fisher 精確檢定再算一次，同樣不顯著 [arXiv:2208.10264]。程式也算了檢定力：以人類 26 ÷ 40 = 0.65 為基準、樣本數 100 對 40，模擬端要偏離兩成以上才有八成把握偵測得到，實際差距是 75 ÷ 100 − 0.65 = 0.1，所以「不顯著」也不能讀成「模擬與人類一致」[arXiv:2208.10264]。模擬的 25 位中斷者有 18 位擠在第 20 級，人類 14 位中斷者分散在 6 個等級、最多的一級 5 位；撰寫時換算最多那一級的占比，人類 5 ÷ 14 ≈ 36%、模擬 18 ÷ 25 = 72% [arXiv:2208.10264]。這段分佈只畫在圖上，快取全文的文字裡沒有，程式沒有驗 [arXiv:2208.10264]。
- **On-line GP 的 ± 值。** 精讀時懷疑標準誤把對話當獨立樣本 [arXiv:1605.07669]。撰寫時試算：把 3 條策略在區間內的對話合起來，兩個區間的樣本數是 (500 − 400) × 3 = 300 與 (850 − 500) × 3 = 1050，以二項比例標準誤代入 Table 1 的六個成功率，六格的 ± 值全部吻合到小數第一位 [arXiv:1605.07669]。程式驗證證實六格全部吻合，而且 400–500 區間能讓四格同時吻合的樣本數範圍很窄，300 不是巧合 [arXiv:1605.07669]。這撐住了精讀時懷疑的一半：± 值沒有計入策略之間的變異；t-test 是否也以對話為單位，表上沒有足夠資訊判定 [arXiv:1605.07669]。
- **其他小樣本。** GenTUS 的 155 位使用者每人做 1 到 48 段，每種模擬器只挑一個在自己身上表現最好的 seed（精讀時發現）[arXiv:2208.10817]。JOUST 全文沒有報變異數或多 seed 結果（精讀時發現）[arXiv:2107.11904]。精讀時估算，Lost in Simulation 每組約 40 人 × 4 題，攤到 6 箱每箱約 27 次完成 [arXiv:2601.17087]。

### 基準率、平凡解與自選子集

- **Self-feeding 的不確定度基線可能等於平凡解。** 精讀時從 Uncertainty Top 在 recall 0.99 時 precision 0.39 推論「不滿意」約佔 38% 到 39% [arXiv:1901.05415]。撰寫時驗算，這其實只是上限：盛行率 π 不超過 precision ÷ recall，Uncertainty Gap 的 0.38 ÷ 1.00 給出 π 最多約 0.38 [arXiv:1901.05415]。把全部判為錯誤的平凡解 F1 是 2π／(1＋π)，π 取上限時是 2 × 0.38 ÷ (1 + 0.38) ≈ 0.55，正好等於 Gap 的表列值，Top 的 0.56 也只高 0.56 − 0.55 = 0.01 [arXiv:1901.05415]。論文沒報 π 的實際值，所以「分類器勝過不確定度 0.28 F1」有多少是勝過平凡解，無法從表中確定 [arXiv:1901.05415]。程式驗證以測試集 1000 筆逐列做整數列舉，確認表格只定得出上限，π 的實際值可以遠低於 0.38，精讀時「約佔 38% 到 39%」的推論不成立；π 越小，平凡解的 F1 越低，Top 勝過平凡解的幅度就越大 [arXiv:1901.05415]。
- **USS 的多數類。** 評分 3 佔 77.5% 到 88.8%；精讀時注意到 XGBoost 的 UAR 只有 0.200 到 0.207，幾乎等於只猜多數類，Rho 卻在 MultiWOZ 達 0.690、CCPE 達 0.707 [arXiv:2105.03748]。MetaSim 用來補偽標籤的後驗網路在 USS 測試集上準確率 97.79%，精讀時發現「普通」回合在三個資料集各佔約 89%、81%、83% [arXiv:2204.00763]。
- **只在有把握的子集上算準確度。** On-line GP 獎勵模型的 P/R/F 只在沒查詢的 2096 通上算，最難判的 454 通被排除；整體 F 值 0.95，失敗類 recall 卻只有 0.52 [arXiv:1605.07669]。Alexa 的 93.4% 是在自己選來改寫的 utterance 上算的，精讀時指出覆蓋率沒報，而 seq2seq 被迫對每一句都輸出改寫 [arXiv:1911.02557]。
- **聚合規則會改變一致率。** BB3 的一致率是 3 位 crowdworker 中只要一位標 dislike 就算 dislike，精讀時指出這會墊高倒讚一致率 [arXiv:2208.03188]。撰寫時推導：若每位各自以機率 p 標 dislike，OR 聚合比多數決多出 3p(1−p)² 的機率判為 dislike，對所有 p 都不小於零 [arXiv:2208.03188]。

### 表格與正文對不上的地方

這些都是精讀時發現、撰寫時再到全文核對過的，引用對應數字時要小心。

- **UserLM 的 Table 3 與 Table 5。** %Repeat Required 對每段對話是二元值，數學與程式合併後的比例必須落在兩個分任務值之間；但 GPT-4o 模擬的數學 44.0、程式 12.2，總體卻是 9.4 [arXiv:2510.06552]。精讀時推測數學列的兩格放反了；撰寫時以區間算術驗證，對調後唯一能同時算回三個總體值的是 20 題數學、其餘 65 − 20 = 45 題程式，GPT-4o 為 (20 × 3.0 + (65 − 20) × 12.2) ÷ 65 ≈ 9.37 [arXiv:2510.06552]。程式驗證列舉不對調與九種單一對調，證實只有數學列 GPT-4o 與 UserLM-8b 兩格互換能同時算回三個總體值，而且只容許 20 題數學；兩處以上同時放錯的情形沒有列舉 [arXiv:2510.06552]。同一套區間算術也發現另外兩格在 20 題數學下對不上：UserLM-8b 的 Intent Coverage 總體 76.7，高於數學 76.5 與程式 76.6 兩者；GPT-4o 的 %Add Demands 總體 1.1，數學 0.5、程式 1.1，照 20 題數學應是 (20 × 0.5 + (65 − 20) × 1.1) ÷ 65 ≈ 0.92 [arXiv:2510.06552]。所以兩張表之間的不一致不只一處，引用 Table 5 的分任務數字時要保留 [arXiv:2510.06552]。
- **2403.16416 的排除規則。** 若只移除受洩漏影響的成功對話，recall 不可能上升，但 Table 1 有格子是正的，例如 ChatGPT ReDial -history Recall@50 +2.1% [arXiv:2403.16416]。撰寫時逐格清點，recall 上升的格子 Table 1 有 6 格、Table 2 有 4 格；-both 理應排除 -history 的超集合，卻有兩張表各 4 格的 -both 高於 -history [arXiv:2403.16416]。程式驗證逐格重算證實這組清點，並發現 Table 1 有一格論文自己的百分比與表上兩個值對不上：OpenDialKG -history 的 KBRD R@1 從 0.269 到 0.120，表上印 −53.3%，但相對跌幅是 (1 − 0.120 ÷ 0.269) × 100 ≈ 55.4 [arXiv:2403.16416]。精讀時另外指出，論文沒寫怎麼判定一段對話受到洩漏影響；程式列出全文所有含 leak 的句子逐句人讀，三種排除各有一句定義，但沒有一句描述判定程序，例如比對標題字串、人工標註或交給 LLM 判斷 [arXiv:2403.16416]。
- **τ²-bench 的 Table 2。** 撰寫時核對全文，說明文字寫 telecom 沒有 critical error，表內與正文卻都寫 3（6%）[arXiv:2506.07982]。
- **iEvaLM 的引言。** 精讀時發現引言寫 ReDial 的 Recall@10 升到 0.570，但這個數字不在任何表中，Table 5 的對應值是 0.536 與 0.440 [arXiv:2305.13112]。
- **MetaSim 的 Table 5。** Recommender tester 最弱的 β=0.1 變體與 MetaSim 互動的 Success 是 87.40，高於基礎系統的 80.25；Domain tester 最弱的 γ=0.01 在人工 Success 拿到 82.13，遠高於基礎系統的 39.50 [arXiv:2204.00763]。若不是筆誤，ED「變體必然單調變弱」的前提就不成立 [arXiv:2204.00763]。
- **ICL 模擬器的 §6.3。** 正文說 prompt-based 模擬器在目標完成前就終止的對話不到 45%，但 Table 2 中 prompt-based 模擬器的 Compl Rate 最高只有 0.44（ABUS-T 是 0.93），代表這類模擬器至少 1 − 0.44 = 0.56 的對話沒把 book 槽位填完 [arXiv:2306.00774]。
- **CIPHER 的真人勝率。** 精讀時指出，15 對、每對多數決只能得出 1/15 的倍數，還原不出 23.7% [arXiv:2404.15269]。
- **SOTOPIA 的標註數。** 正文說抽 200 個 episode 給人類標，附錄說 222 個 [arXiv:2310.11667]。
- **TC-Bot 的論文與程式碼。** 精讀時依公開程式碼發現，README 標為加了 NLU 雜訊的那組指令，傳的雜訊機率其實是 0.00；論文說 agenda 類似堆疊，程式碼卻用 random.choice 隨機挑下一個 slot [arXiv:1612.05688]。

## 爭議、矛盾與反證

### 模擬器排出的名次能不能代表真人：證據互相打架

- **NUS 說能，但證據很弱。** NUS 主張交叉模型評估的優勢延續到真人：N2、N1 的成功率 93.4%、91.8%，高於 A1、A2 的 90.0%、88.5% [arXiv:1805.06966]。拆到每個模擬器上看，送去真人的四個策略在模擬端各只有一個值：以 NUS 測時 N1 的 98.0 高於 A1 的 71.5，與真人同向；以 ABUS 測時 N2 的 99.8 反而略低於 A2 的 99.9，與真人的 93.4 對 88.5 相反，但模擬端這點差距本身沒有意義（N2 對應哪一格，依論文 Table 4 的說明推定）[arXiv:1805.06966]。上一節的重算顯示，照表面值這些差距沒有一對達到顯著；最大的一對 N2 對 A2 落在邊界，換成與表列百分比相容的其他場數就可能跨過 0.05，但即使這一對成立，同一模擬器內的兩對（N2 對 N1、A1 對 A2）在所有組合下都不顯著 [arXiv:1805.06966]。
- **GenTUS 的資料說不能，而論文沒有討論。** 真人 success 的順序是 GenTUS 訓出的 0.86 最高、ABUS-S 的 0.79 次之、ABUS-T 的 0.75 最低 [arXiv:2208.10817]。模擬端以 ABUS-T 或 ABUS-S 測試時，順序都是 ABUS-T 訓出的最高、GenTUS 訓出的最低 [arXiv:2208.10817]。撰寫時取列平均，ABUS-T 訓出的是 (0.78 + 0.63 + 0.50) / 3 ≈ 0.64，GenTUS 訓出的是 (0.68 + 0.43 + 0.53) / 3 ≈ 0.55，也是相反 [arXiv:2208.10817]。只有以 GenTUS 自己測試的那一欄，GenTUS 訓出的 0.53 排第一 [arXiv:2208.10817]。程式驗證指出，這一欄雖然不相反，也不一致，兩個 ABUS 的順序與真人對調；0.53 對 0.50 即使忽略 seed 間變異也只在顯著的邊界 [arXiv:2208.10817]。另一方面，作者自己說 ABUS-S 與 ABUS-T 的真人差距不顯著，所以「相反」裡能當證據的只有 GenTUS 對兩個 ABUS 這兩組，程式驗證以兩比例 z 檢定重算，這兩組在真人端與模擬端都顯著 [arXiv:2208.10817]。精讀時發現論文反而把交叉模型結果讀成「ABUS 最容易對付」的佐證 [arXiv:2208.10817]。要注意兩張表比的東西不同：模擬端是 5 個 seed 的平均，真人端是每種模擬器挑一個在自己訓練模擬器上最好的策略 [arXiv:2208.10817]。
- **iEvaLM 說能，但比的是「人扮的 oracle 使用者」。** 4 個系統在模擬器與人扮使用者下排名一致，作者據此主張模擬器可以代替人類評估者 [arXiv:2305.13112]。精讀時指出，那些「人」也拿到同一份含目標 item 的角色指令，驗證的不是對真實使用者的效度；上一節的重算又顯示唯一帶資訊的 KBRD 與 BARCOR 差距不到一個標準誤 [arXiv:2305.13112]。
- **MetaSim 的標準答案與自家資料矛盾。** ED 把設計者規定的變體順序當成人類預期，而自家 Table 5 就有兩格不單調；人類 ED 只做了 MultiWOZ，其他兩個資料集沒有上限可對照 [arXiv:2204.00763]。程式驗證把 Table 5 的 7 個變體當成 7 個系統，與 MetaSim 互動的 Success 和真人 Success 的名次幾乎無關；拿掉那兩格後剩 5 個變體，順序才大致一致，但這是看過資料之後的排除 [arXiv:2204.00763]。同一張表不經模擬器的測試集 Success，與真人的名次反而比模擬端接近（程式驗證）[arXiv:2204.00763]。Table 10 的 3 個第三方系統，模擬端的 Success 與真人滿意度順序一致，只是 3 個系統完全排對的機率本來就有六分之一 [arXiv:2204.00763]。
- **📖 那篇是反例，但只能當反例。** 它主張模擬器應貼近真人，自己的模擬器卻給 PPTOD 25.0 高於 Soloist 23.4，真人是 Soloist 71.9 高於 PPTOD 56.9 [arXiv:2309.13233]。這只是兩個系統的單一反例 [arXiv:2309.13233]。

撰寫時的綜合判斷：在本章計入的論文裡，「交叉模型或模擬器評估表現好 → 真人評估表現好」不是穩定、經過檢定的關係；規模最大的 MetaSim 7 個變體名次幾乎無關，其餘比較只有 2 到 4 個系統 [arXiv:1805.06966][arXiv:2208.10817][arXiv:2204.00763][arXiv:2305.13112]。唯一大規模拿真人校準 LLM 模擬器的 Lost in Simulation 又只用一個 agent [arXiv:2601.17087]。放寬到其他節點讀過的論文，最強的正面證據是 AlpacaFarm 的方法排名，但它模擬的是單輪偏好標註者，而且精讀時指出，真正是模擬回饋訓練對上真人回饋重訓的只有 4 個方法，其餘 6 個點兩欄都只差在評估者，其中 4 個是未訓練的參照模型；GATE 的附錄 D 在兩個領域大致相關、在一個領域不相關，而且沒有係數 [arXiv:2305.14387][arXiv:2310.11589]。所以就本研究讀過的論文而言，「多輪互動的模擬使用者排出的對話系統名次，能不能保住真人的名次」沒有直接而且夠大的證據；真正沒解的是在夠多、彼此獨立的系統上，同時跑模擬使用者與真人。本章沒有讀的前作不在這個判斷的範圍內，見「已知缺口與未讀」第 2 條。

### 模擬器讓系統看起來更強還是更弱：方向隨機制而定

- **讓任務變簡單的證據。** CRS 的模擬器會直接說出答案標題，排除後 ChatGPT 在 ReDial 的 R@10 從 0.539 掉到 0.271 [arXiv:2403.16416]。撰寫時換算相對跌幅為 (0.539 − 0.271) ÷ 0.539 ≈ 49.7% [arXiv:2403.16416]。要注意 0.539 是 2403.16416 自己重跑的基線，不是 iEvaLM Table 5 的 0.536 或 0.440；精讀時又指出它沒寫怎麼判定一段對話受到洩漏影響，撰寫時逐句人讀全文所有含 leak 的句子（清單由程式列出），沒有一句描述判定程序，表上的數字也與「只移除成功對話」的讀法不相容，見「表格與正文對不上的地方」[arXiv:2403.16416][arXiv:2305.13112]。UserLM 主張提示型模擬器太配合，同一個 GPT-4o assistant 由 GPT-4o 模擬使用者時 Assistant Score 是 74.6，換成 UserLM-8b 是 57.4 [arXiv:2510.06552]。Lost in Simulation 的真人對話失敗有 62.2% 歸因於使用者，模擬對話只有 40.0% [arXiv:2601.17087]。
- **讓任務變難的證據。** τ²-bench 的 critical error 會讓任務根本無法完成，airline 達 13% [arXiv:2506.07982]。ICL 模擬器的 Succ 遠低於 agenda 模擬器，部分來自 NLU 與終止規則 [arXiv:2306.00774]。iEvaLM 自己的 Table 8 也是這個方向：同樣的系統，模擬使用者評出的 Recall@10 全面低於人扮使用者（ChatGPT 0.46 對 0.56、KBRD 0.18 對 0.21）[arXiv:2305.13112]。
- **同一篇裡也會翻。** Lost in Simulation 的美國受試者在最難的 0% 箱有 30.8% 成功，在 60% 箱反而只有 39.0% [arXiv:2601.17087]。精讀時提醒，這個型態有一部分光靠選題就會出現 [arXiv:2601.17087]。

iEvaLM 這一條最值得注意：同一套設定，2403.16416 說洩漏讓分數虛高，iEvaLM 自己的對照卻說模擬器評出的分數比人扮使用者低 [arXiv:2403.16416][arXiv:2305.13112]。撰寫時的讀法是兩者不必互斥，因為人扮使用者拿到的是同一份含目標的指令，可能洩漏得更多；但兩篇都沒有拿帶著潛在、模糊需求的真實使用者來校準，所以真正的方向不知道 [arXiv:2305.13112][arXiv:2403.16416]。UserLM 的落差也要打折：它比的是兩個模擬器，而且精讀時指出 UserLM-8b 在數學題的 Intent Coverage 只有 76.5（GPT-4o 模擬為 97.1），分數下降混進了必要資訊沒給夠的效果 [arXiv:2510.06552]。不過程式驗證發現，76.5 所在的 Intent Coverage 那一列與總體值對不上，總體 76.7 高於數學 76.5 與程式 76.6，這個數字要保留地讀 [arXiv:2510.06552]。撰寫時的綜合判斷：模擬器的偏差沒有固定方向，不能用一個常數去校正模擬分數；這是從上述幾篇歸納的，不是任何一篇的結論。

### 對齊過的模型當模擬器：過度精確、過度配合，卻仍常被拿來扮使用者

- **兩篇的證據指向同一方向。** TE 發現超準確失真在 text-davinci-003、ChatGPT、GPT-4 上最明顯，未對齊的 davinci 在人骨數與鋁熔點的 IQR 是 346 與 887.25，人類是 108 與 532 [arXiv:2208.10264]。UserLM 從 instruct checkpoint 起訓的版本，在意圖分解、結束 F1、naturalness 上都比從 base 起訓的差（naturalness 56.54 對 80.21）[arXiv:2510.06552]。
- **另兩篇正好用了這種設定。** iEvaLM 的模擬器是 text-davinci-003，也就是 TE 標為出現超準確失真的那個模型；RecAgent 用 ChatGPT；兩篇都沒有檢查這個偏差 [arXiv:2305.13112][arXiv:2306.02552][arXiv:2208.10264]。iEvaLM 的初版在 2023-05，TE 的超準確結果不確定是哪一版公開的，所以這是事後回看才看得出的張力 [arXiv:2305.13112][arXiv:2208.10264]。
- **證據鏈本身也不乾淨。** UserLM 從 instruct 起訓的版本在兩項守持指標上反而略高（role adherence 95.45 對 93.95）[arXiv:2510.06552]。精讀時也指出，UserLM 摘要所說「更好的 assistant 反而是更差的模擬器」說過頭，Llama3-8b-Instruct 的 intent adherence 以 78.05 對 54.95 領先 1b 版 [arXiv:2510.06552]。TE 的「對齊造成超準確」只是 9 個訓練細節不明的模型之間的相關，精讀時還發現 text-davinci-001 在 4 題就已是正確答案且 IQR 為 0 [arXiv:2208.10264]。
- **「冗長」在兩篇裡量到的不一樣。** SOTOPIA-hard 上 GPT-4 每回合 45.5 字、人類 16.8 字 [arXiv:2310.11667]。Lost in Simulation 的使用者每回合字數，撰寫時核對全文 Table 6，模擬是 13.4，真人各組在 11.2 到 14.8 之間 [arXiv:2601.17087]。兩者角色不同：SOTOPIA 的 GPT-4 是溫度 1 的對等角色，τ-Bench 的模擬器則照使用者提示扮演顧客 [arXiv:2310.11667][arXiv:2601.17087]。撰寫時歸納，兩篇共同指向的不是冗長，而是過度配合與太客氣 [arXiv:2310.11667][arXiv:2601.17087]。
- **取樣溫度也是逼真度的變數。** OOOM 在溫度 0.001 時把所有受訪者的種族都生成成 white，溫度 0.7 時 Cramer's V 差值平均 −0.026 [arXiv:2209.06899]。iEvaLM 的模擬器與 RecAgent 的 repo 設定都用 temperature 0，兩篇的精讀筆記都沒有記錄溫度敏感度分析 [arXiv:2305.13112][arXiv:2306.02552]。

### 裁判與對手同源：跨三個子領域的同一個弱點

撰寫時把三組並讀，發現「產生行為或訓練訊號的一方」與「判定結果的一方」是同一套東西，在三個子領域都出現：

- **模擬器自己判成敗。** TC-Bot 的判定規則與產生使用者行為的規則同在一個模擬器，而且預設用同一個模擬器訓練、選模和報成功率（精讀時依公開程式碼發現）[arXiv:1612.05688]。MetaSim 打分用的逐輪滿意度由模擬器自己的 policy 預測 [arXiv:2204.00763]。
- **模擬器與策略一起被最佳化。** JOUST 以 RL-Joint 的 self-play 成功率高於 RL-DS，推論模擬器的行為夠逼真、夠多樣；但這個成功率對著一起被最佳化的模擬器量 [arXiv:2107.11904]。精讀筆記另外舉遷移設定的數字當模擬器變得更配合的旁證：五個調適領域平均，Naive 加上 RL 後，使用者端沒回答系統請求的比率從 47.27% 降到 32.60%；這不是 self-play 表裡 RL-Joint 對 RL-DS 的比較 [arXiv:2107.11904]。能排除這個混淆的 corpus-based 基準只報 RL-Joint、沒報 RL-DS（精讀時發現）[arXiv:2107.11904]。
- **回饋的標籤就是評估的標籤。** Alexa 系統的吸收狀態標籤、上傳前過濾與 A/B 的缺陷率全來自同一個 friction 模型；精讀時還指出，上線三個月後的 win/loss 11.8 用的是上傳前已經濾過一輪的同一種 Z-test [arXiv:1911.02557]。FITS 的二元回饋方法學的標籤就是主指標 Good% 的標籤 [arXiv:2208.03270]。On-line GP 以論文自己說不可靠的使用者主觀評分當評估金標準 [arXiv:1605.07669]。
- **模擬使用者與學習者是同一個模型。** CIPHER 的模擬使用者與偏好推論都是 GPT-4，精讀時指出偏好推論解讀的其實是 GPT-4 自己的改寫風格 [arXiv:2404.15269]。

這類設定下，指標上升只能讀成「那個代理判定變好」，不能讀成使用者真的更滿意 [arXiv:1911.02557][arXiv:2208.03270][arXiv:1605.07669][arXiv:2404.15269]。NUS 的過擬合結果說明，即使模擬器固定不動，策略訓越久也越會鑽學出來的模擬器 [arXiv:1805.06966]；撰寫時推論，讓模擬器跟著策略一起變只會讓 self-play 成功率更難解讀，兩篇都沒有直接測這件事 [arXiv:1805.06966][arXiv:2107.11904]。

### 規則式模擬器：安全的訓練環境，還是太好對付的對手

- **TC-Bot 的說法。** 它說已證明規則式模擬可以安全地訓練 RL，並把被鑽漏洞的風險只歸給模型式模擬器 [arXiv:1612.05688]。精讀時依公開程式碼發現一個反例：使用者對目標以外的 slot 一律回答「I do not care」，多問不會引發任何負面反應，代價只有每輪 −1 的獎勵 [arXiv:1612.05688]。
- **兩篇的模擬端資料指向「太好對付」。** NUS 中 ABUS 訓出的策略換到 NUS 上，平均成功率只剩 45.5% [arXiv:1805.06966]。GenTUS 中三個系統都在 ABUS-T 上表現最好，作者稱它是最容易的設定 [arXiv:2208.10817]。但精讀時指出 NUS 那個結果也可能是 regex 解析器解 NUS 文字時出錯、等於注入了語意雜訊，兩種解釋分不開 [arXiv:1805.06966]。
- **MetaSim 的資料指向另一個問題。** 基礎系統與它的 Agenda 模擬器互動，Success 只有 12.19 [arXiv:2204.00763]。精讀時說 Agenda 的 ED 等於隨機；程式驗證在「每格 1000 組偏好、彼此獨立」的假設下發現情況不一：ReDial 三格與 MultiWOZ 的 T_C、T_R 與隨機分不開，MultiWOZ 的 T_D 19.47 已高於隨機，JDDC 的 13.76 與 14.52 則顯著低於 1/6，也就是系統性地把變體排反 [arXiv:2204.00763]。這說的是 agenda 模擬器難以溝通、多數情況分不出系統好壞，在 JDDC 甚至排反 [arXiv:2204.00763]。MetaSim 的 Agenda 是作者用訓練集的動作轉移分佈重做的，不是 PyDial 的 ABUS [arXiv:2204.00763]。
- **LLM 模擬器登場後，agenda 模擬器反而成了高分的一方。** ICL 模擬器那篇的 ABUS-T 成功率 0.83，遠高於 GPT-3.5 的 0.29 [arXiv:2306.00774]。撰寫時的讀法是：這個落差同時可以讀成「LLM 模擬器差」或「agenda 模擬器太好對付」，而論文沒有真人對照可以判斷 [arXiv:2306.00774]。

### 回饋何時要、要多細、要不要清理

- **模型不確定度能不能當觸發器。** On-line GP 用獎勵模型的預測不確定度決定何時問使用者，約 150 次查詢就訓練出穩健的獎勵模型 [arXiv:1605.07669]。Self-feeding 那篇卻說模型不確定度是很差的觸發器，F1 0.56 對分類器的 0.84 [arXiv:1901.05415]。撰寫時的讀法是兩者不矛盾：前者是對話結束後評估器對成敗的不確定，後者是回應排序模型開口前的信心 [arXiv:1605.07669][arXiv:1901.05415]。精讀時也指出後者的比較條件不對等，分類器看得到使用者的下一句話，基線看不到；程式驗證逐段核對原文證實了這一點，論文自己把前者描述成看使用者下一句話的事後判斷、把後者描述成 bot 開口前的觸發 [arXiv:1901.05415]。加上前一節的平凡解驗算，「模型不確定度沒用」最多只能收窄成「排序模型的事前信心，在這個設定下沒有明顯比全判為錯誤更好」[arXiv:1901.05415]。
- **回饋越細越好，還是越輕越好。** FITS 的結論是模組回饋優於只給最終回應的回饋，模組加二元回饋餵給 Director 最好 [arXiv:2208.03270]。Self-feeding 那篇發現，平均而言 20k 筆 Feedback 的幫助約等於 60k 筆 HB [arXiv:1901.05415]。但 BB3 的作者推測，真實使用者比較適合輕量回饋，要求詳細回饋可能降低參與度 [arXiv:2208.03188]。精讀時指出，FITS 比的是每輪都有、全部收齊的情況，沒有在相同標註成本下比較 [arXiv:2208.03270]。
- **回饋要不要清理。** Self-feeding 那篇主打回饋不必清理也能用，精讀時卻在附錄樣本裡看到使用者回了一句普通聊天、照樣進入 Feedback 集的例子 [arXiv:1901.05415]。BB3 的 SafetyMix 顯示，50% troll 時不過濾的錯誤率 31%，過濾後可降到 12% [arXiv:2208.03188]。精讀時也指出，單獨的使用者層級過濾（23%）比例子層級過濾（19%）還差，SafetyMix 又是人工混合的基準 [arXiv:2208.03188]。撰寫時歸納：三篇的使用者群分別是付費工作者、付費受試者與公開部署的使用者，沒有一篇在同一個使用者群上比較清理與不清理 [arXiv:1901.05415][arXiv:1605.07669][arXiv:2208.03188]。
- **拿模型自己的輸出當目標。** Self-feeding 那篇發現把 bot 自己的回應當訓練目標會降分，131k HH 從 44.7 降到 40.4 [arXiv:1901.05415]。FITS 的 reward-based learning 也拿自己 rerank 過的輸出當目標；撰寫時核對全文 Table 3，它在 BB2 上的 Good% 是 36.4%，只略高於 reranking 的 36.1%，Rating 2.83 則是三種二元方法中最低、也低於基線的 3.09 [arXiv:2208.03270]。

### 「持續學習」實際閉合了幾次

BB3 標題寫 continually learns，精讀時指出本文沒有任何用真實部署回饋重訓的快照，釋出的 BB3 只用了群眾工作者環境下的 FITS 模組監督 [arXiv:2208.03188]。FITS 的 v1 → v2 只有自動 F1，而 v2 的訓練資料是 9817 ÷ 5592 ≈ 1.76 倍於 v1，增益可能只是資料量（精讀時指出）[arXiv:2208.03270]。Self-feeding 那篇完整的「自己餵自己」只發生過一次（精讀時指出）[arXiv:1901.05415]。在本章計入的論文裡，唯一有營運中迴路的是 Alexa，它每天重跑挖掘；但精讀時指出，改寫上線後原句的缺陷消失、使用者不再改述，之後的日誌就缺少支撐這條改寫的證據，論文沒有討論這種自我遮蔽 [arXiv:1911.02557]。FITS 與 BB3 也都說以 3B 模型收集的回饋能改進 175B 模型，兩份筆記的精讀都指出這沒有被隔離：BB3-175B 同時換了規模、加了許多其他資料集，對照的 OPT-175B 完全沒微調 [arXiv:2208.03270][arXiv:2208.03188]。以真實部署資料重訓的工作本章沒有讀：FITS 在相關研究中提到，在 LIGHT 對話遊戲上部署、讓模型模仿人類對話者的做法，並說它不適用於一方提問、一方回答的不對稱對話 [arXiv:2208.03270]。FITS 引用的那篇，以及其他依標題處理部署回饋的論文，本章都沒有讀，見「已知缺口與未讀」第 5 條；本節的判斷只涵蓋本章計入的論文。

### 論文的概括比自家表格寬

- **JOUST。** 作者說領域調適上 RL 平均帶來 7–10% 的提升；精讀時發現這些是 combined score 的絕對分數，而且表格的範圍比這更寬，從 predicted 下 EWC 的 73.5 − 66.9 = 6.6 到 oracle 下 Naive 的 98.5 − 87.5 = 11.0 [arXiv:2107.11904]。它的「新 state-of-the-art」也只在 oracle belief 下成立，predicted 下 Comb 96.0 低於 MinTL-BART 的 97.8 [arXiv:2107.11904]。turn-R 優於 dial-R 也有反例：只更新系統端時 turn-R 的 70.34 低於 dial-R 的 70.67（精讀時發現作者概括時略過了）[arXiv:2107.11904]。
- **SimpleUserSim。** 換成 SimpleUserSim 後，UniCRS 的 ReDial Recall@1 從 0.219 掉到 0.073；作者稱排除洩漏後 KBRD 墊底，但 ReDial -both Recall@50 是 KBRD 0.451 高於 BARCOR 0.430（精讀時發現）[arXiv:2403.16416]。
- **OOOM。** 正文說人類與 GPT-3 清單在五項內容特徵上都相似；撰寫時核對附錄的係數與標準誤，traits、issues、groups 分別是 0.058 ÷ 0.007 ≈ 8.3、0.033 ÷ 0.007 ≈ 4.7、0.078 ÷ 0.007 ≈ 11.1 個標準誤 [arXiv:2209.06899]。精讀時另外指出，評估者猜中寫作者黨派的比例，GPT-3 清單是 52.8%、人類清單是 60.1%（p < .001），作者卻把它寫成支撐準則 2 的證據 [arXiv:2209.06899]。
- **TE。** 論文把 LM-5 在 $2 offer 上男性回應女性提議者接受 60%、女性回應男性 20% 稱為與 chivalry 假說一致，卻把群眾智慧的偏離叫 distortion；精讀時指出在沒有同條件人類資料時，三倍的差距更可能是刻板印象被放大 [arXiv:2208.10264]。
- **CIPHER。** 精讀時指出，摘要報的兩個成本降幅 31% 與 73% 分別取自不同的嵌入模型；改以「No Learning 到 Oracle 的差距縮小多少」計算，摘要只縮小 (48,269 − 32,974)／(48,269 − 6,573) ≈ 37% [arXiv:2404.15269]。email 的檢索準確率只有 25.45% 到 26.57%，與 4 個來源的隨機 25% 幾乎一樣，成本降幅卻比摘要大得多（精讀時發現）[arXiv:2404.15269]。
- **FITS 的「學會新技能」。** 以 SeeKeR 為基底時，Test Unseen F1 基線 20.8，free-form、supervised、module 都低於基線（精讀時指出）[arXiv:2208.03270]。
- **GenTUS 的 RL 使用者。** 作者說兩個 RL 使用者的 success 都比監督版高，但 User 2 的 0.78±0.04 與監督版的 0.76±0.08 區間重疊；塑形的動機是讓系統更穩健，論文卻沒拿塑形出的使用者去訓練任何系統（精讀時發現）[arXiv:2208.10817]。

### Alexa 的數學論述：精讀的判斷有一半被撰寫時的推導推翻

論文寫 Q 是機率矩陣所以範數小於 1；精讀時指出這不成立，因為隨機矩陣的範數可以等於 1 [arXiv:1911.02557]。撰寫時推導也認同這一半：只要某個解讀從不直接被吸收，Q 的那一列加總就是 1 [arXiv:1911.02557]。但精讀進一步推論「所以 Φ∞ 不是機率、循環會膨脹分數」，撰寫時推導不同意：依論文 Eq. 13–14，各步的項是「第 n 步位於某解讀、下一步被成功吸收」的機率，不同 n 的事件互斥，相加仍是機率，總和不會超過從來源解讀被成功吸收的總機率 [arXiv:1911.02557]。撰寫時認為真正的問題在別處：Φ∞ 量的是「從來源出發、最後一個解讀是某目標並以成功收場」的機率，不是「把來源改寫成那個目標之後成功」的機率，拿它和原句的成功率比，比的是兩個不同的事件 [arXiv:1911.02557]。精讀時另外指出的「實作剪掉循環路徑、理論與實作不一致」仍然成立 [arXiv:1911.02557]。

### 論文自述部署

- **Alexa 的 feedback-based self-learning：有第一方商用採納證據。** 論文自述在生產環境做了兩週以上的 A/B 測試並長期上線 [arXiv:1911.02557]。Amazon Science 官方部落格描述同一套以吸收馬可夫鏈建模改述序列的系統已經部署，每週修正數百萬則聽錯或說錯的請求，大約每學到 1 個無效替換就學到 12 個有效替換（https://www.amazon.science/blog/how-we-taught-alexa-to-correct-her-own-defects）[arXiv:1911.02557]。部落格說部署已超過一年，論文說超過 9 個月，兩者撰寫時點相差數月，大致相容 [arXiv:1911.02557]。兩個來源都出自 Amazon，沒有第三方稽核；現今的 Alexa 是否仍在使用這個機制，未見證據 [arXiv:1911.02557]。
- **BlenderBot 3：有公開部署，但是研究型 demo。** 論文自述 BB3-3B 與 BB3-175B 公開部署在 https://blenderbot.ai，限美國成年使用者，並分析了 15,088 則（3B）與 9,197 則（175B）bot 訊息的使用者回饋 [arXiv:2208.03188]。Meta AI 官方部落格說明了公開 demo 與讚／倒讚機制，更新段寫到已收集 70K 段對話、25% 的參與者對 260K 則 bot 訊息給過回饋，也寫明 demo 僅供研究與娛樂，沒有提到整合進任何 Meta 產品（https://ai.meta.com/blog/blenderbot-3-a-175b-parameter-publicly-available-chatbot-that-improves-its-skills-and-safety-over-time/）[arXiv:2208.03188]。ParlAI 專案頁把部署對話資料標為 coming next，2026-09-26 讀取時仍未見釋出（https://parl.ai/projects/bb3/）[arXiv:2208.03188]。這個回饋迴路用在商用產品，未見證據 [arXiv:2208.03188]。
- **FITS：只經由 BB3 進到公開 demo。** FITS 自己的「部署」對象是 MTurk 工作者 [arXiv:2208.03270]。同一篇 Meta 部落格連到 FITS 專案並提到 Director（https://ai.meta.com/blog/blenderbot-3-a-175b-parameter-publicly-available-chatbot-that-improves-its-skills-and-safety-over-time/）；能確認的是 BB3 用了 FITS 的模組監督資料，無法確認部署中的 BB3 用了本文訓練的 Director 模型 [arXiv:2208.03270]。第三方商用採納未見證據 [arXiv:2208.03270]。

### 廠商官方文件採用

- **τ²-bench：一家模型廠商在官方發表中當評估基準，並改了模擬器提示詞。** Anthropic 的 Claude Sonnet 4.5 官方發表頁在方法說明中寫到，τ2-bench 分數是在 Airline 與 Telecom 的 agent policy 加上提示補充後取得，Telecom 的 User prompt 也加了補充說明，避免使用者錯誤結束對話（https://www.anthropic.com/news/claude-sonnet-4-5）[arXiv:2506.07982]。採納的範圍只到「廠商在模型發表中拿 τ2-bench 當 agent 評估基準」；這套使用者模擬器設計被用在實際客服產品的開發或上線流程，未見證據，論文本身也沒聲稱作者方的產品有部署 [arXiv:2506.07982]。精讀時的推論是，這也表示廠商回報的分數用的是改過的模擬器，跨廠商分數不能直接比較 [arXiv:2506.07982]。OpenAI 的相關頁面精讀時無法開啟，沒有列入 [arXiv:2506.07982]。

### 僅作者自家釋出

以下都是作者方或同一研究社群的釋出，屬於可重現性與學術影響力，不算商用採納：

- **τ²-bench。** 官方程式碼庫由作者方 Sierra 持續維護，後來加了 banking_knowledge 領域、語音全雙工模式與 75 個以上的任務修正（https://github.com/sierra-research/tau2-bench）[arXiv:2506.07982]。
- **SOTOPIA。** 開源實作（https://github.com/sotopia-lab/sotopia）與 Hugging Face 資料集（https://huggingface.co/datasets/cmu-lti/sotopia），頁面都沒有列出公司或產品採用 [arXiv:2310.11667]。

- **RecAgent。** 官方 repo 授權寫 MIT，但另註明資料與程式碼只能用於學術用途（https://github.com/RUC-GSAI/YuLan-Rec）[arXiv:2306.02552]。
- **TC-Bot。** 公開儲存庫是研究用程式碼（https://github.com/MiuLab/TC-Bot）；SLT 2018 的 Microsoft Dialogue Challenge 沿用同一套命令列介面（https://github.com/xiul-msr/e2e_dialog_challenge），屬於研究社群的共同基準 [arXiv:1612.05688]。
- **其他研究程式碼與資料。** JOUST（https://github.com/andy194673/joust）[arXiv:2107.11904]；GenTUS 收進 ConvLab-3（github.com/ConvLab/ConvLab-3）[arXiv:2208.10817]；ICL 使用者模擬器是 ConvLab-2 的 fork（github.com/telepathylabsai/prompt-based-user-simulator）[arXiv:2306.00774]；TE 由 Microsoft 以 MIT 授權釋出、已封存（github.com/microsoft/turing-experiments）[arXiv:2208.10264]；人類教學那篇的語料以 Sim-GEN 名義公開（https://github.com/google-research-datasets/simulated-dialogue）[arXiv:1804.06512]；USS（https://github.com/sunnweiwei/user-satisfaction-simulation）[arXiv:2105.03748]；PRELUDE（https://github.com/gao-g/prelude）[arXiv:2404.15269]；FITS 的資料集與模型放在 ParlAI（https://parl.ai/projects/fits/）[arXiv:2208.03270]。

### 未見證據

NUS、MetaSim、OOOM、iEvaLM、2403.16416、Lost in Simulation、on-line GP、self-feeding chatbot 的採納摘要都沒有附 URL 的證據 [arXiv:1805.06966][arXiv:2204.00763][arXiv:2209.06899][arXiv:2305.13112][arXiv:2403.16416][arXiv:2601.17087][arXiv:1605.07669][arXiv:1901.05415]。其中幾篇有作者任職於公司（例如 Lost in Simulation 有 Cohere 的作者），但論文沒說該公司的產品採用了這套方法，共同署名不構成採納證據 [arXiv:2601.17087]。📖 那篇同樣未見證據 [arXiv:2309.13233]。

## 與其他節點的關係

三條邊的清單都是精讀者自己標的，有些標得很鬆。以下逐條依各篇筆記裡的 how 判斷：誰實際處理了那條資料流、怎麼處理、只做一半的缺哪一半。分類是撰寫時的判斷。

### E1 External Input（T6→T1）：使用者或模擬器的輸入進入目標對齊

標了這條邊的筆記有四十一篇。完整的資料流是：使用者（或模擬器）產生輸入，進入 agent 的意圖辨識、狀態追蹤或偏好推斷，論文並量出這條輸入對目標對齊的影響。

**實際處理、而且量了影響的 T6 論文。** 有幾篇刻意操縱這條流：TC-Bot 用 error model 在 intent 與 slot 層加噪 [arXiv:1612.05688]；NUS 在系統回報查無結果時改變目標、製造可控的目標漂移，但它的交叉模型與真人評估比的是兩種模擬器訓出的策略，沒有把目標變更當成自變數，所以目標漂移本身的影響沒有單獨量（本章讀法）[arXiv:1805.06966]。有幾篇把模擬器的話語當成系統唯一的外部輸入來量對齊：JOUST 的 DS 從 US 的話語抽出 slot-value 限制，inform 與 success 量的正是 DS 有沒有對齊 US 背後的目標；iEvaLM 的受測 CRS 會主動反問，靜態資料接不住這種反問，才需要模擬器補上輸入，attr 設定則把這條輸入限縮成樣板化的屬性值 [arXiv:2107.11904][arXiv:2305.13112]。有幾篇拿它當壓力測試：GenTUS 只把自然語言交給系統的 BERTNLU，系統在訓練時就得面對意圖辨識誤差；ICL 模擬器的正常說法被系統 NLU 判成空的對話行為，暴露出 T1 端的盲點 [arXiv:2208.10817][arXiv:2306.00774]。有幾篇量了通道本身的成本或品質：MetaSim 的 Context tester 限制系統可見的歷史句數，量系統吸收多輪輸入的能力；τ²-bench 從 No-User 到 Default 的落差，部分量的就是這條通道的成本；UserLM 用 Intent Coverage 量意圖在傳遞中被覆蓋多少；2403.16416 控制進入 CRS 的資訊量 [arXiv:2204.00763][arXiv:2506.07982][arXiv:2510.06552][arXiv:2403.16416]。Lost in Simulation 把輸入來源本身當自變數：argument error 在模擬是 32.2%，落在真人的 23.2–45.8% 之內；真人對話的失敗有 62.2% 歸因於使用者，模擬對話只有 40.0%，作者據此認為模擬使用者照指示照得更精確，只看模擬會把失敗多算在 agent 頭上 [arXiv:2601.17087]。

**介入的是輸入本身，而不是對齊模型。** Alexa 在 NLU 之前把使用者原句換成較可能被正確解讀的改寫，修的是進入目標對齊的外部輸入 [arXiv:1911.02557]。人類教學那篇讓逐輪更正直接成為目標追蹤器的訓練標籤，但更正來自模擬器 [arXiv:1804.06512]。CIPHER 把使用者修改轉成自然語言偏好，下次遇到相似脈絡時插回提示詞 [arXiv:2404.15269]。

**他節點的論文有迴圈、有模擬器的。** 以 persona 模擬使用者產生訓練對話的有 2311.05584、STaR-GATE、CollabLLM、2410.13788、2402.09205 [arXiv:2311.05584][arXiv:2403.19154][arXiv:2502.00640][arXiv:2410.13788][arXiv:2402.09205]。以模擬使用者為評估輸入的有 τ-bench、ToolSandbox、Lost in Conversation、Proactive Agent、2311.09469 [arXiv:2406.12045][arXiv:2408.04682][arXiv:2505.06120][arXiv:2410.12361][arXiv:2311.09469]。2602.16666 則擾動使用者措辭，量 agent 在同一目標下換說法時的穩定度 [arXiv:2602.16666]。

**只有 T1 那一半。** 下列論文處理的是進入 T1 的靜態、單輪輸入，沒有 T6 的生產端，也沒有互動迴圈：澄清問題排序、意圖與 OOS 資料集、Mahalanobis OOD 偵測、open-world 意圖發現、離線合成的意圖訓練句、Llama Guard 的輸入分類、對 agent 的注入攻擊、WebShop 的一次性指令 [arXiv:1805.04655][arXiv:1909.02027][arXiv:2101.03778][arXiv:2310.10176][arXiv:2305.07157][arXiv:2312.06674][arXiv:2407.20859][arXiv:2207.01206]。SGD 的模擬器只用來離線生成資料，1907.06554 的「使用者」是靜態查表，ClariQ 的真人回答在 v1 只是規劃，Generative Agents 在這條流上只有示範、沒有評估 [arXiv:1909.05855][arXiv:1907.06554][arXiv:2009.11352][arXiv:2304.03442]。

**標得鬆的。** BB3 標的是輸入進來時的安全分類與敏感話題分流，精讀者自己也說範圍很窄，不是目標對齊 [arXiv:2208.03188]。TE 標的是 Milgram 實驗裡把模擬受試者的文字分類成「終止／服從」，驅動的是寫死的實驗者腳本，不是 agent 的目標對齊；它的價值在揭露模擬者脫稿、捏造細節、替實驗者寫台詞這類失敗模式 [arXiv:2208.10264]。📖 那篇只把系統當受測物，不研究意圖偵測本身 [arXiv:2309.13233]。

**多數論文缺的那一半：模擬輸入從沒和真人輸入在同一批任務上比過。** 補上的分成幾類。同一批任務：Lost in Simulation 讓真人與模擬器做同一批任務；iEvaLM 用同樣 100 筆 ReDial 比較 LLM 模擬器與人扮使用者，但人拿到同一份含目標 item 的指令 [arXiv:2601.17087][arXiv:2305.13112]。同一批系統：NUS、GenTUS、MetaSim 把模擬器與真人放在同一批系統上各評一次，見評估一節的對照表；📖 那篇也做過，只當反例 [arXiv:1805.06966][arXiv:2208.10817][arXiv:2204.00763][arXiv:2309.13233]。他節點的：CollabLLM 把在模擬器上學到的行為換到 201 位 MTurk 真人身上驗證；2402.09205 測試時換成 8 位真人；2310.11589 在附錄把模擬與真人的互動紀錄改算成同一套指標做相關 [arXiv:2502.00640][arXiv:2402.09205][arXiv:2310.11589]。STaR-GATE 換不同模型當模擬器，量的是對輸入來源的敏感度，不是效度 [arXiv:2403.19154]。

### E4 Nominal Path（T4→T6）：正常路徑繼續與使用者互動

標了這條邊的筆記只有 3 篇。這條邊的意思是：軌跡分析沒有發現異常時，agent 走正常路徑繼續與使用者互動。

- **Self-feeding chatbot 最接近，但判斷依據不是軌跡分析。** 滿意度估計高於門檻時 bot 照常對話，使用者在這條路徑上的回覆同時被收成 HB 訓練範例，所以正常路徑本身也產出資料 [arXiv:1901.05415]。但決定走哪條路的是讀使用者下一句話的滿意度分類器，不是 T4 對 agent 軌跡的分析 [arXiv:1901.05415]。
- **MINT 不分路徑。** 每一輪都把完整軌跡交給 GPT-4 模擬使用者產生回饋，沒有正常與異常之分 [arXiv:2309.10691]。
- **τ²-bench 只有正常迴圈。** agent 與模擬器持續互動，直到模擬器輸出結束 token，沒有任何偵測器在決定要不要繼續 [arXiv:2506.07982]。

撰寫時的判斷：就標了這條邊的三篇來看，這條邊幾乎沒有被實作。三篇都「繼續互動」，但沒有一篇由 T4 的軌跡分析來決定繼續，缺的正是 T4 這一端。

### E6 Interaction Logs（T6→T7）：互動紀錄回流評估

標了這條邊的筆記有五十六篇，是三條邊中最多的。完整的資料流是：使用者或模擬器與 agent 的互動紀錄被保存，交給獨立的評估端算出指標。

**主線：同一份紀錄同時當訓練訊號與評估依據。** On-line GP 的成功估計器輸出同時是評估結果與 RL 獎勵 [arXiv:1605.07669]。TC-Bot 的模擬器結果同時決定學習曲線、選模與 replay buffer，精讀者直接點出這是這條邊在該篇的主要弱點 [arXiv:1612.05688]。人類教學那篇、JOUST、Alexa、FITS 也都讓互動紀錄同時回流訓練與評估 [arXiv:1804.06512][arXiv:2107.11904][arXiv:1911.02557][arXiv:2208.03270]。NUS 的交叉模型評估表既是評估結果，也是挑選哪些策略送去真人評估的依據；作者還從跨模擬器的落差偵測出策略對模擬器過擬合 [arXiv:1805.06966]。CIPHER 的同一份修改紀錄既觸發偏好推論，又直接算成 token 級 Levenshtein 成本這個主指標，每輪推出的偏好也拿去和真實偏好比對 [arXiv:2404.15269]。他節點的 STaR-GATE、Proactive Agent、CollabLLM 同樣以同一個判斷來源篩選訓練資料並做評估 [arXiv:2403.19154][arXiv:2410.12361][arXiv:2502.00640]。處理這個問題的做法有兩種：NUS 用跨模擬器的落差偵測過擬合，GenTUS 用交叉模型評估估計泛化能力 [arXiv:1805.06966][arXiv:2208.10817]；在設計上就把訓練與評估的模擬器分開的是 2410.13788，訓練用自己訓練的模擬器、評估用 GPT-4，刻意讓兩端的模擬器不同，以免過度擬合特定模擬器 [arXiv:2410.13788]。

**模擬器既是對手，也是評估的來源。** GenTUS 以三種模擬器各與每個系統互動，形成交叉模型矩陣，而這個矩陣的排名與真人相反 [arXiv:2208.10817]。MetaSim 的互動紀錄同時回流到評估系統與評估模擬器兩端 [arXiv:2204.00763]。ICL 模擬器、τ²-bench、SOTOPIA、UserLM、RecAgent 的評估也都完全從模擬互動紀錄導出 [arXiv:2306.00774][arXiv:2506.07982][arXiv:2310.11667][arXiv:2510.06552][arXiv:2306.02552]。TE 提醒了一個細節：Milgram 的紀錄只保留每次生成的第一句，紀錄怎麼剪裁本身就會影響評估結果 [arXiv:2208.10264]。

**真人互動紀錄回流評估。** BB3 把使用者的讚／倒讚直接當部署評估指標，再抽樣請 crowdworker 重標以量一致率 [arXiv:2208.03188]。Chatbot Arena 把真實使用者的對話與投票回流成排行榜與 LLM 評審的金標準 [arXiv:2306.05685][arXiv:2403.04132]。AlpacaFarm 用真實 demo 的使用者指令驗證評估集的代表性 [arXiv:2305.14387]。Constitutional AI 的 helpfulness 與 harmlessness Elo 來自群眾工作者的多輪互動偏好 [arXiv:2212.08073]。2402.09205 的真人在對話中逐輪自標提問數、選項數與選項是否合理，再由 GPT-4 把紀錄裡的提問對到標準的缺漏細節，算出 Recover Rate 等指標 [arXiv:2402.09205]。

**同一套判分同時處理模擬紀錄與真人紀錄。** 這一組直接回答本章的主軸問題。iEvaLM 在 §5.1 與 §5.2.2 把模擬互動紀錄和人扮使用者的互動紀錄拿來對照，以驗證評估結果是否可靠；但評估一節已指出，那裡的「人」拿到同一份含目標 item 的指令 [arXiv:2305.13112]。📖 那篇把模擬出的整篇對話與人類在同一批系統上的 Human2Bot 紀錄送進同一套 MultiWOZ 指標，兩個系統的排名相反，只當反例 [arXiv:2309.13233]。2310.11589 在附錄 D 把模擬使用者與真人的互動紀錄改算成同一套輪數制指標，逐方法做相關 [arXiv:2310.11589]。Lost in Simulation 把模擬與真人兩種紀錄送進同一套自動判分，指出只看模擬紀錄會過度強調 agent 的執行錯誤、掩蓋真人帶來的失敗 [arXiv:2601.17087]。

**稽核消費端的。** 2507.02825 用什麼都不做的 agent 與灌資料的 agent 實際跑 τ-bench，顯示只看終態與子字串的評分可以被鑽，airline 分別拿到 38% 與 40% [arXiv:2507.02825]。2602.16666 強調要分析完整軌跡而不是只看終態，才看得到中間的政策遵守情況 [arXiv:2602.16666]。2510.07777 逐輪比較模擬器相對參考模擬器的分佈距離，但 agent 回應固定，評的是模擬器本身而不是整段互動 [arXiv:2510.07777]。HAL 把「模擬使用者偏離既定指示」列為環境障礙，卻因 few-shot scaffold 洩漏把 TAU-bench 排除在主要分析外 [arXiv:2510.11977]。MT-Bench-101 的金上下文對自預測上下文實驗，回答了送進評估的互動歷史該由誰產生：用理想歷史會因模仿而虛高，用模型自己的歷史會累積錯誤 [arXiv:2402.14762]。2403.16416 標出模擬器與 CRS 互動紀錄裡的標題洩漏，排除後重算 Recall@k，並統計成功發生在第幾輪、用 LLM 標出 CRS 每輪的意圖分佈，檢查評估結果有沒有被灌水 [arXiv:2403.16416]。他節點的 1805.04655 則是「拿真實紀錄當正解本身就有雜訊」的直接證據：留言裡的原始提問只有 20% 被兩位專家都選為最佳、88% 至少有一位認為可以接受，作者因此改以專家標註為主要評估 [arXiv:1805.04655]。

**他節點的基準與方法：模擬互動紀錄就是評估原料。** 2311.05584 讓 50 位持有隱藏正解活動的 GPT-3.5 模擬使用者與 agent 即時互動，逐段算出每則發言的 token 數、第一個推薦是否命中、15 則發言內是否命中；這些紀錄只用於評估，沒有回饋進訓練，訓練資料是事先想像出的合成對話 [arXiv:2311.05584]。 τ-bench 在模擬器輸出結束 token 後，以最終資料庫狀態與 agent 對使用者的訊息算獎勵，彙總成 pass^k；完整軌跡另交人工做失敗分類，並回頭修正有錯字或歧義的任務指令 [arXiv:2406.12045]。ToolSandbox 把使用者模擬器、agent 與執行環境之間的完整訊息連同每輪的世界狀態留下，事後整份做 milestone／minefield 比對 [arXiv:2408.04682]。MINT 以有無模擬使用者回饋兩組軌跡的成功率差量回饋的價值，並掃描全部軌跡追溯格式失敗 [arXiv:2309.10691]。AgentBench 依結束原因替每條軌跡分類，但只有 LTP 的對手是 LLM 模擬的對話角色，其餘環境的 user 是確定性的程式 [arXiv:2308.03688]。2305.13626 的目標導引部分以 self-play 讓不知道目標的模擬使用者與系統對話，再從紀錄算成功率、輪數與連貫性，並交標註者評分 [arXiv:2305.13626]。Lost in Conversation 把每一輪 assistant 回應分成七類策略，並在附錄以人工檢查模擬紀錄的品質 [arXiv:2505.06120]。Generative Agents 的評估直接用 agent 之間的互動紀錄：人評看 replay 與完整記憶流後排名，端到端評估把每個肯定回答對回記憶流裡的來源對話，用來判定幻覺 [arXiv:2304.03442]。

**只做一半的。**

- **紀錄回流到訓練，不是評估。** Self-feeding 的部署紀錄主要變成訓練資料，重訓後的模型是在靜態的 PersonaChat 測試集上評估的 [arXiv:1901.05415]。
- **有離線紀錄，沒有系統層級的彙總。** USS 從五個語料的紀錄推估逐輪滿意度，但沒有把它彙整成系統分數去比較不同的對話系統 [arXiv:2105.03748]。
- **只有靜態紀錄、沒有迴圈。** MultiWOZ 的測試集、MT-Bench-101 事先寫好的逐字稿、G-Eval 的表單式評分都用離線紀錄，模型的回覆不會回到使用者端 [arXiv:1810.00278][arXiv:2402.14762][arXiv:2303.16634]。LoCoMo、LongMemEval、MemoryBank 由模擬器產生多 session 的互動紀錄，經人工修正或標註後凍成靜態的評估材料，受測系統的回覆不會回到模擬器，缺了迴圈；LongMemEval 另有一段讓人工標註者與商用系統實際逐輪互動的研究 [arXiv:2402.17753][arXiv:2410.10813][arXiv:2305.10250]。
- **模擬的不是使用者。** TheAgentCompany 的互動紀錄確實流進 evaluator 計分，但模擬的是同事；使用者指令只有一次性的 task intent，沒有多輪的使用者回饋 [arXiv:2412.14161]。
- **只有規劃，或只用一個欄位。** ClariQ 規劃了蒐集評分三元組，v1 沒有任何資料；Cost-of-Pass 只取互動紀錄的 token 數，沒說模擬器的 token 有沒有計入；2411.16594 是綜述，只整理文獻 [arXiv:2009.11352][arXiv:2504.13359][arXiv:2411.16594]。

## 未解問題

1. **模擬器排出的系統名次，對真人名次有多少預測效度。** 在本章計入的論文裡，做過多系統對照的四篇（另有不計入的 📖 一篇）中，規模最大的是 MetaSim 的 7 個受控降級變體，名次與真人幾乎無關；其餘只有 2 到 4 個系統，方向還互相矛盾：NUS 方向一致但差距不顯著或只在邊界，GenTUS 的模擬端與真人相反，iEvaLM 的「真人」拿到同一份含目標的指令 [arXiv:2204.00763][arXiv:1805.06966][arXiv:2208.10817][arXiv:2305.13112]。其他節點的 AlpacaFarm 以 10 個系統得到高度一致的排名，但其中 4 個是未訓練的參照模型，精讀時指出 0.98 主要由它們撐起；它模擬的也是單輪偏好標註者 [arXiv:2305.14387]。唯一拿多個真人族群校準 LLM 模擬器的 Lost in Simulation 只固定一個 agent，作者自己也說不知道較強或較弱的 agent 校準型態是否不同 [arXiv:2601.17087]。卡在成本與資料：真人實驗每人做 4 題約要 35–40 分鐘，名次比較又得在多個 agent 上重複；RecAgent 也指出真實使用者資料受商業機密與隱私限制 [arXiv:2601.17087][arXiv:2306.02552]。依標題與這一題相關的未讀論文，見「已知缺口與未讀」第 1、2 條。
2. **策略鑽模擬器漏洞時怎麼偵測、怎麼防，裁判與對手要怎麼分開。** TC-Bot 在 2016 年就警告過，NUS 在 2018 年看到了 [arXiv:1612.05688][arXiv:1805.06966]。卡在三處：本章看到的偵測方式都是比較策略在另一個模擬器上的表現，精讀時發現 97.3% 降到 94.0% 看不出策略利用了哪一種缺陷 [arXiv:1805.06966]。規則式模擬器那側只有 NUS 在兩個訓練長度上做過跨模擬器對照：ABUS 訓出的策略在 NUS 上從訓 1000 場的 42.3% 變成訓 4000 場的 45.5%，作者說沒看到過擬合，但也沒量策略利用了 ABUS 的哪種缺陷 [arXiv:1805.06966]。JOUST 讓模擬器跟著策略一起變，問題更難看清 [arXiv:2107.11904]。回饋迴路那一側也一樣，Alexa、FITS、CIPHER 的評估訊號都與訓練訊號同源 [arXiv:1911.02557][arXiv:2208.03270][arXiv:2404.15269]。
3. **逼真度要用什麼直接量，和下游結果是什麼關係。** 多樣性、「人分不出來」、AI 偵測器、關聯指標、ECE 各自有已知的漏洞 [arXiv:2208.10817][arXiv:2209.06899][arXiv:2510.06552][arXiv:2601.17087]。卡在兩處：在本章計入的論文裡，撰寫時沒有看到任何一篇把模擬器的某個直接指標，和「用它訓出或評出的系統在真人上的表現」放在一起分析。其他節點的 AlpacaFarm 是部分反例：它比較了變異度不同的兩種模擬標註者當訓練訊號，保留人類般雜訊的模擬器訓出的 PPO 給真人評只有 43%，低於 SFT 起點的 44%，改用低變異的單一 GPT-4 標註者訓練則是 50%；但它模擬的是單輪偏好標註者，不是多輪互動的使用者 [arXiv:2305.14387]。另一處是缺一套同時量邊際分佈、關聯結構與群體異質性的標準，而對齊與低溫都會把分佈推向一致 [arXiv:2208.10264][arXiv:2209.06899][arXiv:2305.13112]。
4. **給模擬器目標而不洩漏，並分開「逼真的困難」與「資訊不足」。** 模擬器知道答案標題時會直接說出口，改成只給屬性，仍會透過世界知識二次洩漏 [arXiv:2305.13112][arXiv:2403.16416]。反方向，UserLM-8b 在數學題只覆蓋 76.5% 的必要資訊（這一格所在的列與總體值對不上，見程式驗證）；τ²-bench 附錄寫明 airline 的 critical error 以漏掉限制條件為主，retail 則是提早結束與漏掉限制並列 [arXiv:2510.06552][arXiv:2506.07982]。卡在沒有量具：精讀時指出 2403.16416 沒寫洩漏怎麼判定，撰寫時逐句人讀全文所有含 leak 的句子，沒有一句描述判定程序；也沒有任何指標同時量「給了多少必要資訊」與「任務在這些資訊下是否可解」[arXiv:2403.16416][arXiv:2510.06552]。
5. **誰有權結束一集，長程互動會不會脫稿。** 提早結束反覆出現：ICL 模擬器被系統的 bye 騙到而收掉對話，τ²-bench 的 telecom 錯誤全是提早輸出 ###TRANSFER### [arXiv:2306.00774][arXiv:2506.07982]。精讀時建議把轉接改成「偵測到轉接工具被呼叫才結束」，但本章論文中沒有一篇做過這個消融 [arXiv:2506.07982]。卡在：代表目標達成的 ###STOP### 若改由環境判定，就得先知道目標何時達成，而那正是評估要量的東西（撰寫時的推論）[arXiv:2506.07982]。長程一致性也沒解：RecAgent 的可信度到第 15 回合全部跌破 4 分，UserLM-8b 需要四道生成護欄才能用，而護欄本身會改變被評估的模擬器 [arXiv:2306.02552][arXiv:2510.06552]。
6. **在真實使用者身上閉合回饋迴路，並配上獨立的結果指標。** 在本章計入的論文裡，只有 Alexa 在真實使用者身上閉合了迴路並做 A/B，但標籤、過濾與結果指標都來自同一個 friction 模型；精讀時還指出改寫上線後使用者不再改述，證據會自我遮蔽 [arXiv:1911.02557]。BB3 有真實使用者，卻沒把回饋接回訓練 [arXiv:2208.03188]。卡在：要有一個不被訓練訊號定義的結果量測，例如使用者自評或留存，又要能在營運中取得，本章計入的論文沒有一篇同時做到 [arXiv:1911.02557][arXiv:2208.03188]。依標題可以檢驗這一句的未讀論文，見「已知缺口與未讀」第 5 條。
7. **稀疏、自願、帶方向的回饋下，回饋類型與演算法怎麼排，滿意度估計準不準。** FITS 的排序建立在每輪全覆蓋的付費回饋上，而 BB3 真實部署的按讚只有 4.0% [arXiv:2208.03270][arXiv:2208.03188]。滿意度估計也缺金標準：USS 的標籤是第三方推定的，英文四個語料的最佳 UAR 只比五類隨機的約 0.2 高約 4 到 9 個百分點，JDDC 最佳也只有 0.339；self-feeding 的分類器只辨認得出不滿；精讀時指出 on-line GP 的雜訊模型假設對稱，使用者的錯誤卻偏向回報成功 [arXiv:2105.03748][arXiv:1901.05415][arXiv:1605.07669]。卡在：缺一份同時有真實稀疏回饋、可控標註成本與使用者自評的資料，而正面訊號又讀不出來，只能當成「沒有負面」[arXiv:1901.05415][arXiv:1911.02557]。依標題專做滿意度估計的未讀論文，見「已知缺口與未讀」第 4 條。
8. **拿 LLM 模擬使用者產生回饋或分數時，換成真人後還剩多少。** 在原版 τ-Bench retail 上只換使用者 LLM 就差 8.9 個百分點，四個模型中只有 GPT-4o 在 18 題子集上和真人校準過，其餘三個沒有；作者也說分不出 Sonnet 4.5 當使用者時分數最高是能力提升還是資料污染 [arXiv:2601.17087]。τ²-bench 只用 gpt-4.1 當使用者，精讀時發現沒做換模擬器的敏感度分析，而廠商回報分數時又自行改了使用者提示詞 [arXiv:2506.07982]。CIPHER 的模擬使用者與學習者都是 GPT-4，人類教學那篇的回饋來自持有真實目標的模擬器，兩篇都沒有把學習迴圈放到真人身上重跑（精讀時指出）[arXiv:2404.15269][arXiv:1804.06512]。卡在：每換一個模擬器模型都要重做一次真人校準，成本與前一題相同 [arXiv:2601.17087]。

## 已知缺口與未讀

這一輪依審稿補缺口時沒有讀任何新論文。下列未讀論文只依標題說明它們可能補的區塊，本章沒有引用它們的任何數字、結果或結論。每一條寫三件事：缺了什麼、哪些結論因此只在本章語料內成立、哪些未讀論文可以補。正文對應的句子已經收窄成「在本章計入的論文裡」。

1. **經典模擬器的源頭與常用對照組。**
   - 缺了什麼：ABUS 是 NUS、GenTUS 與 ICL 模擬器那篇共同的對照組，出自 Schatzmann 等人 2007 年的工作；它不在 arXiv 上，本章沒有收 [arXiv:1805.06966][arXiv:2208.10817][arXiv:2306.00774]。GenTUS 的直接前作 TUS、NUS 自述受其啟發的 seq2seq 模擬器也都沒有讀 [arXiv:2208.10817][arXiv:1805.06966]。這條線的名單配額是 6，只計入 5 篇。
   - 只在本章語料內成立的結論：演進一節把「從語料學出的 seq2seq」這一步掛在 NUS 名下；評估一節「做過多系統模擬與真人對照的是這幾篇」；未解問題 1 與 3 的現況描述。
   - 可以補的未讀論文：A Sequence-to-Sequence Model for User Simulation in Spoken Dialogue Systems（arXiv 1607.00070，未讀）；Domain-independent User Simulation with Transformers for Task-oriented Dialogue Systems（arXiv 2106.08838，未讀）；依標題研究任務型對話使用者建模的 User Modeling for Task Oriented Dialogues（arXiv 1811.04369，未讀）；依標題研究怎麼建出用來訓練 RL 對話策略的模擬器的 How to Build User Simulators to Train RL-based Dialog Systems（arXiv 1909.01388，未讀），它可以檢驗「沒有一篇把模擬器的直接指標和真人下游放在一起分析」這一句。
2. **以模擬使用者評估 CRS 的前作。**
   - 缺了什麼：iEvaLM 在引言把 Zhang 與 Balog 在 2020 年的工作歸為既有的模擬評估方法，本章沒有讀它 [arXiv:2305.13112]。
   - 只在本章語料內成立的結論：LLM 使用者模擬器一節讓「以模擬使用者評 CRS」這條線從 iEvaLM 開始；爭議一節對「名次能不能保住」的綜合判斷；未解問題 1 的現況描述。
   - 可以補的未讀論文：Evaluating Conversational Recommender Systems via User Simulation（arXiv 2006.08732，未讀），依標題研究以模擬使用者評估 CRS。
3. **以 LLM 模擬使用者訓練對話 agent。**
   - 缺了什麼：本章計入的 10 篇 LLM 模擬器論文沒有一篇把模擬器用在訓練；其他節點讀過的幾篇整理在 LLM 使用者模擬器一節的開頭 [arXiv:2403.19154][arXiv:2502.00640][arXiv:2410.13788]。
   - 只在本章語料內成立的結論：三條線的交會一節「LLM 模擬使用者被放進對話 agent 學習迴圈的只有 CIPHER」；LLM 使用者模擬器一節開頭對「訓練用」那一半的整理。
   - 可以補的未讀論文：PlatoLM: Teaching LLMs in Multi-Round Dialogue via a User Simulator（arXiv 2308.11534，未讀）與 Unlocking the Potential of User Feedback: Leveraging Large Language Model as User Simulator to Enhance Dialogue System（arXiv 2306.09821，未讀），依標題都以使用者模擬器改進對話模型。
4. **滿意度估計。**
   - 缺了什麼：以滿意度估計為主題的只有 USS 一篇，self-feeding 的分類器、MetaSim 的滿意度 slot、BB3 的讚與倒讚都是副產品；LLM 時代的滿意度估計完全沒有涵蓋 [arXiv:2105.03748][arXiv:1901.05415][arXiv:2204.00763][arXiv:2208.03188]。
   - 只在本章語料內成立的結論：「滿意度估計：標籤、指標與基準率並排」一節的判斷，以及未解問題 7。
   - 可以補的未讀論文：User Satisfaction Estimation with Sequential Dialogue Act Modeling in Goal-oriented Conversational Systems（arXiv 2202.02912，未讀）；Interpretable User Satisfaction Estimation for Conversational Systems with Large Language Models（arXiv 2403.12388，未讀）。後者在候補名單上附有產品採納的說法，沒有核實，本章不寫進商用採納一節。
5. **在真實使用者身上閉合回饋迴路。**
   - 缺了什麼：本章計入的論文裡，真實使用者只到 2022 年的 BB3，閉合迴路的只有 Alexa [arXiv:2208.03188][arXiv:1911.02557]。
   - 只在本章語料內成立的結論：回饋迴路一節的「誰扮演使用者」與「真實使用者停在 BB3」；「持續學習實際閉合了幾次」一節；未解問題 6。
   - 可以補的未讀論文：Rewarding Chatbots for Real-World Engagement with Millions of Users（arXiv 2303.06135，未讀）；Improving Open Language Models by Learning from Organic Interactions（arXiv 2306.04707，未讀）；Deploying Lifelong Open-Domain Dialogue Learning（arXiv 2008.08076，未讀），FITS 在相關研究中提過它的做法 [arXiv:2208.03270]；一篇標題為 Leveraging Implicit Feedback from Deployment Data in Dialogue 的論文（未讀，不在本輪可以列出 ID 的名單內）；候補中的 When Life Gives You Lemons, Make Cherryade: Converting Feedback from Bad Responses into Good Labels（arXiv 2210.15893，未讀）與 A scalable framework for learning from implicit user feedback to improve natural language understanding in large-scale conversational AI systems（arXiv 2010.12251，未讀）。依標題，這幾篇都處理部署中的回饋或隱式訊號，可以檢驗「本章計入的論文沒有一篇同時做到」這一句。
6. **從對話中的文字回饋學習的源頭。**
   - 缺了什麼：self-feeding 在相關研究中說，部署時從對話主動學習先在 QA 情境下由 Weston 與 Li 等人探討過，它把這個想法延伸到閒聊 [arXiv:1901.05415]；這兩篇本章都沒有讀。
   - 只在本章語料內成立的結論：回饋迴路一節的時間線從 On-line GP 直接接到人類教學那篇，「以文字回饋學習」這一支的源頭缺席。
   - 可以補的未讀論文：Dialog-based Language Learning（arXiv 1604.06045，未讀）；Dialogue Learning With Human-In-The-Loop（arXiv 1611.09823，未讀）。
7. **LLM 扮演人群：社會科學這條線與它的反方。**
   - 缺了什麼：本章只讀了 TE 與 OOOM 兩篇 [arXiv:2208.10264][arXiv:2209.06899]。
   - 只在本章語料內成立的結論：OOOM 段與「關聯指標蓋得住邊際失真」對 algorithmic fidelity 的質疑；Lost in Simulation 段的方言差異放在這條線上的位置。
   - 可以補的未讀論文：Large language models that replace human participants can harmfully misportray and flatten identity groups（arXiv 2402.01908，未讀），依標題研究以 LLM 取代人類受試者時對身分群體的錯誤描繪與壓平；Large Language Models as Simulated Economic Agents: What Can We Learn from Homo Silicus?（arXiv 2301.07543，未讀）；Whose Opinions Do Language Models Reflect?（arXiv 2303.17548，未讀），依標題研究語言模型反映的是誰的意見；候補中的 LLM Agents Grounded in Self-Reports Enable General-Purpose Simulation of Individuals（arXiv 2411.10109，未讀）。
8. **過度配合與諂媚。**
   - 缺了什麼：三條線的交會一節歸納的「過度配合」，只來自模擬使用者與角色扮演的論文 [arXiv:2310.11667][arXiv:2510.06552][arXiv:2601.17087]。
   - 只在本章語料內成立的結論：那一條歸納本身。
   - 可以補的未讀論文：Towards Understanding Sycophancy in Language Models（arXiv 2310.13548，未讀），依標題研究語言模型的諂媚。
9. **模糊問題的選擇性澄清。**
   - 缺了什麼：本章計入的論文沒有一篇以澄清為主題；「教模型主動澄清」這類工作，本章只透過其他節點讀過、以 LLM 模擬使用者訓練提問或澄清的論文間接處理 [arXiv:2410.13788][arXiv:2403.19154][arXiv:2402.09205]。
