# 01｜Goal Alignment & Intent Detection（目標對齊與意圖偵測）

## 這一章回答什麼

本章處理對話 agent 怎麼判斷使用者要什麼，分四塊：把一句話對到預先定義的意圖（含聯合 intent/slot 與 out-of-scope／OOD 拒識）；LLM 時代的 zero-shot 意圖與依意圖路由；指令模糊或不完整時，何時該問、該問什麼；推斷使用者真正的目標與偏好。對齊人類價值的 RLHF 類研究，只有直接處理「對齊某位使用者當下的目標」時才收；一般文本分類不收。計入的論文依子領域分佈如下：傳統意圖偵測、聯合 intent/slot 與 OOD 意圖 7 篇（配額 7）；LLM 時代的意圖理解、zero-shot 意圖與意圖路由 3 篇（配額 5，另兩篇精讀後判為低價值，只當脈絡或反例）；模糊指令與澄清提問 7 篇（配額 7）；使用者目標推斷與偏好引出 5 篇（配額 5）。合計計入 7＋3＋7＋5＝22 篇，連同那兩篇共精讀 7＋3＋7＋5＋2＝24 篇，另有 10 篇候補未讀。LLM 意圖路由這一塊只計入 3 篇，證據最薄，本章對它的結論也最保留。

## 問題的演進

歸屬的寫法分三層。只附 [arXiv:ID] 的句子，是論文自己的主張或表格數字。寫「精讀時發現」「精讀時推算」「精讀時依公開 repo／公開資料」的，是精讀筆記 limitations_observed 裡精讀 agent 自己的分析，不是論文的結論，也沒有經過同儕審查。寫「本章重算」「本章歸納」的，是組章時用論文報告的數字自行算出或串起來的結果，算式寫在句子裡。

四個子領域表面上各做各的，其實都在回答同一串問題：這句話對到哪個目標？這句話在不在我能做的範圍？資訊不夠時要不要問、問什麼？使用者真正要的是什麼？下面先依子領域各自串成一條線，最後一小節把跨子領域的傳承接起來。

### 傳統意圖偵測、聯合 intent/slot 與 OOD 意圖（2016–2021）

這七篇是 LLM 之前「把一句話對到一個預先定義的目標」的路線，年份取自 arXiv 編號的前兩碼。本章歸納，整條線依序處理了四件事：先做到準（封閉集合的聯合 intent/slot），再把表示做到夠用（組合式意圖），接著讓系統會說「這不在我能做的範圍」（out-of-scope／OOD），最後把成本壓到 few-shot 冷啟動也做得起來。

**2016：封閉集合的聯合 intent/slot。** Liu & Lane 讓意圖分類與 slot 標註共用同一個雙向 LSTM 編碼器，各接一個輸出頭，兩個損失一起回傳 [arXiv:1609.01454]。這解決了過去兩個任務分開訓練、分開部署，而既有聯合模型又不如單任務模型的問題 [arXiv:1609.01454]。在 ATIS 上，聯合版 Attention BiRNN 的 slot F1 是 95.98、意圖錯誤率 1.79%；encoder-decoder 版是 95.87 與 1.57% [arXiv:1609.01454]。論文自己的消融顯示，slot 頭一定要吃與當前字對齊的編碼器狀態；不給對齊、只靠 attention 學對齊時，slot F1 只有 81.64 [arXiv:1609.01454]。標題強調的 attention 本身貢獻很小，學到的權重多半接近平均分散 [arXiv:1609.01454]。它留下的是一個封閉集合、單標籤 softmax 的分類器：每句話都一定輸出 18 類中的一類，沒有拒答，也不看對話歷史 [arXiv:1609.01454]。

**2018：兩條岔路，表示力與新意圖。**

- **表示力：意圖可以巢狀。** TOP 指出，flat 的「一個意圖加一串 slot 標籤」描述不了組合式請求，例如先查出活動地點、再拿來當導航目的地 [arXiv:1810.07942]。作者人工檢查 100 筆樣本，約三成需要巢狀表示 [arXiv:1810.07942]。解法是讓 slot 底下可以再掛一個子意圖，整句變成一棵類似句法樹的結構，再直接用 RNNG 解析；exact match 78.51，勝過 CNN、LSTM、Transformer 三種 seq2seq（75.87／75.31／72.20）[arXiv:1810.07942]。精讀時發現它留下兩個缺口：沒有 flat 聯合模型當基線，所以不知道在占多數的非組合語句上改用樹會不會掉準確率；也沒有 OOD 偵測，9.14% 標成 unsupported 的語句在標籤空間裡怎麼處理沒有交代 [arXiv:1810.07942]。
- **新意圖：不必重新標註。** IntentCapsNet-ZSL 處理「新技能上線時沒有任何標註語句」的問題 [arXiv:1809.00385]。做法是把測試語句對既有意圖跑出的路由投票，依新意圖與既有意圖標籤名稱的詞向量相似度加權混合，當成新意圖的預測 [arXiv:1809.00385]。zero-shot accuracy 在 SNIPS-NLU（2 個新意圖）是 0.7752，在中文商用語料 CVA（20 個新意圖）是 0.8628，都勝過相容性映射式的基線 [arXiv:1809.00385]。精讀時發現，它評估的是傳統 ZSL：argmax 只在新意圖集合上取，測試集只含新意圖語句，沒有既有與新意圖混合的設定，也沒有「都不是」的選項 [arXiv:1809.00385]。

**2019：預訓練取代結構設計，拒識變成可量測的任務。**

- **Joint BERT。** 它把 2016 年那套 RNN 編碼器換成 BERT-Base：[CLS] 判意圖，每個詞的第一個 sub-token 標 slot，兩個交叉熵相加後端到端微調 [arXiv:1902.10909]。它要補的是 RNN 類模型沒有利用大規模預訓練、對罕見實體泛化差的問題 [arXiv:1902.10909]。Snips 上 intent／slot F1／整句框架準確率為 98.6／97.0／92.8，ATIS 上為 97.5／96.1／88.2 [arXiv:1902.10909]。Snips 上的增益主要在 slot 與整句框架準確率；intent 在 slot-gated 基線已有 97.0，接近天花板 [arXiv:1902.10909]。它仍是封閉集合、單輪、無拒答 [arXiv:1902.10909]。
- **CLINC150。** 同年 Larson 等人指出，當時公開的意圖資料集都假設每筆查詢必屬某個標籤；拿其他資料集當 OOD 的做法，產生的 OOD 又和真實使用者說的話差太多 [arXiv:1909.02027]。他們用與 in-scope 相同的群眾外包流程另外收集 OOS 查詢，建出 150 個意圖、22,500 筆 in-scope 加 1,200 筆 OOS 的資料集，並把評估拆成 in-scope 準確率與 OOS recall 兩個指標 [arXiv:1909.02027]。結果很清楚：BERT 的 in-scope 準確率可到 96.9，但所有方法的 OOS recall 最好只有 66.0，而且最佳者是 Rasa 而不是 BERT [arXiv:1909.02027]。它把「意圖偵測必須包含拒識」正式化，但只提供三種弱基線（多一類、機率門檻、兩階段二元閘門），也只在單一操作點上報數字 [arXiv:1909.02027]。

**2020：把成本壓下來。** Casanueva 等人針對「新領域每個意圖只有少量標註、微調整個 BERT 太貴又容易過擬合」的問題，改用凍結的對話式 dual encoder（USE、ConveRT 或兩者串接）產生句向量，上面只訓練一個單隱藏層 MLP [arXiv:2003.04807]。每個意圖只有 10 筆時，它在三個資料集上都略勝完整微調的 BERT-Large（banking77 為 85.19 對 83.42）[arXiv:2003.04807]。在筆電 CPU 上，banking77 10-shot 從訓練到評估約一分鐘 [arXiv:2003.04807]。同一篇釋出單領域、77 個細粒度意圖的 banking77，補上既有基準都是跨領域粗粒度意圖的缺口 [arXiv:2003.04807]。它又退回封閉集合，作者把 out-of-scope 預測列為未來工作 [arXiv:2003.04807]。

**2021：不需 OOD 訓練資料的事後拒識分數。** Podolskiy 等人接上 CLINC150 留下的拒識缺口，而且拿掉「要另外收集 OOS 訓練資料」這個昂貴前提 [arXiv:2101.03778][arXiv:1909.02027]。做法是先用 ID 意圖正常微調 RoBERTa，再把測試語句到最近類別中心的 Mahalanobis 距離當 OOD 分數 [arXiv:2101.03778]。CLINC150 上 AUROC 98.4、FPR@95_OOD 6.8；同一個 RoBERTa 改用 MSP 時是 97.1 與 11.6；先前對話資料上的 SOTA LLR 是 91.4 與 37.0 [arXiv:2101.03778]。它留下的是作者自己點名的最大難題：語意上貼近某個已支援意圖的 OOD 語句會被誤收，例如系統只支援傳簡訊，使用者卻要讀簡訊 [arXiv:2101.03778]。

### LLM 時代的意圖理解、zero-shot 意圖與意圖路由（2020–2023）

這一組精讀五篇，計入的是 [arXiv:2010.05256][arXiv:2305.07157][arXiv:2310.10176]；標 📖 的 [arXiv:2008.06239][arXiv:2304.04256] 精讀後判為低價值、不計入，下文只拿來當脈絡或反例，沒有任何主張只靠它們撐。本章歸納，五篇沿著三條線推進：標籤從「索引」變成「語意」；意圖集合從封閉走向開放；一句話從單一意圖走向多意圖。

**2020-08，GPT-2 priming（📖，脈絡）。** 這篇不更新參數，只在前綴塞範例，並把 SNIPS 的 7 類意圖拆成「每類一個前綴、續寫 true／false」的逐類二元判斷 [arXiv:2008.06239]。10-shot 時 gpt2-xl 準確率 73.0%；1-shot 三個尺寸都只有 13.4%–17.0%，落在 7 類隨機猜的約 14.3% 附近 [arXiv:2008.06239]。作者說直接生成類別名在 GPT-2 上很差，才改用逐類二元，代價是 n 類要 n 次前向 [arXiv:2008.06239]。精讀時查官方 repo 發現，「全部判 false」會落到預設的第 0 類，本來可以當 out-of-scope 訊號的資訊被吞掉 [arXiv:2008.06239]。

**2020-10，few-shot 多意圖偵測（前 LLM 時代的平行線）。** [arXiv:2010.05256] 處理的是單意圖假設之外的情況：一句話帶多個意圖，新領域只有 1～5 個範例。這時固定門檻無從調；而且兩個意圖若只出現在同一句支援句，prototypical network 算出的兩個原型會完全相同 [arXiv:2010.05256]。解法有兩塊。ALR 把 label name 嵌入當錨點，c̃＝β·E(label)＋(1−β)·原型；MCT 是動態門檻，先用 max／min 分數內插出元門檻，再以 Kernel Regression 依支援句的標籤數校正，最終門檻 t＝0.3·t_meta＋0.7·t_est [arXiv:2010.05256]。它把 label name 的語意明確寫進意圖表示，用來分開共用支援句的意圖 [arXiv:2010.05256]。精讀時發現它留下兩個缺口：門檻在結構上不會輸出空集合，所以完全不處理 out-of-scope；TourSG 六個領域共用相近的對話行為標籤，ALR 的增益有很大一部分可能來自標籤重疊 [arXiv:2010.05256]。

**2023-04，ChatGPT 封閉清單 zero-shot（📖，脈絡）。** 這篇把意圖清單與槽位 schema 列進提示，要 ChatGPT 直接輸出意圖名，再用樣板解析 [arXiv:2304.04256]。這正是 GPT-2 那篇因效果差而放棄的「直接生成標籤」做法 [arXiv:2008.06239][arXiv:2304.04256]。SNIPS 意圖準確率 97.71（微調 SoTA 98.80），ATIS 只有 75.22，低於 GPT-3.5 的 90.03 [arXiv:2304.04256]。兩篇 📖 的 SNIPS 數字不能讀成進步幅度：前者是 GPT-2 的 10-shot 範例 priming；後者不給標註語句，但精讀時發現它的提示附了槽位範例值 [arXiv:2008.06239][arXiv:2304.04256]。它留下的是封閉清單、沒有拒答選項，以及未量化的格式違規，例如輸出未定義值或改用長篇自然語言回覆 [arXiv:2304.04256]。

**2023-05，描述式 zero-shot、檢索過濾與 PEFT。** [arXiv:2305.07157] 面對的是工業約束：數千個客戶各自一個意圖模型，冷啟動沒有語料，法規不允許跨客戶混用資料。它往前推了四步 [arXiv:2305.07157]：

- 把「只列意圖名」換成「意圖名＋一句自然語言描述」[arXiv:2305.07157]。
- 在同一個提示裡加 none_of_the_above 選項，把 OOS 偵測併進分類 [arXiv:2305.07157]。
- 意圖太多時，先用句向量檢索 top-5 候選意圖，再交給 LLM，壓低提示長度與成本 [arXiv:2305.07157]。
- 用 Flan-T5＋IA3（T-Few 配方）做參數高效微調 [arXiv:2305.07157]。

全意圖 zero-shot 時，Flan-T5-XXL／GPT-3 在 MASSIVE 是 73.3／73.9，在 B01 是 86.5／89.3 [arXiv:2305.07157]。作者主張 Flan-T5-XL（3B）的 PEFT 在每意圖 1 例時就勝過所有其他方法，但只有圖、沒有數值 [arXiv:2305.07157]。精讀時發現它留下三個缺口：OOS 只在 zero-shot 實驗評，而且只報 recall；意圖描述由作者手寫，沒有開發集；5 個資料集裡有 4 個是私有資料 [arXiv:2305.07157]。

**2023-10，開放世界意圖發現與擴充。** [arXiv:2310.10176] 拿掉封閉集合假設，任務分兩件：把未知意圖（OOD）的查詢分群；以及 GID，也就是把新意圖併入既有意圖集後做聯合分類 [arXiv:2310.10176]。它延續「標籤是語意」這條線：生成式 LLM 分類要靠意圖的語意，而不是抽象的偽標籤編號，所以第一階段讓 ChatGPT 替每群寫出自然語言的 pseudo-intent，第二階段再逐筆分類 [arXiv:2310.10176]。沒有 IND 先驗時，ChatGPT 直接分群在三種切分的 ACC 是 88.00／78.00／58.22，未微調 BERT＋k-means 是 52.00／36.00／29.33 [arXiv:2310.10176]。但在 GID 上，最佳 ChatGPT 方法三種切分平均落後最佳微調方法 17.37（IND ACC）、20.56（OOD ACC）、23.40（ALL ACC）[arXiv:2310.10176]。它假設 OOD 句子已事先挑出、群數已知，一次能分群的量也受上下文長度限制 [arXiv:2310.10176]。精讀時還發現，模型「拒絕歸類」的回答會被強制隨機指派，所以 LLM 做 OOD 偵測的能力根本沒量到 [arXiv:2310.10176]。

合起來看（本章歸納），標籤的語意載體從 label name 嵌入 [arXiv:2010.05256]，走到手寫描述 [arXiv:2305.07157]，再走到 LLM 自己生成的 pseudo-intent [arXiv:2310.10176]。意圖集合從封閉清單，走到「清單加 none 選項」[arXiv:2305.07157]，再走到自動發現新意圖 [arXiv:2310.10176]。但精讀時發現，這組五篇對「這句話不屬於任何已知意圖」的處理，不是缺席，就是只量一邊 [arXiv:2008.06239][arXiv:2010.05256][arXiv:2304.04256][arXiv:2305.07157][arXiv:2310.10176]。

### 模糊指令與澄清提問（2018–2024）

這七篇都處理「使用者的請求缺資訊或有多種解讀時，系統該怎麼問」。本章歸納，依時間排開，重點從「在候選問題中挑一題」逐步移到「何時該問」，再移到「用訓練教模型問」。

**2018：以期望效用替候選問題排序。** EVPI 把「該問哪一題」寫成決策問題：問題 q_i 的價值，是對所有可能答案加總「得到該答案的機率 × 補上答案後貼文的效用」，兩者都用神經網路估計、聯合訓練 [arXiv:1805.04655]。它補上的缺口是：當時的問題生成研究以閱讀理解題為主，社群問答排序只看相關性，都沒處理「問題的價值取決於它引出的答案」[arXiv:1805.04655]。作者從 StackExchange 三個站台的編輯歷史建出 77,097 筆（貼文, 澄清問題, 答案），另有 500 筆專家標註的評估集 [arXiv:1805.04655]。它的候選題只能從 Lucene 檢索到的 10 篇相似貼文借用，每篇只看第一個澄清問題，資料也只收「被問之後有編輯」的貼文，所以模型從不判斷要不要問 [arXiv:1805.04655]。

**2019：把澄清搬進開放領域檢索，建立離線評估協定。** Qulac 用 TREC Web Track 2009–2012 的 facet 代表使用者的真實意圖，一個 facet 視為一位使用者；每個 (topic, facet, question) 群眾外包一個答案，組成可查表的答案函數，藉此離線評估「問完之後檢索變好多少」[arXiv:1907.06554]。規模是 198 個主題、762 個 facet、2,639 題、10,277 組問答 [arXiv:1907.06554]。系統分三段：BERT-LeaQuR 召回候選題，NeuQS 依查詢與對話歷史選下一題，再以加入問答的查詢語言模型重新檢索 [arXiv:1907.06554]。oracle 分析顯示問對一題能大幅提升 P@1，而且查詢越短、越模糊，受益越多 [arXiv:1907.06554]。但架構圖裡「是否呈現結果」的信心判斷沒有實作，回合數固定，系統永遠會問 [arXiv:1907.06554]。

**2020：把「何時問」獨立成一個子任務。** ConvAI3 的 ClariQ 仿照 Qulac 重新群眾外包對話形式的資料，並替每個使用者請求加上 1–4 的澄清必要性標籤，把澄清拆成「何時問」與「問什麼」兩個可以各自評分的任務 [arXiv:2009.11352][arXiv:1907.06554]。主題除了 faceted 與 ambiguous，另外加了 39 個 single 主題 [arXiv:2009.11352]。但 v1 只是競賽規格，沒有任何實驗結果；論文本文也沒給「何時問」任務的指標，第二階段的真人評估只是計劃 [arXiv:2009.11352]。

**2023：LLM 的澄清能力評估與提示法。** ProCoT 把 LLM 時代的澄清分成 CNP（Clarification Need Prediction，何時問）與 CQG（Clarification Question Generation，問什麼）[arXiv:2305.13626]。它發現 gpt-3.5-turbo-0301 與 Vicuna-13B 在只要求生成回應的 Standard 提示下，兩個澄清資料集上的人工 Help. 分數全為 0.0 [arXiv:2305.13626]。ProCoT 要求模型先寫模糊性分析，再選「回答」或「澄清」；它讓 ChatGPT 在一般領域的 Abg-CoQA 上 CNP F1 達到 27.9（one-shot），高於微調 SOTA 的 23.6 [arXiv:2305.13626]。但在金融領域的 PACIFIC 上，LLM 最佳 CNP F1 只有 28.0，SOTA 是 86.9 [arXiv:2305.13626]。評估是離線單回合，澄清問題問出去之後沒有使用者回答 [arXiv:2305.13626]。

**2023：把「何時問」形式化為不確定性排序。** Clarify When Necessary 把流程拆成三個依序的子任務：何時問、問什麼、拿到回答後怎麼答 [arXiv:2311.09469]。「何時問」被定義成給每個輸入一個純量，這個純量要與「澄清後表現會提升多少」相關，而不是與「現在會不會答錯」相關；目的是把意圖模糊造成的 aleatoric 不確定性，與缺知識造成的 epistemic 不確定性分開 [arXiv:2311.09469]。評估用兩種指標：只准對 b% 的輸入發問時的端任務表現，以及預測「澄清會不會讓這題變好」的 AUROC [arXiv:2311.09469]。作者提出的 Intent-Sim 讓模型自問一題、取樣 10 個模擬使用者回答、以 NLI 分群後算意圖熵 [arXiv:2311.09469]。「問什麼」則交給握有 gold 解讀的 GPT-3.5 oracle 固定下來，所以本篇只量第一與第三子任務 [arXiv:2311.09469]。

**2024：用自我改進訓練「問什麼」。** STaR-GATE 讓 Mistral-7B 對握有隱藏 persona 的 LLM 使用者模擬器提問，以「引出的對話能讓 GPT-4 所寫 gold 回應的 log-prob 變多高」為分數，每組只留最高分的一段對話做 SFT，反覆三輪 [arXiv:2403.19154]。它發現只訓練提問會讓模型忘了作答，因此加上以前一輪自己的回應做 SFT 的 response regularization [arXiv:2403.19154]。它不需要人工提問示範 [arXiv:2403.19154]。但精讀時指出，輪數由外部在 1 到 3 之間抽樣，提示詞強制每輪都要提問，所以它也不處理「何時問」[arXiv:2403.19154]。

**2024（ICLR 2025）：用模擬的未來輪次同時教「問什麼」與「何時問」。** 這是 Clarify When Necessary 同一組作者的後續工作：把資料集裡多位標註者給出的不同答案，當成 k 位意圖不同的模擬使用者，讓他們各自回答同一個澄清問題，再以第 4 輪答案的 EM 平均替候選回應排序，轉成 DPO 偏好 [arXiv:2410.13788][arXiv:2311.09469]。澄清問題與直接回答放在同一把尺上比，平手時偏向直接回答，藉此懲罰不必要的提問 [arXiv:2410.13788]。它把 STaR-GATE 式的似然給分列為對照組之一，也把 ProCoT 當作「何時問」的基線 [arXiv:2410.13788][arXiv:2403.19154][arXiv:2305.13626]。以 Match 給分的 DPO，在三個基底模型上 All F1 比單輪 reward model 標註高 4.4–5.6 [arXiv:2410.13788]。

**這組的共同判準（本章歸納）。** 七篇幾乎都用「使用者回答之後的下游結果」評估一個問題：EVPI 用補上答案後的效用 [arXiv:1805.04655]；Qulac 與 ClariQ 用檢索改善 [arXiv:1907.06554][arXiv:2009.11352]；Clarify When Necessary 用澄清帶來的增益 [arXiv:2311.09469]；STaR-GATE 用 gold 回應的 log-prob [arXiv:2403.19154]；Future Turns 用多位模擬使用者的 EM 平均 [arXiv:2410.13788]。這個判準讓「問得好不好」變得可量，但分數也因此綁在「回答從哪裡來」上，〈評估方式與關鍵數字〉會逐篇列出回答端的失真。ProCoT 的澄清評估則根本沒有回答者，問題問出去就結束 [arXiv:2305.13626]。「何時問」的處理方式一路在變：先是不處理 [arXiv:1805.04655][arXiv:1907.06554]，接著加上標籤 [arXiv:2009.11352]，再到提示模型做二元判斷 [arXiv:2305.13626]、做不確定性排序 [arXiv:2311.09469]，最後以平手規則在偏好訓練中學 [arXiv:2410.13788]；STaR-GATE 又回到只處理「問什麼」[arXiv:2403.19154]。

### 使用者目標推斷與偏好引出（2023–2025）

這五篇回答的是：使用者一開始說的話不足以決定 agent 該做什麼時，agent 要怎麼把真正的目標或偏好弄清楚 [arXiv:2310.11589][arXiv:2311.05584][arXiv:2402.09205][arXiv:2410.12361][arXiv:2502.00640]。依 arXiv 編號排列，這條線從「用提示讓強模型去問」，走到「用模擬使用者的回饋訓練模型自己學會問」；問題範圍也一路擴大，先是單一領域的偏好判斷，再到 agent 任務的執行前澄清，最後到沒有任何查詢時的主動介入（本章歸納）。下文凡是沒有註明為論文自己定位的承接關係，都是本章依筆記所做的歸納。

**GATE：把「學習」改寫成任務引出。** 這篇把使用者的偏好看成一個待學的函式 [arXiv:2310.11589]。它依「是否互動」與「規格是範例還是自由形式」把既有方法分成四格，指出「互動＋自由形式」這一格還沒有方法 [arXiv:2310.11589]。填補的做法是讓 GPT-4 身兼兩職：當引出者時，生成邊界案例、是非題或開放式問題；當預測器時，讀完整段對話紀錄，對新案例口述 0–1 的機率 [arXiv:2310.11589]。實驗是 388 人的預註冊受試者間設計，每人互動上限 5 分鐘 [arXiv:2310.11589]。GATE 在三個領域都優於「不互動直接預測」，但 email 領域只有生成式主動學習達到 0.05 顯著；它在多數設定下勝過使用者自寫的偏好描述；是非題在每個設定都勝過自寫描述，只是道德推理領域的檢定力不足以判定顯著 [arXiv:2310.11589]。它最有份量的觀察，是使用者高估了自己的描述：提示組看過測試題之後，自評涵蓋度在內容推薦從 5.3 降到 3.9，在道德推理從 5.4 降到 4.8 [arXiv:2310.11589]。「最有資訊量的問題」完全交給 GPT-4 自行判斷，沒有任何資訊增益或不確定性估計，作者自己把顯式不確定性列為未來工作 [arXiv:2310.11589]。精讀時也指出它沒有停止規則，實驗一律固定 5 分鐘 [arXiv:2310.11589]。

**想像對話＋離線 RL：從提示轉向訓練。** 這篇的出發點是：直接提示 LLM 當 agent，它會模仿對話的樣子，卻不為對話的結果最佳化，表現為不問就給冗長答案，或一次丟出整份問卷；標準 RLHF 又只最佳化單輪回覆 [arXiv:2311.05584]。作者把使用者的私有資訊形式化成 hidden-parameter MDP 的隱藏參數 z [arXiv:2311.05584]。流程分三步：GPT-3.5 先列出使用者的 persona；依 persona 與預先抽好的成敗標籤，每個任務「想像」出 50K 段對話，再以準則改寫；最後用 ILQL 在這批合成對話上訓練 GPT-2 [arXiv:2311.05584]。在 50 位 GPT-3.5 模擬使用者的旅遊推薦中，每則發言的 token 數從 118 降到 43，第一個推薦就命中的比例從 18% 升到 44% [arXiv:2311.05584]。精讀時指出 z 從不顯式輸出，隱藏參數空間又小又封閉：教學任務只有 4 種背景，旅遊任務是 5 種 persona × 18 項活動 [arXiv:2311.05584]。作者自承每個任務都要人工撰寫三組專屬提示詞；精讀時補充，每換一個任務也得重新訓練 [arXiv:2311.05584]。

**Tell Me More／IN3：把推斷出的目標寫成顯式的交接物。** 這篇把場景搬到 agent 任務上：AutoGPT、XAgent 這類框架預設指令已經清楚，照著模糊指令執行，就會出現看似完成、實則偏離的「假成功」[arXiv:2402.09205]。它在執行前插入一個上游模組：先判斷任務模糊與否，清楚就原樣放行；模糊就帶著一份缺漏細節清單（標有三級重要性與候選選項），每輪只問一題；最後逐條列出使用者的約束，輸出一到兩句的明確目標 t_user 交給下游 [arXiv:2402.09205]。為此它建了 IN3 基準（訓練 1,261 題、測試 108 題），並把 Mistral-7B 全參數微調成 Mistral-Interact [arXiv:2402.09205]。相對於把使用者目標藏在模型狀態裡的想像對話那篇，這是本組第一個把推斷結果做成可檢查輸出的設計（本章歸納）[arXiv:2311.05584][arXiv:2402.09205]。作者自承只在執行前做意圖理解，執行中的詢問、中斷與授權都不在範圍內 [arXiv:2402.09205]。

**Proactive Agent：沒有查詢時要不要開口。** 這篇明確把 Tell Me More 這類工作歸為另一類：使用者仍要先給初始查詢，模型只在查詢模糊時多問幾句 [arXiv:2410.12361]。它處理的是完全沒有查詢的情況，要從桌面活動事件推斷潛在需求 [arXiv:2410.12361]。每個事件時點的輸出是一個任務或 null；若預測 null、而使用者也確實不需要協助，就算被接受，所以「不打擾」成了可以得分的行為 [arXiv:2410.12361]。使用者的接受判斷由一個 LLaMA-3.1-8B reward model 模擬，它以 1,640 筆人工接受／拒絕標註訓練，另外 120 筆當測試集；agent 的訓練資料則是 GPT-4o 驅動的 gym 合成的 6,790 個事件 [arXiv:2410.12361]。它有一個對評估很重要的副產品：現成 LLM 當評審時，幾乎什麼提議都接受，GPT-4o 在 False-Detection 情境的一致率是 0.00% [arXiv:2410.12361]。作者自承 false alarm 偏高；精讀時依公開 repo 另外發現循環評估的問題，見〈評估方式與關鍵數字〉[arXiv:2410.12361]。

**CollabLLM：用往後模擬的獎勵學「何時問」。** 這篇改寫了每一輪回應的獎勵，稱為 Multiturn-aware Reward（MR）：以帶著隱藏目標的 GPT-4o-mini 使用者模擬器往後模擬 w＝2 輪、取 3 條未來軌跡；每條軌跡依整段對話的任務指標、token 成本與 LLM judge 的互動性評分給分，再取平均；以此為獎勵，用 SFT、DPO、PPO 微調 Llama-3.1-8B-Instruct [arXiv:2502.00640]。論文自己把它與想像對話那篇區隔開：後者用模擬器合成資料來訓練小模型，CollabLLM 則把模擬器用在往後取樣，估計一輪回應的長期效果 [arXiv:2502.00640]。靠這個設計，模型不需要任何「何時該問」的標註就學會澄清 [arXiv:2502.00640]。它另外拿既有基準 Abg-CoQA 做零樣本測試，直接檢驗「模糊才問、清楚就答」[arXiv:2502.00640]。精讀時指出它留下兩個問題：模擬器被明令一開始只給模糊的需求；模型不顯式表示使用者的目標 [arXiv:2502.00640]。

綜合來看（本章歸納），這條線在三個軸上移動。**問什麼**：從強模型自行判斷 [arXiv:2310.11589]，到人工標註的缺漏清單 [arXiv:2402.09205]，再到從模擬結果回推 [arXiv:2311.05584][arXiv:2502.00640]。**何時問、何時停**：從固定的時間預算 [arXiv:2310.11589]，到把「不介入」放進輸出空間 [arXiv:2410.12361]，再到用往後模擬替澄清記功 [arXiv:2502.00640]。**推斷出的目標怎麼表示**：在「隱含於模型狀態」[arXiv:2311.05584][arXiv:2502.00640] 與「顯式交接」[arXiv:2402.09205] 之間擺盪。

### 跨子領域的傳承

下面分兩種寫法：論文自己寫明的引用或沿用，只附出處；概念上的串接則標「本章歸納」。

**論文自述的傳承。**

- **資料集往下游流。** 開放世界那篇的實驗資料是 Casanueva 等人 2020 年的 Banking 與 Larson 等人 2019 年的 CLINC，也就是第一組的 banking77 與 CLINC150 [arXiv:2310.10176][arXiv:2003.04807][arXiv:1909.02027]。
- **澄清與偏好引出直接接上。** STaR-GATE 自述是把 GATE 的主動偏好引出，與 STaR 的自我改進迴圈結合 [arXiv:2403.19154][arXiv:2310.11589]。CollabLLM 在相關工作的比較表裡列了 STaR-GATE，也引用 Clarify When Necessary 與想像對話那篇 [arXiv:2502.00640][arXiv:2403.19154][arXiv:2311.09469][arXiv:2311.05584]。
- **何時問的基線互相引用。** Future Turns 以 ProCoT 當「何時問」的基線，以 STaR-GATE 式似然給分當對照 [arXiv:2410.13788][arXiv:2305.13626][arXiv:2403.19154]。Proactive Agent 把 Tell Me More 這類「有查詢才問」的工作與自己的「無查詢主動介入」分開 [arXiv:2410.12361][arXiv:2402.09205]。
- **同一個基準，不同的量法。** ProCoT 與 CollabLLM 都在 Abg-CoQA 上測「該不該問」，但前者報 CNP F1、後者報兩類動作正確率與 Macro Accuracy，兩邊的數字無法直接對照 [arXiv:2305.13626][arXiv:2502.00640]。Clarify When Necessary 與 Future Turns 都用 AmbigQA，後者是前者作者群的後續工作 [arXiv:2311.09469][arXiv:2410.13788]。

**本章歸納的傳承。**

- **標籤語意的載體。** IntentCapsNet-ZSL 用標籤名稱的詞向量把既有意圖的投票轉給新意圖 [arXiv:1809.00385]；ALR 把 label name 嵌入當原型的錨點 [arXiv:2010.05256]；描述式 zero-shot 改用手寫描述 [arXiv:2305.07157]；開放世界那篇讓 LLM 自己寫 pseudo-intent [arXiv:2310.10176]。這條線裡，意圖從一個索引，變成一段模型讀得懂的文字。
- **「不作為」這個輸出，換了好幾個名字。** 意圖偵測叫它 OOS 拒識 [arXiv:1909.02027][arXiv:2101.03778]，LLM 路由叫它 none_of_the_above [arXiv:2305.07157]，澄清研究叫它「何時問」的反面：不必問、直接答 [arXiv:2009.11352][arXiv:2305.13626][arXiv:2311.09469][arXiv:2410.13788]。目標推斷那組則有 IN3 的「清楚就放行」[arXiv:2402.09205]，以及 Proactive Agent 的 null [arXiv:2410.12361]。四個子領域都要做「這句輸入能不能直接照做」的二元決策，而〈評估方式與關鍵數字〉會看到，它們在量這個決策時犯了同一種錯。
- **目標的表示越來越鬆。** 傳統路線把目標寫成封閉的意圖標籤加 slot [arXiv:1609.01454][arXiv:1902.10909]，TOP 把它寫成可巢狀的樹 [arXiv:1810.07942]。到了目標推斷那組，IN3 的交接物是一到兩句自由文字 t_user [arXiv:2402.09205]，Proactive Agent 的輸出是一句自由文字任務，沒有意圖類別或槽位 [arXiv:2410.12361]，想像對話與 CollabLLM 則完全不顯式表示目標 [arXiv:2311.05584][arXiv:2502.00640]。結構化表示帶來的可檢查性，在 LLM 這一段大多被放掉了。

### 陷阱一：「能不能直接照做」的決策，缺平凡基準或只報單一操作點（本章歸納）

〈問題的演進〉最後說過，四個子領域都在做「這句輸入能不能直接照做」的二元決策。它們量這個決策時犯的是同一種錯：類別比例懸殊，卻不報「一律判多數類」的基準，或只報一個操作點。以下依子領域列出。

- **CLINC150 只報一個操作點。** 它只報 in-scope 準確率與 OOS recall，不報 OOS precision、F1，也不報與門檻無關的 AUROC；理由是把 in-scope 誤判成 OOS 只會觸發 fallback，代價較低 [arXiv:1909.02027]。oos-threshold 的門檻取在驗證集整體準確率最高的值，而驗證集 OOS 只占 100 / (3,000 + 100) ≈ 3.2%，選門檻的目標幾乎由 in-scope 準確率決定 [arXiv:1909.02027]。精讀時據此推論，Rasa 在 Small／Imbalanced 的 OOS recall 1.0／0.0、SVM Imbalanced 的 0.0，可能是這個選取準則的產物，不一定代表模型沒有拒識訊號；論文把這類結果統稱為方法不穩定 [arXiv:1909.02027]。
- **多意圖的「該輸出幾個」與平凡基準打平。** [arXiv:2010.05256] 用「預測的意圖數是否正確」主張 MT 與 KR 有助於決定標籤數，精讀時發現它沒有和「永遠只猜一個意圖」比較 [arXiv:2010.05256]。本章依 Table 1 的多標籤句比例重算：TourSG 的平凡基準＝100−(22.7＋18.2＋16.0＋17.4＋18.1＋16.4)／6＝81.87%，StanfordLU 的平凡基準＝100−(21.3＋24.6＋3.8)／3＝83.43% [arXiv:2010.05256]。完整模型在 Table 6 是 TourSG 82.26／82.05、StanfordLU 80.92／84.70，與平凡基準的差如下（算式把基準展開寫）[arXiv:2010.05256]：
  - TourSG 1-shot：82.26−(100−(22.7＋18.2＋16.0＋17.4＋18.1＋16.4)／6)＝0.39 [arXiv:2010.05256]
  - TourSG 5-shot：82.05−(100−(22.7＋18.2＋16.0＋17.4＋18.1＋16.4)／6)＝0.18 [arXiv:2010.05256]
  - StanfordLU 1-shot：80.92−(100−(21.3＋24.6＋3.8)／3)＝−2.51 [arXiv:2010.05256]
  - StanfordLU 5-shot：84.70−(100−(21.3＋24.6＋3.8)／3)＝1.27 [arXiv:2010.05256]

  這個重算有三個前提：每句至少一個意圖；query 分布近似領域整體；Table 6 和主表的 Ave. 一樣是逐領域簡單平均，但 Table 6 本身沒寫明 [arXiv:2010.05256]。程式驗證證實這四格差距；Table 6 沒註明嵌入器並不影響結論，因為平凡基準只用 Table 1 的資料統計 [arXiv:2010.05256]。程式驗證也指出結論依賴第三個前提：StanfordLU 的 Weather 領域多標籤句只占 3.8%，單領域基準是 100−3.8＝96.2，若 Table 6 其實按 query 數加權，StanfordLU 的比較會大幅擺動；TourSG 則對平均方式不敏感（見〈程式驗證〉）[arXiv:2010.05256]。
- **ProCoT 沒報正類比例。** Abg-CoQA 上的 CNP F1 是 Baseline 22.1、SOTA 23.6、ChatGPT 23.8–27.9 [arXiv:2305.13626]。精讀時指出，論文沒報正類比例，也沒有「全部判為模糊」這類平凡基準，「與 SOTA 相當」的資訊量有限 [arXiv:2305.13626]。
- **Future Turns 的 Ambig Acc 低於多數類。** 它的 Ambig Acc 是 53.7／54.0／54.3（Llama2／Llama3／Gemma）[arXiv:2410.13788]。精讀時依論文數字重算，「一律判為模糊」的多數類基準是 1,172 ÷ 1,960 ≈ 59.8%，三個模型都低於它；前提是 Ambig Acc 的分母為整個測試集，論文沒有明說 [arXiv:2410.13788]。依相同前提，直接回答比例為 p 時，隨機決策的期望準確率是 p × 788/1,960 + (1 − p) × 1,172/1,960（測試集 788 題未模糊、1,172 題模糊）[arXiv:2410.13788]。精讀時只代入了 Llama2 那一格：p 為 44% 時 0.44×788/1,960＋(1−0.44)×1,172/1,960≈51.2%，論文的 Random 是 52.1 [arXiv:2410.13788]。本章另外代入 Llama3 與 Gemma 的 p（43%、38%），得 0.43×788/1,960＋(1−0.43)×1,172/1,960≈51.4%、0.38×788/1,960＋(1−0.38)×1,172/1,960≈52.4%，對上報告的 51.1、52.1；三格都相差不到 1 個百分點 [arXiv:2410.13788]。程式驗證證實上面兩步（見〈程式驗證〉）。這只說明與「分母為全集」的前提相容，不算證明；程式驗證另外發現，balanced accuracy 這種讀法只在 5% 邊界上被排除，而在那種讀法下一律提問只有 (100＋0)/2＝50%，三個模型反而高於它 [arXiv:2410.13788]。
- **IN3 的模糊判斷準確率低於多數類。** IN3 測試集 108 題中有 95 題是模糊題 [arXiv:2402.09205]。精讀時發現，一律判模糊就有 95/108＝87.96%，比 Mistral-Interact 的 92/108＝85.19% 與 GPT-4 的 89/108＝82.41% 都高；程式驗證證實 [arXiv:2402.09205]。本章核算，答對 92 題與「13 題清楚題全部放行」「一題都沒放行」兩種極端都相容，這張表無法說明模型是否學會「何時不該問」；程式驗證算出四個模型的清楚題放行數都可以是 0 到 13 的任一個 [arXiv:2402.09205]。精讀時另外發現，缺漏細節召回率與總結涵蓋率的分母，是各模型自己判為模糊的題目集合，跨模型比的不是同一批題目 [arXiv:2402.09205]。
- **Abg-CoQA 的 Macro Accuracy 有 50% 的地板。** CollabLLM 的論文沒有給 Macro Accuracy 的計算式；本章依 Table 2 核算，三列的值都等於兩類動作正確率的算術平均：GPT-4o (15.44＋95.60)/2＝55.52，Llama (16.26＋90.40)/2＝53.33，CollabLLM (52.84＋72.32)/2＝62.58 [arXiv:2502.00640]。所以「一律提問」和「一律直接回答」都拿 50%，GPT-4o 與 Llama 只略高於這個地板 [arXiv:2502.00640]。換成條件提問率，CollabLLM 在非模糊題也有 100−72.32＝27.68% 會提問，兩類提問率相差 52.84−27.68＝25.16；同一個差距，GPT-4o 是 15.44−(100−95.60)＝11.04，Llama 是 16.26−(100−90.40)＝6.66 [arXiv:2502.00640]。精讀時認為大部分增益來自整體提問門檻的降低，正文卻說它在非模糊題上仍維持高正確率 [arXiv:2502.00640]。
- **Proactive Agent 的 False-Alarm 不帶獨立資訊。** 本章依 Table 3 重算，八列的 Precision＋False-Alarm 都等於 100%，例如 GPT-4o 是 48.15＋51.85，GPT-4o-mini 是 35.28＋64.73＝100.01，差的一點屬於捨入 [arXiv:2410.12361]。Table 4 的 12 列中有 11 列也成立，唯一例外是 LLaMA-3.1-8B w/ RM：42.52＋57.41＝99.93 [arXiv:2410.12361]。精讀時依公開 repo 的評估腳本確認，實作正是 FP/(TP+FP)，而且「需要協助、但任務給錯」也被算成 FP；這與正文把 False-Alarm 描述成「不需要卻提議」不一致 [arXiv:2410.12361]。精讀時也發現，FN 只在「預測 null、且 RM 拒絕 null」時才會出現；Table 3 八列中有七列的 Recall 介於 97.89% 到 100% [arXiv:2410.12361]。Recall 等於 1 時 F1＝2P/(1+P)，是 Precision 的單調函數；本章依 Table 3 核算，這七列的 F1 排名與 Precision 排名完全相同，而最佳 Precision 只有 49.78% [arXiv:2410.12361]。

合起來看（本章歸納），量這個決策時用上與門檻無關量法的只有兩處，都是 AUROC：Mahalanobis 那篇 [arXiv:2101.03778] 與 Clarify When Necessary [arXiv:2311.09469]。CollabLLM 在 Abg-CoQA 上把兩類動作正確率分開報，至少避開了類別比例的問題，但那仍然只是單一操作點，換一個提問傾向數字就會變 [arXiv:2502.00640]。兩個 AUROC 正好可以對照：同樣以 AUROC 量「能不能直接照做」，拒識那一邊在 CLINC150 上是 98.4，「何時問」那一邊只有 0.371–0.628 [arXiv:2101.03778][arXiv:2311.09469]。本章判斷這個落差比較像基準難度不同，而不是方法強弱。一邊是精讀時發現 CLINC150 的 OOS 偏向領域外，近鄰 OOS 沒有被系統性涵蓋 [arXiv:1909.02027]。另一邊的「該不該問」，各篇的標籤定義不一：有的用人工模糊標籤，有的用「澄清後會不會變好」[arXiv:2305.13626][arXiv:2009.11352][arXiv:2311.09469]。

### 陷阱二：測試集小，差距落在雜訊內

- **ATIS 與 Snips 近飽和。** ATIS 測試集 893 句、Snips 700 句 [arXiv:1609.01454][arXiv:1902.10909]。精讀時換算，Liu & Lane 聯合訓練讓意圖錯誤率從 2.02% 降到 1.57%，893 × 2.02% ≈ 18.04，893 × 1.57% ≈ 14.02，只少錯約 4 句；「相對降低 22.2%」放大了這個差距 [arXiv:1609.01454]。Joint BERT 在 Snips 上聯合對分開的 intent 差 0.6 個百分點，700 × 0.6% = 4.2，約 4 句 [arXiv:1902.10909]。
- **1,000 筆 OOS 的抽樣雜訊。** 精讀時依二項分布估計，以 1,000 筆 OOS 估 recall 的 95% 信賴區間約正負 3 個百分點；oos-train Full 下 MLP 47.4 對 Rasa 45.3 這類名次差距落在雜訊內，每個設定也都只跑一次 [arXiv:1909.02027]。
- **開放世界分群一次只分幾十句。** OOD 發現一次只分群 25／50／75 句，跑 3 次取平均 [arXiv:2310.10176]。本章依論文表格重算：1:1 時每次 75 句、跑 3 次，DC ACC 58.22 對應 75 × 3 × 58.22% ≈ 131 句答對，恰好是整數 [arXiv:2310.10176]。所以一句約 100／(75 × 3)≈0.44 個百分點 [arXiv:2310.10176]。精讀時發現，3:1 時 DeepAligned 的 ACC／NMI／ARI 全是 100.0，實際只是 25 句全對；3 次執行、又沒報標準差，撐不起表頭的 p < 0.01 [arXiv:2310.10176]。
- **私有基準很小。** [arXiv:2305.07157] 的 B01、B02 測試集分別只有 300、420 句（含 OOS），精讀時推算 in-scope accuracy 的一個百分點不到 3–4 句 [arXiv:2305.07157]。
- **澄清與目標推斷的評估集也小。** EVPI 評估集只有 500 筆；以原題為正解時，EVPI 與 Neural(p,q,a) 的 p@1 只差 21.4 − 20.5 = 0.9 點，約 0.9% × 500 ≈ 4.5 篇 [arXiv:1805.04655]。Proactive Agent 的 Qwen2-7B-Proactive 對 GPT-4o 的 F1 差 66.47−64.60＝1.87 個百分點；精讀時以 Precision 約 50%、約 233 個事件估算二項標準誤約 3.3 個百分點，而 Precision 的分母只含有提議的事件，實際標準誤只會更大（本章補充）[arXiv:2410.12361]。想像對話那篇的 final success 是 82% 對 86%，n＝50，只差 2 位模擬使用者；以 (82＋86)/2＝84% 代入 p(1−p)/n 再開根號，二項標準誤約 5 個百分點 [arXiv:2311.05584]。精讀時估算，CollabLLM 的 MATH 若評估集就是那 200 題，對 Base 的 +5.5 個百分點約等於 200×0.055＝11 題 [arXiv:2502.00640]。IN3 接 XAgent 的執行評估只有 10 題，標註者就是與 Mistral-Interact 對話的同一位使用者（精讀時發現）[arXiv:2402.09205]。
- **few-shot 的增益與雜訊同量級。** 精讀時發現，dual encoder 在 10-shot 贏 bert-tuned 0.97–1.77 點、30-shot 贏 0.54–1.89 點，而光換超參數 dual 模型就會浮動 0.5–1.5 點；每個 few-shot 設定只抽一組訓練子集 [arXiv:2003.04807]。

### 陷阱三：回答端與使用者模擬器的失真

澄清與目標推斷兩組的分數，幾乎都綁在「誰來回答問題」上（本章歸納）。各篇的回答端失真方向不同：

- **回答者知道真人不會知道的東西。** Qulac 的答案由看得到 facet 描述的群眾工作者撰寫 [arXiv:1907.06554]。精讀時發現，facet 描述與 TREC 相關性判斷同源，成功案例正是答案把 facet 描述中的關鍵詞帶回查詢，構成一種洩漏 [arXiv:1907.06554]。Table 3 裡只看單一 QPP 分數選題的 σ-QPP，就讓 MRR 從 0.2715 升到 0.3570（0.3570 ÷ 0.2715 ≈ 1.31）；最差題 WorstQuestion 的 nDCG@20 為 0.1483，還略高於不問的 OriginalQuery 0.1470 [arXiv:1907.06554]。精讀時據此判斷，增益有相當一部分來自答案文字，而不是選題能力 [arXiv:1907.06554]。ClariQ 的文件相關性評估把黃金使用者回答附進查詢；精讀時指出，只要回答帶資訊，照這個計分方式「問」總是比「不問」好，這和它自己「學會何時不問」的研究問題衝突 [arXiv:2009.11352]。
- **候選集混進未來的資訊。** EVPI 的候選集裡一定有原貼文自己的 (q, a)，候選答案含有作者被問「之後」才寫的真實編輯；作者自承含原題的設定過度樂觀 [arXiv:1805.04655]。精讀時進一步發現，能看到答案的模型的優勢，可能部分來自辨認「哪個答案真的補進了這篇貼文」[arXiv:1805.04655]。
- **問題來自 oracle。** Clarify When Necessary 的預算評估裡，被選中發問的輸入拿到的是 GPT-3.5 依 gold 解讀生成的問答，不是 Intent-Sim 自己生成的問題 [arXiv:2311.09469]。精讀時指出，Table 4 的增益因此是上限 [arXiv:2311.09469]。
- **模擬器拿得到答案。** Future Turns 的評估模擬器（gpt-4-0613）拿得到目標答案，只用「回答中是否出現答案字串」過濾洩漏 [arXiv:2410.13788]。精讀時依 Table 1 發現兩個旁證：完全沒做偏好訓練的 Clarify SFT 在未模糊題上就比直接回答高 +5.6／+6.4／+9.6 F1；Match 相對 RM 的增益在未模糊題（+7.3／+6.7／+6.8）比模糊題（+2.5／+5.0／+2.9）還大 [arXiv:2410.13788]。沒有歧義可消的題目反而受益最多，這與「double-turn 偏好教會模型消歧」的說法不一致；精讀時也指出，訓練端的模擬器提示詞沒有「不得包含答案」的限制 [arXiv:2410.13788]。想像對話那篇的模擬使用者手上有正解活動，作者自承它回答得太直接，使最終成功率偏高 [arXiv:2311.05584]。
- **模擬器被設定成偏向某一邊。** CollabLLM 的模擬器提示詞明令它一開始只給模糊、不完整的需求，讓 AI 主動來問；精讀時因此認為這個環境本身就在獎勵提問 [arXiv:2502.00640]。IN3 的 User-GPT 被要求在被問到偏好時自行編造具體答案 [arXiv:2402.09205]。STaR-GATE 的模擬器被要求有問必答、persona 資訊密度高，精讀時認為對提問者過度友善 [arXiv:2403.19154]。
- **評審或模擬器與被測物同源。** STaR-GATE 的 gold 回應由 GPT-4 撰寫，win rate 的評審也是 GPT-4，評審看得到完整 persona [arXiv:2403.19154]。精讀時指出這是同源偏誤，72% 反映的可能是「更像 GPT-4 式的個人化」，而全文沒有任何人工評估，對照組也只有同樣被強迫提問的初始模型 [arXiv:2403.19154]。精讀時發現，CollabLLM 訓練時的往後模擬與評估用的是同一個 GPT-4o-mini 模擬器、同一份提示詞，訓練獎勵中的 R_LLM 與評估指標 ITR 量的也都是互動性 [arXiv:2502.00640]。精讀時依公開 repo 發現，Proactive Agent 用同一個 RM 篩選訓練資料（只收它接受的預測，被拒時附上理由重試，最多 15 次），又用它判定所有 agent 分數，全文沒有任何 agent 輸出經過人工評估 [arXiv:2410.12361]。想像對話那篇的訓練資料、提示基準與模擬使用者全都是 GPT-3.5（精讀時發現）[arXiv:2311.05584]。IN3 裡 GPT-4 參與了生成任務、提供標註起點、合成訓練對話，以及判定提問與標準缺漏細節的配對，最後一項只抽約 5% 做人工檢查 [arXiv:2402.09205]。

只有 GATE 以目標使用者本人對保留題的逐題判斷當主指標的真值 [arXiv:2310.11589]。但精讀時發現，GATE 的測試題題數沒有交代，受試者標註測試題時還可以回頭看自己的對話紀錄；生成式主動學習的紀錄在形式上與測試題最接近，照紀錄作答會抬高這個方法的一致度 [arXiv:2310.11589]。

### 陷阱四：指標本身的定義會誤導

- **越嚴的指標越會放大差距。** Joint BERT 在 Snips 上 slot F1 從 88.8 到 97.0，整句框架準確率從 75.5 到 92.8 [arXiv:1902.10909]。TOP 的 RNNG 有 100% 的 Tree Validity，但那是轉移系統在結構上保證的；精讀時發現 seq2seq 的不合法率只有 0.06%–0.45%，解釋不了 2–6 點的 exact match 差距 [arXiv:1810.07942]。
- **加權 recall 與 accuracy 對不上。** IntentCapsNet 報的 Precision、Recall、F1 是依樣本數加權的平均，加權 recall 在定義上等於 accuracy；精讀時發現 Table 4 中 CVA 完整模型的加權 Recall 0.8629 與 Accuracy 0.8628 不一致 [arXiv:1809.00385]。2 選 1 的 zero-shot 隨機基線是 0.5，0.7752 對 0.7588 的差距意義有限（精讀時發現）[arXiv:1809.00385]。
- **人為的 OOS 比例與事後的門檻。** CLINC150 測試集的 OOS 比例（1,000／5,500）與實際產品流量無關，精讀時指出 OOS recall 無法直接換算成使用者感受到的錯誤率 [arXiv:1909.02027]。Mahalanobis 那篇的 FPR@95 用的是事後依測試分布定的門檻，也沒報 ID 意圖分類準確率（精讀時發現）[arXiv:2101.03778]。
- **兩個「何時問」指標排出不同順序。** Clarify When Necessary 裡，MT GPT-3 上 Self-Ask 的 AUROC 0.371 是全表最低，但 b=20% 與 30% 的增益占比 25%、37% 在四個方法中最高 [arXiv:2311.09469]。精讀時推論，AUROC 的正類是二元的「會不會變好」，預算指標算的是淨增益，會把澄清後變差的題目也算進去；「占總增益的百分比」的隨機期望值剛好等於 b [arXiv:2311.09469]。
- **有序標籤被當成名目類別。** ClariQ 論文本文沒給「何時問」任務的指標；精讀時指出，README 補的 Precision／Recall／F1 把 1–4 的有序標籤當成名目類別，猜 3 與猜 1 對黃金標籤 4 懲罰相同 [arXiv:2009.11352]。
- **自動指標與人評方向相反。** ProCoT 用 BLEU-1 與 ROUGE-2 評澄清問題；精讀時發現 ChatGPT ProCoT 從 zero-shot 到 one-shot，BLEU-1 從 21.6 降到 18.4、ROUGE-2 從 21.5 降到 16.2，人工 Help. 卻上升 [arXiv:2305.13626]。EVPI 的專家對「單一最佳問題」的 Cohen's κ 只有 0.15，放寬後是 0.87；作者因此改用 best 聯集與 valid 交集當正解 [arXiv:1805.04655]。
- **oracle 上界的基準各處不一。** Qulac 摘要說只問一題就讓 P@1 提升超過 170%，引言說超過 100%，結論說超過 150% [arXiv:1907.06554]。精讀時發現，§6.2 的基準 P@1 0.1933 不等於 Table 3 的 OriginalQuery 0.1842；改用 Table 3 自己的數字，BestQuestion 的 P@1 是 0.3815 ÷ 0.1842 ≈ 2.07 倍，MRR 是 0.4673 ÷ 0.2715 ≈ 1.72 倍 [arXiv:1907.06554]。
- **重縮放放大了相對提升。** CollabLLM 附錄寫明，ITR 先以 A＝3、B＝2、C＝1 評分，再以 S'＝2(S−2.5) 重縮放 [arXiv:2502.00640]。精讀時指出，這種帶平移的線性轉換只保住排序，不保住相對提升的百分比 [arXiv:2502.00640]。換回原始尺度（S＝S'/2＋2.5），MediumDocEdit-Chat 的 Proactive Base 是 0.62→2.81、Online DPO 是 0.92→2.96，相對提升約 2.96/2.81−1≈5.3%，論文報 48.3%；依同法 BigCodeBench-Chat 約 3.4%（論文報 54.3%）[arXiv:2502.00640]。MATH-Chat 那一格的 36.4% 等於 60.0/44.0−1，是對 Base 算的，改對 Proactive Base 應為 60.0/46.0−1≈30.4% [arXiv:2502.00640]。
- **口述機率的校準移動。** GATE 的主指標是 Δp(correct) 對互動時間的曲線下面積，p(correct) 直接取自 GPT-4 口述的機率；作者自承換成只看排序的 AUROC 後，改善較小、變異較大 [arXiv:2310.11589]。精讀時據此推論，部分增益可能只是機率被推向某一端的校準移動 [arXiv:2310.11589]。
- **多候選輸出沒計負擔。** Proactive Agent 的 pred@3 只要任一候選被接受就算對，精讀時指出它沒有計入使用者讀三個候選的負擔 [arXiv:2410.12361]。

### 陷阱五：用測試集做選擇、單次執行、樣本相依

- **挑最好的一次。** Liu & Lane 表中的 slot F1 95.78 是最佳一次的數字；精讀時發現同一模型的平均 95.47±0.22，低於表中 Kurata 等人的 95.66 [arXiv:1609.01454]。
- **在測試集上挑設定。** 精讀時發現：Joint BERT 的 epoch 表列的是測試集數字，20 epochs 的 intent 99.0 高於主結果採用的 30 epochs 的 98.6 [arXiv:1902.10909]；dual encoder 的 Table 4 超參數敏感度在測試集上量 [arXiv:2003.04807]；Mahalanobis 的官方程式碼依 AUPR_OOD 挑最佳模型，用到的 OOD 驗證語句在 CLINC150 只有約 100 句 [arXiv:2101.03778]。
- **變異來源不一致。** 精讀時發現，[arXiv:2305.07157] Table 4 的增補結果是 3 個隨機種子的平均，基線卻直接沿用 Table 2 以 5 次抽樣得到的 K=5 數字 [arXiv:2305.07157]。
- **樣本相依卻當成獨立。** Qulac 的多回合擴充有 907,366 個實例、75,200 個對話歷史，顯著性用雙尾成對 t 檢定加 Bonferroni 校正 [arXiv:1907.06554]。精讀時計算，每組問答平均以候選題身分出現約 907,366 ÷ 10,277 ≈ 88 次，每個 facet 平均約有 75,200 ÷ 762 ≈ 99 個對話歷史，成對 t 檢定卻把它們當成獨立樣本 [arXiv:1907.06554]。
- **單次執行、沒有檢定。** 精讀時指出：Clarify When Necessary 的 v1 完全沒做顯著性檢定，NAACL 2025 正式版補上 bootstrap 後，AUROC 只有三格標為顯著 [arXiv:2311.09469]；STaR-GATE 只跑單一訓練 seed，誤差棒是跨 prompt 的 SEM [arXiv:2403.19154]；ProCoT 的結果都是單次執行 [arXiv:2305.13626]；想像對話那篇的使用者研究只有 12 人，Table 1 沒有任何顯著性檢定 [arXiv:2311.05584]；CollabLLM 的 201 人使用者研究分三組，沒有顯著性檢定 [arXiv:2502.00640]。

### 陷阱六：解析、後處理與「zero-shot」的定義

- **解析規則會進分數。** 開放世界那篇規定，漏分的句子隨機指派，重複分派只取第一個；在 1:1 時，三種方法平均的 missing recall 是 24.15%、repeated recall 是 4.44% [arXiv:2310.10176]。精讀時據此認為，1:1 的結果有相當比例在量「能不能照格式列全編號」[arXiv:2310.10176]。[arXiv:2305.07157] 在補完裡找第一個出現的意圖名，找不到就判為 OOS；精讀時發現，這讓幻覺、格式跑掉與真正選 none 混進同一個 OOS 數字 [arXiv:2305.07157]。
- **OOS 只量一邊。** [arXiv:2305.07157] 的 in-scope accuracy 分母只算已知意圖的樣本，OOS 只報 recall；精讀時發現它沒報 OOS precision，也沒報 in-scope 句子被判成 none 的比例 [arXiv:2305.07157]。過濾後 GPT-3 的 OOS recall 從 0.67 升到 0.97（B01）、0.87（B02）；精讀時提出另一種解讀：過濾後的候選清單對 OOS 句來說全是錯的意圖，模型更傾向回 none，這個升幅可能部分是拒答偏移 [arXiv:2305.07157]。
- **「zero-shot」的定義會漂移。** [arXiv:2305.07157] 自己寫明，top-5 過濾要每意圖幾個例句做檢索，所以是 few-shot，真正 zero-shot 的只有全意圖那幾列 [arXiv:2305.07157]。開放世界那篇的「無先驗」分群，其實把真實群數寫在提示裡 [arXiv:2310.10176]。📖 的 ChatGPT 評估主結果附了槽位範例值，精讀時據此認為它比不給範例值的 zero-shot 多了不少領域資訊 [arXiv:2304.04256]。

### 陷阱七：比較雙方的監督量或基底不對等

- 開放世界那篇的微調 baseline 用所選類別的全部訓練樣本，ChatGPT 只看到提示裡的 25–75 句；精讀時指出「落後微調方法」混了模型能力與資料量兩個變數 [arXiv:2310.10176]。
- [arXiv:2305.07157] 的「3B 小模型勝過 GPT-3」，比的是零樣本的 GPT-3 對 K 樣本微調的 Flan-T5；精讀時指出缺了把 K 個例句放進 GPT-3 提示的 in-context 對照 [arXiv:2305.07157]。
- Joint BERT 的三個外部基線全部抄自 Goo et al.，也沒有其他預訓練表示的基線；精讀時發現增益混合了「有沒有預訓練」與「模型結構」兩個因素 [arXiv:1902.10909]。
- 精讀時發現：CollabLLM 的 Table 1 沒有列 GPT-4o，而離線訓練資料正是以 GPT-4o 當助理生成的 [arXiv:2502.00640]；Mistral-Interact 從 Mistral-7B-v0.1 base 微調，對照組卻是 Mistral-7B-Instruct-v0.2 [arXiv:2402.09205]；想像對話那篇的 Table 1 與 Table 2 都沒有 BC 對照 [arXiv:2311.05584]。

## 爭議、矛盾與反證

凡標「精讀時發現」「精讀時推論」「精讀時依公開 repo」的，都是精讀 agent 自己的分析，不是論文的結論，也沒有經過同儕審查。

### 一、名次隨引用來源或量法反轉

**ATIS 上誰贏，要看引哪一份數字。** Joint BERT 的 Table 2 把 Liu & Lane 的 Attention BiRNN 列為 ATIS 意圖準確率 91.1、slot F1 94.2，這些數字引自 Goo et al.，不是重跑 [arXiv:1902.10909]。Liu & Lane 自報的聯合 Attention BiRNN 意圖錯誤率是 1.79%，換算準確率 100 − 1.79 = 98.21；slot F1 是 95.98 [arXiv:1609.01454]。換成自報數字，Joint BERT 在 ATIS 的意圖準確率 97.5 低於 100 − 1.79 = 98.21，slot F1 96.1 對 95.98 只高 96.1 − 95.98 = 0.12 [arXiv:1902.10909][arXiv:1609.01454]。成因是同名 ATIS 的標籤集不同：Liu & Lane 用 18 個意圖、127 種 slot 標籤，Joint BERT 沿用 Goo et al. 的切分，是 21 個意圖、120 種 slot 標籤，只有測試句數都是 893 [arXiv:1609.01454][arXiv:1902.10909]。本章的判斷是，這組數字反映的不是誰的方法比較好，而是「ATIS SOTA」取決於用哪一份切分、引哪一份重現。

**同一份 CLINC150 測試集，一篇說拒識很難，另一篇的數字接近解決。** 兩篇的測試集都是 4,500 in-scope＋1,000 OOS [arXiv:1909.02027][arXiv:2101.03778]。CLINC150 論文認為所有被評估的方法在 OOS 偵測上都表現不佳，OOS recall 最佳只有 66.0，BERT 在 oos-threshold Full 是 52.3 [arXiv:1909.02027]。Mahalanobis 論文的 RoBERTa＋Mahalanobis 則有 AUROC 98.4、FPR@95_OOD 6.8 [arXiv:2101.03778]。本章推論差距主要來自量法：前者報的是單一操作點，oos-threshold 的門檻還由 OOS 只占約 3% 的驗證集挑出；後者報的是與門檻無關的曲線指標，或事後依測試分布定的門檻 [arXiv:1909.02027][arXiv:2101.03778]。再加上模型不同（bert-large-uncased 對未標明大小的 RoBERTa），以及精讀時發現後者用 AUPR_OOD 挑模型 [arXiv:1909.02027][arXiv:2101.03778]。兩篇都沒有在同一個模型上同時報兩種量法，所以拆不出各因素的份量 [arXiv:1909.02027][arXiv:2101.03778]。

### 二、表示要不要微調

dual encoder 那篇說凍結的對話式 dual encoder 加 MLP，就能在 few-shot 意圖分類勝過微調 BERT [arXiv:2003.04807]。Mahalanobis 那篇則用 Fig. 3 主張，ID 微調才讓 OOD 語句在低變異主成分上分得開，未微調的 RoBERTa 與 CNN 都看不到這種分離 [arXiv:2101.03778]。精讀時發現，後者的主張只有熱圖、沒有數值，Table 2 也沒有未微調的對應列 [arXiv:2101.03778]。兩篇沒有交集：dual encoder 那篇完全不做 OOS，Mahalanobis 那篇沒測對話式凍結編碼器 [arXiv:2003.04807][arXiv:2101.03778]。dual encoder 那篇把 bert-fixed 落後歸於 BERT 的語言模型式預訓練目標，banking77 10-shot 上 bert-fixed 與 USE 差 84.23 − 67.55 = 16.68 點；精讀時發現實驗裡沒有「句子層級目標、非對話資料」的編碼器（例如 Sentence-BERT），分不清差距來自對話資料還是句子層級目標 [arXiv:2003.04807]。

### 三、LLM 做意圖分類是贏還是輸

[arXiv:2305.07157] 主張描述式 zero-shot 整體優於 few-shot 分類器，[arXiv:2310.10176] 則說 ChatGPT 在 GID 全面落後微調方法。兩者並不衝突：前者的對照是每意圖 3 或 5 例的句向量分類器（或由 5 句種子增補出 20 句），後者的對照吃了所選類別的全部訓練資料 [arXiv:2305.07157][arXiv:2310.10176]。即使在前者自己的資料上，主張也不全面：精讀時發現，Benchmark02 上全意圖 zero-shot 的 GPT-3 61.3、Flan-T5-XXL 69，都低於 GTR-3B K=5 與 Parrot T5 增補的 73 [arXiv:2305.07157]。精讀時還發現，各表用的資料集集合不一致，可跨表比較的只有 MASSIVE、B01、B02，這個結論實際上只建立在 2–3 個資料集上 [arXiv:2305.07157]。

### 四、示範是幫忙還是雜訊

開放世界那篇發現，IND 先驗給得越多，OOD 分群越差：1:1 時 DC 58.22 > ZSD 50.67 > FSD 49.78 [arXiv:2310.10176]。同一篇的 GID-FSD 在 3:1 把 IND ACC 從 GID-DC 的 68.44 拉到 79.11，OOD ACC 卻從 75.33 崩到 17.33 [arXiv:2310.10176]。[arXiv:2305.07157] 的 Flan-T5-XL PEFT 則是每意圖 1 例就是最佳方法（只有圖），但那些例句是拿來微調 IA3 adapter 的訓練資料，不是放進提示的示範，論文裡也沒有「示範覆蓋與未覆蓋的類別」這種對照，不能拿來和上面的結果並讀 [arXiv:2305.07157]。所以能說的只限於開放世界那篇的設定：IND 示範幫的是它覆蓋的 IND 類別，對沒覆蓋的 OOD 類別幫不上忙，甚至有害（本章歸納）[arXiv:2310.10176]。但精讀時提醒：ZSD／FSD 提示明說兩組意圖不重疊，卻給同領域示範，模型可能刻意避開 IND 類似的切分；沒有拿掉這句聲明的消融，就不能把效果全算在 in-context learning 頭上 [arXiv:2310.10176]。精讀時也發現，GID-FSD 在較容易的 3:1 崩到 17.33，在 3:2 卻有 52.00，作者沒有逐次檢查是不是解析失誤或單次極端值 [arXiv:2310.10176]。

### 五、標籤語意由什麼承載，沒有定論

[arXiv:2010.05256] 拿掉 label name 錨點，TourSG 1-shot 掉 38.53；但精讀時發現，TourSG 各領域共用相近的對話行為標籤，目標領域的 label name 在來源訓練時早已見過 [arXiv:2010.05256]。[arXiv:2310.10176] 發現把 pseudo-intent 換成真實意圖名只小幅提升，再加上人工描述才顯著提升，但數值只在圖中。[arXiv:2305.07157] 沒有做描述寫法的消融。📖 的 ChatGPT 評估提供了一個反例：在槽位層面，加範例值（Slot F1 58.24）遠比加描述（33.88）有用，意圖準確率則幾乎不受影響；精讀時還發現它的內文結論與 Table 5 相反 [arXiv:2304.04256]。

### 六、「何時問」的閘門，在不同設定下結論不一

**ProCoT 的效果高度依賴設定。** ProCoT 原論文報告，ChatGPT 加 ProCoT 在 Abg-CoQA 上的 CNP F1 27.9 高於微調 SOTA 的 23.6 [arXiv:2305.13626]。Future Turns 自己重做 ProCoT 當基線，用 instruct 版模型在 AmbigQA 上測：Llama2 的 Answer F1 只有 15.6，低於同表 Random 的 23.4（兩者的直接回答比例分別是 35% 與 44%）；在 Llama3 與 Gemma 上則退化成從不直接回答 [arXiv:2410.13788]。兩邊的模型、資料集、實作者與指標都不同，本章不把它當直接反證，而視為 ProCoT 的效果高度依賴設定的訊號；ProCoT 原論文自己的 PACIFIC 結果（28.0 對 SOTA 86.9）也指向同一件事 [arXiv:2305.13626][arXiv:2410.13788]。精讀時另外指出兩個可能讓原論文數字偏高的因素：one-shot 示範的思考鏈是從三位標註者的版本中挑表現最好的一版；ProCoT 的指令除了多一段推理，還多了「先判斷是否模糊」的要求，兩個因素沒有拆開消融 [arXiv:2305.13626]。Future Turns 的作者也承認，ProCoT 基線必須用 instruct 版模型，數字可能因基底較強而被高估 [arXiv:2410.13788]。

**模擬未來輪次的給分方式並非一致有效。** STaR-GATE 以 gold 回應的 log-prob 當提問獎勵，win rate 最高到 72% [arXiv:2403.19154]。Future Turns 把沿用這個想法的 Likelihood 給分列為對照：在 Llama2 上 All F1 27.2，還低於單輪 RM 的 28.3；在 Llama3 上 35.9，幾乎與 Match 的 36.5 打平 [arXiv:2410.13788]。精讀時指出，哪一種給分方式有用依模型而異，論文把功勞統一歸給 double-turn 偏好，說得太滿 [arXiv:2410.13788]。

**精巧的選題與最便宜的訊號差距很小。** 精讀時依 Qulac 的 Table 3 重算，以 WorstQuestion 到 BestQuestion 的 MRR 區間（0.2479–0.4673）為尺度，NeuQS 補上 (0.3625 − 0.2479) ÷ (0.4673 − 0.2479) ≈ 0.52 的差距，σ-QPP 補上 (0.3570 − 0.2479) ÷ (0.4673 − 0.2479) ≈ 0.50 [arXiv:1907.06554]。Clarify When Necessary 裡，Intent-Sim 與輸出空間的 Semantic Entropy 在 QA GPT-3 上三個預算的數字完全相同（55.5、56.1、57.0）[arXiv:2311.09469]。精讀時指出，論文沒有消融能證明「對澄清答案的分布算熵」比「對輸出的分布算熵」更能分開 aleatoric 與 epistemic，核心賣點沒有被直接驗證 [arXiv:2311.09469]。EVPI 那邊，排除原題後 EVPI 的 p@1 23.7 與 Community QA 的 22.6 在統計上無法區分，B1∪B2 的 MAP 甚至是 Community QA 29.3 略高於 EVPI 29.1 [arXiv:1805.04655]。

### 七、問了一定比較好嗎

Qulac 逐 facet 看，NeuQS 選出的問題讓 45% 的 facet MRR 改善、19% 變差 [arXiv:1907.06554]。Future Turns 會自己決定問或答的 Clarify-or-Direct Ans DPO，F1 為 24.3／29.1／24.6，低於一律提問、沒做偏好訓練的 Clarify SFT（25.9／31.5／28.8），同時平均要 1.56–1.61 輪 [arXiv:2410.13788]。作者把這描述成效率與效果的折衷；精讀時指出，論文沒有定義「多一輪值多少 F1」，這個平衡無法驗證 [arXiv:2410.13788]。STaR-GATE 的消融顯示問得好還不夠：讓未訓練的初始模型在訓練後模型引出的對話上作答，勝率第 2 輪最高 57%，第 3 輪就回到 50% [arXiv:2403.19154]。

### 八、提示就夠，還是一定要訓練

佐證「提示就夠」的有兩篇：GATE 以提示驅動的 GPT-4 做引出，在三個領域都優於不互動，多數設定下也勝過使用者自寫的描述 [arXiv:2310.11589]；IN3 的 Table 3 中，在精讀時認為最能代表意圖理解的兩項（Lv3 召回、總結涵蓋率）上，以提示驅動的 GPT-4 反而最高，75.22%、100.0% 高於 Mistral-Interact 的 72.28% 與 96.37% [arXiv:2402.09205]。佐證「需要訓練」的也有兩篇：想像對話那篇的 GPT-2 IE+RL 在兩個任務的四項評分全部高於以提示驅動的 GPT-3.5，例如教學任務的整體滿意度從 2.4 升到 4.2 [arXiv:2311.05584]；CollabLLM 說提示版 Proactive Base 增益有限、行為僵硬，本章依 Table 1 核對，Online DPO 在九格指標上都勝過它 [arXiv:2502.00640]。兩邊的提示基準強弱差很多：分別是 GPT-4 [arXiv:2310.11589][arXiv:2402.09205]、GPT-3.5 [arXiv:2311.05584]，以及加了提示的 Llama-3.1-8B [arXiv:2502.00640]。精讀時另外指出，想像對話那篇沒有試 few-shot、「一次只問一題」這類提示，也沒有試 GPT-4 [arXiv:2311.05584]。在同一份測試集上把訓練法與強的提示模型並排的有兩篇。IN3 拿全參數微調的 Mistral-Interact 對提示驅動的 GPT-4，108 題、同一批 8 位使用者，結果互有勝負：模糊判斷準確率 85.19% 對 82.41% 是前者高，Lv3 召回與總結涵蓋率是後者高 [arXiv:2402.09205]。但模糊判斷準確率兩邊都低於一律判模糊的 87.96% [arXiv:2402.09205]。Proactive Agent 微調後的 Qwen2-7B 在 F1 上以 66.47% 略勝 GPT-4o 的 64.60% [arXiv:2410.12361]；精讀時估計這 66.47−64.60＝1.87 個百分點落在約 3.3 個百分點的二項標準誤內，而且判分的是篩選訓練資料的同一個 RM [arXiv:2410.12361]。這兩組比較的兩邊都是不同的基底模型；CollabLLM 雖然在同一個基底上比較提示與訓練，提示那一邊卻是 8B 模型 [arXiv:2402.09205][arXiv:2410.12361][arXiv:2502.00640]。所以沒有一篇在相同基底、相同條件下比較訓練法與強的提示，這組矛盾目前無法裁決（本章歸納）[arXiv:2311.05584][arXiv:2402.09205][arXiv:2410.12361][arXiv:2502.00640]。

### 九、模型是太愛介入，還是太少發問

- **過度主動。** Proactive Agent 發現閉源模型普遍過度主動：GPT-4o 的 Recall 98.11%、False-Alarm 51.85%，GPT-4o-mini 的 Recall 100%、False-Alarm 64.73%；只有 Claude-3-Sonnet 相反，Recall 只有 27.47% [arXiv:2410.12361]。
- **很少發問。** CollabLLM 在 Abg-CoQA 上看到 GPT-4o 只在 15.44% 的模糊題上提問，Llama 是 16.26%，論文的描述是兩者不論模糊與否都很少問 [arXiv:2502.00640]。ProCoT 發現在 Standard 提示下，LLM 在兩個澄清資料集上的人工 Help. 全為 0.0 [arXiv:2305.13626]。
- **兩種病都有。** IN3 的 10 題初步測試裡，LLaMA-2 在「問個不停」上是 Severe，Mistral 則在「問太少、急著總結」上是 Severe [arXiv:2402.09205]。

本章歸納：前兩者不必然矛盾，在 Proactive Agent 與 Abg-CoQA 裡，現成模型都傾向產出一個實質動作（提議任務、直接回答），而不是按兵不動 [arXiv:2410.12361][arXiv:2502.00640]。但在 IN3 那種明說要先澄清的流程裡，偏向哪一邊就看模型，「LLM 問太多還是太少」沒有單一答案 [arXiv:2402.09205]。

訓練或推論介入之後，兩篇都出現操作點的移動。CollabLLM 在模糊題的提問率從 16.26% 升到 52.84%，代價是非模糊題的直答率從 90.40% 降到 72.32% [arXiv:2502.00640]。Proactive Agent 加入 RM 回饋後，GPT-4o 的 Recall 從 98.11% 掉到 56.76%，F1 從 64.60% 降到 56.00%，作者承認模型收到回饋後就傾向保持沉默 [arXiv:2410.12361]。差別在分辨力：CollabLLM 的兩類提問率差距從 Llama 的 16.26−(100−90.40)＝6.66 升到 52.84−(100−72.32)＝25.16 個百分點，確實分得更開[arXiv:2502.00640]；Proactive Agent 則因 False-Alarm 在數值上等於 1−Precision，而精讀時依公開 repo 發現 TN 與 FN 都只由 RM 對 null 的判斷決定，從表上看不出分辨力有沒有變 [arXiv:2410.12361]。

**「RLHF 讓模型不問」還只是假說。** STaR-GATE 引用前人指出 RLHF 會壓抑追問傾向 [arXiv:2403.19154]。Future Turns 推測根源是只看下一輪的單輪偏好標註，並顯示用現成單輪 RM 的偏好訓練效果不一致，All F1 對 Clarify SFT 是 Llama2 28.3 對 25.9、Llama3 30.9 對 31.5、Gemma 29.5 對 28.8 [arXiv:2410.13788]。但精讀時指出，Future Turns 刻意只用未做指令微調的預訓練基底模型，沒有檢驗已做過 RLHF 的 instruct 模型 [arXiv:2410.13788]。本章據此判斷，在本節點的論文裡，沒有一篇在 RLHF 前後的同一模型上直接量過這個因果 [arXiv:2305.13626][arXiv:2403.19154][arXiv:2410.13788]。

### 十、模擬使用者往哪邊偏，目標是否固定

**三種模擬器設計，讓「該不該問」往三個方向偏（本章歸納）。** 想像對話那篇的模擬使用者手上有正解，回答得太直接，提問因此顯得多餘 [arXiv:2311.05584]。CollabLLM 的模擬器被明令一開始只給模糊需求，提問因此總是划算 [arXiv:2502.00640]。IN3 的 User-GPT 被問到偏好就編造具體答案，抹掉了「使用者自己也不知道」的情況 [arXiv:2402.09205]。只有 GATE 正式拿模擬器去對真人結果：內容推薦與 email 大致一致，道德推理則不一致 [arXiv:2310.11589]。CollabLLM 也只是定性列出差異，指出真人句子更短、更破碎，而且會中途改變方向 [arXiv:2502.00640]。

**目標固定的假設有反證。** CollabLLM 以隱藏目標 g 與參考解 y_g 定義任務成功 [arXiv:2502.00640]；想像對話那篇的隱藏參數 z 從一個事先列舉的小集合中抽出 [arXiv:2311.05584]；IN3 把意圖拆成執行前就固定的有限個缺漏細節 [arXiv:2402.09205]。反證有兩條：GATE 的使用者看過測試題後自評涵蓋度下降，email 領域自寫描述反而略降表現，作者列出的可能原因之一是使用者寫下的規則與實際判斷不一致 [arXiv:2310.11589]；CollabLLM 自己的使用者研究也觀察到真人會中途改變方向 [arXiv:2502.00640]。本章歸納，這三篇的訓練設定表達不出「使用者還沒想清楚」的情況。

### 十一、論文正文與自己的表格不一致

以下都能在論文的表格裡直接核對；除了標明「本章核對全文」或「本章重算」的之外，都是精讀時的發現。

- **CLINC150。** 正文說 Wikipedia 擴充同時改善 in-scope 與 OOS，但 Table 3 顯示表現最好的兩個模型 OOS recall 都下降：MLP 52.8→32.4、BERT 46.5→40.4 [arXiv:1909.02027]。精讀筆記推測強模型學到了「不像查詢就是 OOS」的風格捷徑，這違反該論文自己的前提 [arXiv:1909.02027]。
- **dual encoder。** 說「全面最佳」，但 banking77 全量時 bert-tuned 93.66 高於 USE＋ConveRT 93.36，clinc150 全量時 ConveRT 單獨 97.16 與組合模型打平 [arXiv:2003.04807]。
- **Joint BERT。** 說加 CRF「相當」，實際方向不一致：ATIS 上 intent 97.9 對 97.5 較高，Snips 上三項都較低 [arXiv:1902.10909]。
- **IntentCapsNet。** 說 SNIPS-NLU 上三個元件各貢獻約 2–3% F1，表中的絕對差是 0.7750 − 0.7547 = 0.0203、0.7750 − 0.7616 = 0.0134、0.7750 − 0.7675 = 0.0075 [arXiv:1809.00385]。
- **TOP。** 說 depth ≤2 與 depth >2 的兩人定案率相近，實際是 68.87% 對 62.03%，差 68.87 − 62.03 = 6.84 點 [arXiv:1810.07942]。
- **描述式 zero-shot。** 內文說 ELMSE 與 GTR-3B「only 2-3% worse」，但 Table 2 在 K=5 的 B02 是 67 對 73、B03 是 79 對 84，K=3 的 B02 是 63 對 70 [arXiv:2305.07157]。精讀時說意圖過濾在 in-scope accuracy 上多半降分；本章對照全文 Table 5，八格中六格下降（例如 MASSIVE 73.3→68.6、73.9→69.2），例外是 B02 的 Flan-T5-XXL 從 69 升到 69.7，以及 B01 的 Flan-T5-XXL 持平在 86.5 [arXiv:2305.07157]。「過濾能提升 OOS recall」也只對 GPT-3 成立，Flan-T5-XXL 反而下降（B01 0.48→0.43、B02 0.7→0.65）[arXiv:2305.07157]。
- **開放世界意圖。** Table 5 表頭寫所有 LLM 都在 IND/OOD=3:2 下比較，精讀時查表發現 ChatGPT 的 GID 欄 68.44／75.33／70.17 與 Table 2 的 3:1 GID-DC 相同 [arXiv:2310.10176]。本章用一條恆等式獨立確認：ALL ACC 必然是 IND 與 OOD ACC 依樣本數的加權平均，每類抽樣數相同時 3:1 的權重是 0.75／0.25，3:2 是 0.6／0.4 [arXiv:2310.10176]。ChatGPT 列 0.75×68.44＋0.25×75.33＝70.16，與報告的 70.17 只差四捨五入；按 3:2 權重是 0.6×68.44＋0.4×75.33＝71.20，對不上 [arXiv:2310.10176]。同表其他三個模型都吻合 3:2：Claude 0.6×56.67＋0.4×70.00＝62.00，text-davinci-003 0.6×59.56＋0.4×63.33＝61.07，text-davinci-002 0.6×31.56＋0.4×28.67＝30.40 [arXiv:2310.10176]。照 3:2 比，ChatGPT 應是 Table 2 的 64.67／61.33／63.33，Claude 是一增一減：IND ACC 低 64.67−56.67＝8.00，OOD ACC 反而高 70.00−61.33＝8.67，ALL ACC 只低 63.33−62.00＝1.33；論文「Claude 在 GID 較弱」的結論站不太住 [arXiv:2310.10176]。程式驗證證實 ChatGPT 的 GID 欄是 3:1 的數字，而且三項獨立檢查（加權恆等式、與 Table 2 逐欄比對、換算整數句數）都指向同一個答案；「站不太住」屬於判斷，數字撐得住的是「兩邊各有取捨」，不是「Claude 全面較弱」（見〈程式驗證〉）[arXiv:2310.10176]。
- **多意圖偵測的 MCT 增益。** 精讀時發現消融表與主表的「不含 MCT」對不上，認為 MCT 的真實增益遠小於 Table 4 報的數字 [arXiv:2010.05256]。本章依論文數字重算（皆為 Electra 嵌入）後，這個說法只在 StanfordLU 成立：以主表 MPN+ALR 為對照，StanfordLU 的 MCT 增益是 42.51−35.93＝6.58 與 50.82−47.11＝3.71，小於 Table 4 的 10.12 與 17.45；TourSG 卻是 51.07−33.46＝17.61 與 52.63−32.98＝19.65，反而大於 Table 4 的 12.52 與 16.70 [arXiv:2010.05256]。能確定的只有：論文用了兩種固定門檻（消融調在來源領域，主表調在開發領域）卻沒交代，所以 MCT 的增益大小取決於拿哪一個當對照 [arXiv:2010.05256]。
- **Clarify When Necessary。** v1 摘要說只准對 10% 輸入發問時，增益是隨機挑選的兩倍 [arXiv:2311.09469]。Table 4 裡 Intent-Sim 在 b=10% 的增益占比是 13%、24%、14%、17%、6%、11%，六格平均 (13+24+14+17+6+11) ÷ 6 ≈ 14.2%，只有一個組合達到兩倍 [arXiv:2311.09469]。v1 §6.3 說兩種熵方法在所有預算下都贏隨機，精讀時從 Table 4 數出 18 格裡 Intent-Sim 有 6 格低於隨機；精讀時對照 NAACL 正式版發現這兩句都已刪除，Table 4 數字不變 [arXiv:2311.09469]。
- **Future Turns。** 摘要說「何時問」的判斷準確率比既有方法高 3%；精讀時依 Table 4／6 逐一相減，本方法對 ProCoT、PPDPP 的差值沒有一個接近 3 [arXiv:2410.13788]。PPDPP 的 Ambig Acc 在 Llama2 上 59.0 高於本方法的 53.7，在 Llama3 上 53.4 則低於本方法的 54.0 [arXiv:2410.13788]。
- **EVPI。** 排除原題的 §5.2.3，正文說神經模型勝過非神經基線，但補充材料 Table 2 裡 B1∪B2 的 p@1 是 EVPI 23.7 對 Community QA 22.6，作者自己註明除了 Random 與 Bag-of-ngrams 之外差距都不顯著；B1∪B2 的 MAP 還是 Community QA 29.3 略高於 EVPI 29.1 [arXiv:1805.04655]。
- **ClariQ。** Table 1 裡 informational 577 加 navigational 185 只有 762 個 facet，與總數 891 差 891 − 762 = 129 個；問題數 3,304 也與 README 的 3,929 不一致 [arXiv:2009.11352]。
- **Proactive Agent。** 正文 §4.2 寫 LLaMA-3.1-8B 的 F1 從 44.78% 升到 61.74%、最高 F1 為 66.07%，Table 3 卻是 55.06%→66.25%、最高 66.47%（精讀時發現，本章核對全文屬實）[arXiv:2410.12361]。本章核對全文 Table 4 還發現一處：LLaMA-3.1-8B 加入 RM 回饋後，F1 從 55.06% 變成 54.81%，正文卻說 GPT-4o-mini 與 LLaMA-3.1-8B 的 F1 都明顯改善 [arXiv:2410.12361]。精讀時比對 repo 的公開結果（227 個事件）：GPT-4o 的 F1 是 66.27%（表上 64.60%），Claude-3-Sonnet 是 55.83%（表上 31.65%）[arXiv:2410.12361]。
- **想像對話。** 偏好引出任務的資訊蒐集項（C），IE+RL 是 2.6±0.11，IE+BC 是 2.5±0.11，幾乎持平，與正文強調資訊蒐集問題明顯進步的說法不符；教學任務的 (C) 則是 4.0 對 1.9（本章核對全文屬實）[arXiv:2311.05584]。
- **IN3。** 每個子任務的工具呼叫只從 5.22 降到 4.79，正文卻寫成顯著下降 [arXiv:2402.09205]。
- **CollabLLM。** 摘要中「滿意度 +17.6%」在 §6 找不到可以核對的分組數字；標題數字挑了 Online DPO，但 PPO 在 BLEU（38.5 對 36.8）與 PR（14.0 對 13.0）上其實更好 [arXiv:2502.00640]。

### 十二、設計與實作上的結構性漏洞（精讀時推論或依公開程式碼發現，未經實驗驗證）

- **IntentCapsNet-ZSL 的兩個新意圖可能原理上分不開。** 新意圖預測向量裡唯一依新意圖而異的是相似度向量 q_l，而 q_l 只由標籤名稱決定、與語句無關；兩個新意圖若對既有意圖的相似度分布接近，對任何語句都分不開 [arXiv:1809.00385]。σ 只在 zero-shot 推論路徑起作用，用既有意圖的三折交叉驗證選不到它，很可能看過新意圖資料才選 [arXiv:1809.00385]。
- **Mahalanobis 的「正交」更可能是 simplex ETF。** 論文把類別中心兩兩 cosine 接近 0 解讀為互相正交；精讀時依 neural collapse 推論，中心會趨向 simplex ETF，兩兩 cosine 應為 −1/(C−1)：CLINC150 的 C 是 150，預測約 −0.007、觀測 0±0.08；ROSTD 的 C 是 12，預測約 −0.09、觀測 −0.05±0.13 [arXiv:2101.03778]。小 C 時出現負值，正是 simplex 而非正交的特徵 [arXiv:2101.03778]。
- **EVPI 的程式碼與論文不符。** 精讀時依 GitHub 公開程式碼發現，答案模型 F_ans 建了卻不進任何 loss，測試時分數的指數方向與論文的 Eq 2 相反；不過程式碼提交時間晚於 arXiv v2，無法確定就是產生 Table 2 的版本 [arXiv:1805.04655]。
- **Intent-Sim 的分群可能低估熵。** 它只要單向 entailment 就連邊，再以 DFS 取連通分量，等於把蘊含當成可遞移；論文沒報分群準確度 [arXiv:2311.09469]。
- **STaR-GATE 的設定對不上。** 公開 repo 唯一提交的 Roleplayer 設定指向 Mistral-7B-Instruct-v0.2，與論文寫的 mixtral-8x7b-instruct 不符 [arXiv:2403.19154]。
- **Future Turns 的「不同使用者」有一部分只是格式差異。** 附錄例子顯示 NQ-Open 的多答案有些只是同一重量分別以公斤與磅表示，用這些答案模擬不同使用者，會獎勵去區分根本不是意圖差異的東西 [arXiv:2410.13788]。
- **Proactive Agent 的 RM 與標註一致率。** RM 測試集 120 筆的 96 個事件軌跡，全部也出現在訓練集 [arXiv:2410.12361]。91.67% 的標註一致率算的是每位標註者與多數決相符的比例，而多數決就是這三人決定的；repo 中三人意見完全一致的是 90/120 筆，(90×3＋30×2)/360＝91.67% [arXiv:2410.12361]。測試集的公開檔沒有 daily life 類，但訓練集有 2,161/6,790 個事件屬於這一類 [arXiv:2410.12361]。
- **想像對話的獎勵是想像出來的標籤。** 附錄的旅遊範例中，被要求寫成「失敗」的對話，實際上以 150 美元套裝成功收尾，只是批判步改寫了最後幾輪；精讀時據此推論，Q 函數可能學到的是結尾情緒，而不是前面問對了什麼 [arXiv:2311.05584]。
- **CollabLLM 的偏好標籤可能很吵。** BigCodeBench-Chat 上 chosen 是 0.494±0.621，rejected 是 0.207±0.763，標準差比兩者的平均差 0.494−0.207＝0.287 還大 [arXiv:2502.00640]。「長期」其實只看 w＝2 輪，而訓練對話平均有 4.61–5.25 輪 [arXiv:2502.00640]。
- **IN3 的執行評估可能偏向澄清組。** 「不必要」與「過於籠統」是對照澄清後的目標來判定，而模糊組從未拿到這些資訊 [arXiv:2402.09205]。精讀時查 XAgent repo，發現它最早的 README 就已有向使用者求助的工具，論文沒有說執行評估時這個工具是否啟用 [arXiv:2402.09205]。
- **GATE 缺非適應式對照。** 如果所有受試者都拿同一份 GPT-4 事先生成的固定問卷，可能就拿到大部分增益，所以論文無法證明互動與適應性本身是增益來源；「生成勝過池選」也只在內容推薦一個領域比較過 [arXiv:2310.11589]。
- **TOP 的小樣本比例被當成定值。** 「三成請求需要巢狀表示」只來自 100 筆人工樣本，95% 信賴區間約 22%–40%；三人都不一致的約 5.91% 語句直接丟棄，等於拿掉最模糊的樣本 [arXiv:1810.07942]。RNNG 對 CNN 的 exact match 只差 78.51 − 75.87 = 2.64 點、只跑一次，而 RNNG 只訓練 1 個 epoch，seq2seq 訓練 30–50 個 epoch [arXiv:1810.07942]。

## 與其他節點的關係

### E1 External Input（T6→T1）：使用者模擬器或真實使用者的輸入進入目標對齊

這條邊的標註由各篇精讀者自行決定，鬆緊不一。本章依各篇的 how 逐條判斷，分成四類：本節點裡輸入真的進入「問、答、再推斷」迴圈的；本節點裡只有靜態或單向輸入、缺了迴圈那一半的；其他節點裡把 T1 當受測物、量輸入品質的；以及標得太鬆、只沾到邊的。

**第一類：輸入進入迴圈，而且拿來訓練或評估（本節點）。**

- **GATE：真人與模擬器兩邊都做。** 主實驗是真人受試者，附錄是以 persona 提示的 GPT-4 模擬使用者；他們的回答累積成對話紀錄，直接成為預測器推斷偏好的規格，也是下一輪問題生成的條件 [arXiv:2310.11589]。它也是本節點唯一拿模擬結果對照真人結果做量化檢驗的，道德推理領域不一致 [arXiv:2310.11589]。
- **想像對話：模擬器同時是訓練資料的來源與評估對象。** GPT-3.5 依抽樣的 persona 扮演使用者，批判步強制「不主動暴露隱藏特質、只在對話中逐步透露」，產生的 50K 段對話是 agent 學習推斷目標的唯一訓練來源；評估另有 50 位持有隱藏正解活動的模擬使用者 [arXiv:2311.05584]。缺的一半是真人：使用者研究只有 12 人，而評估模擬器回答得太直接（作者自承）[arXiv:2311.05584]。
- **IN3：訓練用模擬器，測試換真人。** 訓練時由 GPT-4 扮演的 User-GPT 回答每一輪提問，分 passionate 與 succinct 兩種語氣，被問到偏好時自行編造具體答案；測試時換成 8 位真人自由回答 [arXiv:2402.09205]。兩半都有，但真人規模很小 [arXiv:2402.09205]。
- **STaR-GATE：模擬器是唯一資訊來源。** 握有隱藏 persona 的 Roleplayer 對澄清問題的回答，是 Questioner 推斷偏好的唯一來源，訓練與評估都經過這條流 [arXiv:2403.19154]。它換用 mistral-7b、gemma-7b 當模擬器，量 T1 策略對輸入來源的敏感度：win rate 分別為 65% 與峰值 62%，低於主設定的 72% [arXiv:2403.19154]。缺的一半是真人 [arXiv:2403.19154]。
- **Future Turns：模擬器的品質直接決定對錯。** k 位模擬使用者各自持有 Questioner 看不到的目標答案，對澄清問題給出回答；模擬器輸出 None 或洩漏答案時，該使用者直接判錯 [arXiv:2410.13788]。缺的一半是真人，而且評估模擬器拿得到答案 [arXiv:2410.13788]。
- **Clarify When Necessary：兩條流全是 LLM。** 一條是評估時被選中發問的輸入收到 GPT-3.5 依 gold 解讀生成的回答；另一條是 Intent-Sim 內部讓受測模型自己取樣 10 個使用者回答，當作意圖分布的樣本 [arXiv:2311.09469]。全程沒有真人。
- **Proactive Agent：迴圈閉在同一個 RM 上。** GPT-4o 模擬器依使用者設定產生活動，經 gym 轉成事件流，是 agent 推斷需求的唯一輸入；w/ RM 設定中，以 RM 為核心的使用者模擬器還會對初步預測給回饋，再進入 agent 修正最終預測 [arXiv:2410.12361]。精讀時依公開 repo 發現，建構訓練資料時 RM 的拒絕理由同樣會回饋給預測模型重試，而同一個 RM 又是評審 [arXiv:2410.12361]。
- **CollabLLM：訓練與評估同一個模擬器，另測真人。** 帶著隱藏目標的 GPT-4o-mini 模擬器被要求一開始只給模糊需求，模型要從不完整的輸入推斷目標；§6 換成 201 位 MTurk 真人，驗證行為能不能轉移 [arXiv:2502.00640]。精讀時發現訓練的往後模擬與評估用的是同一個模擬器、同一份提示詞 [arXiv:2502.00640]。

**第二類：只有靜態、預錄或單向的輸入，缺了迴圈那一半（本節點）。**

- **EVPI** 的輸入是真實 StackExchange 發文者尚未補齊資訊的貼文，答案模型預判「使用者會怎麼回」決定排序；資料是靜態單輪，沒有模擬器，也沒有多輪互動 [arXiv:1805.04655]。
- **Qulac** 的答案函數本質上是查表式的使用者模擬器：群眾外包的答案被內插進查詢語言模型，並作為對話歷史影響下一題；但查表不會隨對話產生新答案 [arXiv:1907.06554]。**ClariQ** 第一階段用預錄的使用者回答補齊意圖，第二階段的真人回答在 v1 只是規劃 [arXiv:2009.11352]。
- **CLINC150** 以群眾工作者充當代理使用者，刻意收集「對系統能力只有部分認知」時會說的 in-scope 與 OOS 查詢；**Mahalanobis** 的偵測器作用在每一則語句上，實驗只用離線單輪語料 [arXiv:1909.02027][arXiv:2101.03778]。
- **開放世界意圖**只示範 T1 端怎麼吸收 open-world 輸入，未標註的 OOD 查詢是靜態測試句、離線批次分群，不涉及輸入怎麼產生 [arXiv:2310.10176]。
- **描述式 zero-shot** 用 GPT-3 與 Parrot T5 離線合成每意圖 20 句使用者語句當訓練輸入，是最陽春的 T6 側輸入：單輪、一次性生成、不接收分類結果回饋；論文只以下游 in-scope accuracy 間接衡量合成語句的好壞，沒檢查它像不像真實使用者 [arXiv:2305.07157]。

本章歸納：這一類缺的是「使用者對系統輸出的反應」。拒識或分類錯了，沒有下一輪可以修正，所以這些論文量不到「拒識之後使用者改口」或「誤收之後使用者抱怨」這類後果 [arXiv:1909.02027][arXiv:2101.03778][arXiv:2310.10176][arXiv:2305.07157]。本節點其他計入的論文沒有標這條邊，它們也都只用靜態基準 [arXiv:1609.01454][arXiv:1902.10909][arXiv:2003.04807][arXiv:1809.00385][arXiv:1810.07942][arXiv:2010.05256]；其中 ProCoT 的澄清評估最極端，問題問出去之後沒有任何回答 [arXiv:2305.13626]。

**第三類：其他節點把 T1 當受測物，或量進入 T1 的輸入品質。** 本章歸納，這一類補的正是第一類缺的那一半：模擬器的效度。

- **模擬器與真人的輸入不一樣。** 以 τ-Bench retail 任務對照真人與 LLM 模擬使用者：模擬使用者的回合含問句的比例是 18.8%，真人是 9.8%；真人對話的失敗有 62.2% 歸因於使用者，模擬對話是 40.0% [arXiv:2601.17087]。精讀者在邊的標註裡據此認為，模擬器的輸入比真人更精確、更照指示，會高估目標對齊這一段的表現 [arXiv:2601.17087]。但精讀時也指出，真人端是在 Prolific 上照書面說明角色扮演的人，62.2% 可能部分反映閱讀說明與注意力的問題 [arXiv:2601.17087]。
- **模擬器洩漏目標，系統就不必推斷。** 對話推薦的 iEvaLM 模擬器在發話中說出目標標題，讓系統不必推斷使用者目標就能命中；改成只提供屬性、依系統意圖切換提示詞，才控制住進入目標理解環節的資訊量 [arXiv:2403.16416]。
- **提示出來的模擬器守不住原意圖。** 訓練型使用者模型與提示型模擬器相比：被 assistant 帶偏時，GPT-4o 當模擬器的 intent adherence 是 70.95，UserLM-8b 是 94.65；提示型模擬器也幾乎不會結束對話，GPT-4o 的對話結束 F1 只有 1.38 [arXiv:2510.06552]。精讀時指出，UserLM-8b 的低 Intent Coverage 混進了「使用者根本沒給必要條件」的效果，沒有和「使用者表達模糊、assistant 該問卻沒問」分開 [arXiv:2510.06552]。
- **資訊逐輪揭露時，模型會迷失。** 把單輪指令切成碎片、由模擬器逐輪揭露，15 個模型平均掉 39%，而一次給齊的 Concat 平均保有 Full 的 95.1% [arXiv:2505.06120]。這量的是意圖逐步補齊時 assistant 的表現，和本節點「何時問」的研究是同一條資料流的兩面（本章歸納）[arXiv:2505.06120]。
- **目標漂移在 T6 端有現成機制。** 神經使用者模擬器在系統回報查無結果時會改變目標，並在下一句說出新目標，等於對目標對齊端製造一次可控的目標漂移 [arXiv:1805.06966]。以規則模擬器訓出的策略換到它上面，成功率掉到 45.5% [arXiv:1805.06966]。
- **模擬器能暴露 T1 的盲點。** LLM 模擬器說出問價格、要電話、「現在就訂」這類正常說法，系統 NLU 判成空的 dialog act 就回 bye [arXiv:2306.00774]。古典任務型對話的模擬器，則以 error model 在 intent 與 slot 層刻意加噪 [arXiv:1612.05688]；另有模擬器只給自然語言、不給語意動作，讓系統在訓練時就面對意圖辨識誤差 [arXiv:2208.10817]。
- **使用者輸入直接改寫或修正目標。** 從真實使用者改述中學到的改寫，在 ASR 之後、NLU 之前替換原句，修的是進入意圖辨識的輸入本身 [arXiv:1911.02557]。使用者對「追蹤到的目標」的逐輪更正，直接成為目標追蹤的訓練標籤 [arXiv:1804.06512]。使用者的修改被轉成自然語言偏好，下次遇到相似脈絡時插回提示 [arXiv:2404.15269]。
- **agent 基準裡持有隱藏目標的模擬器。** τ-bench 的模擬器持有對 agent 隱藏的身分、意圖與偏好，逐步揭露需求，也會拒絕提供某些資訊 [arXiv:2406.12045]。ToolSandbox 刻意以模糊或缺參數的請求開場，要求 agent 追問 [arXiv:2408.04682]。τ²-bench 的 No-User 模式由 agent 自己操作所有工具；改回要指導使用者動手的 Default 模式，gpt-4.1 與 o4-mini 的 pass^1 分別下滑 18% 與 25% [arXiv:2506.07982]。精讀者在邊的標註裡認為，這個差距部分量的就是使用者這條通道的成本 [arXiv:2506.07982]。對話推薦的評估也需要模擬器回應系統的澄清 [arXiv:2305.13112]。可靠度研究則以改寫使用者措辭量 agent 是否仍理解同一個目標 [arXiv:2602.16666]。
- **只把 T1 當管線裡的一段。** 以目標為條件的模擬器把語句送進受測系統的 NLU 或 DST，系統只是受測物，論文不研究意圖偵測本身 [arXiv:2107.11904][arXiv:2204.00763][arXiv:2309.13233]。Schema-Guided Dialogue 只是離線資料生成加靜態評估，模型與模擬器之間沒有線上互動 [arXiv:1909.05855]。WebShop 的輸入是群眾工作者寫的一次性指令，沒有澄清也沒有模擬器互動 [arXiv:2207.01206]。

**第四類：標註太鬆，只沾到邊。**

- **安全分流不是目標對齊。** BlenderBot 3 對真實使用者訊息做安全分類與自傷、醫療主題檢查，偵測到就回罐頭訊息或轉移話題 [arXiv:2208.03188]。Llama Guard 在訊息進入 agent 之前判定 safe／unsafe 與違反類別 [arXiv:2312.06674]。兩者都是對輸入做分流，不是推斷使用者要什麼，本章判為只沾到邊。
- **注入攻擊把輸入端當成攻擊者可控。** 在使用者指令後附上「忽略先前指示」形式的注入，量目標被覆蓋的比例 [arXiv:2407.20859]。論文沒有使用者模擬器，也沒有討論怎麼從輸入中分出使用者真正的意圖，本章判為相關威脅而非目標推斷。
- **只有示範或實驗腳本。** Generative Agents 裡使用者以「內心聲音」輸入的話會成為 agent 的目標，但只有示範、沒有評估 [arXiv:2304.03442]。以 LM 模擬 Milgram 實驗時，模擬受試者的自由文字被分類成「是否終止」「是否服從」，再決定實驗腳本的下一步；形式上是對模擬輸入做意圖分類，但下游是實驗腳本而不是替使用者辦事的 agent [arXiv:2208.10264]。

**合起來看（本章歸納）。** 這條邊的兩半很少碰頭。本節點把迴圈閉起來的論文，用的多半是自己搭的模擬器，量化對照真人的只有 GATE [arXiv:2310.11589][arXiv:2403.19154][arXiv:2410.13788][arXiv:2502.00640]；其他節點驗證模擬器效度的論文，又把 T1 當成固定的受測物 [arXiv:2601.17087][arXiv:2510.06552][arXiv:2403.16416]。後者量到的偏差，例如模擬使用者問得更多、更照指示、較少結束對話、會洩漏目標，都還沒有被拿回來重估本節點「何時問」與「目標推斷」的結果 [arXiv:2601.17087][arXiv:2510.06552][arXiv:2403.16416]。

## 未解問題

1. **語意貼近已支援意圖的近鄰 OOS，以及「已知／新增／範圍外」的三向判斷。** Mahalanobis 分數的前提是 OOD 落在 ID 子空間之外的低變異方向，作者自己的錯誤分析顯示近鄰 OOD 正好違反這個前提 [arXiv:2101.03778]。卡在基準：精讀時發現 CLINC150 的 OOS 偏向領域外，ROSTD 的 OOD 多為風格明顯不同的 far-OOD [arXiv:1909.02027][arXiv:2101.03778]。SNIPS 多次隨機切分下的 FPR@95_OOD 是 12.3±10.3；作者把這麼高的變異歸因於相近意圖被拆到 ID／OOD 兩側，但錯誤分析只有定性舉例，沒有給這類切分的單獨數字 [arXiv:2101.03778]。也卡在協定：zero-shot 那篇只在新意圖集合上取 argmax、不拒識，拒識那兩篇假設意圖集合固定，開放世界那篇假設 OOD 已事先分出，沒有一篇的評估同時含既有、新增與範圍外語句 [arXiv:1809.00385][arXiv:1909.02027][arXiv:2101.03778][arXiv:2310.10176]。精讀時也發現，Mahalanobis 要估 768 或 1,024 維的共用共變異數，新增意圖只有個位數樣本時 Σ 容易奇異，這種情境沒測過 [arXiv:2101.03778]。

2. **「不作為」決策的操作點怎麼挑、怎麼量完整。** 要同時知道拒識的召回、拒識的精確度，以及已知意圖被誤拒的比例。卡在三處。CLINC150 假設 fallback 代價低，只量 OOS recall；Mahalanobis 那篇沒談部署時怎麼挑門檻 [arXiv:1909.02027][arXiv:2101.03778]。LLM 路由唯一報 OOS 的 [arXiv:2305.07157] 只報 recall，解析規則還把幻覺與格式錯誤算成 OOS；開放世界那篇把拒絕歸類當成錯誤、隨機指派 [arXiv:2305.07157][arXiv:2310.10176]。兩段式路由的誤差也沒被分解：top-5 檢索召回只報「超過 0.85」，等於最多約 1−0.85＝0.15 的查詢在檢索這一步就已失去正確意圖，論文沒有把錯誤拆成「檢索漏掉」與「LLM 判錯」[arXiv:2305.07157]。本節點沒有一篇提出能把「真拒答」「解析失敗」「拒答偏移」分開計分的評估協定，也沒有把誤拒與誤收一起算進任務完成率的端到端指標 [arXiv:1909.02027][arXiv:2101.03778][arXiv:2305.07157][arXiv:2310.10176]。

3. **有沒有能穩定勝過基準率的「何時問」偵測器。** 本節點多數「何時問」訊號離隨機或多數類基準不遠：Clarify When Necessary 各方法的 AUROC 在 0.371–0.628 之間 [arXiv:2311.09469]；精讀時依 Future Turns 的表格相減，它的提問決策在相同直接回答比例下 F1 只比隨機高 0.6–1.0，Ambig Acc 還低於多數類基準 [arXiv:2410.13788]；IN3 的模糊判斷準確率低於一律判模糊 [arXiv:2402.09205]。例外是 CollabLLM 在 Abg-CoQA 上的結果：模糊題與非模糊題的提問率差 52.84−(100−72.32)＝25.16 個百分點，高於 GPT-4o 的 15.44−(100−95.60)＝11.04 與 Llama 的 16.26−(100−90.40)＝6.66，分辨力確實有提升，代價是非模糊題也有 100−72.32＝27.68% 會提問（本章依 Table 2 重算）[arXiv:2502.00640]。ProCoT 是另一種情況：它在 PACIFIC 上的 CNP F1 28.0 遠低於微調 SOTA 的 86.9；精讀時指出論文沒報正類比例，所以看不出它離隨機多遠 [arXiv:2305.13626]。卡在兩處：標籤定義不一，有的用人工模糊標籤，有的用「澄清後會不會變好」，兩者不是同一件事 [arXiv:2305.13626][arXiv:2009.11352][arXiv:2311.09469]；aleatoric 與 epistemic 的分離只是動機，精讀時指出沒有在分別控制兩種不確定性的子集上驗證過 [arXiv:2311.09469]。

4. **回答端不失真的評估協定，以及模擬器的效度。** 本節點自動評估的回答端各有失真：回答者握有真人沒有的措辭或答案 [arXiv:1907.06554][arXiv:2410.13788]，問題來自 oracle [arXiv:2311.09469]，模擬器過度合作或被設定成模糊 [arXiv:2403.19154][arXiv:2502.00640]，候選集混進事後資訊 [arXiv:1805.04655]，或者根本沒有回答端 [arXiv:2305.13626]。卡在三處。沒有一篇做「模擬器只知道意圖、不知道答案」或「模擬器會拒答、含糊」的對照，精讀時把前者列為 Future Turns 最大的缺口 [arXiv:2410.13788]。真人評估規模小：想像對話 12 人、IN3 8 人、CollabLLM 201 人，Proactive Agent 的 agent 輸出完全沒有人工評估 [arXiv:2311.05584][arXiv:2402.09205][arXiv:2502.00640][arXiv:2410.12361]。評估還有循環：CollabLLM 訓練與評估同一個模擬器，Proactive Agent 同一個 RM 篩資料又當評審 [arXiv:2502.00640][arXiv:2410.12361]。其他節點已量到模擬使用者比真人更常發問、更照指示 [arXiv:2601.17087]，但這些偏差還沒被拿回來重估本節點的結果。

5. **發問成本與任務成功的交換率，以及何時停止。** 成本目前只以替代品表示：固定的發問比例 b [arXiv:2311.09469]、「平手時偏向直接回答」的規則 [arXiv:2410.13788]、token 數懲罰 [arXiv:2502.00640]、規劃中的 Naturalness 評分 [arXiv:2009.11352]。精讀時指出，Qulac 的評估沒有計入多問一回合的成本 [arXiv:1907.06554]；GATE 在形式化中有規格成本項，實驗卻固定 5 分鐘、沒有停止規則 [arXiv:2310.11589]。停止條件也沒被研究：EVPI 只看第一個澄清問題，Qulac 回合數固定，STaR-GATE 的輪數由外部在 1–3 之間抽樣，Future Turns 只處理一到兩輪，Clarify When Necessary 只問一次 [arXiv:1805.04655][arXiv:1907.06554][arXiv:2403.19154][arXiv:2410.13788][arXiv:2311.09469]。卡在量法：精讀時指出，Future Turns 沒有人工評估量使用者的負擔或滿意度，也沒有定義「多一輪值多少 F1」的綜合指標，所以它「選擇性提問的 F1 比一律提問低」到底划不划算，無從判斷 [arXiv:2410.13788]。有真人量測的兩篇也沒補上這個換算：GATE 以 1–7 的 Likert 量表量了主觀心力負擔，結果只以圖呈現 [arXiv:2310.11589]；CollabLLM 量了使用者花費的時間（比 Base 少 10.4%）與文件品質評分 [arXiv:2502.00640]。兩篇都沒有換算成「多問一輪值多少任務分數」的共同指標（本章歸納）[arXiv:2310.11589][arXiv:2502.00640]。

6. **推斷出的目標要怎麼表示，才能單獨檢查。** 隱含表示量不出推斷品質：精讀時指出，想像對話的 z 與 CollabLLM 的目標都只在模型狀態裡，one-shot success 同時混合了推斷與推薦兩件事 [arXiv:2311.05584][arXiv:2502.00640]。顯式表示會漏資訊：IN3 把約束壓進至多兩句話，總結涵蓋率 96.37%，精讀時換算約每 1 ÷ (1 − 0.9637) ≈ 27.5 項漏一項 [arXiv:2402.09205]。Proactive Agent 的輸出是一句自由文字任務，沒有意圖類別或槽位 [arXiv:2410.12361]。多意圖與組合式意圖也還沒有 LLM 版本的答案：LLM 路由的論文都停在單一意圖，[arXiv:2305.07157] 取補完中第一個意圖名，[arXiv:2310.10176] 重複分派只保留第一個；唯一處理多意圖的 [arXiv:2010.05256] 在標籤數上與平凡基準打平。TOP 的 Top-1 是 78.51、Top-5 升到 92.48，作者建議交給考量 agent 能力的 hypothesis ranker，但這個 ranker 沒有實作也沒有評估 [arXiv:1810.07942]。本章判斷，卡在傳統路線的結構化表示（意圖加 slot、樹）在 LLM 這一段被放掉，而新的表示還沒有配套的評估。

7. **使用者自己也不確定，或中途改變目標。** 本章歸納，目標推斷那組三篇的訓練目標都需要一個事先固定的目標或參考解才能計分，持有固定目標的模擬器也產生不出目標漂移 [arXiv:2311.05584][arXiv:2402.09205][arXiv:2502.00640]。反證已經有了：GATE 顯示使用者對自己偏好的內省不完整，CollabLLM 的真人研究觀察到使用者會中途改變方向 [arXiv:2310.11589][arXiv:2502.00640]。T6 端也已經有會在查無結果時換目標的模擬器 [arXiv:1805.06966]。卡在任務定義：沒有固定目標就不知道怎麼算「對齊成功」，所以本節點沒有一篇把目標漂移放進評估 [arXiv:2310.11589][arXiv:2311.05584][arXiv:2402.09205][arXiv:2410.12361][arXiv:2502.00640]。

8. **增益該歸給方法本身、強老師的蒸餾，還是更好的提示。** 各篇都缺關鍵對照。精讀時發現：想像對話的主要表格沒有 BC 對照 [arXiv:2311.05584]；CollabLLM 缺「用 GPT-4o 生成資料、但不經 MR 篩選」的對照 [arXiv:2502.00640]；IN3 的基底 checkpoint 與對照組不同 [arXiv:2402.09205]；GATE 缺非適應式的固定問卷對照 [arXiv:2310.11589]；[arXiv:2305.07157] 缺把 K 個例句放進 GPT-3 提示的對照。標籤語意也一樣：沒有一篇在同一資料集、同一模型上並排比較名稱、描述、範例三種載體，手寫描述又沒有開發集，無從排除對測試集調過 [arXiv:2010.05256][arXiv:2305.07157][arXiv:2310.10176]。本章判斷，這些對照補齊之前，「方法本身有效」與「用了更強的老師模型或更多監督」分不開。
