**E6 生產端與消費端的交叉核對（本文自己做，稽核員 3 補正過；T7 抽取時 T6 還不存在）**：把 T6 生產端的「該傳」逐項對 T7 消費端：

- **對得上**：模擬器的模型、版本、提示與溫度（兩端都列）；真人與模擬分開標記（兩端都列）；洩漏旗標（T6 產生，T7 另要自己掃）。
- **有缺口（推論，標 C）**：
  1. 逐輪環境或世界狀態快照：T7 要、T6 只給「判分用的終態」。沒有快照，T7-08 的過程檢查做不起來。
  2. 每一則訊息的原文（使用者或模擬器、agent、工具或環境回傳，附回合序號與發話方）：T7 要「每一則訊息」，T6 生產端只列終態與 agent 訊息；沒有模擬器發話原文，T7-09 的字串比對洩漏掃描與 T6-07 的逐回合稽核都沒有原料。
  3. 給模擬器的**目標原文**：T6 只傳「資訊等級」這個標籤，標籤不是目標內容，洩漏掃描需要原文。目標原文只進評估端紀錄，不進 E1（E1 擋的是 T1 端，與這條不衝突）。
  4. T7-10 的五項驗收（只靠紀錄不重跑 agent）：評審身分與版本、設定欄位（scaffold、預算、步數上限、基準版本、種子）、模擬器的 token 與呼叫數（T8-09 要算進成本），兩端都沒列；依 T7-10 自己的驗收，E6 目前列的欄位不及格。
  5. 反方向多出來、消費端沒收的欄位：T6 的「誰結束、為什麼結束」與逐回合模擬器稽核標記（critical 與否）；T6-07 要排除含 critical 模擬器錯誤的對話再算分，這一步在評估端做，所以 T7 端應該要收。
- **兩邊都要做、不能互相替代**：T6 產生洩漏旗標，T7-09 要求評估端自己再掃一次（規則 3）。
- **「不能傳」欄一致**：兩端都禁止模擬器自己判的成敗當評估標籤、禁止與訓練訊號同源的指標偽裝成獨立結果；T6 另外禁止用金標修補過的對話歷史，以 T6 為準。

**其他邊的同類缺口**（同一個核對方法，稽核員 3 指出；這裡列結論，欄位細節見上面各端的「該傳」）：

- **E1**：T1 消費端要每段輸入的來源標記（真人，或哪個模擬器與提示詞版本）；T6 的 E1 生產端只列逐輪話語、資訊等級與 persona，來源標記只出現在 E6。E1 生產端要補上來源標記。
- **E2**：T2 消費端要目標 key、操作類型、新值、修正來源、偵測器身分與誤判率、輪次；T5 生產端只給修正後的事實與來源、是否經外部驗證，缺 key、操作類型、輪次與誤判率。操作的列舉值取決於待決的 T2-08，先留空待量。
- **E3 兩端的詞彙方向相反**：T5 把「FPR」定義成把錯的放行、「FNR」是把對的判錯；T4 生產端的「誤報率」依 T4-02 是把無錯軌跡判成有錯，等於 T5 說的 FNR。照字面建欄位會兩端各指一件事。**統一寫法**：欄位一律寫成「把對的判錯的比率」與「把錯的放行的比率」，不用縮寫。
- **各邊沒有共同的連結鍵**：E3 的步驟索引、E5 的每一次修正嘗試、E6 的每集一筆之間，沒有共同的集 id、回合序號、步驟索引或修正嘗試 id，評估端接不起「同一集的修正紀錄與互動紀錄」。**建議（推論，C）**：所有邊的紀錄至少共用 `episode_id`、`turn_idx`、`step_idx`、`attempt_id`、`source`（真人或模擬器身分）五個欄位；八份抽取沒有任何一份量過這個，這是接線時要自己補的缺口。
