### 主幹五條箭頭 M1–M5（T1→T2→T3→T4→T7→T8）：推論的介面契約

**這一段整段是推論，每一條契約的等級都是 C。** 圖上實線的主幹不在調研一開始定義的六條邊裡（`data/topics.json` 只有 E1–E6），讀過的論文也沒有把這五條箭頭當邊來研究，所以上面的「該傳／不能傳」不是從文獻逐字彙整的，是從相鄰的決策卡與 E3–E6 的欄位推出來的。每一項都標出處卡；出處卡本身的等級照該卡的標題，不因為被引用而升級。

五條契約共用同一個理由，這個理由本身也是推論：**箭頭上的東西要寫成可單獨檢查的交接物，這樣上下游才量得開，不會把上游的錯和下游的錯混成一個成敗**。T1-10 對 M1 就是這樣說的（「目標推斷得對不對」要能單獨量），T7-10 對 M4 用「只拿紀錄、不重跑」來驗收，T3-05 要求一次只換觀測，其餘固定，都是同一個形狀。以下把這個形狀逐條套到五條箭頭上。

每條契約有四欄：**該傳**（箭頭上要有的欄位）、**不能傳**、**收到之後的驗收**（下游怎麼確認交接物夠用）、**缺口與待決**。驗收欄借用的是各卡已有的量法，不是新發明的量測；金標替換這類做法只能當診斷上限，不能當系統分數報（T2-05）。

##### M1　T1 → T2：把推斷出的目標交給狀態追蹤

- **該傳**：
  1. 顯式交接物：逐條列出使用者給的約束，外加一到兩句的明確目標；約束清單本身也交給下游保留核對，不只交一句壓縮過的自然語言（T1-10）。
  2. 閘門判定：放行、拒識、先問、輸出 null 之中的哪一種，以及該閘門在同一份測試集上量過的兩類各自正確率（T1-01、T1-02）；T2 要靠它分辨「這一輪沒有新的狀態可寫」和「T1 沒判出來」。
  3. 輸入的來源標記：真人，或哪一個模擬器與哪一份提示詞（E1 消費端；T1-08）。T2 的狀態分數要能只看真人子集、或換模擬器重評，就需要這個標記一路帶到 T2。
  4. 每一條約束出自第幾輪（T2-05 要求把分數按輪次序號拆開）。
- **不能傳**：答案字串、目標標題、與評分標籤同源的描述文字（T1-08、E1 的「不能傳」）；只有壓縮過的單句目標而沒有約束清單（T1-10）；系統自己提議、使用者沒有明確拒絕的值，不經標記就當成使用者的約束寫進去（T2-12 是待決，所以至少要標「隱含接受」，不能混成明說）。
- **收到之後的驗收**：T1 這一端用 T1-10 的做法單獨量目標推斷對不對；T2 這一端照 T2-05 的做法，歷史一律由受測系統自己產生，不用參考回覆重播，再另跑一次把 T1 的輸出換成金標，兩次的落差就是 T1 的錯誤傳到 T2 的量。
- **缺口與待決**：約束清單要不要直接等於 T2 的 schema 欄位，文獻沒有人量過；T2-03 只回答欄位要不要附描述。使用者中途改口時，交接物要用撤回或覆寫（T2-02 的撤回入口），舊值硬刪、標記失效或保留到讀取時裁決見 T2-08（待決）。多問一輪值多少、什麼時候停止發問見 T1-12（待決）。

##### M2　T2 → T3：把目前的狀態與該保留的指令交給觀測層

- **這是五條裡證據最薄的一條。** 沒有任何一張卡以「T2 交什麼給 T3」為題，也沒有卡以「T3 從 T2 接什麼」為題；下面的欄位只是把 T2 與 T3 各自有定論的卡拼在一起，拼法沒有論文驗過。
- **該傳**：
  1. 目前狀態：每個欄位的值、這個值是哪一輪寫入或更新的、來源是使用者明說還是外部修正（T2-02、T2-05）。
  2. 需要被保留的早先指令：多輪之後仍要被遵守的規定，連同它上一次被放進上下文的輪次（T2-10 量它有沒有漂移，T2-11 用重插來補救並要同時量能力成本）。
  3. 使用外部記憶時，取回的內容以什麼單位交（T2-09 的起手是原文的 round）。
  4. 狀態版本與追蹤器版本：T3 要評估觀測改動時，T2 這一端必須固定（見下面的驗收）。
- **不能傳**：金標狀態代替系統自己追蹤出的狀態（T2-05 的金標替換只能當診斷上限）；沒有過 T2-07 驗收的記憶寫入結果被當成已驗證的事實。
- **收到之後的驗收**：評估 T3 的改動時，照 T3-05 的做法在同一批任務上一次只換觀測，動作空間、模型、步數預算與 T2 追蹤器都固定；差距要同時高過什麼都不做的地板與重跑雜訊。換 T2 時反過來，T3 固定。
- **缺口與待決**：每輪是從完整歷史重算整份狀態，還是只算本輪變化（T2-04，待決），決定了這條箭頭交的是整份狀態還是差異。舊的觀測在上下文裡留多久、更早的要截斷、摺成一行還是做摘要（T3-02，待決），決定了 T3 會不會把 T2 剛交過來的東西擠出去。狀態裡哪些欄位算是「觀測」、哪些算是「記憶」，沒有卡定義過。

##### M3　T3 → T4：把模型實際看到的東西寫進軌跡

- **該傳**：
  1. 每一步的觀測，同時留兩份：工具或環境的原始回傳，以及經過介面改寫、模型實際看到的版本（T3-01 的改寫層是產生這兩個版本的地方）。章內看過工具自己的錯誤被摺成「沒有結果」（E3 T3 生產端的「不能傳」），只留改寫後的版本就查不出來。
  2. 模型實際讀到的欄位：有沒有推理、工具參數、工具輸出（T3-09；E3 T3 生產端）。監控器、評估端要知道它讀的是哪些。
  3. 被截斷、摺疊或摘要的標記：哪些舊觀測因為上下文上限沒進模型（T3-02 待決，所以先記錄，不假設做法）；T4-03 要求超出上下文或輸出無法解析的樣本留在分母裡算判錯，並另報比例，沒有這個標記就報不出。
  4. 監控器的逐步輸出：可疑分數、門檻與它怎麼校準、量測時的陽性比例（T3-07、T3-11；E3 T3 生產端）。
  5. 這一步在軌跡中的位置：步驟索引，以及多 agent 時負責的 agent 或 span id（E3 T4 生產端；格式見下）。
- **不能傳**：測試案例專屬的風險清單或欄位、評估用的地面真值（T3-08；E3 T3 生產端）；被監控模型自己對可疑片段的辯護；把監控分數接成訓練 reward（T3-10）；單步離線分數當觀測改動的驗收依據（T3-06，只當開發中的診斷）。
- **收到之後的驗收**：T4 這一端要能只靠軌跡回答「模型在這一步看到的是什麼」。做法借 T7-10 第二項：不重跑 agent，只拿紀錄重建每一輪的環境或世界狀態，原始回傳與改寫版本對得上才算交接成功。
- **缺口與待決**：軌跡用哪一種格式記錄、失敗用哪一套分類法標，文獻沒有答案（T4-08，待決）；所以這條契約只規定欄位，不規定格式。推理拿得到但被拿來當訓練目標時，監控器讀推理的訊號就不乾淨（T3-09、T3-10），這時第 2 項要標明推理已不可信。

##### M4　T4 → T7：軌跡就是評估端唯一的輸入

- **這是五條裡依據最多的一條**：T7-10（C）直接以它為題，T7-08（A）、T7-09（B）與 E5、E6 的消費端都在規定評估端要讀到什麼。但 T7-10 自己也是推論。
- **該傳**：
  1. 完整軌跡：每一輪每一則訊息的原文，附回合序號與發話方，加上每輪的環境或世界狀態快照（T7-10 第二項；E6 消費端）。只有終態、沒有過程的紀錄不及格（T7-08；E6 的「不能傳」）。
  2. 每一個判定出自哪個評審或判定器、哪個版本與提示（T7-10 第三項）；評審與受測模型是否同一家族（T7-05）。
  3. 設定欄位：scaffold、預算、步數上限、基準版本、種子（T7-10 第五項；T7-07 說不同設定的分數不能直接排名）。
  4. 偵測器的判定，連同位置與所用的命中定義與容忍度、異常類別與分類法版本、偵測器身分與版本、在含成功與失敗軌跡的集合上量到的兩種錯誤率（E3 T4 生產端；T4-02、T4-03）。T4-03 另要求記錄標籤版本，這裡一併帶上。
  5. 每一次修正嘗試的原始紀錄，含沒觸發的：修正前後的輸出、觸發判定與偵測分數、送出的回饋、呼叫次數與 token（E5 消費端）。
  6. 模擬使用者的身分、版本、提示與拿到的目標原文，真人與模擬分開標記（E6 消費端與本節 E6 缺口 3）。
  7. 這一份紀錄有沒有也被轉成訓練訊號（E5 消費端；T4-06）。
- **不能傳**：迴圈內的驗證器或評審自己的「修好了」判定當評估標籤（E5）；模擬器自己判的成敗當評估標籤（E6）；被跳過或解析失敗的軌跡被當成「正常」放行（E4 的「不能傳」）；進過訓練的樣本混進評估而不標記（E5）；只在失敗軌跡上評過的偵測器的位置被當成已驗證（E3 T4 生產端；T4-02）。
- **收到之後的驗收**：T7-10 的五項驗收原樣沿用：只拿紀錄、不重跑 agent，評估端要能一、重算報告裡的每個分數；二、重建每一輪的環境或世界狀態；三、指出每個判定出自哪個評審與版本；四、重跑洩漏稽核（T7-09）與平凡基準（T7-01）；五、讀到設定欄位。任一件做不到，這條箭頭的交接就不及格。
- **缺口與待決**：軌跡格式與失敗分類法（T4-08，待決）。多輪評估要用金上下文重播還是閉環、開放式任務沒有終態時 gold 從哪裡來（T7-11，待決），決定紀錄裡要不要同時存兩種歷史。E3、E5、E6 之間沒有共同的連結鍵（見上面「其他邊的同類缺口」），M4 是這個鍵最該落地的地方：每筆紀錄至少要有集 id、回合序號與步驟索引，才接得起同一集的偵測、修正與互動。

##### M5　T7 → T8：把判定結果與它的可信度交給計分

- **該傳**：
  1. 逐題、逐次重跑的原始結果，不要先彙整成單一成功率：每題要有重跑次數 n 與成功次數 c，才算得出 pass^k 與 pass@k（T8-05），也才算得出重跑標準差與以題目為單位的區間（T7-06、T8-06）。
  2. 分類別的結果與題數：每一類的題數、各類的平凡 agent 地板（什麼都不做、把資料全吐出來、隨機挑合法動作）（T7-01、T8-01）；T8 要算「按題數加權」「按類別等權」「拿掉不做事也能拿分的類別」三種總分（T8-08）。
  3. 判定器的兩種錯誤率，分開報、依難度或類別分層：偽陽性率與偽陰性率（T7-01、T8-03）；T7-12（待決）問的是這兩個率怎麼傳進任務層級的誤差棒，所以這裡只規定要傳，不規定怎麼用。
  4. 終態以外的檢查結果：回歸檢查與過程、禁止事件檢查的通過與否（T7-08）；比例不可忽略時，成功要改成終態與這兩項同時通過才算，M5 就要傳這兩項的分別結果，不是只傳合併後的成功。
  5. 受洩漏影響的成功要標出來，排除後重算分數與排名，兩個版本並列（T7-09）。
  6. 每次 run 的失敗原因與環境指紋：agent 出錯、限流、逾時、環境壞掉、判準出錯，以及時間、地區、瀏覽器、外部 API 版本；並寫明這些 run 是重跑、排除還是照算（T8-10）。
  7. 每次 run 的成本：包含失敗的 run、judge 或驗證器的呼叫、使用者模擬器，以及輸入與輸出 token；單價另存（T8-09）。
  8. 評分程式版本、任務集版本、步數上限、使用者模擬器與其溫度、聚合方式與刻度來源（T8-04；與 T7-10 第五項的設定欄位合併成一組）。
- **不能傳**：只有一個合併後的數字（T8-04、T8-08）；只跑一次的分數當成排名依據（T7-06）；沒有標明同源的評審判定（T7-05）；沒有重算的別人自報的同名指標（T8-04）；部分分數單獨當完成率（T8-07，要與二元成功率並列）；在多次 run 中取最好的一次（T8-05）。
- **收到之後的驗收**：T8 只拿 M5 的內容，不回頭去讀軌跡，要能做到：一、用同一份評分程式重算每一個分數（T8-04）；二、算出三種總分並看名次有沒有變（T8-08）；三、算出每一類的地板並與受測 agent 並列（T8-01）；四、算出誤差棒與 pass^k（T8-05、T8-06）。做不到哪一項，就回頭補 T7 該交的欄位。
- **缺口與待決**：T7-06 與 T8-06 都寫了區間與誤差棒，兩節的邊界沒有人劃過；這裡暫定「T7 交逐題逐次的原始結果，區間在算彙總的 T8 算」，這是推論。成功率、成本、使用者滿意度、失敗嚴重度要不要合成一個分數、嚴重失敗要否決還是扣分（T8-11，待決）；pass^k 的信賴區間與重跑變異怎麼拆成 agent 取樣、使用者模擬器、API 非確定性與環境漂移（T8-12，待決）。T8 是主幹的終點，沒有任何一條箭頭把分數送回去，見第 2 節的範圍說明。

**五條契約合起來的三個觀察（推論）**：

- **欄位會沿著主幹累積，不會在某一站消失**。M3 的第 1、3 項是 M4 第一項的前提；M4 第 2–3 項是 M5 第 3、8 項的前提。上游少記一個欄位，下游就補不回來，所以實作時應該從 M4 倒推需要的欄位，再往上游補。
- **五條契約裡能直接拿去驗收的只有 M4**：T7-10 給了一個不重跑 agent 的可執行檢查。M1 與 M2 的驗收是借 T2-05、T3-05 的金標替換與一次只換一件事，M3 與 M5 的驗收是我照 M4 的形狀仿寫的，沒有現成的量法。
- **M2 的缺口最大**，值得優先自己量：T2-04 與 T3-02 兩個待決題的答案，會直接改變這條箭頭交的是整份狀態還是差異、舊觀測留不留。
