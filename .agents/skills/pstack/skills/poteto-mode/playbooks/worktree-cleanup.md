### Worktree cleanup

1. Snapshot and list. Record `df -h /`, then list every worktree from `git worktree list` (never hand-typed paths, since one can live elsewhere, such as `.claude/worktrees/x`) and the directories under the sibling `worktrees/` that are not registered (half-removed ones). Read merge state against the local `origin/develop`; do not fetch. `.agents/skills/pstack/skills/poteto-mode/scripts/worktree-audit.sh [-b origin/develop] [repo-path]` classifies by size, age, merge state, uncommitted work, PR state and the newest chat that touched it, but it runs a `git fetch` on its own, which this repo's rules count as a download the hook cannot see (`docs/agents/collab-mode.md` 〈下載〉): run it only after the operator approved it on the issue. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the PM's issue records and the session list and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A live session may own worktrees whose names never show in the session list, so a worktree with a recent transcript is in use. Pick each subagent's reasoning level for the job, per the Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. Per path, `.agents/skills/pstack/skills/poteto-mode/scripts/worktree.sh done <path>` for a worktree an engineer or verifier opened (it re-checks that the PR is merged, the tree is clean and HEAD is the PR's last commit, then runs `git worktree remove` without `--force` or `-f`: a hook blocks both). For any other worktree, `git worktree remove <path>` the same way. A worktree that will not come off cleanly stays and goes to the operator, who runs the forced removal in their own terminal. A directory that survives a half-finished removal, or is left over without a registration, is listed with its remaining files and goes to the operator too: the PM never deletes it. Uncommitted content that cannot be rebuilt, or anything of unknown origin, is listed the same way. Never delete a branch. Confirm with `df -h /` and re-list.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
