You are working for the operator. The operator is the person this whole run works for, not the agent that wrote your kickoff. These rules hold for every task even where your kickoff does not repeat them. Your kickoff overrides one only when it says so in so many words.

- If you start an agent, the first line of its kickoff is `Read <path>/worker.md before anything else.`, with `<path>` the absolute path of the folder that holds this file.
- The repo's `AGENTS.md` and `docs/standards.md` hold for every task. Where they and pstack disagree, the repo wins.
- The bar in your kickoff is the whole bar. Add no check, gate, sign-off or review round above it, except the ones `AGENTS.md` sets.
- With no bar stated, the change must be no worse than its base and pass its own tests.
- Hold or block only for a failing run at this head or a bug a user would hit. Report a problem the base already has in one line.
- Never call a tool that shows a person a question. Make any choice you can undo, then say what you chose and why on the issue. Stop only for an action the **poteto-mode** Autonomy section says to pause for.
- Work in your own worktree, opened with `.agents/skills/pstack/skills/poteto-mode/scripts/worktree.sh new <type>/<name> <issue> [eng|ver]` (run it from the main checkout). It runs `git worktree add --no-track -b <type>/<name> <path> origin/develop` at the fixed location `<main checkout's parent>/worktrees/<eng|ver>-<issue>`, then `pnpm install --offline` and `pnpm run build:lib`. A hook blocks a `git worktree add` whose literal path does not have that shape (it cannot tell which `worktrees` folder sits next to the main checkout, and a path built from a variable or `$(...)` gets through, so the rule holds there too). Remove it with `worktree.sh done <path>` (`--open-ok` for a verifier whose PR is still open). A verifier does not use `new` (it branches off `develop`): it opens its worktree on the PR's code with `git worktree add --detach ../worktrees/ver-<pr> <head SHA>` from the main checkout, which the hook allows, and `done --open-ok` finds the PR by that SHA while it is still open. `done` refuses a PR that is not merged (`--open-ok` also accepts an open one), uncommitted content or a HEAD that is not the PR's last commit, never forces, and reports a half-removed directory instead of deleting it. Push with `git push origin HEAD:refs/heads/<branch>`, then check with `git ls-remote` that `develop` did not move. Never force-push.
- Keep context only in tracked files or the shared memory directory. Do not create `.claude/settings.local.json` in a worktree, and read `.env` from the main checkout.
- Downloads need the operator's approval. The one standing approval is `git fetch origin develop` (that remote and ref only) once before you cut your branch; after that, no fetch. `pnpm install` and `pnpm deploy` always take `--offline`; if that cannot run, leave it to CI. Never `git pull`, never a fetch without that exact remote and ref. Anything else that downloads: write the command and why on the issue, stop, and wait for the operator; the PM cannot approve for them. After approval, a command of a shape the hook below blocks is run by the operator in their own terminal, and neither you nor the PM runs it for them. A shape the hook does not block (for example `git fetch origin develop` to resolve a conflict) is run by the session that needs it. A hook (`.github/scripts/session_hooks.py pre-download`) blocks these git and pnpm shapes in Bash, Monitor and the Terminal panel. It does not catch other download commands or anything inside scripts, so the rule holds there too. See `docs/agents/collab-mode.md` 〈下載〉.
- Temp files, `--force`, npx: write, overwrite or delete temp files only in your own scratchpad, never `/tmp` or any shared temp directory. `git worktree remove` never takes `--force` or `-f`; if a worktree will not come off cleanly, write that on the issue and stop. Never `npx`, `npm exec` or `pnpm dlx`; run what is installed with `pnpm exec`. A hook blocks the common shapes in Bash, Monitor and the Terminal panel, but not paths it cannot resolve (relative, `$VAR`, `$(...)`) or a script that writes files itself, so the rule holds there too. When you start a subagent (no-comments included), copy these rules and the download rule into its prompt word for word. See `docs/agents/collab-mode.md` 〈指令護欄〉.
